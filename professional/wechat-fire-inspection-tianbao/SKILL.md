# 微信聊天记录转消防整改材料

甲方在群里发「314 号巡检发现 B2 车库东段 12 只烟感连续误报，限 3 月 15 日前处理完」，
施工回「收到」，三天后又来一句「别催」——
这些话**散在几百条聊天里，真正值钱的只有几句**。

这个技能把聊天记录倒进来，本机扫一遍，告诉你
**哪些问题归哪类设施、各多少条、哪几条已经超期、该找谁、推诿了没有、哪些系统反复出**，
再给你能直接抄的整改登记表、整改通知单和报监管话术。

## 硬边界（先读）

| 能做 | 不能做 |
|---|---|
| 按 10 类设施归类问题、抽数量与期限 | 不做消防技术鉴定（给口径，不定合格与否） |
| 算超期天数、标反复出现系统 | 不替你编造没发生过的问题 |
| 识别责任方与推诿表述 | 不代替消防救援机构/住建部门作认定 |
| 给整改单、回复单、投诉话术模板 | 不预测检查/验收结果 |
| 列材料缺口与补强渠道 | 不能伪造、剪辑记录 |

## 三步上手

```bash
# 1) 聊天记录导成本地文件，每行一条
python scripts/extract.py --file 聊天记录.md

# 场景：problem 隐患登记 | acceptance 验收备案 | duty 维保履职 | all 全部（默认）
python scripts/extract.py --file 聊天记录.md --scenario problem

# 2) 换基准日重算超期（比如按当天现场判断）
python scripts/extract.py --file 聊天记录.md --as-of 2026-04-01

# 3) 只看整改相关 / 只看推诿
python scripts/extract.py --file 聊天记录.md --focus 整改
python scripts/extract.py --file 聊天记录.md --focus 推诿
```

输入行格式：

```
[2026-03-08 14:20] 甲方老张: B2 车库东段 12 只烟感误报 限3月15日前处理完
[2026-03-08 14:35] 施工小李: 收到，3 月 15 日前换完
```

参数：

| 参数 | 说明 |
|---|---|
| `--file` | 聊天记录文件（.md / .txt），必填 |
| `--scenario` | problem 隐患登记 / acceptance 验收备案 / duty 维保履职 / all（默认） |
| `--as-of` | 超期判定基准日 YYYY-MM-DD，默认今天 |
| `--focus` | 只看含该词/类别的消息。类别：整改、隐患、验收、值班、推诿、升级 |
| `--format` | md（默认） / json |
| `--out` | 输出文件；不填打印到终端 |

## 报告八段

1. **结论先行** —— 覆盖率、问题条数、覆盖几类设施、数量合计、**超期条数**、7 天内到期条数
2. **要件命中表** —— 隐患 10 项 / 验收 8 项 / 维保 8 项，标**举证方在谁**
3. **缺失要件与补强方向** —— 书面期限去哪要、复检谁来做、台账谁保管
4. **⭐ 问题条目（按 10 类设施归类）** —— 发现日 / 系统 / 数量 / 期限 / 距到期 / 责任方 / 反复
5. **责任推诿与升级节点** —— 对方每条推诿原话 + 破了它往哪走
6. **关键节点** —— 问题提出、确认收到、承诺整改、责任推诿、修复完成、申请升级、书面单据
7. **关键证据片段**
8. **下一步行动清单**

## 三个别人不说的点

**一、一条消息里常报好几个问题，别合并。**
「2 只应急灯不亮，还有防火门闭门器坏了 3 个」是两个条目——
整体抽数量会变成 5，整改单直接写错。脚本按子句拆，各算各的。

**二、期限要书面，别信群里那句「限 3 月 15 日前」。**
口头期限在复议时等于没说。找他要**限期改正通知书/整改单**，
没有文书就问一句「那我按 3 月 15 日报给您确认一下，行吗」——让他落个字。

**三、反复出现的系统，比第一次出现更致命。**
同一个系统冒第三回，说明第一次「已整改」是假的。维保单位听到这句最紧张：
「你们巡检是怎么写的」。

## 跑出来长这样

```
- 抽出 8 条消防问题，覆盖 5 类设施（火灾自动报警×2、应急照明与疏散指示×2…）
- 提到数量合计 24
- ⚠️ 已过期限 3 条：火灾自动报警、消防给水与供水、未归类（需补设施类别）
- 反复出现的系统：应急照明与疏散指示（2 次）
```
