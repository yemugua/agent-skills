# 微信聊天记录转消防整改材料

群里一条：「314 号巡检发现 B2 车库东段 12 只烟感连续误报，限 3 月 15 日前处理完」
底下二十多条「收到」「明天来」「换好了」，
但真正撑得起一份整改单的只有几句：**哪天发现、哪、什么设施、什么故障、几只、限哪天、谁负责**。

这个技能把消防相关的聊天记录倒进来，本机跑一遍，告诉你
**问题归哪类设施、各多少条、哪几条已经超期、该找谁、推诿了没有、哪些系统反复冒**，
再给你能直接抄的整改登记表、整改通知单、投诉报监管话术。

---

## 为什么通用 AI 帮不上消防整改

把聊天记录贴给通用 AI，它给你一段「建议保留现场照片、注意留痕」的正确废话。
缺的是三样：**按设施系统归类**、**可复跑**、**聊天记录不出本机**。

- 通用 AI 看不见第 63 条「应急灯明天换，防火门这周找厂家」——
  这一条同时是 2 条独立问题、2 个责任方、2 个期限
- 通用 AI 每次问都要重贴全部记录，你没法让它反复核对「3 月那批到底改没改」
- 而且消防维保的沟通记录是甲方的，贴出去就不可控

这个技能在你机器上跑，Python 标准库，不联网、不上传。

## 三种角色，三套要件

| 场景 | 你站哪边 | 要证明什么 |
|---|---|---|
| **problem 隐患登记** | 现场/甲方/管理的 | 问题存在 + 数量 + 谁负责 + 期限 + 改完了 |
| **acceptance 验收备案** | 施工/甲方 | 审图→施工→检测→验收/备案 闭环 |
| **duty 维保履职** | 维保单位/单位 | 合同 + 巡检 + 派工 + 修复 + 值班记录 |

| all 全查 | 分不清是哪边 | 三套都扫一遍再定 |

共同骨架只有一句：**问题写清「部位 + 设施 + 故障 + 数量」四件套，落到书面，到期复检，留档。**

## 报告八段

1. **结论先行** —— 覆盖率、问题条数、覆盖几类设施、数量合计、**超期条数**、7 天内到期
2. **要件命中表** —— 隐患 10 项 / 验收 8 项 / 维保 8 项，**标了举证方在谁**
3. **缺失要件与补强方向** —— 书面期限去哪要、复检谁来做、台账谁保管
4. **⭐ 问题条目（按 10 类设施归类）** —— 发现日 / 系统 / 数量 / 期限 / 距到期 / 责任方 / 反复
5. **责任推诿与升级节点** —— 每条推诿原话 + 破了它往哪走
6. **关键节点** —— 问题提出、确认收到、承诺整改、责任推诿、修复完成、申请升级、书面单据
7. **关键证据片段**
8. **下一步行动清单**

## 最值钱的功能一：一句话多问题，不合并

「2 只应急灯不亮，还有防火门闭门器坏了 3 个」——
这是一个消息里的 **两个独立条目**，分别 2 只 / 3 个。
整体抽数量会变成 5，整改单写错，复检时指认不了。

脚本按子句拆：
- 「2 只应急灯不亮」→ 应急照明与疏散指示，数量 2
- 「防火门闭门器坏了 3 个」→ 防火分隔，数量 3

而且句子里说「3 层东区」的「3 层」**不会被当成设备数量**（2 只应急灯差点变成 5）。

## 最值钱的功能二：超期是自动算出来的

```
「限3月15日前处理完」said on 3/8 → 期限 2026-03-15
基准日 10/04 → 超期 202 天 → 报告里单独列
```

还有两条规则容易被忽略、但测出来才长记性的：

- **同月内说过去的日子 → 当年**。3 月 20 日说「限 3 月 15 日前」是当年 3 月 15，
  别自作聪明退到去年（第一版就是这么错的，测出 2025-03-15）
- **早了 6 个月以上才判跨年**（12 月说的「3 月 10 日前」→ 退一年）

## 最值钱的功能三：反复出现的系统

同一个系统冒第三回，说明第一次「已整改」是假的。
报告会标「反复」，并把它推到行动清单第一条——
维保单位听到「你们巡检是怎么写的」这句，比罚款还紧张。

## 10 类设施，问题归类不细就写不出可验收的描述

火灾自动报警 / 自动喷水灭火 / 消火栓系统 / 灭火器等消防器材 / 防烟排烟 /
应急照明与疏散指示 / 防火分隔 / 消防给水与供水 / 消防通信与广播 / 消防控制室与值班

> 归类不细 → 复检时对方一句「没改到位」把你打回来。
> 写问题要写「**部位 + 设施 + 具体故障 + 数量**」：
> 「3 层东区 12 只感烟探测器 3 月 8 日 14:20 起连续误报，疑似积灰」
> ——不是「烟感有问题」。

## 三个最容易翻车的点

**第一层：只发微信、不落书面。**
微信是证据，但**闭环凭证在整改单**上：编号、发出日、签收人、验收人签字，缺一份都不算闭环。

**第二层：消防泵、阀门被关了没人管。**
这是最典型、最容易罚的项，也是检查当场最先问的。

**第三层：控制室值班记录补一个月。**
每日 24h、每班不少于 2 人、持证上岗——**记录缺一天比某个烟感坏掉更扎眼**，因为它证明的是「你根本没做」。

## 参数怎么用得上

```bash
# 全量扫描（默认 all）
python scripts/extract.py --file 聊天记录.md

# 只看隐患登记，换基准日重算超期
python scripts/extract.py --file 聊天记录.md --scenario problem --as-of 2026-04-01

# 对方一直拖，只看推诿/拖延
python scripts/extract.py --file 聊天记录.md --focus 推诿

# 只看验收/备案相关
python scripts/extract.py --file 聊天记录.md --focus 验收

# 拿去别处处理
python scripts/extract.py --file 聊天记录.md --format json --out out.json
```

## 边界在哪

- 它是**材料整理与留痕口径**，不是消防技术鉴定
  —— 定合格与否、定重大隐患要素，得报消防救援机构或请专业人士复核
- 它给规则口径（10 类设施、整改闭环六步、值班硬性周期、处罚速查），不给检测结论
- 它不替你编事实——需要现场确认的一律标【待现场填写】
- 法规版本会更新（消防验收按住建部令口径、各地抽查比例不同），
  **提交前核一下现行版本**，别引用废止条文

需要先把微信本地聊天库导出来的，配套技能 `wechat-local-reader-tianbao` 是同样的零上传本地方案。
