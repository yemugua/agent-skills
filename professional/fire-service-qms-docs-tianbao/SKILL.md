# 消防技术服务质量体系（QMS）认证材料

给消防维保 / 检测 / 评估类技术服务机构用：**把散落的现状信息（人员、设备校准、
已有体系文件、项目记录）整理成一份能拿去答辩的受控文件包自查报告。**

和市面上通吃的「ISO9001 文件生成器 / 内审助手」不同，这一套是**消防技术服务行业专用**：
要素表按消防维保/检测/评估的业务过程铺，内置人员资质（注册消防工程师、消防设施操作员、
社保关系）与测量溯源（校准证书）两条特有红线，以及 2026 版认证规则的排期硬约束。

## 硬边界

- 只做**文件与记录层面**的符合性自查，用于补齐受控文件包、识别认证风险；
  **不替代现场核查，也不给出认证结论**——最终以认证机构现场审核为准。
- 不替你编造任何真实数据。填不出的字段一律写【待现场填写】。
- 「已有体系文件」段只填**真实存在**的文件；凑数会让脚本低估风险。
- 不联网、不读客户资料、不碰现场设备；输入一个 md，输出一个 md + 可选 json。

## 三步上手

1. **填现状表**：复制 `templates/机构现状信息采集表.md`，按分节填本机构真实信息。
   分节标题保持「## 人员」「## 设备与校准」「## 已有体系文件」「## 项目与服务记录」。
2. **跑脚本**：

   ```bash
   python scripts/qms_check.py --file 现状.md --today 2026-10-04 --json qms.json
   ```

   --today 可省略（默认系统当天）。跑完会打印一份八段式报告。
3. **人工复核**：拿 `templates/要素覆盖度核查表.md` 逐条过一遍，
   再用 `templates/内审检查表与不符合项闭环.md` 把补件做成真正的内审记录。

## 报告八段

| 段 | 内容 | 主要看什么 |
|---|---|---|
| 一 | 结论摘要 | 当前能不能申报、缺失几项、人员/设备/内审/management review 概览 |
| 二 | 要素覆盖度矩阵 | 14 个过程要素的「已建立 / 部分覆盖 / 缺失」 |
| 三 | 人员资质与到期预警 | 谁过期、谁 90 天内到期 |
| 四 | 设备校准溯源台账 | 逐台超期天数、临期 90 天清单 |
| 五 | 内审与管理评审 | 上次日期、距今天数、是否超 12 个月、下次动作 |
| 六 | 认证时间线 + 2026 新规 | 一二阶段 ≥5 天、审核员年 180 天上限等排期约束 |
| 七 | 补件清单 | 建议受控文件编号、关联要素、责任人（建议编号从 DXCX40 之后起，避免撞号） |
| 八 | 高风险项 | 会直接导致审核不通过的项 + 逐条处置建议 |

## 输入格式

```markdown
## 基本信息
机构名称：上海度消技术咨询有限公司
上次内审：2025-11-20
上次管理评审：2025-12-05

## 人员
- 吴涛，总经理，一级消防工程师，证书有效期 2028-06-30
- 林凤钦，技术负责人，一级消防工程师，证书有效期 2027-09-15
- 张红星，消防设施操作员（四级），证书有效期 2025-08-01

## 设备与校准
- 数字万用表，校准号 JLSZ-2025-0118，校准日期 2025-04-10，有效期至 2026-04-09
- 声级计，校准号 JLSZ-2024-0902，有效期至 2025-09-30

## 已有体系文件
- DXCX01 文件控制程序
- DX/JL013-A 客户回访登记表
- 57 份设备校准证书

## 项目与服务记录
- 佰联二期消防维保，2025-03 至 2026-02
```

日期支持 `2026-04-09` / `2026/4/9` / `2026年4月9日` / `2026.4.9`。

## 判定口径（脚本内置）

- **要素覆盖度**：在「已有体系文件 + 项目记录」文本里做关键词命中统计。
  ≥2 处 = 已建立，=1 处 = 部分覆盖（只有文件或只有记录），=0 处 = 缺失。
  单条文件最多被 3 个要素引用，避免一份模板文件刷分。
- **超期天数**：`剩余天数 = 有效期 - 今天`，负数即超期；≤90 天标临期。
  **报告里显示的是负值**，如 -178 表示已超期 178 天。
- **年度周期**：上次日期 +1 年，跨年不进位；二月末按 28 日兜底。
- **补件编号**：从 `DXCX41` 起顺排，记录类用 `DX/JL` 系列，均为建议值，
  最终以本机构《文件控制程序》为准。
