# 火灾案例库与事故分析（fire-case-analysis）

> 领域：消防 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据火灾事故调查规定与案例复盘方法，生成清单：案例信息要素结构化、起火原因与蔓延路径还原、管理原因与暴露问题、教训转化为检查条款、培训教材与定期复盘。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 火灾案例分析
- 火灾事故复盘
- 典型案例库
- 警示教育材料
- 事故原因还原

## 三、工作流
1. 结构化整理案例信息要素
2. 还原起火原因与蔓延路径
3. 分析管理原因与暴露问题
4. 将教训转化为检查条款
5. 编制教材并定期复盘

## 四、核心内容（检查清单与判定）
案例分析的终点不是讲个故事，而是沉淀为可执行条款。若复盘中只追设备原因不追管理原因，同类事故几乎必然重演。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含案例信息要素结构化 | 要素 |
| Q2 | FAIL | 未含起火原因与蔓延路径还原 | 还原 |
| Q3 | FAIL | 未含管理原因与暴露问题 | 管理原因 |
| Q4 | WARN | 未含教训转化为检查条款 | 转化 |
| Q5 | WARN | 未含培训教材与定期复盘 | 复盘 |

> 脚本 `fire-case-analysis_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python fire-case-analysis_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python fire-case-analysis_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
