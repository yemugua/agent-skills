# 检测实验室 ISO/IEC 17025 体系（iso17025-system）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 CNAS-CL01 / ISO/IEC 17025，生成清单：公正性与保密承诺、人员能力与授权、方法选择与验证确认、设备计量溯源与期间核查、结果报告与申诉处理。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- ISO/IEC 17025
- CNAS-CL01
- 检测实验室体系
- 方法验证确认
- 公正性风险控制

## 三、工作流
1. 建立公正性与保密承诺
2. 确认人员能力与授权范围
3. 完成方法选择与验证确认
4. 保证计量溯源与期间核查
5. 规范结果报告与申诉处理

## 四、核心内容（检查清单与判定）
17025 除了技术要求，更强调公正性与保密。利益冲突未识别、报告随意修改、投诉不闭环，是评审中常见的不符合来源。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含公正性与保密承诺 | 公正性 |
| Q2 | FAIL | 未含人员能力与授权 | 授权 |
| Q3 | FAIL | 未含方法选择与验证确认 | 方法验证 |
| Q4 | WARN | 未含计量溯源与期间核查 | 期间核查 |
| Q5 | WARN | 未含结果报告与申诉处理 | 申诉 |

> 脚本 `iso17025-system_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python iso17025-system_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python iso17025-system_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
