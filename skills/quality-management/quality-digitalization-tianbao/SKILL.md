# 质量信息化与系统建设（quality-digitalization）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据质量管理体系信息化实施方法，生成清单：业务痛点与需求范围、数据模型与编码统一、系统集成接口（ERP/MES/PLM）、报表与看板设计、权限合规与数据备份。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 质量信息化
- QMS 系统建设
- 质量数据看板
- 质量系统选型
- MES 质量模块

## 三、工作流
1. 梳理痛点与需求范围
2. 统一数据模型与编码
3. 打通系统集成接口
4. 设计报表与质量看板
5. 落实权限合规与数据备份

## 四、核心内容（检查清单与判定）
信息化失败多因「把线下坏流程搬到线上」。先做流程优化与编码统一再上系统，同时约定接口口径与备份策略，才能避免形成新的数据孤岛。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含痛点梳理与需求范围 | 需求 |
| Q2 | FAIL | 未含数据模型与编码统一 | 编码 |
| Q3 | WARN | 未含系统集成接口设计 | 接口 |
| Q4 | WARN | 未含报表与看板设计 | 看板 |
| Q5 | FAIL | 未含权限合规与数据备份 | 备份 |

> 脚本 `quality-digitalization_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python quality-digitalization_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python quality-digitalization_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
