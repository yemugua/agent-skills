# 新品试产管理（npi-trial-run）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据先期质量策划与试产管控方法，生成清单：试产方案与准入条件、物料与工装准备确认、过程参数记录与偏差、试产问题清单与责任闭合、量产放行评审。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 新品试产
- NPI 试产管理
- 试产方案
- 试产问题清单
- 量产放行评审

## 三、工作流
1. 编制试产方案与准入条件
2. 确认物料与工装准备
3. 记录过程参数与偏差
4. 形成问题清单并闭合
5. 组织量产放行评审

## 四、核心内容（检查清单与判定）
试产的目的是暴露问题而非赶产量。把试产当生产跑、问题不闭环就放行量产，是新品上市后批量返工和质量事故的主要来源。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含试产方案与准入条件 | 方案 |
| Q2 | FAIL | 未含物料与工装准备确认 | 工装 |
| Q3 | WARN | 未含过程参数与偏差记录 | 参数 |
| Q4 | FAIL | 未含问题清单与责任闭合 | 闭环 |
| Q5 | WARN | 未含量产放行评审 | 放行 |

> 脚本 `npi-trial-run_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python npi-trial-run_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python npi-trial-run_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
