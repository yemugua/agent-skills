# 供应商质量提升与帮扶（supplier-quality-improvement）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据供应商开发与目标管理方法，生成清单：绩效排名与分级策略、共性缺陷与要因诊断、联合改善项目与目标、过程能力帮扶与验证、升级处置与退出机制。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 供应商质量提升
- 供应商帮扶计划
- 供应商分级管理
- 来料缺陷改善
- 供应商淘汰

## 三、工作流
1. 开展绩效排名与分级策略
2. 诊断共性缺陷与要因
3. 实施联合改善项目并设目标
4. 提供过程能力帮扶与验证
5. 升级处置并明确退出机制

## 四、核心内容（检查清单与判定）
只开罚单不派技术支持，供应商往往把成本转嫁回去或阳奉阴违。分级施策、对有潜力的供应商做过程帮扶，才能真正降低来料风险。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含绩效排名与分级策略 | 分级 |
| Q2 | WARN | 未含共性缺陷与要因诊断 | 诊断 |
| Q3 | FAIL | 未含改善项目与目标设定 | 项目 |
| Q4 | WARN | 未含过程能力帮扶与验证 | 帮扶 |
| Q5 | WARN | 未含升级处置与退出机制 | 退出 |

> 脚本 `supplier-quality-improvement_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python supplier-quality-improvement_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python supplier-quality-improvement_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
