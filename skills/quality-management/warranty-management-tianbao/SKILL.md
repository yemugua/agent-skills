# 保修与三包质量管理（warranty-management）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据产品保修政策与家用汽车及消费品三包规定，生成清单：保修范围判定与免责条款、索赔数据统计分析、失效责任划分与供应商追偿、保修备件管理、政策修订与顾客沟通。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 产品保修管理
- 三包政策
- 保修索赔分析
- 供应商追偿
- 保修备件管理

## 三、工作流
1. 判定保修范围与免责情形
2. 统计索赔数据并分析趋势
3. 划分失效责任并追偿
4. 管理保修备件供应
5. 修订政策并沟通顾客

## 四、核心内容（检查清单与判定）
保修成本若不能逆向追溯到供应商与内部原因，就只能当费用处理。建立索赔到零部件再到批次的链路，追偿才有依据。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含保修范围与免责判定 | 范围 |
| Q2 | FAIL | 未含索赔数据统计与分析 | 索赔 |
| Q3 | WARN | 未含责任划分与供应商追偿 | 追偿 |
| Q4 | WARN | 未含保修备件管理 | 备件 |
| Q5 | WARN | 未含政策修订与顾客沟通 | 沟通 |

> 脚本 `warranty-management_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python warranty-management_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python warranty-management_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
