# 失效分析技术与流程（failure-analysis）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据失效分析通用流程，生成清单：现场保护与失效现象收集、宏观检查与无损检测、断口与显微分析、机理分析与复现验证、纠正措施与水平展开。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 失效分析
- FA 分析报告
- 断口分析
- 金相检验
- 失效机理

## 三、工作流
1. 保护现场并收集失效现象
2. 开展宏观检查与无损检测
3. 进行断口与显微分析
4. 推定失效机理并复现验证
5. 制定纠正措施并水平展开

## 四、核心内容（检查清单与判定）
一旦破坏了原始断口或先入为主猜结论，失效分析基本失败。坚持「先取样保存、再看现象推论、最后复现验证」，才能避免反复走弯路。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含现场保护与现象收集 | 现象 |
| Q2 | WARN | 未含宏观检查与无损检测 | 无损 |
| Q3 | WARN | 未含断口与显微分析 | 显微 |
| Q4 | FAIL | 未含机理分析与复现验证 | 复现 |
| Q5 | FAIL | 未含纠正措施与水平展开 | 水平展开 |

> 脚本 `failure-analysis_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python failure-analysis_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python failure-analysis_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
