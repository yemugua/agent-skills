# 售后与现场质量分析（field-quality-analysis）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据早期故障与市场失效分析方法，生成清单：故障信息采集与要素完整、失效件回收与检验、帕累托故障模式分布、浴盆曲线与浴盆期判断、改进闭环与顾客通报。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 售后质量分析
- 早期故障率
- 市场退货分析
- 失效件回收
- 售后故障模式

## 三、工作流
1. 采集故障信息并确保要素完整
2. 回收失效件并开展检验
3. 统计故障模式分布
4. 判定浴盆曲线所处阶段
5. 推动改进闭环并通报顾客

## 四、核心内容（检查清单与判定）
售后数据是改进的金矿，前提是信息要素完整：机型、批次、使用时长、环境。要素缺失会让分析无法收敛，最终只能笼统归因。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含故障信息采集与要素完整 | 要素 |
| Q2 | FAIL | 未含失效件回收与检验 | 回收 |
| Q3 | FAIL | 未含故障模式分布统计 | 分布 |
| Q4 | WARN | 未含浴盆曲线阶段判定 | 浴盆曲线 |
| Q5 | WARN | 未含改进闭环与顾客通报 | 通报 |

> 脚本 `field-quality-analysis_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python field-quality-analysis_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python field-quality-analysis_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
