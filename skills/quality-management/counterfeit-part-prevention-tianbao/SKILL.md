# 假冒伪劣件防范（counterfeit-part-prevention）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据防假冒件与供应链追溯要求，生成清单：可疑件定义与报告流程、供应商资质与授权链核验、到货外观与标识比对、开封检验与破坏性验证、隔离封存与溯源处置。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 假冒件防范
- 伪劣零件识别
- 可疑件处置
- 授权经销核验
- 到货标识比对

## 三、工作流
1. 定义可疑件并建立报告流程
2. 核验供应商资质与授权链
3. 开展到货外观与标识比对
4. 实施开封检验与破坏性验证
5. 隔离封存并溯源处置

## 四、核心内容（检查清单与判定）
假冒件往往外观足以乱真，但包装标识、材质与追溯码经不起比对。建立信任代理清单并保持可疑件强制报告，是低成本有效的防线。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含可疑件定义与报告流程 | 报告 |
| Q2 | FAIL | 未含供应商资质与授权链核验 | 授权链 |
| Q3 | WARN | 未含到货外观与标识比对 | 比对 |
| Q4 | WARN | 未含开封检验与破坏性验证 | 验证 |
| Q5 | FAIL | 未含隔离封存与溯源处置 | 隔离 |

> 脚本 `counterfeit-part-prevention_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python counterfeit-part-prevention_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python counterfeit-part-prevention_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
