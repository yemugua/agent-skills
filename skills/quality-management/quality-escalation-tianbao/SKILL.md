# 重大质量问题升级与响应（quality-escalation）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据危机管理与顾客投诉处理要求，生成清单：升级判定标准与等级、响应组织架构与授权、时效要求与信息通报、围堵遏制与根因处理、客户沟通与复盘纠偏。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 质量问题升级
- 重大客诉响应
- 召回预警判定
- 围堵遏制措施
- 质量事故通报

## 三、工作流
1. 设定升级判定标准与等级
2. 组建响应组织并授权
3. 明确时效与信息通报
4. 执行围堵遏制与根因处理
5. 做好客户沟通与复盘纠偏

## 四、核心内容（检查清单与判定）
升级机制失效通常因为判定标准模糊与怕担责任而压着不报。事先约定硬触发条件与有权叫停的人，才能在小时级窗口内止损。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含升级判定标准与等级 | 判定 |
| Q2 | FAIL | 未含响应组织与授权 | 授权 |
| Q3 | FAIL | 未含时效要求与信息通报 | 时效 |
| Q4 | FAIL | 未含围堵遏制与根因处理 | 围堵 |
| Q5 | WARN | 未含客户沟通与复盘纠偏 | 复盘 |

> 脚本 `quality-escalation_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python quality-escalation_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python quality-escalation_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
