# 顾客验厂与社会责任审核（customer-factory-audit）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据二方审核与社会责任守则要求，生成清单：审核范围与检查表确认、劳工与人权合规要点、健康安全与环境要求、文件与现场一致性、整改计划与回复时限。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 顾客验厂
- 二方审核
- 社会责任审核
- 人权验厂
- 验厂整改回复

## 三、工作流
1. 确认审核范围与检查表
2. 核查劳工与人权合规要点
3. 核查健康安全与环境要求
4. 核对文件记录与现场一致性
5. 编制整改计划并按时回复

## 四、核心内容（检查清单与判定）
验厂翻车多因文件与现场不一致：工资表与考勤对不上、消防记录后补。临时做假远比平时把基础台账做扎实风险更高。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含审核范围与检查表确认 | 范围 |
| Q2 | FAIL | 未含劳工与人权合规要点 | 劳工 |
| Q3 | WARN | 未含健康安全与环境要求 | 健康安全 |
| Q4 | FAIL | 未含文件与现场一致性核对 | 一致性 |
| Q5 | WARN | 未含整改计划与回复时限 | 时限 |

> 脚本 `customer-factory-audit_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python customer-factory-audit_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python customer-factory-audit_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
