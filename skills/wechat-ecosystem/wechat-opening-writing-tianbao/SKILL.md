# 公众号文章开头写法与留存核查（wechat-opening-writing）

公众号文章的打开率由标题决定，**完读率由开头决定**。开头三行决定读者是否往下滑。

这个技能做三件事：**用五类写法写出前 3 秒钩子** → **控制首段的信息密度与句长** → **避开四类把人赶走的写法**。

---

| 能做 | 不能做 |

| 给出首段字数与句长控制标准 | ❌ 保证文章被推荐或获得多少阅读 |
| 标出开头与标题重复、开头过长等问题 | ❌ 代写整篇公众号文章 |
| 给出长短句节奏规则与改写方法 | ❌ 指导标题党、诱导分享或虚假承诺 |
| 给出完读率排查顺序 | ❌ 指导抄袭、洗稿或搬运他人内容 |

- 平台算法与推荐规则会调整 —— 本技能只提供写作方法，不涉及刷量、诱导分享等违规手段

## 二、完整工作流

```
第 1 步  确定文章的核心承诺：读者看完能得到什么（写一句话）
第 2 步  用 rules/opening_types.md 的五类写法拟 3 个开头备选
第 3 步  跑脚本体检：python scripts/opening_check.py --file article.json
第 4 步  看四个数：首段字数、句长分布、标题重复度、开头信息点密度
第 5 步  按 rules/sentence_rhythm.md 调句长：前长后短或前短后长，形成节奏
第 6 步  按 §六 避开四类写法，改掉自我介绍式开场
第 7 步  发布前人工确认（§八）
```

**顺序不能颠倒**：开头必须先有「核心承诺」，再选写法。没有承诺的开头就是自我介绍。

## 三、五类开头写法（前 3 秒钩子）

### 写法一：结论先行型

```
结构：一句话给出核心结论 + 为什么值得往下看

示例：
「这篇讲的不是方法论，是三个可以直接抄的操作。
 看完你今天下午就能改掉 XX 环节的重复劳动。」

适用：教程、复盘、干货类
优点：读者立刻知道能得到什么
```

### 写法二：场景切入型

```
结构：还原一个具体场景 + 引出这个场景的普遍性

示例：
「周三晚上十点，第七版方案改到第 3 页。这时候你会发现一个规律：
 越是改到后半程，越容易改回去。」

适用：故事、观察、行业分析
优点：具体场景比抽象论述留人更久
```

### 写法三：数字清单型

```
结构：给出数量 + 每个的数量 + 第一个是什么

示例：
「我复盘了最近半年做的 40 份方案，
 总结了 3 个共同问题。第一个是：目标写得越具体，改稿越多。」

适用：清单、总结类
优点：数量给出预期管理，降低读者跳出
```

### 写法四：反常识型

```
结构：一个违反直觉的判断 + 站得住的解释

示例：
「写得越详细，改稿越多。
 过去半年我统计了 40 份方案，方向越明确的那批，
 反而平均少改 1.8 版。原因其实很简单。」

适用：观点、行业分析
优点：认知冲突制造阅读张力
```

### 写法五：提问切入型

```
结构：一个读者正在经历的问题 + 暗示本文能回答

示例：
「为什么你写的方案总是改到第七版？
 不是写得不好，是你在写别人要的结果。」

适用：问题导向、答疑类
注意：问题必须后文真的回答
```

### 开头标准

| 项 | 标准 | 说明 |
|---|---|---|
| 长度 | 首段 80-150 字 | 移动端首屏约 4-5 行 |
| 信息点 | 1 个核心承诺 + 1 个信息钩子 | 不要塞三个论点 |
| 句长 | 首句 15-30 字 | 一口气能读完 |
| 重复度 | 与标题重合 ≤ 40% 字面 | 重复会让读者觉得「我已经知道了」 |
| 自我介绍 | 不出现 | 「大家好我是」是完读率杀手 |

## 四、首段信息密度控制

**信息密度 = 首段信息点数 ÷ 首段句数**，建议 0.5-1.0，即每 1-2 句给一个有效信息。

| 密度 | 表现 | 判定 |
|---|---|---|
| 过低 | 首段全是铺垫、背景、来历 | 读者滑走 |
| 适中 | 每 1-2 句一个新信息 | 合格 |
| 过高 | 首段塞满 5 个以上论点 | 读者记不住 |

**首段必须包含的三件事（缺一件就有问题）：**

| # | 内容 | 缺失后果 |
|---|---|---|
| 1 | **核心承诺**（读完能得到什么） | 读者不知道为什么要读下去 |
| 2 | **相关性**（为什么和我有关） | 读者觉得与自己无关 |
| 3 | **阅读指引**（往下的结构是什么） | 长文读者中途放弃 |

## 五、长短句节奏

### 节奏规则

| 规则 | 说明 |
|---|---|
| 开篇宜短 | 首句 15-30 字，一口气读完 |
| 论述宜长 | 展开段可用 30-50 字长句承载逻辑 |
| 转折宜短 | 转折句用短句，10-15 字，力度最强 |
| 结尾宜短 | 收尾句短，形成落点 |
| 忌全程长句 | 全是长句会让人疲惫 |
| 忌全程短句 | 全是短句会显得急促、缺乏层次 |

### 排比句的用法

```
短 + 短 + 短 + 长（收束）→ 效果最好
短 + 短 + 短 + 短 → 太碎，缺落点
长 + 长 + 长 + 长 → 太闷，读者走神
```

### 标点与停顿

| 符号 | 节奏效果 |
|---|---|
| 逗号 | 标准停顿 |
| 句号 | 落点，力度强 |
| 分号 | 承接，弱停顿 |
| 省略号 | 拉长尾音，适合悬念 |
| 破折号 | 转折、补充 |
| 冒号 | 引出下文 |

**一条实用规则**：连续三句长度相近，节奏就死了。**主动制造长短落差。**

## 六、四类应避开的写法

### 避法一：自我介绍式开场

```
✗ 大家好，我是 XX，某大厂 XX 年 XX，从业 XX 年，今天给大家分享……

✓ 直接进入主题：
  「做了 6 年方案之后，我发现改稿最多的那批，
   往往不是写得最差的那批。」

原理：第一行要的是「这篇跟我有关」，不是「写作者是谁」。
```

### 避法二：标题原句复述

```
✗ 标题：为什么你的方案总是改到第七版
  开头：为什么你的方案总是改到第七版。这个问题困扰了很多人……

✓ 标题：为什么你的方案总是改到第七版
  开头：上周三，第七版改到第 3 页。同一个方案，第三版到第七版
       只改了两行字。

原理：重复会让读者觉得「我已经知道了」，直接滑走。
```

### 避法三：长铺垫

```
✗ 先写 300 字背景、行业趋势、公司介绍，再进入主题

✓ 场景 + 冲突 + 承诺，三句话进主题：
  「周三晚上十点，第七版改到第 3 页。
   这次又改回去了。
   改到第七版还在改，问题可能不在态度。」

原理：移动端首屏只有 4-5 行，超过就等于没写。
```

### 避法四：空话开场

```
✗ 在当今快速发展的时代，效率已经成为衡量企业竞争力的重要标准……

✓ 直接给具体：
  「同样一件事，流程走 6 步和 3 步，团队一周差 4 小时。」

原理：空话在信息流里没有任何竞争力。
```

## 七、开头模板库（可直接填空）

```
【结论先行型】
这篇讲的不是 [常见理解]，是 [真正的核心]。
看完你能 [具体动作]。

【场景切入型】
[时间] + [地点]，我 [具体事件]。
那一刻我发现 [一个规律或冲突]。
[这个规律适用于哪些人]

【数字清单型】
我统计/复盘了 [数量] 的 [对象]。
发现 [N] 个共性问题。第一个是：[结论]。
[后面 N-1 个是什么]

【反常识型】
[违反直觉的判断]。
[支撑数据或样本量]。
原因其实是 [解释]。

【提问切入型】
为什么 [读者的具体困境]？
不是 [常见归因]，是 [真实原因]。
下面三个层面拆开说。
```

## 八、脚本用法

```bash
python scripts/opening_check.py --file article.json --out 开头体检.md
python scripts/opening_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 文章信息 JSON，见下方结构 |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 输出文件，默认 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON：

```json
{
  "title": "为什么你的方案总是改到第七版",
  "opening": "大家好，我是老李，做了 8 年产品。今天想跟大家聊聊改稿这件事。在当今快速变化的环境中，效率非常重要。我发现改稿最多的一批人，往往不是写得很差，而是方法不对。下面我分三点讲讲我的看法。第一点是……",
  "core_promise": false,
  "relevance": false,
  "roadmap": true,
  "opening_type": "intro"
}
```

| 字段 | 说明 |
|---|---|
| `title` | 文章标题 |
| `opening` | 开头正文（前几段） |
| `core_promise` | 首段是否给出核心承诺 |
| `relevance` | 是否说明与读者的相关性 |
| `roadmap` | 是否给出阅读指引 |
| `opening_type` | 实际使用的写法类型 |

脚本输出：首段字数与句数、平均句长与最长/最短句、标题重复度、信息点密度、五类写法命中判定，以及四类应避开的写法检测（自我介绍式、标题复述、空话、长铺垫）。

> 脚本只做长度、句长、重复与写法的形式核查，**不预测完读率或阅读量**。

## 九、人工确认清单（这步不能省）

- [ ] 文章核心承诺已写成一句话
- [ ] 首段长度在 80-150 字
- [ ] 首句 15-30 字，一口气能读完
- [ ] 首段包含核心承诺、相关性、阅读指引三件事
- [ ] 开头未出现「大家好我是」式自我介绍
- [ ] 开头与标题字面重复度不超过 40%
- [ ] 开头属于五类写法之一
- [ ] 句子有长短落差，未连续三句长度相近
- [ ] 无「在当今……的时代」类空话
- [ ] 开头没有长铺垫（背景不超过 2 句）
- [ ] 标题承诺在正文中确实兑现
- [ ] 引用他人内容、数据已标注来源

## 十、最常见的坑

**坑一：开头先介绍自己。**
错误做法：「大家好，我是老李，做了 8 年产品……」。正确做法：第一句直接进主题。**读者是来看内容的，不是来认识作者的。**

**坑二：把标题原句在开头复述一遍。**
错误做法：标题「为什么你的方案总是改到第七版」，开头第一句照抄。正确做法：用具体场景或数据开篇。**重复等于告诉读者「你已经知道了」，直接滑走。**

**坑三：长铺垫。**
错误做法：先写 300 字行业趋势再进主题。正确做法：场景 + 冲突 + 承诺三句话进主题。**移动端首屏只有 4-5 行。**

**坑四：空话开场。**
错误做法：「在当今快速发展的时代，效率已经成为……」。正确做法：「流程走 6 步和 3 步，一周差 4 小时」。**空话在信息流里没有任何竞争力。**

**坑五：首段塞太多论点。**
错误做法：第一段就把五点结论全说完。正确做法：首段只给核心承诺 + 一个钩子，剩下往下走。**记不住的内容等于没写。**

**坑六：句子长度全程一致。**
错误做法：每句都是 25 字左右。正确做法：首句短、论述长、转折短、收尾短。**连续三句长度相近，节奏就死了。**

**坑七：首段没有阅读指引。**
错误做法：长文开头不提结构，读到一半不知道走到哪。正确做法：开头点明「下面讲三点」。**长文尤其需要指引。**

**坑八：标题党，开头兑现不了。**
错误做法：标题写「三个方法让你效率翻倍」，开头没提方法，正文也没有。正确做法：标题承诺什么，开头就给什么。**开头是标题的兑现，不是标题的重复。**

**坑九：把开头写成结论，整篇没有过程。**
错误做法：开头直接给结论，正文全是重复论证。正确做法：开头给结论 + 保留悬念（「原因其实和大多数人想的不一样」），正文再展开。**全给完，读者就没必要读下去了。**

**坑十：把开头排版成大段。**
错误做法：一段 300 字不换行。正确做法：移动端每段 2-4 行换行，重点句单独成段。**密集的文字块会降低阅读意愿。**
