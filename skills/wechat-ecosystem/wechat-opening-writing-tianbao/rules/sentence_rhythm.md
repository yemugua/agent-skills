# 长短句节奏与信息密度规则

> 开头过了「有没有钩子」这一关之后，句长决定读者能不能读下去。

---

## 一、句长节奏规则

| 位置 | 建议句长 | 原因 |
|---|---|---|
| 首句 | 15-30 字 | 一口气能读完，立刻进入状态 |
| 展开段 | 30-50 字 | 长句承载逻辑与限定条件 |
| 转折句 | 10-15 字 | 短句力度最强，适合转折 |
| 举例句 | 20-30 字 | 例子要具体但不长 |
| 收尾句 | 10-20 字 | 短句形成落点 |

**一条实用规则：连续三句长度相近，节奏就死了。** 主动制造长短落差。

### 排比句的力度排序

```
短 + 短 + 短 + 长（收束）→ 效果最好
短 + 短 + 短 + 短       → 太碎，缺落点
长 + 长 + 长 + 长       → 太闷，读者走神
长 + 短 + 长 + 短       → 平稳，缺爆发点
```

## 二、标点与停顿

| 符号 | 停顿强度 | 适用场景 |
|---|---|---|
| 逗号 | 标准 | 句内连接 |
| 顿号 | 弱 | 并列项内 |
| 分号 | 弱 | 分句之间 |
| 句号 | 强（落点） | 强调 |
| 问号 | 强 | 设问、疑问 |
| 感叹号 | 强 | 公众号慎用，2 次以内 |
| 省略号 | 延长尾音 | 悬念 |
| 破折号 | 转折/补充 | 插入说明 |
| 冒号 | 引出下文 | 清单、说明 |

**注意**：感叹号在公众号里容易显得轻浮，全篇不超过 2 次。

## 三、信息密度

```
信息密度 = 首段信息点数 ÷ 首段句数
建议区间：0.5 - 1.0（即每 1-2 句给一个有效信息）
```

| 密度 | 表现 | 判定 | 处理 |
|---|---|---|---|
| 过低 | 首段全是铺垫、背景、来历 | < 0.5 | 压缩背景，直接进主题 |
| 适中 | 每 1-2 句一个新信息 | 0.5-1.0 | 合格 |
| 过高 | 首段塞满 5 个以上论点 | > 1.0 | 只留核心承诺 + 1 个钩子 |

### 什么算「有效信息点」

| 算 | 不算 |
|---|---|
| 一个具体数据 | 背景铺垫 |
| 一个可验证的事实 | 情绪描述 |
| 一个明确的判断 | 客套话 |
| 一个具体场景 | 泛泛而谈 |
| 一个承诺 | 自我介绍 |

## 四、移动端排版规则

| 项 | 建议 | 说明 |
|---|---|---|
| 每段行数 | 2-4 行 | 超过 5 行会形成密集文字块 |
| 单行字数 | 15-25 字 | 适配移动端屏宽 |
| 重点句 | 单独成段 | 制造视觉停留点 |
| 段间距 | 一行空白 | 用留白分段，不靠标点 |
| 小标题 | 每 300-500 字一个 | 给长文读者路标 |
| 加粗 | 只加关键词 | 全篇加粗等于没有重点 |

## 五、句长改造方法

### 方法一：长句拆短

```
✗ 这个方案之所以会被改到第七版，主要是因为在最初的需求确认阶段
  我们没有把成功标准写清楚，而这一点在后续执行中又被反复提及。

✓ 这个方案改到第七版，主因是需求确认阶段没写清成功标准。
  这一点在后续执行中被反复提及。
```

### 方法二：短句合并成长句

```
✗ 需求不清。执行就跑偏。跑偏就返工。返工就加班。

✓ 需求不清会导致执行跑偏，跑偏导致返工，返工最终转化为加班成本。
```

### 方法三：转折用短句

```
✗ 然而，从实际统计的结果来看，情况却并非如此简单的因果关系。

✓ 但数据不支持这个直觉。
```

### 方法四：删掉填充词

| 填充词 | 处理 |
|---|---|
| 其实 | 删除 |
| 基本上 | 改为「基本完成」 |
| 进行了一次 | 改为具体动作 |
| 相关的 | 多数可删 |
| 方面的 | 删除 |
