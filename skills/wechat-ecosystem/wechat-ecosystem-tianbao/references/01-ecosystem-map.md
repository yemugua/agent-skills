# 微信生态全景与责任主体

## 一、六个子生态

| 子生态 | 面向谁 | 典型诉求 | 官方后台 |
| --- | --- | --- | --- |
| 基础通讯 | 个人 | 聊天、群、朋友圈、通讯录、隐私 | 客户端内（无独立后台） |
| 微信支付 | 个人 + 商户 | 付款、收款、账单、退款、分账 | `pay.weixin.qq.com`（商户） |
| 小程序 | 用户 + 开发者 | 使用、授权、订单、开发运营 | `mp.weixin.qq.com` |
| 公众号 / 视频号 | 读者 + 创作者 | 阅读、关注、发布、带货、直播 | `mp.weixin.qq.com` |
| 企业微信 | 企业 + 员工 | 客户管理、审批、打卡、协同 | `work.weixin.qq.com` |
| 开放平台 | 开发者 | 第三方应用、网站登录、移动应用 | `open.weixin.qq.com` |

## 二、判断责任主体（决定问题找谁）

遇到"出问题了"，按下面的顺序判断该找谁：

```
1. 是不是我自己的设置问题？        → 自己处理（设置 / 授权 / 免密）
2. 是不是某个商户/小程序的问题？     → 先找商户（订单详情页一般有客服入口）
3. 商户不理 / 找不到商户？          → 微信平台投诉（订单 → 对订单有疑惑）
4. 平台处理不满意或涉及金额较大？    → 12315 / 消协 / 警方
5. 账号本身出问题（盗号、封禁）？    → 微信安全中心，不走商户
```

### 责任主体速查

| 问题类型 | 第一责任方 | 升级路径 |
| --- | --- | --- |
| 商品没收到 / 与描述不符 | 商户（小程序 or 视频号小店） | 订单投诉 → 12315 |
| 扣款成功但订单没生成 | 商户 → 微信支付 | 账单页「对订单有疑惑」 |
| 莫名其妙被扣钱 | 先看是不是免密/自动续费 | 关闭续费 → 投诉 → 12315 |
| 转账转错人 | 收款方（协商）→ 微信客服 | 金额大可报警 |
| 红包/转账被骗 | 微信投诉 + 报警 | 110 / 反诈中心 96110 |
| 孩子玩游戏充值 | 平台未成年人退款通道 | 12315 / 消协 |
| 账号被限制/封禁 | 微信安全中心申诉 | — |
| 小程序内容违规 | 小程序方 → 平台投诉 | 12315（若涉消费） |

## 三、不同生态的"时效感"

不要给用户承诺具体时效（平台规则会变），只给相对顺序：

- **支付类**：有订单号 → 处理最快（平台能定位交易）
- **账号类**：需要身份核验 → 中间（材料齐全才能推进）
- **内容违规类**：需要人工复核 → 较慢（且结论以平台为准）
- **跨平台纠纷**：最慢（需要监管或司法介入）

## 四、信息收集的黄金四项

无论哪类问题，先让用户准备好这四项，能大幅提升处理效率：

1. **时间**：具体到日期和大致时刻
2. **金额 / 账号**：交易金额、订单号、微信号或手机号
3. **对方**：商户名、小程序名、公众号名、对方微信号
4. **凭证**：截图（订单页、聊天页、扣款通知、报错页）

> 订单号是支付类问题最关键的字段，优先让用户去账单里复制。

## 五、常见误判

| 用户以为 | 实际 |
| --- | --- |
| "微信扣了我的钱" | 多数是商户发起的免密/自动续费，不是微信 |
| "小程序骗了我" | 责任主体是小程序的运营方，微信是平台 |
| "公众号发的内容是微信发的" | 公众号由第三方运营，微信只提供平台 |
| "企业微信就是微信" | 两个独立产品，数据不互通，管理主体是企业 |
| "视频号小店 = 微信商城" | 视频号小店有独立的经营主体和售后规则 |
