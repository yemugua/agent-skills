# 微信聊天记录转保险理赔材料（wechat-insurance-claim）

**保险理赔是场证据战。对方是持牌机构，有法务、有模板。**

这个技能做四件事：**扫要件** → **算时效** → **找拒赔破绽** → **列下一步**。

---

## 硬边界

| 能做 | 不能做 |
|---|---|
| 扫描聊天记录里的理赔要件线索 | ❌ 出具法律意见 |
| 抽取金额、日期、程序节点 | ❌ 预测赔付金额或胜诉率 |
| 计算法定时效倒计时 | ❌ 代你与保险公司交涉 |
| 识别拒赔表述并对照《保险法》给出破局方向 | ❌ 修改、剪辑或伪造任何记录 |
| 生成材料清单、时间线、抗辩分析 | ❌ 判断具体案件最终结果 |
| 指出程序性权利窗口（如 3 日复核期） | ❌ 代替执业律师 |

> **绝不建议修改或伪造聊天记录。** 这是刑事红线，且在任何争议中都会被"完整记录"抗辩击穿。

**触发即转律师的情形**：金额较大（数十万以上）、已收到书面拒赔、临近时效、涉及伤残等级争议、涉及刑事风险。

---

## 四类场景

| 场景参数 | 险种 | 核心争议 | 首要动作 |
|---|---|---|---|
| `health` | 健康保险 | 既往症、等待期 | 查投保告知记录 |
| `accident` | 意外伤害保险 | 是否属意外、伤残等级 | **尽快做伤残鉴定** |
| `property` | 财产保险 | 是否属标的、金额多少 | 找评估/维修凭证 |
| `liability` | 责任保险 | 行为与损害的因果 | 固定损害事实 |

不确定用哪个就填 `all`，脚本会合并四类要件库。

## 三步上手

```bash
# 1. 导出聊天记录（依赖 wechat-local-reader-tianbao）
#    没有的话，手动把记录整理成每行 [YYYY-MM-DD HH:MM] 发送者: 内容 也行

# 2. 选场景扫描
python scripts/extract.py --file 聊天记录.md --scenario accident

# 3. 换个视角复核
python scripts/extract.py --file 聊天记录.md --scenario all --as-of 2026-10-04
```

> `--as-of` 用来按指定日期算时效。**做正式材料时务必显式指定**，别用脚本的默认今天。

| 参数 | 必填 | 说明 |
|---|---|---|
| `--file` | ✅ | 聊天记录文件（`.md` / `.txt`） |

## 报告结构

固定八段，每段都对应一个实务问题：

1. **结论先行** —— 覆盖率、时效剩余、争议焦点、最大金额
2. **要件命中表** —— 每项要件的举证责任方、命中处数、命中关键词
3. **缺失要件与补强方向** —— 缺什么、去哪里补
4. **争议焦点** —— 拒赔原话 + 《保险法》破局点
5. **关键程序节点** —— 报案/材料/定损/拒赔/到账/催告
6. **金额梳理** —— 时间倒序表格，提示三重扣除
7. **关键证据片段** —— 带要件归属与举证责任
8. **下一步行动清单** —— 按紧迫度排序

## 报告读法

**要件覆盖低 ≠ 你没证据。**
聊天里没有只说明"这件事没在微信里聊过"，材料很可能在纸质单据或系统后台。

**时效那一行优先看。**
《保险法》第 26 条规定非人寿保险请求权时效 **2 年**。时效过了，道理再对也拿不到钱。
起算点是"**知道或应当知道事故发生之日**"，不是事故发生日——两者可能差很远。

**拒赔理由是礼物。**
对方写下来的拒赔理由，是他们的正式主张，也是你对照条款和法条逐条反击的靶子。
《保险法》第 19 条给的武器很硬：免责条款**未作提示或明确说明的，该条款不产生效力**，而**举证责任在保险公司**。

---

## 三个最常见的坑

**1. 以为"有聊天记录就能赔"**
聊天记录只证明"沟通发生过"。要拿到钱还需要三样：合同关系 + 损失凭证 + 责任认定。

**2. 收到拒赔后沉默**
复核期只有 **3 日**（《保险法》第 25 条）。保险公司答复理赔请求应在 **30 日**内（第 23 条）。

**3. 忘了扣除项**
医保统筹、第三方已赔、保单免赔额——这三重扣除不扣，就会被当成"多报"直接否掉。
