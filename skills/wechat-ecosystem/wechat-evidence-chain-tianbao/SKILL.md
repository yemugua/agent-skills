# 微信聊天记录转法律证据（wechat-evidence-chain）

聊天记录本身不是证据，**整理成要件齐全的证据包才是**。

这个技能做三件事：**扫出要件** → **算清时效** → **列出缺什么**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按要件归类聊天片段 | ❌ 出具法律意见 |
| 提取金额、日期、主体 | ❌ 预测胜诉率或赔偿金额 |
| 生成证据清单 / 时间线 / 缺失项报告 | ❌ 代替律师或法律援助 |
| 提示证明力风险与补强方向 | ❌ 伪造、剪辑、补造证据 |
| 计算法定时效剩余天数 | ❌ 保证结果 |

**遇到以下情况，务必建议当事人咨询专业律师或当地法律援助中心：**
- 争议金额较大（劳动争议建议超过当地月社平工资 10 倍的工龄，或标的超 10 万元）
- 涉及刑事风险（诈骗、侵占、故意伤害）
- 涉外、涉港澳台
- 一审败诉后拟上诉
- 对方已进入刑事程序

**永远不要为了"补齐要件"而建议用户修改、拼接、伪造聊天记录。** 剪辑过的记录在质证中通常直接被否，还可能反过来损害可信度。缺什么就如实写"缺"，并说明去哪儿补。

## 二、完整工作流

```
第 1 步  读取聊天记录（两条路）

第 2 步  确认场景 + 时间区间
    场景决定用哪套要件库，区间决定时效怎么算

    证据清单 / 时间线 / 缺失项报告 / 质证风险提示

第 6 ��  交付时必须附免责声明
```

## 三、第 1 步：拿到聊天记录

### 路线 A：已经导出了文件

直接把文件路径给脚本，跳到第 3 步。

### 路线 B：还没导出，用读取技能

```bash
# 先看有哪些会话，拿到准确名字
wechat-cli sessions --limit 30

# 导出（按时间区间，别只导片段）
wechat-cli export "群名或对方昵称" \
  --format markdown \
  --start-time "2024-01-01" --end-time "2026-10-01" \
  --output "D:\证据\某某群.md"
```

**导出时必须注意的三件事：**

1. **时间区间要拉满**，不要只导"有印象的那几段"。时效从"知道权利受损之日"起算，中间断了反而可能被对方主张"你早就知道"。
2. **不要在导出后做脱敏**（`--mask`）除非确有必要——脱敏会破坏金额和日期的可用性。要脱敏就**在生成材料之后**做。
3. **导出的 md 是明文**，用完按需 `wechat-cli clean`。

---

## 四、第 2 步：选场景

`scripts/extract.py` 支持六类场景。用 `--scenario` 指定：

| 值 | 场景 | 典型主张 |
|---|---|---|
| `labor` | 劳动争议 | 拖欠工资、违法解除、加班费、经济补偿 |
| `rent` | 租房押金 | 押金退还、房屋损坏赔偿、擅自解约 |
| `loan` | 民间借贷 | 还款、利息、逾期催收 |
| `contract` | 合同/买卖/服务 | 交付、验收、付款、违约、结算 |
| `tort` | 侵权 | 人身伤害、财产损坏、名誉侵害 |
| `family` | 婚姻家事 | 离婚、彩礼、抚养、夫妻共同财产、分居 |
| `all` | 全部场景（初步摸底用） | — |

**场景判断不了时，先用 `all` 跑一遍**，看哪个场景命中密度最高，再切到该场景细跑。

---

## 五、第 3 步：跑扫描脚本

```bash
python scripts/extract.py --file "D:\证据\某某群.md" --scenario labor --as-of 2026-10-04
```

### 完整参数

| 参数 | 说明 |
|---|---|
| `--file` | 必填。`wechat-cli export` 出来的 `.md` 或 `.txt` |
| `--scenario` | 场景代码，默认 `all` |
| `--as-of` | 时效计算的基准日，默认取今天。格式 `YYYY-MM-DD` |
| `--since` / `--until` | 只扫描指定时间区间 |
| `--focus "张三"` | 只看某个人的发言（对方姓名） |
| `--out` | 报告输出路径，不写就打到屏幕 |
| `--format` | `md`（默认，人读）或 `json`（给 AI 继续处理） |

### 脚本做了什么

1. **解析** `[2026-09-01 10:23] 张三: 内容` 格式，容忍缺发送者、全角冒号、多级 `-` 前缀
2. **关键词命中**：按场景的要件关键词库逐条扫描，命中就挂到对应要件下
3. **金额抽取**：识别"8000""3万""1.5 万元"等，聚合成候选金额（标注是"对方承认"还是"我方主张"）
4. **关键日期识别**：入职、离职、解除、催款、承诺还款等节点
5. **时效计算**：从关键日期起算法定时效，给出**剩余天数**和**是否已过**
6. **输出报告**：要件命中表 + 命中片段 + 金额 + 时间线 + 时效提示 + 缺项提醒

> ⚠️ **脚本只做关键词匹配，不做法律判断。** 它标"命中"不等于这条消息在法律上有效。必须人工逐条确认。

---

## 六、第 4 步：人工确认（这步不能省）

脚本跑完，逐项过一遍：

- [ ] 命中的片段是否**真的**证明了这件事？（"我明天发你照片" ≠ 已交付）
- [ ] 发言人身份是否明确？（群聊里的昵称可能不是本人，注意备注名 ≠ 真名）
- [ ] 有没有断章取义的风险？（前后文可能被对方引用）
- [ ] 关键要素是否具备**主体 + 时间 + 行为 + 意思表示**四要素
- [ ] 金额、日期、主体三项是否在**同一条记录**里出现

**必须重点核对的四类"陷阱消息"：**

| 陷阱 | 表现 | 怎么办 |
|---|---|---|
| 单方陈述 | "你欠我 3 万" —— 对方从未回应 | 找对方确认过的那条 |
| 玩笑话 | "等我发财了还你" | 排除，别当借款合意 |
| 第三方转述 | 别人说"他承认了" | 需本人确认才有效 |
| 图文不符 | 文字说"收到"，但没转账 | 用转账记录佐证 |

---

## 七、第 5 步：生成四份材料

按 `templates/` 下的模板产出：

| 文件 | 用途 |
|---|---|
| `templates/证据清单.md` | 提交给仲裁员/法院的证据目录 |
| `templates/时间线.md` | 事实经过时间轴 |
| `templates/缺失项报告.md` | 还差什么证据、去哪补、怎么补 |
| `templates/质证风险提示.md` | 对方可能怎么攻击、怎么提前防 |

### 输出结构（固定 7 段，AI 生成时按此排版）

1. **结论先行** —— 这个场景能不能立得住，卡在哪
2. **要件命中表** —— 哪个要件有证据、哪个没有
3. **金额梳理** —— 主张金额 + 对方认可金额 + 分歧
4. **时间线与时效** —— 关键节点 + 剩余天数
5. **证据清单** —— 编号、名称、来源、证明对象
6. **缺失项与补强方向** —— 去哪儿补
7. **质证风险 + 免责声明**

---

## 八、要件库在哪

`rules/` 目录下是本技能的核心资产，**不是提示词，是规则表**：

| 文件 | 内容 |
|---|---|
| `rules/elements.md` | 六场景逐个要件清单：要件名、举证责任方、微信里能找什么、缺失后果 |
| `rules/proof.md` | 微信电子数据的证明力规则、常见抗辩、应对补强、质证要点 |
| `rules/deadlines.md` | 时效、管辖、金额门槛速查表 |

**生成任何材料之前，先读对应的 `rules/` 文件。** 不要凭印象写法律要点。

---

## 九、最常见的坑

**坑一：只导了片段，时间线断了。**
时效可能从"你第一次催款"起算，中间大段空白会被对方主张"你早就知道、怠于行使"。

**坑二：把"对方没回复"当成"对方默认"。**
沉默不是承诺。要找**明确的**确认、同意、还款动作。

**坑三：金额散落各处，没汇总。**
对方说"3万"、你说"25000"、转账记录是"28000"——三个数都要列出来，标清来源和说话人，不要自己取平均。

**坑四：过了时效才发现。**
`--as-of` 参数就是干这个的。**任何劳动争议都要先算时效。**

**坑五：以为导出就能当证据。**
导出文件是**整理稿**，不是原始载体。关键证据要保留原始设备、必要时做录屏或时间戳。

## 十、边界与免责

- 本技能**不提供法律咨询**，只做材料整理与要件对照
- 输出的要件表和时效计算**可能因地区差异、案情特殊而失准**，最终以律师意见为准
- **不得用于伪造、篡造、剪辑聊天记录**
- 涉及他人隐私时，务必脱敏后再流转
- 争议金额较大、涉及刑事风险、涉外、拟上诉 → **一律建议先咨询律师**
