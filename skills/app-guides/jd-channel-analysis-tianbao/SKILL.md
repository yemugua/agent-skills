# 招聘 JD 编写与渠道分析（jd-channel-analysis）

JD 是招聘的"第一份产品"：**写得模糊，来的人不对；写得漂亮但不真实，入职就流失**。渠道是流量的入口——岗位和渠道错配，烧钱还没人。

这个技能做四件事：**写好 JD** → **定准资格** → **选对渠道** → **算清漏斗**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 讲解 JD 编写方法与渠道分析 | ❌ 替代用人决策 |
| 生成 JD 模板与漏斗计算 | ❌ 保证招聘效果 |
| 整理关键词与渠道匹配口径 | ❌ 突破招聘平台规则 |

**JD 不得含有歧视性、违法性表述**（性别、年龄、地域、婚育限制等），合规红线。

**永远不要**用"美化"的 JD 骗候选人进来——入职即流失，成本翻倍。

## 二、完整工作流

```
第 1 步  明确岗位：职责来源（用人经理访谈）、职级、薪酬结构
第 2 步  读规则文件 rules/jd_rules.md
第 3 步  按步骤取用：
    - 写好 JD → 七段结构（第三节）
    - 定准资格 → 硬性/加分拆分（第四节）
    - 选对渠道 → 渠道匹配（第五节）
    - 算清漏斗 → 漏斗指标（第六节）
    - 体检表 → python scripts/jd_check.py --file JD.json
第 4 步  按 templates/JD模板.md 输出
第 5 步  人工确认：薪酬带宽真实性、用人经理确认
```

## 三、JD 七段结构

1. **职位名称**——市场通用叫法（别自造词，影响搜索）
2. **部门与汇报线**——向谁汇报、带不带团队
3. **岗位职责**——5~8 条，动词开头，按重要性排序
4. **任职资格**——硬性（必须）与加分（优先）分开
5. **薪酬与福利**——结构透明（固定+绩效+福利），写清区间
6. **工作地点与时间**——含出差、班次要求
7. **团队与成长**——团队构成、发展路径

> 原则：**真实、具体、可检索**；每条职责对应一个可验证的工作产出。

---

## 四、职责动词库与资格拆分

**动词库**：负责/主导/搭建/优化/复核/编制/排查/组织/协同/交付/复盘——避免"参与""协助"满屏（那是打杂不是岗位）。

**任职资格拆分**：

| 类型 | 内容 | 用法 |
|---|---|---|
| 硬性 | 学历、证书、年限、必备技能、到岗时间 | 缺一项即筛掉 |
| 加分 | 行业经验、软件工具、语言 | 同等条件下优先 |

> 硬性项宁少勿滥：每多一条不合理硬性，简历量掉一截；先跑数据再收紧。

## 五、渠道-岗位匹配表

| 渠道 | 适合岗位 | 特点 |
|---|---|---|
| BOSS 直聘 | 初中级职能/技术岗、批量岗 | 量大、响应快、需主动沟通 |
| 猎头 | 中高级、稀缺、保密岗位 | 精准、费率高 |
| 内推 | 各层级 | 质量高、留存好 |
| 垂直社区/论坛 | 技术、专业岗位 | 精准但量小 |
| 校园/社招活动 | 储备、批量 | 季节性 |

**组合原则**：一个岗位主渠道 + 1 个辅渠道；跑满 2 周看数据再调，不拍脑袋换。

## 六、漏斗指标

```
曝光 → 打招呼/沟通 → 简历投递 → 初筛通过 → 面试 → offer → 入职
```

| 指标 | 计算 | 诊断 |
|---|---|---|
| 沟通转化率 | 沟通/曝光 | 低 = 薪酬或 JD 开头不吸引 |
| 投递率 | 投递/沟通 | 低 = 需求不匹配或回复慢 |
| 约面率 | 面试/初筛通过 | 低 = 面试邀约话术或时间问题 |
| 到面率 | 实到/约面 | 低 = 邀约确认与提醒缺失 |
| offer 接受率 | 接受/发出 | 低 = 薪酬竞争力或面试体验 |
| 入职留存 | 过试用期/入职 | 低 = JD 失真或面试失真 |

## 七、脚本用法（JD 体检与漏斗计算）

```bash
python scripts/jd_check.py --file "D:\招聘\JD.json"
python scripts/jd_check.py --funnel --impressions 5000 --chats 800 --resumes 120 --interviews 20 --offers 5 --onboard 4
```

输出：JD 七段完整性、硬性项数量提示、关键词覆盖、漏斗各环节转化率与瓶颈诊断。

> ⚠️ 脚本只做结构与数值计算，**不替代平台规则与用人决策**。

## 八、人工确认（这步不能省）

- [ ] 职责是否经用人经理确认（不是 HR 代编）
- [ ] 薪酬区间是否与内部带宽一致
- [ ] 硬性项是否有数据支撑（不是凭感觉加码）
- [ ] JD 无违法歧视表述
- [ ] 渠道预算与周期是否明确
- [ ] 漏斗数据是否每周复盘

## 九、输出结构（固定三段）

1. **JD 能不能打**——结论先行：完整可用 / 有缺口 / 有合规问题
2. **体检明细**——结构、资格、关键词、渠道
3. **优化动作**——先改什么、再测什么、多久复盘

## 十、最常见的坑

**坑一：JD 抄模板。** 把别家公司的岗位描述抄过来，职责和自家业务两张皮。

**坑二：硬性项堆成山。** 五年经验 + 三个证书 + 年龄限制，简历量归零还涉嫌违法。

**坑三：薪酬写"面议"。** 沟通转化率直接砍半，双方浪费时间。

**坑四：渠道从一而终。** 技术岗只挂 BOSS，垂直社区没人运营。

**坑五：约面不确认。** 发个时间就不管，到面率三成不到。
