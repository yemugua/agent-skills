# 小红书笔记撰写与标题拟定核查（xiaohongshu-note-writing）

小红书笔记的问题，八成不在「内容不够好」，而在**标题没给点击理由、正文没给留人理由、封面没给停留理由**。

这个技能做三件事：**用公式拟标题** → **用四段结构搭正文** → **扫掉极限词与违禁表述**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出标题公式与模板库 | ❌ 预测流量、点赞数或爆款概率 |
| 给出正文四段结构与字数配比 | ❌ 保证笔记被推荐或不被限流 |
| 列出极限词与违禁表述分类及替代表达 | ❌ 提供规避平台审核、绕过检测的方法 |
| 核查标题长度、关键词布局、结构完整度 | ❌ 代替平台规则（平台规则以官方最新公告为准） |
| 给出封面文案规范 | ❌ 指导发布虚假测评、虚假种草 |
| 排查笔记没人看的原因 | ❌ 代写商业推广、虚假种草内容 |

**必须先停下来确认的情形：**
- 医疗、药品、医美、金融理财、食品保健、法律服务等**受监管类目** —— **以现行法律法规、平台类目规则与主管部门要求为准**，本技能不提供该类目的推广写法
- 涉及品牌合作、商业推广 —— 需按平台商业推广规则标注，并遵守广告法相关规定
- 涉及他人肖像、测评对象、未成年人 —— 需取得相应授权
- 平台规则会调整 —— **以平台官方最新规则和提示为准**，本技能的词表只作常见风险参考

## 二、完整工作流

```
第 1 步  选题：从真实体验切入，写清「给谁看、解决什么问题」
第 2 步  标题：用 rules/title_formulas.md 的五类公式拟 3 个备选，跑长度校验
第 3 步  正文：按 rules/note_structure.md 的四段结构写，字数按配比控制
第 4 步  关键词：按布局位放置，检查是否覆盖核心搜索词
第 5 步  跑脚本体检：python scripts/xhs_note_check.py --file note.json
第 6 步  看四个数：标题长度合规、风险词命中数、结构完整度、关键词覆盖数
第 7 步  封面：按 rules/cover_rules.md 写文案，控制字数
第 8 步  发布前人工确认（§七），删掉所有未标注的商业内容
```

**顺序不能颠倒**：先写正文再拟标题，等于让标题去迁就内容，容易变成「正文摘要」而不是「点击理由」。

## 三、五类标题公式

### 公式一：数字型

```
结构：[数量] + [对象] + [结果/收益]

示例：
- 5 个 Excel 公式，财务人每天省 1 小时
- 3 步搞定一顿早餐，最快 8 分钟
- 7 天断糖实录，第 4 天最难熬

适用：有明确清单、可计数内容的笔记
风险：数字要真实。虚报数量属于虚假宣传
```

### 公式二：痛点型

```
结构：[人群/场景] + [痛点] + [解法承诺]

示例：
- 通勤党早餐吃什么？我总结了 6 个 5 分钟方案
- 简历投了 50 份没回音，问题可能在这 3 行

适用：解决具体困扰的笔记，收藏率高
风险：痛点要具体（「不会做饭」太泛，「一个人住不会做三菜一汤」才具体）
```

### 公式三：对比型

```
结构：[A] vs [B] + [结论]

示例：
- 挂脖风扇 vs 落地扇，实测差在哪
- 早八 vs 早九，一周下来差了很多

适用：测评、选购、决策类笔记
风险：对比要公平，不能贬低特定品牌
```

### 公式四：悬念型

```
结构：[反常识结论] + [留白]

示例：
- 存款 10 万和 10 万负债，一年后差距出乎意料
- 我把日程表删了，效率反而更高了

适用：有反差感的笔记
风险：悬念要在正文兑现，标题党会拉低完读率与账号权重
```

### 公式五：身份标签型

```
结构：[身份] + [场景/限制] + [结果]

示例：
- 32 岁转行第 3 年，我做对了哪 3 件事
- i 人独居两年，这些东西真的提升了生活质量

适用：人设类、长期系列笔记
风险：身份要真实，不要编造
```

### 标题长度规则

| 项 | 建议 | 说明 |
|---|---|---|
| 标题字数 | 16-20 字为主，超过 24 字易被截断 | 关键信息前置 |
| 数字 | 出现在前半段 | 前 8 个字决定点开率 |
| 分隔符 | 用空格、竖线或标点，不要连排 | 提升断句清晰度 |
| 表情 | 0-1 个，不要堆 | 堆表情会被判为营销号风格 |
| 禁用 | 标题党式省略（「你绝对想不到」） | 与正文不符会拉低完读率 |

## 四、正文四段结构（照抄填空）

```
【钩子】前 2 行决定是否继续看，必须承接标题
  写法：把标题里的承诺兑现，或直接给出结论。
  示例：「这 6 个方案我全试过一周，最常用的是第 3 个。」

【共鸣】让读者确认「说的是我」
  写法：描述具体处境，越具体越好。
  示例：「早上 7 点起，地铁 40 分钟，中午只有 20 分钟吃饭时间。」

【干货】主体，给可执行的具体内容
  写法：分点、编号、给数据或步骤。3-7 条为宜。
  示例：「① 提前一晚备菜 …」「② 用 XX 替代 …」

【行动】给一个明确的下一步
  写法：提问、引导收藏、或者给下期预告。
  示例：「需要的话我把采购清单放在评论区置顶了。」
```

### 字数配比建议

| 段落 | 占比 | 说明 |
|---|---|---|
| 钩子 | 5%-10% | 前 2 行，不要铺垫 |
| 共鸣 | 10%-15% | 建立身份认同 |
| 干货 | 60%-70% | 主体，决定收藏率 |
| 行动 | 5%-10% | 一个明确动作，不要多个 |

**最常见的错误**：钩子写太长（前三行还在自我介绍），干货只有两条。

## 五、关键词布局

| 位置 | 放什么 | 作用 |
|---|---|---|
| 标题 | 1 个核心关键词 | 决定搜索匹配 |
| 开头前 2 行 | 1 个核心关键词 | 正文字数计入权重 |
| 正文分段小标题 | 2-3 个相关词 | 长尾匹配 |
| 正文自然出现 | 3-5 次 | 不要堆砌 |
| 话题标签 | 3-5 个，1 个大词 + 2-4 个精准词 | 决定标签流 |

**原则**：核心关键词在标题、开头、分段小标题各出现一次，自然分布而非堆砌。**堆砌会被判为低质内容。**

## 六、极限词与违禁表述清单

**说明：以下为常见风险词分类示例，不构成完整清单。平台规则与监管要求以官方最新规定为准。**

| 类别 | 风险表述示例 | 替代表达 |
|---|---|---|
| **最高级** | 最、第一、顶级、极致、最好、最佳 | 改成具体描述：「我用过里面最顺手的」 |
| **绝对化** | 100%、绝对、彻底、根治、永久、必然 | 「基本」「通常」「在 XX 条件下」 |
| **虚假承诺** | 包过、包瘦、稳赚、保证有效、无效退款 | 删除，或改成有条件的表述 |
| **权威暗示** | 专家推荐、央视推荐、权威认证（无实际证明） | 有证明则写明具体出处，无则删除 |
| **医疗用语** | 治疗、根治、抗炎、消炎、祛痘（药品类） | 改用「护肤」「改善」，涉及医疗的改用合规表述 |
| **金融用语** | 保本、稳赚、高收益、无风险（投资理财类） | 「可能存在风险」「收益不保证」 |
| **虚假促销** | 最后一天、仅此一次、马上涨价（无实际依据） | 写明具体时间与依据 |
| **引人不适** | 胖子、丑、矮（人身评价） | 中性描述 |
| **过度承诺效果** | 一周瘦 10 斤、彻底告别失眠 | 「我个人的变化是 …」 |

### 风险等级与处理

| 等级 | 判定 | 处理 |
|---|---|---|
| 高风险 | 最高级、绝对化、虚假承诺、医疗/金融违规用语 | **必须改**，不做「可能没事」的判断 |
| 中风险 | 权威暗示、过度承诺效果、绝对化时间 | 改为具体条件表述 |
| 低风险 | 情绪化但合规的夸张表达 | 视情况保留 |

**处理原则**：拿不准就删。删一个词的成本，远低于被限流的成本。

## 七、封面文案规范

| 项 | 建议 | 说明 |
|---|---|---|
| 字数 | 8-14 字 | 封面图上字太多等于没写 |
| 字号 | 手机上一眼能看清 | 缩略图场景下才清楚 |
| 位置 | 上方或居中，避开底部遮挡区 | 底部常被昵称与点赞图标盖住 |
| 数量 | 1 句话，或 3-5 字短语 | 不要写段落 |
| 视觉 | 主色 1 种 + 文字色 1-2 种 | 太多颜色在小图上不可读 |
| 与标题 | 互补不重复 | 封面写结果，标题写场景 |

### 封面文案示例

| 类型 | 封面 | 标题 |
|---|---|---|
| 清单型 | 「6 个方案」 | 通勤党早餐吃什么？我总结了 6 个 5 分钟方案 |
| 对比型 | 「实测结果」 | 挂脖风扇 vs 落地扇，实测差在哪 |
| 结果型 | 「省了 1 小时」 | 5 个 Excel 公式，财务人每天省 1 小时 |
| 悬念型 | 「出乎意料」 | 存款 10 万和 10 万负债，一年后差距出乎意料 |

## 八、脚本用法

```bash
python scripts/xhs_note_check.py --file note.json --out 笔记体检.md
python scripts/xhs_note_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 笔记信息 JSON，见下方结构 |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 输出文件，默认 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON：

```json
{
  "title": "5 个 Excel 公式，财务人每天省 1 小时",
  "cover_text": "6 个方案",
  "body": "这 5 个公式我用了半年，最常用的是第三个。\n\n每天做表的重复劳动太多了。\n\n① 快速查找 ② 日期换算 ③ 分类汇总 ④ 去重计数 ⑤ 条件求和\n\n需要的话我把模板放在评论区了。",
  "keywords": ["excel", "财务", "效率工具"],
  "hashtags": ["excel技巧", "职场效率", "财务"]
}
```

| 字段 | 说明 |
|---|---|
| `title` | 笔记标题 |
| `cover_text` | 封面文案 |
| `body` | 正文文本，脚本会扫风险词并检测段落 |
| `keywords` | 想覆盖的核心关键词 |
| `hashtags` | 话题标签 |

脚本输出：标题长度与截断风险、封面字数、结构完整度（钩子/共鸣/干货/行动四段是否齐备）、关键词覆盖情况、风险词命中分类清单与替代表达。

> 脚本只做长度、结构与词表核查，**不预测流量，也不判断内容质量与真实性**。

## 九、人工确认清单（这步不能省）

- [ ] 标题字数在 24 字以内，关键信息在前 8 字
- [ ] 标题有明确点击理由，不是正文摘要
- [ ] 标题承诺在正文中已兑现，不是标题党
- [ ] 正文前 2 行已给出钩子，不是自我介绍开场
- [ ] 干货段有 3-7 条具体内容，不只有两条
- [ ] 关键词在标题、开头、分段小标题各出现一次，自然分布
- [ ] 话题标签 3-5 个，含 1 个大词 + 2-4 个精准词
- [ ] 已逐条扫过极限词与违禁表述，高风险项已改
- [ ] 涉及个人真实体验的内容确有其事，无编造成分
- [ ] 商业推广内容已按平台规则标注
- [ ] 封面文案在手机缩略图下能看清，位置避开了遮挡区
- [ ] 图片与正文中的人物、商标使用已取得授权

## 十、最常见的坑

**坑一：标题写成正文摘要。**
错误做法：「关于早餐的一些记录和心得体会」。正确做法：「通勤党早餐吃什么？我总结了 6 个 5 分钟方案」。**标题给的是点击理由，不是内容概述。**

**坑二：标题超过 24 字被截断。**
错误做法：「一个普通上班族的周末两天时间安排的完整记录和心得分享（附清单）」。正确做法：压到 20 字内，把「6 个方案」这类关键信息前置。**前 8 个字决定点开率。**

**坑三：正文前三行还在自我介绍。**
错误做法：「大家好，我是 XX，今年 XX 岁，今天给大家分享……」。正确做法：第一行直接给结论或呼应标题。**读者是来看内容的，不是来认识你的。**

**坑四：干货段只有两条。**
错误做法：列两个小点就结束。正确做法：3-7 条具体内容，每条可执行。**干货密度决定收藏率，收藏率决定长期流量。**

**坑五：极限词直接写上去。**
错误做法：「最有效的方法」「绝对能学会」。正确做法：「我用过里面最顺手的」「我个人的方法是」。**最高级和绝对化表述是高频违规项。**

**坑六：关键词堆砌。**
错误做法：正文里出现 20 次同一个词。正确做法：核心词在标题、开头、分段小标题各出现一次，共 3-5 次自然分布。**堆砌会被判低质。**

**坑七：封面写满了字。**
错误做法：封面图上放三行文字。正确做法：8-14 字，一句话或 3-5 字短语，字号在缩略图下能看清。**封面在信息流里只有拇指大小。**

**坑八：标题党，标题承诺正文没兑现。**
错误做法：标题写「必看」，正文全是日常流水。正确做法：标题承诺什么，正文必须给到什么。**标题党会拉低完读率，长期影响账号权重。**

**坑九：悬念型标题在正文没有答案。**
错误做法：标题「出乎意料」，正文平铺直叙。正确做法：正文兑现反差，给出真实结论。**悬念必须闭环。**

**坑十：编造体验或数据。**
错误做法：「我用了三个月瘦了 15 斤」（实际没有）。正确做法：写真实发生的事，标注为个人体验。**虚假宣传是违规风险，不只是效果问题。**
