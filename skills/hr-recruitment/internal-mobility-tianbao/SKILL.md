# 内部竞聘与岗位轮换（internal-mobility）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据人才发展通道设计方法，生成清单：内部岗位发布与报名资格、竞聘流程与评价标准、现岗位交接与放行、轮岗周期与目标、效果评估与保留。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 内部竞聘
- 岗位轮换
- 内部招聘发布
- 轮岗计划
- 内部人才流动

## 三、工作流
1. 发布内部岗位与报名资格
2. 规范竞聘流程与评价标准
3. 安排现岗位交接与放行
4. 设定轮岗周期与目标
5. 评估效果并保留人才

## 四、核心内容（检查清单与判定）
内部竞聘若承诺不兑现会严重打击员工信任；交接不放行也会让主管抵制。流程透明、评价公开、结果有反馈，机制才能持续运转。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含岗位发布与报名资格 | 发布 |
| Q2 | FAIL | 未含竞聘流程与评价标准 | 标准 |
| Q3 | WARN | 未含现岗位交接与放行 | 交接 |
| Q4 | WARN | 未含轮岗周期与目标 | 周期 |
| Q5 | WARN | 未含效果评估与保留 | 评估 |

> 脚本 `internal-mobility_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python internal-mobility_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python internal-mobility_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
