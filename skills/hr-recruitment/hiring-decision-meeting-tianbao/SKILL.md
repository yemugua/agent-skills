# 录用决策会议机制（hiring-decision-meeting）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据集体决策与评价校准方法，生成清单：参会角色与决策权限、评价材料齐备性检查、独立打分与集体评议、异议处理与表决规则、录用结论与反馈时效。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 录用决策会
- 人才评审委员会
- 招聘评价校准
- 面试意见不一致
- 录用表决规则

## 三、工作流
1. 明确参会角色与决策权限
2. 检查评价材料齐备性
3. 组织独立打分与集体评议
4. 执行异议处理与表决规则
5. 形成录用结论并控制反馈时效

## 四、核心内容（检查清单与判定）
决策会失效通常来自材料不齐与先入为主。要求面试官会前独立打分、会上先晾分数再讨论，能显著降低从众效应。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含参会角色与决策权限 | 权限 |
| Q2 | FAIL | 未含评价材料齐备性检查 | 材料 |
| Q3 | FAIL | 未含独立打分与集体评议 | 打分 |
| Q4 | WARN | 未含异议处理与表决规则 | 表决 |
| Q5 | WARN | 未含录用结论与反馈时效 | 时效 |

> 脚本 `hiring-decision-meeting_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python hiring-decision-meeting_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python hiring-decision-meeting_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
