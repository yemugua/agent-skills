# 远程与混合办公管理（remote-work-policy）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据劳动管理与信息安全要求，生成清单：适用岗位与审批流程、设备配置与费用承担、工时记录与成果考核、信息安全与数据防泄漏、劳动关系与工伤认定边界。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 远程办公制度
- 混合办公管理
- 居家办公规定
- 远程绩效考核
- 居家工伤

## 三、工作流
1. 明确适用岗位与审批流程
2. 确定设备配置与费用承担
3. 建立工时记录与成果考核
4. 落实信息安全与防泄漏
5. 界定劳动关系与工伤边界

## 四、核心内容（检查清单与判定）
远程办公最容易出问题的是工时认定与工伤边界；制度中应约定起止时间、响应要求与安全责任，并对涉密岗位做专门限制。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含适用岗位与审批流程 | 审批 |
| Q2 | WARN | 未含设备配置与费用承担 | 设备 |
| Q3 | FAIL | 未含工时记录与成果考核 | 考核 |
| Q4 | FAIL | 未含信息安全与防泄漏要求 | 信息安全 |
| Q5 | WARN | 未含劳动关系与工伤边界 | 工伤 |

> 脚本 `remote-work-policy_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python remote-work-policy_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python remote-work-policy_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
