# 业务经理招聘赋能（hiring-manager-enablement）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据招聘协作机制设计方法，生成清单：用人标准共识与需求澄清、招聘时效承诺与分工、面试技能与反问环节训练、决策会议规则与异议处理、招聘结果纳入直线经理绩效。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 业务经理招聘赋能
- 用人部门招聘培训
- 需求澄清会
- 招聘时效承诺
- 招聘责任分摊

## 三、工作流
1. 召开需求澄清会达成标准共识
2. 约定招聘时效与分工
3. 训练面试技能与反问环节
4. 明确决策会议与异议规则
5. 将招聘结果纳入直线经理考核

## 四、核心内容（检查清单与判定）
招聘不力多半是用人部门的责任而非 HR：需求变来变去、反馈不及时、面试随意改标准。把这些写成分工承诺与考核项，机制才跑得动。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含用人标准与需求澄清 | 需求 |
| Q2 | FAIL | 未含时效承诺与分工机制 | 分工 |
| Q3 | WARN | 未含面试技能与反问训练 | 训练 |
| Q4 | WARN | 未含决策会议与异议规则 | 决策 |
| Q5 | WARN | 未含招聘结果纳入直线经理考核 | 考核 |

> 脚本 `hiring-manager-enablement_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python hiring-manager-enablement_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python hiring-manager-enablement_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
