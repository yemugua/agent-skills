# 招聘需求审批与编制管控（requisition-approval）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据编制与人效管理逻辑，生成清单：岗位必要性论证与替代方案、层级与薪酬区间核准、编制额度与总员控制、审批链条与权限阈值、超编例外审批与复盘。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 招聘需求审批
- 编制管控
- 增员申请流程
- 人效论证
- 超编特批申请

## 三、工作流
1. 论证岗位必要性与替代方案
2. 核准层级与薪酬区间
3. 核对编制额度与总员控制
4. 执行审批链条与权限阈值
5. 管理超编例外并复盘

## 四、核心内容（检查清单与判定）
增员审批的关键是先看能否通过流程优化或内部调配解决。没有必要性论证的招募会把组织成本固化下来，后续很难压缩。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含必要性论证与替代方案 | 论证 |
| Q2 | WARN | 未含层级与薪酬区间核准 | 区间 |
| Q3 | FAIL | 未含编制额度与总员控制 | 编制 |
| Q4 | FAIL | 未含审批链条与权限阈值 | 权限 |
| Q5 | WARN | 未含超编例外审批与复盘 | 例外 |

> 脚本 `requisition-approval_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python requisition-approval_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python requisition-approval_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
