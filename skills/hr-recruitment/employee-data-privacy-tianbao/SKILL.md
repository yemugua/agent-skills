# 员工个人信息保护合规（employee-data-privacy）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据《个人信息保护法》与劳动用工场景要求，生成清单：处理目的的必要性界定、告知同意与单独同意、敏感信息与健康信息处理边界、跨境传输与第三方共享、留存删除与安全事件响应。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 员工个人信息保护
- 个人信息合规
- 健康信息处理边界
- 背景调查授权
- 职场监控合规

## 三、工作流
1. 界定处理目的与必要性
2. 履行告知同意与单独同意
3. 划定敏感信息与健康信息边界
4. 规范跨境传输与第三方共享
5. 落实留存删除与安全事件响应

## 四、核心内容（检查清单与判定）
劳动关系下的同意往往难以真正自愿，因此更依赖必要性原则。健康数据属敏感信息，须单独同意并采取更严格的访问控制。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含处理目的与必要性界定 | 必要性 |
| Q2 | FAIL | 未含告知同意与单独同意 | 同意 |
| Q3 | FAIL | 未含敏感信息与健康信息边界 | 敏感信息 |
| Q4 | WARN | 未含跨境传输与第三方共享规范 | 共享 |
| Q5 | WARN | 未含留存删除与安全事件响应 | 响应 |

> 脚本 `employee-data-privacy_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python employee-data-privacy_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python employee-data-privacy_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
