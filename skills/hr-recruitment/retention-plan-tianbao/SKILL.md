# 核心人才保留（retention-plan）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据留才管理与离职预警方法，生成清单：关键岗位与流失风险识别、离职面谈与前兆信号、个性化保留包与职业发展、直线经理留才责任、保留效果复盘。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 核心人才保留
- 留才计划
- 流失预警
- 挽留面谈
- 关键岗位识别

## 三、工作流
1. 识别关键岗位与流失风险
2. 捕捉离职面谈与前兆信号
3. 设计个性化保留包与通道
4. 压实直线经理留才责任
5. 复盘保留效果并迭代

## 四、核心内容（检查清单与判定）
员工离职通常先有信号再有行为：参与度下降、拒绝长期任务、频繁请假。等到提交辞呈才挽留，成功率很低，成本高且伤团队。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含关键岗位与风险识别 | 识别 |
| Q2 | WARN | 未含离职面谈与前兆信号 | 信号 |
| Q3 | FAIL | 未含个性化保留包与通道 | 保留包 |
| Q4 | WARN | 未含直线经理留才责任 | 责任 |
| Q5 | WARN | 未含保留效果复盘 | 复盘 |

> 脚本 `retention-plan_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python retention-plan_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python retention-plan_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
