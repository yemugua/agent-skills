# 大模型幻觉缓解与核查 · 能力概览

## 你会得到什么

**先分清幻觉成因，再开药。** 四类成因——检索不到、检索到了但没用上、题目超出知识边界、被提示注入——处置完全不同。最常见的误判是把前两类混为一谈，两者都表现为「答得不对」，但第一类改了提示词完全无效。**分水岭是先验证检索结果里到底有没有正确答案。**

**grounding 六条硬约束，可直接写进系统提示词。** 其中两条最常被忽略：**数值必须原文出现、禁止换算与推算**（「7 天无理由退货」被说成「15 天」是极典型的幻觉——模型合理地「推断」了），以及**拒答授权**（「回答『未找到相关信息』是被鼓励的正确行为」比「不要编造」有效得多，模型倾向于给点有用的东西，不明确授权它就硬答）。

**引用溯源四要素与伪造引用检测。** 引用必须含来源标识、标题、定位信息、原文摘录。只写「根据相关规定」不是引用，是幻觉的伪装。最恶劣的一类是**伪造引用**——输出 `[来源5]` 但只检索到 3 个来源，说明模型在系统性地假装有依据，必须按严重错误处理。

**三级置信判定与阈值标定方法。** 可答/需人工/拒答的判定条件写清，并说明相似度阈值**不能拍脑袋定**：抽 100 个已知答案的问题，比较「有答案」与「无答案」两组的相似度分布取切点，不同 embedding 模型分布差异很大。三条不可协商规则：结果为空必须拒答、单一来源至少标注需人工、来源冲突必须显式告知。

**兜底话术的合格/不合格对照表。** 并给出高危词清单：大概、应该是、一般来说、通常、估计、差不多、我记得。「一般来说退货期是 7 天」这句本身就是幻觉，而且因为带了限定词，用户更难追究。

**幻觉率必须分类统计。** 总幻觉率 3% 听着不错，若其中「数值篡改」占 2%，对客服场景就是灾难——用户按错误的退货期限操作。

**降 temperature 不能单独解决幻觉**，它只影响输出随机性，不影响是否有依据；模型照样会自信地编。

## 典型用法

1. 用户反馈机器人乱答：先按四成因分类，验证检索结果里有没有答案，再决定修检索还是修提示词。
2. 上线前审核答案：跑脚本查引用覆盖率、伪造引用、数值是否原文出现。
3. 定置信阈值：在评测集上标定高/低置信切点，而不是抄 0.7。
4. 合规场景：高风险场景无条件转人工，触发条件硬编码而不靠模型判断。

## 边界

- 提供的是架构约束与流程方法，**只能降低幻觉率，无法消除幻觉**
- 事实正确性的最终判定依赖领域专家人工核验，脚本只检查结构性问题
- 相似度阈值需在自身评测集上标定，不可照搬
- 涉及医疗、法律、金融的具体建议类问题必须无条件转人工
- 提示词细节调优、模型选型与部署属另一环节
- 知识库内容的合规性与授权范围由业务方确认，以现行规定和主管部门要求为准
