# 小程序微信虚拟支付（xpay）接入避坑与合规

## 何时使用
- 小程序要卖**虚拟商品**（会员、道具、内容、课程、解锁等）。
- 正在**接入/排查微信虚拟支付（xpay）**，或遇到下单失败、回调不发货、重复发货、掉单。
- **混淆了「虚拟支付 xpay」与「微信支付商户号」**，不确定该走哪条通道。
- 有独立上架 App Store 的 iOS 应用，不确定虚拟商品支付方式。

## 核心结论（先给）
1. **虚拟支付（xpay）≠ 微信支付商户号**：虚拟商品必须走 xpay 通道；普通商户号用于实物/服务交易，不能卖虚拟商品。两者分别开通、分别下单。
2. **主体门槛**：虚拟支付要求**已认证的企业或个体工商户**小程序；个人主体无法开通。
3. **iOS 独立 App 例外**：独立上架 App Store 的 iOS 应用内虚拟商品必须走 **Apple IAP**，不得复用 xpay；微信小程序内虚拟支付不受此限。
4. **回调是命门**：支付成功后靠消息推送 `xpay_goods_deliver_notify` 完成发货，**必须幂等（订单号去重）+ 补发对账**，否则重复发货资损或掉单权益缺失。

## 运行核查脚本
输入一份 Markdown 采集表（字段见 `templates/采集表.md`），输出报告：
```bash
python scripts/miniprogram_xpay_guide.py 采集表.md
```
报告含：结论摘要、前置条件、配置核查（offer/product/价格）、回调与发货、合规要点、接入进度与下一步、操作指引、边界。

## 核查维度
- **前置条件**：主体类型（企业/个体可，个人不可）、小程序认证、商户号 vs 虚拟支付区分、iOS 独立 App 限制。
- **配置核查**：offer_id、product_id 是否配置；价格是否以「分」为整数单位、金额是否异常。
- **回调与发货**：发货回调是否配置；回调是否幂等防重复发货；是否有订单补发机制。
- **合规要点**：是否声明虚拟商品不支持退款；是否做未成年人保护。
- **流程节点**：未开始 / 配置中 / 联调中 / 已上线，并定位下一步。

## 边界

- 不得刷量、套现、虚假交易。
