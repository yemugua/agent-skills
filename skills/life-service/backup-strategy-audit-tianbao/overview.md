# 数据备份策略制定与恢复演练核查 · 能力概览

## 你会得到什么

一套能把「备份任务成功」和「数据真的能恢复」区分开的完整方法——这是备份领域最大的认知差，也是最贵的一课。

**原则层面**：3-2-1-1-0 而不只是 3-2-1。原始 3-2-1 解决的是「介质坏了、设备丢了」，**不解决「数据被加密或被删了」**，所以必须补一个不可变/离线副本，并且备份凭据要与生产隔离；同时补「0 个错误」——没有验证过的备份等价于 0。

**RPO/RTO 层面**：两者的定义与分工（RPO 决定备份频率，RTO 决定恢复方案），以及一张按业务分级的对齐表。更关键的是一条硬判定：**声明 RPO ≤ 5 分钟但备份频率是每日，这个 RPO 就是不可达的**——定时备份无法突破频率限制，只能靠同步复制或日志归档。

**有效性层面**：六层校验法（L1 任务级 / L2 存在级 / L3 完整性级 / L4 逻辑级 / L5 业务级 / L6 灾备级），每层能发现什么、自动化要求、执行成本。判定口径明确写死：**只有 L1–L4 没有 L5，就不得声称备份有效**。以及八种静默失败形态与识别命令。

**演练层面**：按分级的演练频率建议（核心交易每季度）、演练方案六要素、可量化验收标准（六条，其中「流程可用」和「问题闭环」最容易被漏），以及演练失败的六个常见原因。

## 典型用法

1. 制定备份策略：先给数据定级，再由业务方书面确认 RPO/RTO，然后核频率能否支撑 RPO。
2. 审计现有备份「到底有没有用」：按六层校验表逐层核，重点看有没有做过 L5。
3. 备份告警了但没人管：先核静默失败形态表，尤其是 0 字节、空间截断、保留策略没清理。
4. 设计演练方案：按六要素写，验收标准必须可量化。
5. 复核策略自洽性：脚本能直接发现「声明 RPO 5 分钟 + 频率每日」这类自相矛盾。

## 边界

- 只做**策略口径、有效性校验方法与演练方案设计**，不代替现场恢复操作
- RPO/RTO 的具体数值**必须由业务方书面确认**，技术侧无法单方面决定，也**不能承诺一定做得到**
- 留存期限与演练频率的具体要求**以现行规定、行业规范、当地主管部门要求与本单位制度为准**，本技能中的频率与周期是实践建议，**不是合规结论**
- 任何恢复操作尤其在生产环境**必须经审批后执行**，并事先评估数据覆盖风险
- 脚本只做策略文本的口径核对，**不能验证备份文件是否真的可用**，也不会替代真实的恢复演练
- 备份数据可能含敏感信息，存储、传输、访问与销毁须遵守现行规定与本单位数据安全要求
