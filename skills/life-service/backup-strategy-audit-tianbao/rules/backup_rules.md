# 备份策略核查规则表：分级、RPO/RTO、有效性、演练

本文件是 `backup-strategy-audit` 的核心资产。**定策略、核有效性、排演练周期之前，先读本文件，不要凭印象。**

---

## 一、3-2-1-1-0 六要素核查

| 要素 | 要求 | 核查口径 | 不满足的后果 |
|---|---|---|---|
| 3 副本 | ≥ 3 份 | 生产原始 + 至少 2 份备份 | 任一副本损坏即数据丢失 |
| 2 介质 | ≥ 2 种存储类型 | 「本地磁盘 + 对象存储」✅；两块同盘 RAID ❌ | 同盘故障同时带走两份 |
| 1 异地 | ≥ 1 份异地 | 不同机房/可用区，最好不同城市 | 机房级故障带走全部 |
| +1 不可变 | ≥ 1 份离线或不可变 | 保留锁 / WORM / 离线磁带 | 勒索软件同步加密备份 |
| +0 零错误 | 备份必须经验证 | 见第三节六层校验 | 备份只是占空间的垃圾 |

**「2 种介质」的常见误判**：

| 组合 | 是否算 2 种 |
|---|---|
| 本地磁盘 + NAS | ✅ 不同存储类型 |
| 本地磁盘 + 对象存储（S3 兼容） | ✅ |
| 两块同盘做 RAID1 | ❌ 同盘故障一起丢 |
| 两台不同服务器的本地磁盘（无异地） | ⚠️ 算 2 份副本，但不满足异地要求 |
| RAID5 上的备份 + 同一 RAID5 上的原始数据 | ❌ 同盘 |

## 二、分级与 RPO/RTO 对齐表

| 分级 | 典型内容 | RPO 建议 | RTO 建议 | 备份方式 | 演练频率 |
|---|---|---|---|---|---|
| 一级 核心交易 | 订单、支付、账务 | ≤ 5 分钟 | ≤ 1 小时 | 同步复制 + 实时日志归档 | 每季度（L5+L6） |
| 二级 重要业务 | 客户资料、查询、配置 | ≤ 1 小时 | ≤ 4 小时 | 每日全量 + 15 分钟增量 | 每半年（L5） |
| 三级 一般业务 | 内部系统、报表 | ≤ 24 小时 | ≤ 24 小时 | 每日全量 + 每日增量 | 每年（L5） |
| 四级 可重建 | 镜像、构建产物、静态资源 | ≤ 7 天 | ≤ 72 小时 | 代码仓库 + 制品库 | 随发布验证（L4） |
| 日志审计类 | 操作日志、审计日志 | 按现行规定 | 按现行规定 | 独立存储 + 长期留存 | 按规定 |

> 演练频率与留存期限的具体要求，**以现行规定、行业规范与本单位制度为准**。上表为实践建议。

## 三、六层有效性校验表（核心）

| 层 | 名称 | 方法 | 能发现 | 频率 | 自动化 |
|---|---|---|---|---|---|
| L1 | 任务级 | 退出码、调度器状态 | 任务没跑、跑失败 | 每次 | 必须 |
| L2 | 存在级 | 文件存在、大小 > 0、时间戳 | 备份了空气、路径错 | 每次 | 必须 |
| L3 | 完整性级 | 校验和、`tar -t`/`gzip -t`/`unzip -t` | 损坏、截断 | 每次 | 必须 |
| L4 | 逻辑级 | 导出能导入空库、表数行数合理 | 只有结构没数据、结构错 | 每日/每周 | 必须 |
| L5 | 业务级 | 恢复测试环境并跑关键流程 | 备份不完整、应用起不来 | **每月/每季** | 半自动 |
| L6 | 灾备级 | 异地恢复 + 灾难场景切换 | 异地链路、凭证、流程 | **每半年/每年** | 人工 |

**判定口径：**

1. **只有 L1–L4 没有 L5 → 不得声称备份有效。** 至少要做过一次 L5 恢复验证。
2. L1–L4 必须全自动且告警能到人；L5–L6 必须有人工参与并留记录。
3. 「归档可解包」不等于「数据可用」——L3 通过仍可能有 L4 问题（只导了 schema）。

## 四、RPO 与备份频率匹配表

**声明的 RPO 决定了必须用什么备份方式。定时备份无法突破频率限制。**

| 声明 RPO | 可行方式 | 定时备份能否达到 |
|---|---|---|
| ≤ 5 分钟 | 数据库同步复制 / 实时日志归档 | ❌ 不能 |
| ≤ 15 分钟 | 高频增量 / 日志归档 | ❌ 不能 |
| ≤ 1 小时 | 每小时增量或每小时全量 | ⚠️ 需每小时任务 |
| ≤ 24 小时 | 每日全量 | ✅ |
| ≤ 7 天 | 每周全量 | ✅ |

**判定规则**：声明 `RPO ≤ 15 分钟` 但频率是 `hourly` 或更低 → **不合规**。这是最常见的自相矛盾。

**RTO 与备份方式无关**：RTO 取决于恢复方案（技术手段、演练、备件、人员），提高备份频率不改善 RTO。

## 五、静默失败形态表

| 形态 | 根因 | 识别方法 | 对应校验层 |
|---|---|---|---|
| 0 字节文件 | 源路径错、挂载点掉、配额截断 | 大小阈值校验 | L2 |
| 内容是上次的 | 增量基点错、缓存未刷新 | 内容哈希与时间戳比对 | L3 |
| 备份文件消失 | 无权限、无空间、被删 | 定期抽检存在性 | L2 |
| 备份内容损坏 | 源已损坏、备份时源在写 | 恢复验证 + 一致性校验 | L3/L5 |
| 只有结构没有数据 | 导出参数错、只导 schema | 校验恢复后行数 | L4 |
| 备份被加密 | 与生产共用凭据 | 不可变副本 + 凭据隔离 | 制度 |
| 任务成功但被截断 | 空间不足 | 监控备份分区剩余空间 | L2 |
| 时间戳错乱 | NTP 故障 | 先修时钟再核时间戳 | 制度 |

**识别命令：**

```bash
find /backup -type f -size 0 -mtime -7      # 7 天内 0 字节 -> 严重
find /backup -type f -mtime +2 -size +1G    # 超 2 天未更新
tar -tf <file> > /dev/null && echo OK       # 归档可读
gzip -t <file> && echo OK                   # 压缩完整
sha256sum -c /backup/checksums.sha256       # 校验和
unzip -t <file> | tail -3                   # zip 完整
df -h /backup                               # 备份分区空间
du -sh /backup/* | sort -h | tail           # 大小分布
zcat <dump.sql.gz> | grep -c "^INSERT"      # 数据行数粗查
```

## 六、保留周期阶梯

| 类型 | 份数 | 作用 |
|---|---|---|
| 日备 | 7–14 | 覆盖近两周误操作 |
| 周备 | 4–8 | 覆盖一两个月前事故 |
| 月备 | 6–12 | 覆盖跨季度问题 |
| 年备 | 1–3 | 覆盖长期数据错误（误删整年） |
| 不可变/离线 | 按现行规定与业务要求 | 防勒索、防内部恶意删除 |

**必须配置到期清理**，否则备份分区写满 → 任务静默失败。

## 七、演练方案六要素与验收标准

### 7.1 方案六要素

| 项 | 要求 |
|---|---|
| 目标 | 明确验证 RPO/RTO 达成情况与验证哪几层 |
| 范围 | 恢复哪些系统、多少数据量级 |
| 环境 | 同版本测试环境；不在生产做破坏性恢复 |
| 成功标准 | **可量化**（RTO ≤ 60 分钟 + 关键接口校验通过） |
| 时间点 | 具体日期与参与人 |
| 失败处理 | 失败后 3 个工作日内出改进项 |

### 7.2 验收标准

| 检查项 | 通过标准 |
|---|---|
| RPO 达成 | 能恢复到距演练时刻 ≤ 目标 RPO 的时间点 |
| RTO 达成 | 从开始恢复到业务可用 ≤ 目标 RTO |
| 数据完整性 | 关键表行数与备份时点一致（误差容忍需事先约定） |
| 应用可用 | 应用能启动并通过冒烟用例 |
| **流程可用** | **在 RTO 内完成所有步骤** |
| 问题闭环 | 问题有责任人与期限 |

### 7.3 演练常见失败原因

| 原因 | 现象 |
|---|---|
| 备份没做过恢复 | 恢复时发现备份内容不完整或解不开 |
| 凭证没归档 | 找不到数据库密码、证书私钥、密钥 |
| 版本不匹配 | 旧备份恢复到新版本应用起不来 |
| 依赖清单缺失 | 数据恢复了，中间件/配置/密钥找不全 |
| 没人参与 | 只有一人执行，人走流程就断 |
| 时间超预算 | 实际耗时是 RTO 的 3 倍 |

## 八、备份审计核查清单

### 策略层
- [ ] 有书面策略文档（范围、频率、保留、责任分工）
- [ ] 每类数据定级，RPO/RTO **经业务方书面确认**
- [ ] 覆盖全部关键系统（含镜像、配置、密钥、代码仓库）
- [ ] 明确不做备份的清单及原因

### 落实层（3-2-1-1-0）
- [ ] 副本 ≥ 3
- [ ] 存储类型 ≥ 2，且非同盘
- [ ] 异地 ≥ 1，位置书面记录
- [ ] **不可变/离线 ≥ 1**
- [ ] **备份凭据与生产分离**

### 有效性层
- [ ] L1 任务级自动校验 + 告警到人
- [ ] L2 存在级（大小阈值 + 时间戳）
- [ ] L3 完整性级（校验和 + 归档可解）
- [ ] L4 逻辑级（可导入空库 / 行数合理）
- [ ] **L5 业务级恢复验证，有记录**
- [ ] L6 异地恢复演练，有记录
- [ ] 备份大小趋势监控与异常阈值

### 保留层
- [ ] 日/周/月/年备已配置
- [ ] 到期清理已配置
- [ ] 留存期限满足现行规定与业务要求

### 监控层
- [ ] 备份成功率是核心指标而非只看最近一次
- [ ] 告警**演练过真实失败**
- [ ] 备份分区容量有告警
- [ ] 备份窗口与业务高峰不冲突

## 九、反误判清单

| 现象 | 常见误判 | 真实情况 | 正确做法 |
|---|---|---|---|
| 任务成功 | 备份有效 | 只证明写出了文件 | 至少做一次 L5 恢复验证 |
| 有 3 份备份 | 满足 3-2-1 | 其中两份同盘 | 核存储类型与位置 |
| 异地备份 | 异地可用 | 从没恢复验证过 | 定期做 L6 |
| 声明 RPO 5 分钟 | 备份够 | 频率是每日 | 核 RPO 与频率匹配 |
| 文档写了 RTO | RTO 达成 | 从没演练过 | 演练且量化验收 |
| 告警配了 | 告警有效 | 从没验证能否收到 | 演练真实失败 |
| 校验和一致 | 备份可用 | 可能只导了 schema | 校验行数与恢复 |
| 备份有日志 | 审计合规 | 留存期限未确认 | 以现行规定为准 |
