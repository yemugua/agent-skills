# 公文写作规范与常见错误核查

## 你会得到什么

**先解决最容易退回的一步：文种选错。** 给六类文种的完整对照——通知、通报、报告、请示、函、纪要（含意见的辨析），每类标明适用场景、是否需回复、一文几事、行文方向、典型结尾。两个判定树最实用：

- **通知 vs 通报**：要对方做某事 → 通知（写「请遵照执行」）；告知对方发生了什么 → 通报（写「现将有关情况通报如下」）。表彰批评用通报，用通知显得生硬。
- **报告 vs 请示**：报告只说事，结尾「特此报告」，不需回复、可多事；请示要拿事，结尾「妥否，请批示」，**必须回复、必须一文一事**。口诀背后是一条硬红线：**报告中夹带请示事项是退回的高频原因**。

**然后核对八项格式要素**：标题、主送机关、正文、附件说明、发文机关署名、成文日期、抄送机关、印发机关与日期，每项配「写什么」和「常见错误」。标题有四条规则（三要素齐全、事由一句话概括、末尾不加标点、长标题回行对称），主送机关有三条（不越级、不多头、不写「有关部门」），结尾用语按文种给了对照表——**结尾用语是文种判断的最后一道验证，用错了说明前面理解就有问题**。

**最后扫掉四类高频错误，每一类都给可直接对照的改写样例。** 越级行文（县政府发文给村民委员会）、多头主送（三个市局 → 一个主送加两个抄送）、请示与报告混用（一份文件拆成两份的正确拆法）、口语化表述（12 组改写对照：「大概/差不多」→「约/近」、「尽快」→「于 X 月 X 日前」、「有关部门」→ 具体机关名、「不能不出问题」→ 肯定句）。**处理原则是先删再改，删不掉的词用具体表述替换。**

另附八个完整错误样例（原文 / 问题 / 改法三段式），可直接用作培训材料。

## 典型用法

- 起草前先定文种，避免请示报告混着写被退回
- 审核别人起草的文件，逐项对照八要素表
- 检查结尾用语与文种是否匹配
- 清理正文里的口语化表述与形容词堆砌

## 脚本

`scripts/doc_format_check.py` 读入公文要素 JSON，输出要素完整率、文种与要素匹配检查、越级与多头主送风险、请示夹带报告问题、口语化用语命中清单与整改建议。支持 `--file` / `--text` / `--out` / `--format`，带 `--selftest`。

## 边界

本技能提供文种选型、格式要素清单与常见错误核查方法，不构成对文件法律效力的任何认定。法定公文格式（版头、主体、版记、字体字号、字号编排等）以现行党政机关公文处理工作办法及本单位公文格式规定为准。涉密文件按现行保密规定和本单位保密管理制度办理，本技能不处理涉密内容。涉及法律效力的告知类文件建议由法制或法务部门审核。文种选择与要素写定的最终决定权在本单位发文机关。
