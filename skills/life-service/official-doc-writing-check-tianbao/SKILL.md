# 公文写作规范与常见错误核查（official-doc-writing-check）

公文不是「写得像文章」，而是**按规则填空 + 按文种定内容**。

这个技能做三件事：**先选对文种** → **再核对八项格式要素** → **最后扫掉四类高频错误**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出文种选型对照与判断依据 | ❌ 代替本单位办公室（秘书）定稿 |
| 给出格式要素清单与自查方法 | ❌ 代替发文机关审核 |
| 标出越级行文、多头主送等常见错误 | ❌ 对文件的法律效力作出认定 |
| 给出口语化表述的改写样例 | ❌ 保证文件被上级机关采纳 |
| 给出标题拟定的规则与样例 | ❌ 编写涉及国家秘密的涉密文件 |

**必须先停下来确认的情形：**
- 涉密文件 —— **按现行保密规定和本单位保密管理制度办理**，不得在本技能中处理涉密内容
- 法定公文格式（版头、主体、版记、字体字号、字号编排）—— **以现行党政机关公文处理工作办法及本单位公文格式规定为准**，本技能只给要素清单与自查方法
- 需加盖印章、需特定审批流程的文件 —— 按本单位发文办理流程执行
- 涉及法律效力的告知类文件 —— 建议由法制或法务部门审核

## 二、完整工作流

```
第 1 步  先判断：这件事的行政性质是什么（告知/请示/报告/商洽/纪要/指导）
第 2 步  按 rules/doc_type_table.md 选文种，并检查是否属于禁用情形
第 3 步  按 rules/format_elements.md 逐项核对八项格式要素
第 4 步  跑脚本体检：python scripts/doc_format_check.py --file doc.json
第 5 步  看四个数：要素完整率、错误用语命中数、文种匹配度、越级风险
第 6 步  按 rules/writing_errors.md 逐条比对四类高频错误，改写样例对照
第 7 步  按 §六 行文规则做语言清理：删口语、删形容词、删双重否定
第 8 步  交本单位办公室或发文机关审核后定稿
```

**顺序不能颠倒**：文种选错，后面所有格式都对不上——因为请示必须一文一事，报告可以多事，混着写直接退回。

## 三、六类文种选型对照（核心）

| 文种 | 适用场景 | 是否需回复 | 一文几事 | 主送对象 | 最易错点 |
|---|---|---|---|---|---|
| **通知** | 转发/批转上级公文，发布规章制度，传达要求下级办理的事项，通报任免 | 通常不需回复 | 可多事 | 下级机关、有关单位 | 与「通报」混用；把需要对方执行的事写成「望周知」 |
| **通报** | 表彰先进、批评错误、传达重要精神、告知重要情况 | 不需回复 | 可多事 | 下级机关 | 与「通知」混用；表彰用「通知」显得生硬 |
| **报告** | 汇报工作、反映情况、答复询问 | 不需回复 | 可多事 | 上级机关 | **与请示混用；报告夹带请示事项（最常见错）** |
| **请示** | 请求指示或批准 | **必须回复** | **必须一文一事** | 上级机关 | **一文多事；主送错误；用「报告」代替请示** |
| **函** | 不相隶属机关间商洽工作、询问答复问题、请求批准 | 需回复（视情况） | 可多事 | 平级或不相隶属机关 | 上下级之间用函请示；把「函」写成「通知」口气 |
| **纪要** | 记载会议主要情况和议定事项 | 不需回复 | 只记会议 | 相关单位 | 把纪要写成会议记录流水账；写入未议定事项 |

### 通知 vs 通报（最容易混的一对）

| 维度 | 通知 | 通报 |
|---|---|---|
| 内容性质 | 要求办理、发布、传达 | 告知情况、表彰、批评 |
| 是否要求执行 | 通常要求下级照办 | 一般不要求照办 |
| 典型句式 | 「请遵照执行」「请认真贯彻执行」 | 「现将有关情况通报如下」 |
| 表彰批评 | 不用 | 用 |

**一句话判定**：**要对方做什么 → 通知；告知对方发生了什么 → 通报。**

### 报告 vs 请示（错得最多的一对）

| 维度 | 报告 | 请示 |
|---|---|---|
| 行文目的 | 汇报、反映、答复 | 请求指示或批准 |
| 是否需要回复 | 不需要 | **必须回复** |
| 内容数量 | 可多事 | **必须一文一事** |
| 是否可带请求 | **不可** | 可 |
| 结尾用语 | 「特此报告」 | 「妥否，请批示」「请予批复」 |

**判定口诀**：报告只说事，请示要拿事。**报告里出现「请批示」「请批复」「恳请支持」，是退回的高频原因。**

## 四、八项格式要素清单

| # | 要素 | 写什么 | 常见错误 |
|---|---|---|---|
| 1 | **标题** | 发文机关 + 事由 + 文种，一般三要素齐全 | 省略发文机关；事由不清；用书名号随便加 |
| 2 | **主送机关** | 行文的对象机关名称，多头主送要按规定 | 越级行文；多头主送；写「有关部门」 |
| 3 | **正文** | 开头缘由 + 主体事项 + 结尾要求 | 口语化；无缘由；无执行要求 |
| 4 | **附件说明** | 列附件名称与份数，正文中提及附件 | 附件说明缺失；附件与正文引用不一致 |
| 5 | **发文机关署名** | 行文机关全称或规范简称 | 与主送机关混用；落款用非规范简称 |
| 6 | **成文日期** | 会议通过或负责人签发的日期 | 写成签发日与通过日不一致；日期与落款不一致 |
| 7 | **抄送机关** | 需要了解该件的其他机关 | 抄送过多；抄送顺序不规范 |
| 8 | **印发机关与印发日期** | 印发机关全称、印发日期 | 缺失（需印发时） |

**版头、主体、版记的字体字号、字号编排等具体格式要求，请以现行公文处理办法及本单位公文格式规定为准**，本技能只提供要素层面的自查。

### 标题拟定的四条规则

```
1. 三要素齐全：发文机关 + 事由 + 文种
   ✓ 《XX 市水利局关于印发 XX 管理办法的通知》
   ✗ 《通知》              （缺事由）
   ✗ 《关于加强工作的通知》    （缺发文机关、事由笼统）

2. 事由要能概括正文全部内容，一句话说完
   ✓ 《关于调整 XX 标准的通知》
   ✗ 《关于有关事项的通知》  （「有关事项」等于没说）

3. 一般不用标点符号，标题末尾不加标点
   ✓ 《XX 市关于开展安全生产大检查的通知》
   ✗ 《XX 市关于开展安全生产大检查的通知。》

4. 回行时词意完整、排列对称、排列合理，长标题可分行
```

### 主送机关的三条规则

| 规则 | 说明 |
|---|---|
| **越级不写** | 行文不能越级。上级机关不能越级下发给下级机关的下一级 |
| **多头要谨慎** | 上级机关向下级机关行文，一般只写一个主送机关；确需多个的按规定处理 |
| **不用「有关部门」** | 写具体机关名称，或写「各有关单位」并在其后列明具体范围 |

## 五、行文规则十条

| # | 规则 | 判定标准 |
|---|---|---|
| 1 | **一文一事（请示）** | 请示类必须一文一事 |
| 2 | **行文关系明确** | 按隶属关系和职权确定行文方向 |
| 3 | **不越级行文** | 主送机关与行文机关的层级关系正确 |
| 4 | **不多头主送** | 上级对下级一般只写一个主送机关 |
| 5 | **请示与报告分开** | 报告中不夹带请示事项 |
| 6 | **不用「望周知」代替执行要求** | 需要执行的写「请遵照执行」 |
| 7 | **语言准确简洁** | 无错别字、无歧义、无多余修饰 |
| 8 | **不得使用生造难懂词语** | 不用非公知的外来词、网络用语 |
| 9 | **标点正确** | 一逗到底、书名号误用、括号不配对 |
| 10 | **表述庄重平实** | 无口语、无情绪、无反问、无感叹 |

## 六、四类高频错误与改写对照

### 错误一：越级行文

```
✗  某县人民政府直接行文给该县下属某乡的某村民委员会
   （县政府 → 村民委员会，跳过了乡政府）

✗ 某公司直接发文给其分公司的各班组
   （公司 → 班组，跨级）

✓ 改为按隶属关系逐级行文：某县人民政府 → 某乡人民政府
```

### 错误二：多头主送

```
✗  主送：市发改委、市财政局、市住建局
   （上级对下级一般只写一个主送机关）

✓  改为单一主送 + 抄送：
   主送：市发改委
   抄送：市财政局、市住建局
```

### 错误三：请示与报告混用

```
✗  标题：《关于申请 XX 资金并汇报工作情况的报告》
   结尾：「以上情况，请批示。」
   （报告里夹了请示，且结尾用了请示用语）

✓  拆成两份：
   文件一《XX 单位关于 XX 工作情况的报告》——结尾「特此报告。」
   文件二《XX 单位关于申请 XX 资金的请示》——结尾「妥否，请批示。」
```

### 错误四：口语化与不规范表述

| # | 错误写法 | 规范写法 |
|---|---|---|
| 1 | 「大概」「差不多」「基本上」 | 删除或改精确表述：「约」「近」「基本完成」 |
| 2 | 「搞」「弄」「干」 | 「开展」「办理」「实施」 |
| 3 | 「特别重要」「非常重要」 | 删除，用具体要求代替 |
| 4 | 「大家都知道」 | 删除 |
| 5 | 「尽快」「抓紧」 | 「于 X 月 X 日前」（给具体时限） |
| 6 | 「有关部门」「有关方面」 | 写具体机关名称 |
| 7 | 「就这样」「别的就不多说了」 | 删除 |
| 8 | 「说实话」「其实」 | 删除 |
| 9 | 「必须、一定要、千万」 | 「应当」「须」「严格要求」 |
| 10 | 「不能不出问题」 | 改写为肯定句：「应杜绝…」 |
| 11 | 「是否可行」在请示中模糊使用 | 明确写成「妥否，请批示」或「是否可行，请批复」 |
| 12 | 「我认为」「我个人觉得」 | 删除，用客观表述 |

## 七、脚本用法

```bash
python scripts/doc_format_check.py --file doc.json --out 公文体检.md
python scripts/doc_format_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 公文要素 JSON，见下方结构 |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 输出文件，默认 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON：

```json
{
  "title": "公文格式体检",
  "doc_type": "请示",
  "doc_name": "关于申请 XX 专项资金的请示",
  "elements": {
    "title": true,
    "main_recipient": true,
    "body": true,
    "attachment_note": true,
    "issuer_signature": true,
    "written_date": true,
    "cc": true,
    "printer": false
  },
  "main_recipients": ["市发改委", "市财政局"],
  "hierarchy_ok": true,
  "closing": "妥否，请批示",
  "one_issue_only": true,
  "text_body": "我单位计划开展相关工作，需要专项资金支持，现申请资金 XX 万元。差不多能覆盖全部需求，请尽快安排。"
}
```

| 字段 | 说明 |
|---|---|
| `doc_type` | 文种，取值见文种表 |
| `elements` | 八项格式要素，布尔值 |
| `main_recipients` | 主送机关列表，>1 触发多头主送提示 |
| `hierarchy_ok` | 行文关系是否正确 |
| `closing` | 结尾用语 |
| `one_issue_only` | 是否一文一事 |
| `text_body` | 正文文本，脚本会扫错误用语 |

脚本输出：要素完整率、文种与要素匹配检查、越级与多头主送风险、请示夹带报告问题、口语化用语命中清单，以及整改建议。

> 脚本只做要素与用语的形式核查，**不判断文件的法律效力，也不替代发文机关审核**。

## 八、人工确认清单（这步不能省）

- [ ] 文种已按「要对方做什么 / 告知发生了什么」判定
- [ ] 请示类已确认为一文一事，且报告中没有夹带请示事项
- [ ] 主送机关只有一个，或多头主送有明确依据
- [ ] 行文关系正确，无越级
- [ ] 标题三要素齐全，事由能概括正文
- [ ] 正文有缘由、有事项、有执行要求（含具体时限）
- [ ] 附件说明与实际附件一致，正文引用一致
- [ ] 落款机关名称与主送机关、行文机关相符
- [ ] 成文日期与签发、会议通过时间一致
- [ ] 口语化与情绪化表述已逐条清理
- [ ] 字体字号、版式编排按本单位公文格式规定执行
- [ ] 已交本单位办公室或发文机关审核

## 九、最常见的坑

**坑一：请示和报告混着写。**
错误做法：一份文件标题写「关于申请 X 资金的报告」，结尾写「请批示」。正确做法：拆成两份，报告结尾「特此报告」，请示结尾「妥否，请批示」。**报告不需回复、请示必须回复，混着写等于两头不落。**

**坑二：请示一文多事。**
错误做法：一份请示里写三项资金申请。正确做法：一文一事，三项申请拆成三份或改用其他文种。**一文一事是请示的硬规则。**

**坑三：越级行文。**
错误做法：县政府直接发文给村民委员会。正确做法：按隶属关系逐级行文。**越级行文是被退回的高频原因之一，且会暴露行文关系不清。**

**坑四：多头主送。**
错误做法：一份文件主送三个市局。正确做法：一个主送 + 其余抄送。**多头主送会让对方无法确定责任主体。**

**坑五：把「有关部门」当万能主送。**
错误做法：主送「有关部门」。正确做法：写具体机关名称。**「有关部门」等于没写，执行环节会直接卡住。**

**坑六：口语化表述原样留下。**
错误做法：正文写「差不多能覆盖全部需求」「请尽快安排」。正确做法：改成「约可覆盖」「于 X 月 X 日前完成」。**「尽快」在公文里没有约束力，「大概」在公文里没有准确性。**

**坑七：结尾用语与文种不匹配。**
错误做法：报告结尾写「妥否，请批示」。正确做法：按文种配结尾。**结尾用语是文种判断的最后一道验证——用错了说明前面理解有问题。**

**坑八：标题里写「关于有关事项的通知」。**
错误做法：事由笼统。正确做法：事由一句话概括正文全部内容。**「有关事项」等于没写事由，读者无法判断要不要执行。**

**坑九：缺附件说明。**
错误做法：正文提到「附件 1」，但文件里没有附件说明段。正确做法：附件说明列明附件名称，正文引用一致。**附件对不上会直接影响归档与执行。**

**坑十：把规范文件照抄旧版本。**
错误做法：沿用已废止的旧文号、旧表述。正确做法：以现行规定和本单位最新发布为准。**引用失效文件是公文审核的高频退回项。**
