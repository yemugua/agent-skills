# 顾客满意度测评（customer-satisfaction）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001:2015 9.1.2 与顾客满意度测评模型，生成满意度测评方案：指标维度、抽样、测评方法、分析与不满意处置闭环。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 顾客满意度
- 客户满意度
- NPS
- 满意度调查
- 投诉率分析
- 客户体验

## 三、工作流
1. 设计满意度指标维度（质量/交付/服务/价格）
2. 确定样本量与抽样方法
3. 选择测评方法（问卷/投诉率/NPS）
4. 分析并输出改进计划
5. 不满意处置与回访闭环

## 四、核心内容（检查清单与判定）
ISO 9001:2015 9.1.2 要求监视顾客感受；满意度测评应覆盖关键接触点，并将不满意项纳入纠正措施闭环。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未设计满意度指标维度 | 指标 |
| Q2 | WARN | 未明确样本量/抽样方法 | 样本 |
| Q3 | FAIL | 未含测评方法（调查/投诉率/NPS） | 方法 |
| Q4 | WARN | 未含分析与改进闭环 | 改进 |
| Q5 | FAIL | 未含不满意处置与回访 | 闭环 |

> 脚本 `customer-satisfaction_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python customer-satisfaction_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python customer-satisfaction_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
