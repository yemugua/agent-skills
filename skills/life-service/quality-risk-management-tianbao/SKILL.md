# 质量风险管理（quality-risk-management）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001 基于风险的思维与 FMEA 方法，生成清单：风险识别（产品/过程/体系）、风险评价（严重度/发生度/探测度）、风险应对策略、措施实施与有效性验证、风险评审与动态更新。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 质量风险
- 风险管理
- 风险评价
- 风险应对
- 风险评审

## 三、工作流
1. 识别产品/过程/体系风险
2. 按严重度/发生度/探测度评价
3. 确定应对策略（规避/降低/接受）
4. 实施措施并验证有效性
5. 定期评审并动态更新

## 四、核心内容（检查清单与判定）
基于风险的思维要求识别并应对影响质量目标的不确定性；评价用S/O/D，措施须验证有效性，风险随内外部变化动态更新。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含风险识别（产品/过程/体系） | 识别 |
| Q2 | FAIL | 未含风险评价（S/O/D） | 评价 |
| Q3 | WARN | 未含风险应对策略 | 应对 |
| Q4 | FAIL | 未含措施实施与有效性验证 | 措施 |
| Q5 | WARN | 未含风险评审与更新 | 评审 |

> 脚本 `quality-risk-management_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python quality-risk-management_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python quality-risk-management_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
