# 建设工程消防验收材料核查（fire-acceptance-check）

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 判定走哪条路：特殊建设工程走消防验收，其他建设工程走竣工验收消防备案加抽查 | ❌ 代替住房和城乡建设主管部门作出验收结论、出具合格意见 |
| 逐项核材料清单，标出缺失与存疑 | ❌ 认定某项一定能通过现场查验 |
| 列出 12 类高频不合格项并给出整改优先级 | ❌ 代替设计、施工、检测单位的法定责任与技术判定 |
| 计算受理后出件期限、备案窗口、检测报告有效期 | ❌ 保证一定不被抽中、一定验收通过 |
| 输出材料核查表与整改排序 | ❌ 出具竣工图纸、隐蔽工程记录、施工记录等应由责任主体形成的文件 |

**遇到以下情况，必须先转施工设计单位、具备从业条件的消防技术服务机构，或直接咨询当地住建主管部门：**

- 未经消防设计审查擅自施工，或建成后补手续
- 擅自改变使用性质、平面布局、防火分区、疏散设计
- 涉及易燃易爆场所、人员密集场所、超高层、大型综合体、隧道与轨道交通工程
- 竣工图纸与现场明显不一致，需要重新测绘或出具设计变更
- 消防产品缺少强制性认证，或被通报为不合格品

**永远不要建议后补、倒签隐蔽工程验收记录或检测报告日期。**
这类文件的日期一旦被倒推或伪造，在后续验收、抽查或事故调查中会被直接认定为虚假材料，责任主体可能承担行政乃至刑事责任。本技能帮用户补正的是一份**真实的材料**，不是做出一份好看的材料。

## 二、完整工作流

```
第 1 步  理清三个前提：项目是否属特殊建设工程、是否已取得消防设计审查意见、
        是否已竣工验收合格
第 2 步  先读规则文件 rules/acceptance_materials.md 与 rules/defect_library.md
第 3 步  跑核查脚本
    python scripts/acceptance_check.py --file 项目情况.txt --as-of 2026-10-08
第 4 步  按输出补缺失材料：先补一票否决项（设计审查意见、竣工图纸、检测报告），
        再补形式性材料
第 5 步  把 12 类不合格项按 A/B/C 分级排整改顺序
第 6 步  按 templates/材料核查表.md 输出结论：能不能报、缺什么、先改什么
```

## 三、先分路：消防验收 vs 竣工验收消防备案

这一步搞反了，后面全白做。

| 对比项 | 消防验收 | 竣工验收消防备案加抽查 |
|---|---|---|
| 适用对象 | 特殊建设工程 | 其他建设工程 |
| 程序位置 | 竣工验收合格后申请，**先验收后使用** | 竣工验收合格之日起 5 日内报备案，**备案后被抽中才检查** |
| 结果形式 | 出具消防验收意见（合格或不合格） | 备案凭证；被抽中的按验收标准检查并公开结果 |
| 抽查 | 不适用 | 随机抽取，抽取比例与办法由省级住建主管部门确定并向社会公布，**以当地公布口径为准** |
| 关键风险 | 不合格则不得投入使用 | 未备案、或虽未被抽中但隐患被举报发现，同样会被依法处理 |

**特殊建设工程**的范围以现行部门规章和当地主管部门要求为准。实践中高概率被认定为特殊建设工程的情形：

- 总建筑面积较大的宾馆、饭店、商场、市场（实践中常见门槛为 1 万平方米）
- 客运车站候车室、客运码头候船厅、民用机场航站楼
- 体育场馆、会堂，公共展览馆、博物馆的展示厅
- 影剧院、礼堂等演出放映场所
- 歌舞厅、录像厅、放映厅、卡拉OK厅、夜总会、游艺厅、桑拿浴室、网吧、酒吧等歌舞娱乐放映游艺场所（实践中常见门槛为 500 平方米）
- 一类高层住宅建筑
- 城市轨道交通、隧道工程，大型发电变配电工程
- 生产、储存、装卸易燃易爆危险物品的工厂、仓库和专用车站、码头，易燃易爆气体和液体的充装站、供应站、调压站
- 国家机关办公楼、电力调度楼、电信楼、邮政楼、防灾指挥调度楼、广播电视楼、档案楼
- 单体建筑面积较大或建筑高度较高的公共建筑（实践中常见门槛为 4 万平方米、50 米）

> 上述门槛为实践中常见理解，**具体口径以现行规定和项目所在地住建主管部门的认定为准**。拿不准就按最严的要求准备，并提前向主管部门窗口确认。

## 四、15 项申报材料清单

完整口径在 `rules/acceptance_materials.md`，这里列最常见的 15 项：

| # | 材料 | 缺了会怎样 |
|---|---|---|
| 1 | 消防验收申请表（含项目基本信息与使用性质） | 形式审查阶段直接退回 |
| 2 | 工程竣工验收报告，含消防分部工程验收记录 | 一票否决 |
| 3 | 涉及消防的建设工程竣工图纸（总平面、建筑、结构、给排水、暖通、电气） | 一票否决，且必须与现场一致 |
| 4 | 消防设施与系统清单、产品合格证明、强制性认证或型式检验文件 | 一票否决 |
| 5 | 具有防火性能要求的建筑构件、建筑材料、装修材料证明文件与出厂合格证 | 一票否决 |
| 6 | 消防设施检测合格报告（具备从业条件的技术服务机构出具） | 一票否决 |
| 7 | 施工、监理、检测单位的合法身份证明与资质等级证明 | 主体不明，退回 |
| 8 | 建设单位合法身份证明（营业执照等） | 主体不明，退回 |
| 9 | 建设工程规划许可、施工许可文件 | 视情形要求 |
| 10 | 建设工程消防设计审查意见书或设计文件审查合格书 | 一票否决 |
| 11 | 设计变更的技术复核或重新审查文件（有变更时必须有） | 擅自变更是高频不合格原因 |
| 12 | 隐蔽工程验收记录（防火封堵、管线穿越防火分隔、钢结构防火涂料厚度） | 事后无法核验 |
| 13 | 消防设施施工记录、调试记录与联动试验记录 | 无法证明系统功能成立 |
| 14 | 消防安全管理制度、灭火和应急疏散预案（部分情形要求） | 管理类材料缺失 |
| 15 | 专家评审意见及落实情况（涉及特殊消防设计时） | 无法闭环 |

> 三个必须最优先补齐的一票否决项：**消防设计审查意见、竣工图纸、消防设施检测合格报告**。这三项不齐，其余材料再全也推进不动。

## 五、12 类高频不合格项与整改优先级

规则全文在 `rules/defect_library.md`，判定口径：

| 等级 | 含义 | 处置 |
|---|---|---|
| **A 类** | 违反强制性要求或导致系统整体失效 | 停止使用或禁止投入使用，整改后重新申请 |
| **B 类** | 影响消防设施可靠性或疏散安全性 | 限期整改后提交复查材料 |
| **C 类** | 形式性、标识性、资料性缺陷 | 随附材料补正即可 |

| 类别 | 典型表现 | 一般等级 |
|---|---|---|
| 擅自变更 | 平面布局、防火分区、疏散宽度、设施配置与审查过的图纸不符 | A |
| 消防产品不符 | 无强制性认证、型号与证书不符、已被通报为不合格品 | A |
| 系统与联动 | 消防设施未完工、联动逻辑未调试、手动自动切换失效 | A |
| 疏散条件 | 安全出口数量不足、疏散宽度不足、疏散距离超限 | A |
| 防火分隔 | 防火分区面积超标、防火门等级或常开常闭要求不符、防火封堵缺失 | A |
| 装修材料 | 顶棚、墙面、地面燃烧性能等级不达标 | A 至 B |
| 总平面 | 防火间距不足、消防车道净宽净高不足、登高操作场地被占用 | A 至 B |
| 水系统 | 消防水池水位不足、消防泵组流量压力不达标、末端压力不足 | B |
| 供配电 | 双电源未在末端切换、配电线路防火保护不到位 | B |
| 防排烟 | 风机风量不足、正压送风余压不达标、防火阀未联动 | B |
| 资料完整性 | 隐蔽工程记录缺失、检测报告过期或漏项、系统与申报范围不符 | B 至 C |
| 管理条件 | 无制度、无预案、无责任人、标识缺失 | C |

## 六、脚本用法

```bash
python scripts/acceptance_check.py --file "D:\项目\某某厂房情况说明.txt" --as-of 2026-10-08
```

| 参数 | 说明 |
|---|---|
| `--file` | 必填。项目情况说明或材料清单文本（`.txt` / `.md`） |
| `--as-of` | 核查基准日，默认今天，用于推算期限 |
| `--accept-date` | 受理日期，用于推算受理后 15 日内出件的截止日 |
| `--complete-date` | 竣工验收合格日期，用于推算 5 日备案窗口 |
| `--type` | `special`（消防验收）/`other`（备案抽查）/`auto`（默认，按关键词与面积推定） |
| `--out` | 输出文件路径，默认打到屏幕 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本做五件事：

1. **工程类型判定**：按场所类型关键词、建筑面积、建筑高度推定是否属特殊建设工程，并把命中的证据行打出来
2. **材料扫描**：15 项必备材料逐项查有没有，缺的标出来
3. **期限计算**：受理之日起 15 日内出件的截止日；竣工验收合格之日起 5 日备案窗口
4. **不合格项抽取与分级**：按关键词库抽问题并分 A/B/C
5. **整改排序输出**：先 A 后 B 后 C；同级内按先资料后现场、先疏散后设备

> ⚠️ 脚本只做关键词匹配，**不代表工程判断**。标「命中」不等于这一项真的符合要求。

## 七、人工确认（这步不能省）

- [ ] 项目使用性质与申报时填的内容是否一致（改了性质要重新认定）
- [ ] 竣工图纸上每一个防火分区、每一部疏散楼梯是否都对得上现场
- [ ] 检测报告出具单位是否具备相应从业条件、报告是否在有效期内
- [ ] 消防产品铭牌型号与认证证书型号是否逐台对得上
- [ ] 隐蔽工程记录是否有监理签字、日期是否连贯
- [ ] 施工期间的变更有没有走技术复核，还是现场直接改了
- [ ] 不合格项描述是否落到具体部位，而不是笼统写「部分消防设施存在问题」

**四类见到就退回的异常：**

| 异常 | 表现 | 后果 |
|---|---|---|
| 先斩后奏 | 无消防设计审查意见，或未竣工验收就申请 | 不予受理 |
| 图纸与现场两张皮 | 图纸合规，现场却加了隔断或多加了一层 | 现场查验不通过 |
| 检测报告错配 | 报告的工程名称、层数、面积与本项目对不上 | 报告作废，重新委托 |
| 整改项只有一句话 | 写「已整改」，无日期、无责任人、无复查记录 | 闭环不成立 |

## 八、输出结构（固定五段）

1. **走哪条路** —— 消防验收还是备案抽查，依据是什么
2. **材料核查表** —— 15 项逐项标有、缺、存疑，并标出三项一票否决材料
3. **不合格项分级表** —— 等级、部位、描述、整改期限、责任单位
4. **整改排序** —— 谁先改、改完交什么材料、谁来复核
5. **期限提醒** —— 受理出件截止日、备案窗口、检测报告有效期

## 九、最常见的坑

**坑一：把备案当成不用查。**
备案不等于免检。被抽中后按验收标准查，查不过一样不能用；没被抽到但隐患被投诉举报发现，照样依法处理。

**坑二：面积和层数的口径不看怎么算出来的。**
建筑面积是否含地下、是否含裙房，直接影响是否跨过特殊建设工程的门槛。不问口径就拿数字去比对门槛，判定全错。

**坑三：漏了备案窗口。**
备案期限是竣工验收合格之日起 5 日内，不是拿到竣工图纸后 5 日，更不是想起来就报。逾期会带来不必要的麻烦。

**坑四：把型式检验报告当成强制性认证。**
两者不是一回事。列入强制性认证目录的产品要有认证证书，型式检验报告只证明送检样品合格，不能替代。

**坑五：只补资料不核现场。**
材料漂漂亮亮，一到现场发现多了两层隔断、少了一部楼梯。形式审查只是第一关，现场查验才是决定性的。

**坑六：为了赶交付先使用后办手续。**
未经消防验收或者验收不合格擅自投入使用是明确禁止的，且事后极难补正。

**坑七：同一份材料套用到多个项目。**
不同项目的竣工图纸、系统清单、隐蔽工程记录不可能完全一致，套模板会在交叉比对时露出破绽。

## 十、边界与免责

- 本技能**不代替**住房和城乡建设主管部门的消防验收结论，不具备任何行政效力
- 适用对象范围、面积门槛、办理期限、备案抽查比例因地区、工程类型、适用规范版本而有差异，**以现行规定和当地主管部门要求为准**
- **不得用于修改、倒签、伪造申报材料、隐蔽工程记录或检测报告**
- 涉及重大火灾隐患或擅自使用未经消防验收建筑的，应立即停用并报告主管部门，不以核查报告替代现场处置
