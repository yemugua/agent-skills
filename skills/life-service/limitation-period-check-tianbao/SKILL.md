# 诉讼时效起算与中断核查（limitation-period-check）

一件事能不能起诉，先算三个数：**从哪天起算**、**有没有中断**、**还剩几天届满**。

这个技能做四件事：**定起算点** → **验中断** → **算天数** → **出取证动作**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按输入的日期计算起算日、届满日、剩余天数 | ❌ 认定某一主张"一定能胜诉" |
| 逐条核验中断事由是否有效 | ❌ 代替律师出具诉讼方案或法律意见书 |
| 输出剩余天数风险分级与取证动作 | ❌ 预测法院对某一证据的采信结果 |
| 提示中止、最长保护期、不适用时效的情形 | ❌ 代理立案、代发律师函、代收代管款项 |
| 生成期间核查结论表与材料清单 | ❌ 认定"时效已过就等于钱要不回来" |

**遇到以下情况，务必转交执业律师或法律援助机构：**
- 涉及建设工程价款优先受偿权、撤销权、保证期间等**除斥期间**问题
- 涉及涉外、海事、航空、保险等特别法期间
- 即将届满（剩余 30 天内）且需要立即立案
- 已进入诉讼、执行、破产程序
- 涉及刑事追诉时效、行政处罚追究时效

**永远不要把"时效已届满"说成"权利消灭"。** 时效届满产生的是义务人的抗辩权，义务人仍可自愿履行，履行后不得请求返还。这样说错会直接误导当事人放弃主张。

## 二、完整工作流

```
第 1 步  收集三个日期：权利受损害之日 / 知道受损且知道义务人之日 / 今天
第 2 步  先读规则文件 rules/limitation_rules.md（起算、中断、中止、最长保护期）
第 3 步  定期间长度：普通 3 年，特别法另有规定的按其规定
第 4 步  跑计算脚本，得到届满日与剩余天数
    python scripts/limitation_calc.py --start 2020-01-01 --period 3 --as-of 2026-10-08
第 5 步  逐条核验中断事由的证据强度，剔除无效中断
第 6 步  输出四段式结论：期间结论 + 中断链条 + 剩余天数分级 + 取证动作
```

---

## 三、起算点：双知道标准

起算必须同时满足两个条件，缺一个不起算：

| 条件 | 缺口表现 |
|---|---|
| 知道或应当知道权利受损害 | 钱被拖欠但账目未核对、损失金额未确定 |
| 知道或应当知道义务人 | 只知道受损，查不出具体是谁造成的 |

分情形起算口径（完整表见 `rules/limitation_rules.md`）：

| 情形 | 起算日 |
|---|---|
| 约定履行期限 | 履行期限届满之日 |
| 未约定履行期限 | 首次主张被拒之日或宽限期届满之日 |
| 分期履行 | 最后一期履行期限届满之日 |
| 持续侵权 | 侵权行为终了之日 |
| 未成年人遭受性侵害的损害赔偿请求权 | 受害人年满 18 周岁之日 |

---

## 四、中断：重新起算的基准时点

| 类别 | 事由 | 重新起算基准 |
|---|---|---|
| 程序类 | 起诉、仲裁、支付令、申请执行、破产申报 | **程序终结之日** |
| 非程序类 | 调解/投诉被受理、催告到达、义务人认可 | **事件本身发生/到达之日** |

关键差别：**催告类按"到达义务人之日"算，不是你发出的那天。**

无效中断清单（见到就剔除）：

| 情形 | 判定 |
|---|---|
| 催告函写了没寄、寄出被退回未妥投 | 未到达，无效 |
| 起诉后撤诉 | 撤诉视为未起诉，按保守口径不产生中断 |
| 起诉被裁定不予受理或被驳回 | 一般不产生中断效果 |
| 期间届满之后的催告或承诺 | 期间已过，中断无意义 |
| 只有内部催款记录，无对外送达凭证 | 无法证明到达 |

---

## 五、中止与最长保护期

- **中止**：障碍须发生在时效**最后 6 个月内**；效果是自障碍消除之日起**再满 6 个月**届满（补足 6 个月，不是顺延障碍时长）
- **最长保护期**：自权利受损害之日起 **20 年**，不适用中止、中断；与普通时效**取更早的那个**
- 时效**不适用**于：停止侵害/排除妨碍/消除危险、不动产物权与登记动产物权返还、抚养费赡养费扶养费

## 六、脚本用法

```bash
python scripts/limitation_calc.py --start 2020-01-01 --period 3 --as-of 2026-10-08
python scripts/limitation_calc.py --start 2020-01-01 --event "2022-06-01,demand" --event "2023-01-05,sue,2023-08-10" --out result.md
python scripts/limitation_calc.py --start 2019-01-01 --damage-date 2000-01-01 --as-of 2026-10-08
```

| 参数 | 说明 |
|---|---|
| `--start` | 必填。起算日 `YYYY-MM-DD` |
| `--period` | 期间年数，默认 `3` |
| `--as-of` | 核查基准日，默认今天 |
| `--damage-date` | 权利受损害之日，用于算 20 年最长保护期 |
| `--event` | 中断事件，可重复。格式 `<日期>,<类型>[,<程序终结日>]` |
| `--suspend-start` / `--suspend-end` | 中止障碍开始日与消除日 |
| `--out` | 结果写入文件 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置自检（13 条断言） |

`--event` 类型：

| 类型 | 含义 | 类别 |
|---|---|---|
| `sue` | 提起诉讼 | 程序类（从终结日重新起算） |
| `arb` | 申请仲裁 | 程序类 |
| `pay` | 申请支付令 | 程序类 |
| `exec` | 申请执行 | 程序类 |
| `med` | 调解/投诉受理 | 非程序类 |
| `demand` | 催告到达 | 非程序类 |
| `ack` | 义务人认可（还款计划、部分付款） | 非程序类 |

脚本做五件事：起算日锁定 → 中断链条逐条重算 → 中止补足 6 个月 → 20 年最长保护期取早 → 剩余天数与风险分级。

> ⚠️ 脚本按**你输入的日期**计算，不判断证据是否真实存在。所有中断事由必须逐条人工核验送达凭证。

## 七、人工确认（这步不能省）

- [ ] 起算日是否同时满足"知道受损"和"知道义务人"
- [ ] 每条中断事由是否有**到达凭证**，而不只是"我发过"
- [ ] 程序类事件有没有取到**程序终结日**（生效日/结案日），不要默认用立案日
- [ ] 障碍是否真的落在最后 6 个月内
- [ ] 是否误把除斥期间、起诉期限、申请执行期限当成了诉讼时效
- [ ] 期间长度是否受特别法调整（国际货物买卖、海上/航空运输、保险等）

---

## 八、输出结构（固定四段）

1. **期间结论** —— 起算日、适用期间、届满日、剩余天数、风险等级
2. **中断链条表** —— 逐条列事由、发生日、重新起算基准日、重算后届满日、是否有效
3. **特别提示** —— 中止、最长保护期、不适用时效的情形
4. **取证动作清单** —— 按剩余天数分级给出接下来该做什么

## 九、最常见的坑

**坑一：把"受损之日"当起算点。**
起算是"知道受损**且**知道义务人"之日。钱 2015 年被挪走、2023 年才查到是谁干的，起算点是 2023 年。

**坑二：把"发出催告"当"到达"。**
律师函躺在抽屉里、EMS 被退回未妥投，都不产生中断。要有签收或妥投查询记录。

**坑三：撤诉后以为时效重新算过。**
起诉后撤诉按未起诉处理，保守口径下不产生中断。以为安全继续等，等来的是届满。

**坑四：忘了 20 年最长保护期。**
普通时效算出来还有两年，但损害发生已超过 20 年，一样不予保护。两个限制取更早的。

**坑五：中止当成"障碍多久顺延多久"。**
中止的效果是"消除后再补 6 个月"，不是把障碍持续时间往后平移。

**坑六：把申请执行期限、除斥期间混进诉讼时效。**
撤销权 1 年/5 年、优先受偿权 18 个月、保证期间 6 个月都是除斥期间，不中止不中断，混用会算错。

**坑七：告诉当事人"过期了就没办法了"。**
时效届满只产生抗辩权，对方同意履行或自愿履行的仍然有效，且履行后不得请求返还。

## 十、边界与免责

- 本技能输出的是**期间测算与材料整理**，不构成法律意见，不代理案件，不承诺诉讼结果
- 期间长度、起算口径、中断认定标准**以现行《民法典》及司法解释、特别法规定和受诉法院认定为准**，本技能不引用具体条款号
- 届满日遇法定节假日的顺延规则、各地法院对网上立案时点的认定可能存在差异，需人工复核
- 本技能不得用于伪造、倒签催告函、对账单等证据材料
