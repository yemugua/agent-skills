# 汇报节奏表与预期对齐规则库

> 生成任何汇报材料前先读本文件，不要凭印象写。

## 一、汇报对象分档表

先把「我要沟通的人」分开，不同的人关心完全不同的东西。

| 对象 | 关心什么 | 关心什么（不关心） | 频次 | 典型陷阱 |
|---|---|---|---|---|
| 直属上级 | 指标、风险、你的进度是否可控 | 行业八卦、你的情绪 | 日/周 | 只报喜不报忧 |
| 隔级领导 | 方向、资源、跨部门影响 | 细枝末节的操作过程 | 季（必要时） | 直接越级要资源 |
| 平级协作方 | 接口时间点、交付物定义、责任人 | 你的考核结果 | 按接口节奏 | 把协作当汇报 |
| 下属 | 目标、边界、反馈 | 你的上级关系 | 周 | 报喜不报忧传染下去 |

**一条规则**：向谁汇报，就用谁关心的指标口径。不要把给下属的成长型汇报原样发给上级。

## 二、四档节奏表设定规则

| # | 规则 | 说明 | 反例 |
|---|---|---|---|
| 1 | 固定时点优先于频率 | 定在具体时间点（如每周五 15:00），可预期性带来信任 | 「我随时向您汇报」——等于没有节奏 |
| 2 | 形式随内容长度 | ≤5 行用 IM；≤1 页用文档；>3 页用材料 + 会上过 | 三行字发一封邮件标题为《本周工作汇报》的长文 |
| 3 | 阻塞项走日档 | 只要今天有阻塞就必须当天说，不等周报 | 周五下午统一说「这周有 3 个卡点」 |
| 4 | 缺档要写理由 | 「团队仅 3 人，月报与周报合并」是合法理由；不写理由就是漏 | 默默没有月报，季度复盘时才想起 |
| 5 | 内容字段按受众重填 | 同一个岗位，上级换了就要改字段 | 技术岗周报里全是销售漏斗数据 |
| 6 | 静默也是策略 | 无进展无阻塞的日子，不必发「今日无进展」 | 每天发「今日无异常」训练领导忽略你的消息 |

## 三、日档 / 周档 / 月档 / 季档内容清单

### 日档（阻塞优先）

| 字段 | 必填 | 说明 |
|---|---|---|
| 昨日完成 | 是 | 1-2 条，只写结果不写流水 |
| 今日计划 | 是 | 1-2 条 |
| 阻塞项 | 否（无则省略） | 写清：卡在什么 + 卡了多久 + 需要谁做什么 |
| 是否需要决策 | 否 | 需要上级拍板的，在这里点出来 |

**日档的唯一目的是让上级及时知道「需要他介入的事」**。没有阻塞的日档，可以不发。

### 周档（常规汇报位）

| 字段 | 必填 | 字数建议 |
|---|---|---|
| 本周结论（一句） | 是 | ≤30 字 |
| 关键进展 3 条 | 是 | 每条 ≤50 字，含数据 |
| 下周计划 | 是 | ≤3 条 |
| 需要协调/决策 | 是（可写「无」） | ≤3 条 |
| 风险预警 | 否 | 只写有真实风险的 |

### 月档（评价与资源位）

| 字段 | 必填 | 说明 |
|---|---|---|
| 关键指标达成 | 是 | 3-5 项，每项给目标值/实际值/达成率 |
| 风险与预警 | 是（可写「无」） | 每条给影响面与时间点 |
| 资源需求 | 是（可写「无」） | 明确到人和时间 |
| 上月复盘 | 是 | 上月承诺的动作，做了没有 |

### 季档（方向与趋势位）

| 字段 | 必填 | 说明 |
|---|---|---|
| 季度目标达成率 | 是 | 加权口径，说明权重 |
| 趋势判断 | 是 | 与上季比，向上/向下/持平 |
| 方向调整建议 | 是 | 至少 1 条，含理由 |
| 下季资源盘 | 是 | 人/预算/时间 |
| 长期风险 | 是 | 1-3 条 |

## 四、坏消息上报时限判定表

判定维度：**是否可逆** × **是否影响他人动作**。

| 分类 | 具体情形 | 时限 | 判定口径 |
|---|---|---|---|
| P0 立即 | 安全/合规/资金/法律风险、重大舆情 | 发现后立即，不隔夜 | 有留痕窗口要求，以小时计 |
| P0 立即 | 数据泄露、账号与权限异常 | 发现后立即 | 同上 |
| P1 当天（≤4h） | 里程碑延期且下游已依赖 | 4 小时内 | 下游不改计划就全线报废 |
| P1 当天（≤4h） | 客户投诉已扩散 | 4 小时内 | 越晚越像隐瞒 |
| P1 当天（≤4h） | 与其他部门承诺冲突 | 4 小时内 | 越晚越像挑事 |
| P2 次日 | 自身进度偏慢，下游无依赖 | 次日日档 | 有缓冲 |
| P2 次日 | 跨部门资源申请未回复 | 次日 | 会持续累积 |
| P3 周报 | 个人能力缺口，不影响交付 | 周报 + 单独辅导申请 | 日报会显得失控 |
| P3 周报 | 依赖方的低优先级排期 | 周报 | 不制造紧张感 |
| 不进汇报 | 纯情绪、不影响任何人任何事 | 一对一闲聊 | 稀释汇报位 |

**降档规则**：P0/P1 事项在未上报期间，**不得降级为 P2/P3**。已经确认影响面后，只能向上不能向下调。

**防误伤条款**：判定为「已上报」必须有可核查证据（IM 记录、邮件、会议纪要）。**没有留痕的口头上报，按未上报计算。**

## 五、预期对齐四问（每次换周期 / 换项目 / 接新任务各做一次）

| # | 问题 | 直接可抄的话术 | 留痕方式 |
|---|---|---|---|
| 1 | 成功标准 | 「这个任务做到什么程度算完成？我按 A 标准还是 B 标准做？」 | IM 文字确认 / 纪要写一段 |
| 2 | 优先级 | 「如果这两件事撞车，我先保哪个？」 | 纪要 |
| 3 | 节奏 | 「你想多久听到一次进展？什么情况要立刻说？」 | IM |
| 4 | 决策边界 | 「哪些事我可以直接定，哪些要报你？」 | 书面确认 |

**必须留痕**。口头对齐在绩效面谈时等于没对齐。留痕三选一：IM 文字确认、会议纪要明确段落、共用文档让对方回复「确认」。

## 六、越级汇报四条红线与合规路径

| # | 红线 | 判定 |
|---|---|---|
| 1 | 非紧急一律不越级 | 紧急的定义：涉及安全/合规/资金/重大客户，或本级沟通 2 次无响应且等待有实质损失 |
| 2 | 越级前先告知直属上级 | 唯一例外：涉及其自身不当行为 |
| 3 | 只同步信息，不下结论不评价 | 对隔级评价直属上级能力/态度，属职场事故 |
| 4 | 不越级要资源，不越级要承诺 | 要决策走本级，这是组织的权力结构 |

**合规路径**：本级沟通 → 记录沟通事实与时间 → 确有损失风险时以「同步一个进展」名义发隔级并抄送直属上级 → 只讲事实、时间线、已采取动作，不评价人。

## 七、汇报归因的安全写法

| 禁止的结论句 | 替换写法 |
|---|---|
| 「因为 XX 部门不配合」 | 「接口方未在 X 日前确认字段，我已两次催办，需协调升级；已启动 B 方案保核心功能」 |
| 「资源不足导致做不完」 | 「本月计划 5 项完成 3 项，剩余需 1 人 2 周或延至下月，您倾向哪个方案」 |
| 「客户有点不满」 | 「客户 X 对 A 功能投诉（工单号 T123），诉求退款，金额约 X 元，需确认处理方式」 |
| 「这个需求真的过分了」 | 「需求 X 需在 Y 日前交付，与 Z 项目冲突，建议排期至 X 日」 |

**判定口径**：结论句里出现的人或部门，只能出现在「已采取的动作」或「需要对方做什么」里，**不能出现在归因句的主语位置**。

## 八、汇报空转的六个征兆

1. 连续 3 次汇报没有出现任何数字。
2. 汇报里「需要」那一段永远是「暂无」。
3. 汇报发出后从无回复也无后续追问（可能根本没看）。
4. 汇报长度逐次变长，但结论句没有变清楚。
5. 汇报只描述动作（「已沟通」「已推进」），没有结果。
6. 抄送范围越扩越大，但没人回应。

对应整改见 SKILL.md §十。
