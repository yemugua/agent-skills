# 降本优化动作

> 按投入产出排序。先处理会持续放大成本的项，再做清理类动作。

## 一、消灭全表扫描（最高优先）

- 为高频查询字段建立索引。
- 把「拉全量再过滤」改成「带条件查询 + 分页」。
- 避免在循环里逐条查询，改为批量查询一次取回。
- 用 `count` 与聚合替代拉取全量数据统计。

## 二、加缓存

- 热点数据（配置、字典、首页数据）加缓存，避免重复读库。
- 前端避免定时轮询，改为按需拉取或长连接。
- 列表数据分页缓存，减少重复请求。

## 三、缩短函数耗时

- 定位耗时来源：数据库查询、外部 HTTP 请求、大循环。
- 外部请求设置合理超时，避免悬挂拖长函数执行时间。
- 耗时操作异步化或拆分到独立函数。
- 合理设置内存配置：内存过小导致重试与超时，过大则单位时间成本上升。

## 四、批量读写

- 写操作批量合并，避免逐条写入。
- 读操作一次取回所需数据，避免 N+1 查询。
- 只返回需要的字段，不要 `select *`。

## 五、清理与归档

- 清理历史冗余文件与不再使用的存储对象。
- 冷数据归档，降低数据库存储占用。
- 删除测试数据与过期日志。

## 六、文件与流量

- 图片与文件压缩后上传，避免原图直出。
- 大文件走 CDN 分发，减少云存储外网下行。
- 客户端做缓存，避免重复拉取同一资源。
- 列表用缩略图，详情再加载原图。

## 七、定时器治理

- 检查定时触发器的间隔是否必要，避免高频空转。
- 定时任务里避免全量扫描与全量写。
- 无效定时器及时下线。

## 八、治理顺序建议

1. 先配告警（防止继续恶化）
2. 再加索引改查询（降读次数）
3. 然后优化慢函数（降 GBs）
4. 接着处理文件与流量（降下行）
5. 最后清理冗余（降存储）
