# 噪声危害控制（noise-control）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据《工业企业噪声控制设计规范》与 GBZ 2.2 职业接触限值，生成噪声控制清单：噪声源识别与检测、岗位暴露评估（8h等效声级）、工程控制（隔声/吸声/减振）、护听器配备、健康监护与告知。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 噪声控制
- 噪声危害
- 职业性噪声
- 护听器
- 噪声检测

## 三、工作流
1. 识别噪声源并检测
2. 按8h等效声级评估暴露
3. 采取工程控制（隔声/吸声/减振）
4. 配备护听器并培训
5. 开展健康监护与告知

## 四、核心内容（检查清单与判定）
噪声控制优先采用工程措施（隔声、吸声、减振），个体防护（护听器）为补充；超标岗位须检测、评估、监护并告知。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含噪声源识别与检测 | 检测 |
| Q2 | FAIL | 未含岗位暴露评估 | 评估 |
| Q3 | WARN | 未含工程控制措施 | 工程控制 |
| Q4 | FAIL | 未含护听器配备与培训 | 护听器 |
| Q5 | WARN | 未含健康监护与告知 | 监护 |

> 脚本 `noise-control_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python noise-control_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python noise-control_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
