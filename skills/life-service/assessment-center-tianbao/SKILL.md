# 评价中心设计（assessment-center）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据评价中心（AC）方法，生成清单：测评维度与素质模型对应、情景模拟设计（无领导小组/公文筐/角色扮演）、评分标准与观察员培训、结果整合与校准、反馈与发展应用。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 评价中心
- AC测评
- 无领导小组讨论
- 公文筐
- 情景模拟测评

## 三、工作流
1. 对应素质模型确定测评维度
2. 设计情景模拟（无领导/公文筐/角色扮演）
3. 制定评分标准并培训观察员
4. 整合结果并校准
5. 输出反馈并用于发展

## 四、核心内容（检查清单与判定）
评价中心用多情景模拟与多观察员测评，关键在于维度与素质模型对齐、评分标准清晰和观察员培训，结果须校准后反馈应用。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含测评维度与素质模型对应 | 维度 |
| Q2 | FAIL | 未含情景模拟设计 | 模拟 |
| Q3 | WARN | 未含评分标准与观察员培训 | 评分 |
| Q4 | FAIL | 未含结果整合与校准 | 校准 |
| Q5 | WARN | 未含反馈与发展应用 | 反馈 |

> 脚本 `assessment-center_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python assessment-center_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python assessment-center_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
