# 来料检验规范（incoming-inspection）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据ISO 9001:2015 条款8.4与GB/T 2828.1（抽样），生成来料检验（IQC）规范：检验计划、抽样方案、AQL、不合格处置与供应商反馈。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 来料检验
- IQC
- 进料检验
- 抽样检验
- AQL
- 外协检验

## 三、工作流
1. 识别物料特性与关键质量特性
2. 确定抽样方案（GB/T 2828.1，AQL）
3. 编制检验指导书与记录
4. 不合格品标识隔离与评审
5. 数据反馈供应商并跟踪8D

## 四、核心内容（检查清单与判定）
ISO 9001:2015 8.4 要求对外部供方过程/产品进行控制；GB/T 2828.1 为计数抽样检验程序，以AQL表征接收质量限。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未识关键质量特性/检验项 | 8.4 |
| Q2 | FAIL | 抽样方案缺失（AQL/水平） | GB/T 2828.1 |
| Q3 | WARN | 无检验指导书与记录表 | 文件 |
| Q4 | FAIL | 不合格未隔离/评审处置 | 不合格品 |
| Q5 | WARN | 无供应商反馈闭环 | 供方 |

> 脚本 `incoming-inspection_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python incoming-inspection_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python incoming-inspection_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
