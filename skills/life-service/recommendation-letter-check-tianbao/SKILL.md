# 留学推荐信写作与推荐人选择核查（recommendation-letter-check）

推荐信最常见的失败不是文笔，而是**选错了人**：找了一个职称很高但说不出你任何一件具体事的推荐人。招生委员会看的是"这个人真的了解你吗"，不是"这个人头衔够不够大"。

推荐信看三件事：**推荐人打分** → **四段要素是否齐全** → **有没有可核验的具体事例**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按四维度给推荐人打分并给选择建议 | ❌ 代写以推荐人名义提交的内容 |
| 给出四段结构与要素清单 | ❌ 建议伪造推荐人身份或署名 |
| 核查字数、事例条数与推荐强度 | ❌ 保证录取 |
| 提示三封雷同的风险 | ❌ 提供具体院校的推荐信数量与提交规则 |
| 给出素材清单供推荐人参考 | ❌ 建议夸大或虚构经历 |

**诚信红线（这条不能碰）：**
- 推荐信应由**推荐人本人撰写并署名**；申请人可以提供素材，但**不得代写并冒充推荐人提交**
- 不得虚构推荐人身份、职称、与你的关系
- 不得在推荐信中写入推荐人没有真正观察到的事例
- 部分项目要求推荐人通过官方链接直接提交、申请人不得查看内容 —— **以目标院校当年官网要求为准**

**出现以下情况先停下来：**
- 涉及推荐信**数量、提交方式、截止日期** —— 以**目标院校当年官网与官方公告为准**
- 推荐人表示"你自己写吧我签字" —— 这是明确的诚信风险，应换人或由推荐人本人完成
- 三封信内容雷同 —— 招生方能看出来，等于浪费两封

## 二、完整工作流

```
第 1 步  确认目标项目要求的推荐信数量与提交方式（以当年官网为准）
第 2 步  先读 rules/recommender_choice.md，给候选推荐人按四维度打分
第 3 步  读 rules/letter_structure.md，抄下四段结构与要素清单
第 4 步  记录四维打分与信件要素，跑体检脚本
         python scripts/recommendation_letter_check.py --relation 5 --depth 4 --title 4 \
             --willing 5 --words 520 --examples 2 --strength-level top --relationship 1
第 5 步  看脚本给出的推荐人可用性与要素缺口，按 §4 修
第 6 步  给推荐人准备一份素材清单（不是代写稿），包含关系说明、事例与匹配点
第 7 步  三封信分别确认：换掉推荐人姓名后是否各自成立
```

## 三、推荐人四维打分

| 维度 | 看什么 | 高分特征 |
|---|---|---|
| 关联度 | 是否直接指导过你 | 带你做过项目/毕设/直接带过实习 |
| 了解深度 | 能否写出具体事例 | 能说出你做过的某件事的细节 |
| 职称公信力 | 职称与学术/行业身份 | 在相关领域有可查的身份 |
| 表达意愿 | 愿不愿意认真写 | 明确答应并愿意花时间 |

**核心判断**：**了解深度 > 职称**。一个只上过大课的知名教授写的通篇形容词，不如带你做过项目的讲师写的两件具体事。

**可用性判定**：四维总分 ≥16 且了解深度 ≥3 才可用；了解深度 ≤2 一律不建议。

---

## 四、四段结构与要素

| 段落 | 内容 | 必写 |
|---|---|---|
| 1 关系说明 | 怎么认识的、多久、在什么场景下观察过你 | 必写 |
| 2 具体事例 1 | 一件具体的事 + 你的动作 + 结果 | 必写 |
| 3 具体事例 2 | 另一件，最好体现成长或对比 | 建议写 |
| 4 总结推荐 | 明确的推荐强度 + 与项目的匹配 | 必写 |

**硬指标**：常见 400~600 词（以院校要求为准），具体事例 ≥2 条，推荐强度必须明确。

---

## 五、脚本用法

```bash
python scripts/recommendation_letter_check.py --relation 5 --depth 4 --title 4 --willing 5 \
    --words 520 --examples 2 --strength-level top --relationship 1
```

| 参数 | 说明 |
|---|---|
| `--relation` | 关联度 0~5 |
| `--depth` | 了解深度 0~5 |
| `--title` | 职称公信力 0~5 |
| `--willing` | 表达意愿 0~5 |
| `--words` | 推荐信字数 |
| `--examples` | 具体事例条数 |
| `--strength-level` | 推荐强度 `top` / `middle` / `none` |
| `--relationship` | 是否写明关系与时长，1 是 / 0 否 |
| `--limit` | 字数上限（以院校要求为准） |
| `--out` / `--format` | 输出文件路径 / `md`（默认）或 `json` |
| `--selftest` | 跑内置自检 |

脚本做五件事：① 四维打分并判定推荐人是否可用；② 核字数是否落在常见区间与上限内；③ 核具体事例条数；④ 核关系说明与推荐强度是否明确；⑤ 给修改方向。

> 字数区间为常见整理，**具体篇幅以目标院校当年官网要求为准**；打分用于选择依据，不是录取评分。

## 六、人工确认清单（这步不能省）

- [ ] 推荐人是否真的**直接指导过**你（不是只上过课）
- [ ] 推荐人能否说出至少两件具体的事
- [ ] 是否写明了认识多久、在什么场景下观察过你
- [ ] 推荐强度是否明确（不能含糊）
- [ ] 三封信换掉推荐人姓名后是否各自成立
- [ ] 是否由**推荐人本人**撰写并署名
- [ ] 推荐信的数量、提交方式与截止日期是否查过**当年**官网

## 七、最常见的坑

**坑一：只挑职称高的。**
错误做法：找一个只上过大课、叫不出你名字的知名教授；正确做法：优先选能说出你两件具体事的人。招生委员会看的是了解深度。

**坑二：通篇形容词没有事例。**
错误写法："He is an outstanding, hardworking and talented student."；正确写法：讲一件具体的事，说清你的动作与结果。

**坑三：不写关系与时长。**
错误写法：直接进入夸奖，全篇没说怎么认识的；正确写法：第一段写清在什么课程/项目/实习中、观察了多久、以什么身份。

**坑四：三封信一个模板。**
错误写法：三封只换称呼和姓名；正确做法：三封各讲不同的事，分别从学术、研究、实践三个角度。

**坑五：推荐强度含糊。**
错误写法："I believe he will do well."；正确写法：明确给出推荐强度，如"top 5% of students I have taught"。

**坑六：把推荐信写成简历复述。**
错误写法：把你的成绩与经历罗列一遍；正确写法：只写推荐人**亲眼观察到**的部分。

**坑七：申请人代写并以推荐人名义提交。**
错误做法：老师让你自己写、他签字；正确做法：这是诚信风险，应换推荐人或由推荐人本人完成。申请人可以提供素材清单，不能代笔。

**坑八：事例不具体。**
错误写法："He performed well in my course."；正确写法：说清是哪一次作业/项目、你做了什么、结果如何。

**坑九：超字数。**
错误写法：写了 900 词；正确写法：控制在常见 400~600 词，以院校要求为准。

**坑十：只夸不提成长。**
错误写法：全程完美无缺；正确写法：有一处体现成长或前后对比，更可信。

**坑十一：与项目不匹配。**
错误写法：全篇夸你但没有落到目标项目；正确写法：末段说明你为什么适合这个项目。

**坑十二：不确认提交方式。**
错误写法：按去年经验准备；正确做法：先查当年官网，确认数量、提交链接与截止日期。

## 八、边界与免责

- 本技能给出的是**推荐人选择依据与信件结构核查**，不代写以推荐人名义提交的内容
- **推荐信应由推荐人本人撰写并署名**，申请人不得代写、不得虚构推荐人身份与事例
- 推荐信数量、提交方式、截止日期以**目标院校当年官网与官方公告为准**，本技能不提供具体日期与院校规则
- 本技能不保证录取，也不提供任何违背申请诚信的做法
