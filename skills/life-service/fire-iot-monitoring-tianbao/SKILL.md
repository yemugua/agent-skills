# 消防物联网远程监控（fire-iot-monitoring）

> 领域：消防 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据城市消防远程监控系统与消防物联感知数据标准，生成物联网消防方案：感知终端、联网上云、报警处置闭环、平台值守与数据运维。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 消防物联网
- 智慧消防
- 远程监控
- 烟感联网
- 电气监测
- 消防云平台

## 三、工作流
1. 识别感知终端（独立烟感/水压/电气/视频）
2. 联网至远程监控平台或119中心
3. 建立报警接收-派单-确认闭环
4. 制定平台7×24值守制度
5. 数据运维与误报/离线管理

## 四、核心内容（检查清单与判定）
消防物联感知要求终端实时上传火警、故障、联动状态；远程监控中心应建立24h值班与应急处置流程，确保报警快速核实与联动。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未明确感知终端类型（烟感/水压/电气/视频） | 感知终端 |
| Q2 | FAIL | 未联网至远程监控平台/119 | 联网 |
| Q3 | WARN | 未含报警处置闭环（接收-派单-确认） | 报警闭环 |
| Q4 | FAIL | 无平台值守/巡检制度 | 值守 |
| Q5 | WARN | 未含数据运维与误报管理 | 运维 |

> 脚本 `fire-iot-monitoring_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python fire-iot-monitoring_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python fire-iot-monitoring_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
