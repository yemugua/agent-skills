# 直播打光（livestream-lighting-setup）

布光问题九成出在一件事上：**主光的位置站错了。**

角度太小脸像平板、角度太大另一侧全黑、位置太低阴影往上走、背后有窗脸直接变黑——**这些都是位置问题，不是灯不够亮。**

这个技能做三件事：**定主光 → 补辅光 → 分背景**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出三点布光的位置、角度与相对亮度关系 | ❌ 推荐具体灯具的品牌型号与功率参数 |
| 核查照度、光比与色温是否用错 | ❌ 指导暗装、走线、吊顶等需要专业施工的改造 |
| 给出三种场景的布光方案 | ❌ 提供电路改造、强电接线的操作指导 |
| 说明眼镜反光与色温的处理办法 | ❌ 替代专业灯光师在现场的调试 |

**遇到以下情况，按各自渠道处理：**

- 需要**吸顶灯安装、墙面走线、增加插座** → 涉及电气施工，请找具备资质的电工
- 需要**选购具体灯具** → **本技能不推荐品牌型号**，请以器材说明与实际需求为准
- **照度数值**为日常参考区间，不同摄像设备的感光度、镜头与算法差异很大 → **以实际画面为准微调**
- 涉及**他人肖像**的内容 → 发布前应取得本人同意

**安全提示**：使用灯具请注意**用电安全与散热**，**不要超负荷使用插线板**，不要让灯具长时间无人看管。

## 二、完整工作流

### 第一步：先排除两个致命位置

1. **背后不能有强光源**（窗户、亮墙）→ 会让设备整体降曝光，脸直接变黑
2. **不能只有顶光** → 眼窝、鼻下、下巴全是阴影，眼神发黑

### 第二步：定主光（最关键的一步）

| 项目 | 合格口径 |
|---|---|
| **角度** | 镜头侧前方 **30 到 60 度**（小于 15 度是正面直打，判不合格） |
| **高度** | **略高于视线**（低于视线判不合格） |
| **照度** | 不低于 300 勒克斯，建议 600 到 1500 勒克斯 |

### 第三步：补辅光

辅光在另一侧，靠近镜头轴线，**亮度为主光的 0.3 到 0.7**。

**辅光的作用是「提亮暗部」，不是「消灭阴影」。** 太强会把主光造型全抹平。

### 第四步：加轮廓光与背景光

- **轮廓光**：从侧后方打，把人和背景分开——**没有它人会和背景糊在一起**
- **背景光**：背景要有独立打光，但不能比人脸还亮
- **人离墙至少 0.5 米**，否则影子投在墙上

### 第五步：统一色温

**全场只用一种色温，这是底线。** 最常见的事故是房间顶灯 3000K 混直播灯 5600K，一侧黄一侧青，**后期怎么调都调不回来**。

### 第六步：填 JSON 跑自查

把主光角度、高度、照度、辅光比例、色温、是否戴眼镜填进去，脚本一次给出逐项判定与整改顺序。

## 三、核心规则（生成结论前先读规则文件）

**必须先读 `rules/布光方案与检查表.md`，不要凭印象写。** 规则文件里有：

- 三点布光的位置、作用与亮度关系
- 主光角度五档后果对照表、高度四档后果对照表
- 光比两项（辅光÷主光、主光÷环境光）
- 色温统一要求与混用的处理办法
- 眼镜反光的四步处理顺序
- 三种场景方案（坐播、站播、产品展示）
- 判定顺序说明与八条高频坑

**判定顺序不能颠倒**：先看严重项（正后方光源、只有顶光、照度不足、色温不一致、主光低于视线、眼镜反光、正面直打），再看可改进项，最后才看信息是否完整。

**为什么这条重要**：若先判信息完整度，会出现「背后有大窗脸已经全黑，却因为没填辅光比例而被判成待确认」——把问题说轻了，比漏判更糟。

## 四、参数速查

| 项目 | 合格口径 | 严重度 |
|---|---|---|
| 光源方位 | 不得在正后方；背后不得有强窗 | 严重 |
| 顶光 | 不得只有顶光 | 严重 |
| 主光照度 | 不低于 300 勒克斯，建议 600 以上 | 严重 / 可改进 |
| 色温 | 全场统一 | 严重 |
| 主光高度 | 略高于视线（低于视线不合格） | 严重 |
| 主光角度 | 30 到 60 度（小于 15 度直打不合格） | 严重 / 可改进 |
| 眼镜反光 | 戴眼镜时主光角度不小于 30 度 | 严重 |
| 辅光比例 | 主光的 0.3 到 0.7 | 可改进 |
| 轮廓光 / 背景光 | 建议都有 | 可改进 |
| 光比 | 主光 ÷ 环境光 3 到 8 | 可改进 |
| 人物距离 | 离墙至少 0.5 米 | 可改进 |

## 五、脚本用法

```bash
python scripts/lighting_check.py --file lighting.json --out 布光核查.md
python scripts/lighting_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 输入 JSON：`setups` 为布光方案列表，每套填 `key_angle_deg` / `key_height` / `key_lux` 等 |
| `--out` | 结果写入指定文件，默认写 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检（63 条断言，含 BOM 两条路径） |

输入 JSON 示例：

```json
{
  "setups": [
    {
      "name": "坐播桌面",
      "scene": "sit",
      "key_angle_deg": 45,
      "key_height": "above_eye",
      "key_lux": 900,
      "ambient_lux": 150,
      "fill_ratio": 0.5,
      "color_temp_k": 5600,
      "temp_consistent": true,
      "backlight": true,
      "bg_light": true,
      "glasses": false,
      "window_behind": false,
      "top_light_only": false,
      "too_close_to_wall": false
    }
  ]
}
```

`key_height` 取 `above_eye` / `eye_level` / `below`；
`scene` 取 `sit` / `stand` / `product`。
数值字段：`key_angle_deg`（主光与镜头轴线夹角）、`key_lux`（主光照度）、`ambient_lux`（环境照度）、`fill_ratio`（辅光 ÷ 主光）、`color_temp_k`（色温）。
布尔字段：`temp_consistent`、`backlight`、`bg_light`、`glasses`、`window_behind`、`top_light_only`、`too_close_to_wall`。

脚本输出：总体判定、三点布光表、逐套判定表（含不合格原因的 why）、整改顺序、主光高度表、三种场景方案、阈值表、人工确认清单。

## 六、人工确认清单（这步不能省）

- [ ] 看脸：脸是不是均匀亮，有没有一边全黑
- [ ] 看背景：背景有独立打光，人和背景分得开
- [ ] 看色温：关掉房间顶灯，全场只有一种色温
- [ ] 戴眼镜的话镜片上没有白斑
- [ ] 人离墙至少 0.5 米，墙上没有影子
- [ ] 灯具用电安全，没有超负荷使用插线板

## 七、最常见的坑

**坑一：背对窗户直播。**
错误做法：白天背对窗户坐，觉得光线好。正确做法：**背后极亮会让摄像设备整体降曝光，脸直接变黑**。要么拉上窗帘，要么改成侧对或面对窗户。

**坑二：只用头顶那盏灯。**
错误做法：房间吸顶灯开着就开播。正确做法：**顶光会在眼窝、鼻下、下巴留下浓重阴影**，眼神发黑。在侧前方 30 到 60 度补一盏主光。

**坑三：主光正面零角度直打。**
错误做法：环形灯套在镜头上正面直照。正确做法：**脸像一张平板，没有立体感，戴眼镜必反光**。把主光偏到 30 到 60 度。

**坑四：房间顶灯和直播灯混用。**
错误做法：顶灯 3000K 暖光 + 直播灯 5600K 白光一起开。正确做法：**一侧发黄一侧发青，后期怎么调都调不回来**。关掉房间原有顶灯，或给直播灯加同色温的色片。

**坑五：辅光开得太亮。**
错误做法：两盏灯开一样亮，觉得这样最均匀。正确做法：**辅光太强会把主光的造型全抹平**，脸又变成平板。辅光降到主光的 0.3 到 0.7。

**坑六：人和背景糊在一起。**
错误做法：只打了正面光，背景全黑。正确做法：**从侧后方补一盏轮廓光**，在头发肩膀边缘勾一道亮边，人立刻就跳出来了。

**坑七：人贴着墙站。**
错误做法：为了省地方贴着墙播。正确做法：**影子会投在墙上**，背景出现一大片灰影。离墙至少 0.5 米。

**坑八：照度不够靠后期提亮。**
错误做法：画面暗，想着后期调亮。正确做法：**后期提亮会让噪点爆炸**。先加灯，照度提到 600 勒克斯以上。
