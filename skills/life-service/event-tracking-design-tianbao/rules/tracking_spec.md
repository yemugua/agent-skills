# 埋点设计规范

> 设计埋点方案、评审埋点清单、或做上线验收前，先读这份规范。

---

## 一、埋点清单六要素

| # | 要素 | 填写标准 | 反例 |
|---|---|---|---|
| 1 | 事件名 | 规范命名，全局唯一，不含文案 | `buy_now_btn` |
| 2 | 触发时机 | 精确到触发条件与时机点 | 「用户点击时」 |
| 3 | 属性 | 属性名 + 类型 + 取值范围 + 必填性 | 「有若干属性」 |
| 4 | 上报时机 | 立即 / 批量 / 结束时 | 「实时」 |
| 5 | 优先级 | P0 必须 / P1 重要 / P2 可选 | 不标优先级 |
| 6 | 去重规则 | 是否去重 + 去重键 + 去重周期 | 「不去重」 |

### 属性设计三个硬要求

| 要求 | 说明 |
|---|---|
| 提前枚举 | 枚举类属性必须列全取值，禁止上线后追加 |
| 维度预留 | 至少预留渠道、端、版本、用户分群四个维度属性 |
| 敏感不落 | 手机号、证件号、银行卡不进属性，只传脱敏或加密串 |

## 二、曝光与点击时机表

| 场景 | 正确时机 | 错误做法 | 后果 |
|---|---|---|---|
| 列表曝光 | 进入视口 ≥50% 且停留 ≥500ms | 渲染即报 | 快速滑动产生假曝光 |
| 曝光计数 | 按 `item_id + session_id` 去重 | 每次进入视口都报 | 滚动往返导致翻倍 |
| 点击 | 交互发生时立即报 | 延迟到跳转后 | 跳转失败丢失 |
| 页面访问 | 首屏真正渲染完成 | 进入路由即报 | 加载失败也算访问 |
| 结果上报 | 接口成功回调 | 请求发出即报 | 成功率虚高 |

**铁律：接口请求发出不算成功，必须在成功回调中上报。**

### 列表曝光三参数

| 参数 | 建议值 | 目的 |
|---|---|---|
| 视口比例 | ≥ 50% 可见 | 露边不算曝光 |
| 最短停留 | ≥ 500 ms | 防快速滑动误报 |
| 去重键 | `item_id + session_id` | 同会话不重复 |

## 三、去重上报三方案

| 方案 | 做法 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 端内去重 | 端维护已上报集合 | 省流量 | 重启丢失、跨端不去重 | 曝光类 |
| 服务端去重 | 服务端按唯一键去重 | 口径唯一 | 服务端压力 | 关键转化 |
| 不重不漏 | 上报即有效 | 简单 | 必然重复 | 天然幂等动作 |

**分工原则**：同一次行为只在一端上报。端触发 → 端上报；服务端结果 → 服务端上报。**禁止两边都报。**

**转化率一致性铁律**：分子与分母的去重口径必须一致。曝光去重而点击不去重，会算出 300% 的转化率。

## 四、命名规范

```
业务域_对象_动作_位置
trade_order_submit_cart_button
content_video_play_start
user_profile_click_avatar
```

| 规则 | ❌ | ✅ |
|---|---|---|
| 小写+下划线 | `ClickButton` | `click_button` |
| 无中文无空格 | `点击 按钮` | `click_button` |
| 不含文案 | `buy_now_btn` | `trade_order_submit_button` |
| 动宾结构 | `order_button` | `order_click_submit` |
| 带位置 | `click` | `click_submit_button` |

**埋点名不得包含界面文案**，否则改文案即断历史数据。

## 五、埋点丢失与重复的六个原因

| # | 原因 | 表现 | 检查 |
|---|---|---|---|
| 1 | 用户提前退出 | 短会话丢数 | 停留时长分布 |
| 2 | App 被杀/闪退 | 队列未上报 | 崩溃率相关性 |
| 3 | 网络中断 | 弱网缺口 | 弱网会话缺口 |
| 4 | 上报时机太晚 | 结束时才报 | 改立即上报 |
| 5 | 版本灰度不一致 | 老版本无新埋点 | **按版本分组核对** |
| 6 | 去重规则不一致 | 端间规则不同 | 检查各端实现 |

## 六、转化率异常偏高的排查顺序

```
1. 曝光是否漏报        → 曝光量 vs 页面访问量
2. 曝光是否过度去重    → 分子分母去重口径是否一致
3. 点击时机是否晚于曝光 → 是否约束了先后顺序
4. 曝光与点击是否同源  → 端/服务端口径
5. 时间窗是否一致      → 曝光当天 vs 点击不限时间
```

## 七、联调三方对账法

```
端上上报 ─┐
抓包结果 ─┼─→ 差异 ≤1% ?
服务端入库─┘
```

| 环节 | 方法 | 阈值 |
|---|---|---|
| 端 → 网关 | 抓包看请求与字段 | ≤ 0.5% |
| 端 → 服务端 | 入库量 vs 上报量 | ≤ 1% |
| 服务端 → 数仓 | 分区记录数对比 | ≤ 1% |
| 量级合理性 | 上报量 vs 业务预期 | ≤ 20% |

**抓包必查三项**：请求是否真的发出、字段值是否正确、是否有重复请求。

## 八、验收清单

**设计阶段**
- [ ] 曝光/点击/转化口径已与业务方对齐并写入指标字典
- [ ] 端职责已划分，同一行为只在一端上报
- [ ] 六要素填全
- [ ] 列表曝光三参数已定
- [ ] 结果类埋点在成功回调上报
- [ ] 分子分母去重口径一致
- [ ] 枚举取值已列全
- [ ] 属性中无个人敏感信息

**开发联调**
- [ ] 三方对账差异 ≤1%
- [ ] 关键路径全为 P0 且已上线
- [ ] 枚举值与设计一致
- [ ] 去重规则生效
- [ ] 弱网/提前退出/闪退场景已验证
- [ ] 老版本单独标注，不计入异常

**上线后**
- [ ] T+1 复核端上报量 vs 入库量 vs 业务量级
- [ ] 按版本分组核对
- [ ] 灰度期低上报量归因清楚

---

## 九、优先级定义

| 级别 | 含义 | 缺失后果 |
|---|---|---|
| P0 | 必须有，缺失则核心分析无法进行 | 分析链路断裂 |
| P1 | 重要，影响分析深度 | 某维度拆不开 |
| P2 | 可选，后续迭代补充 | 无影响 |

**上线验收必须确认全部 P0 已上线**，不能「基本都上了」。

## 十、埋点需求单模板

```
埋点编号：TE-____
事件名：  trade_order_submit_cart_button
优先级：  P0
端职责：  客户端 / 服务端（二选一）
触发时机：用户在购物车页点击「提交订单」按钮的瞬间
上报时机：立即（点击回调触发）
去重规则：不去重（用户每次点击都应计入点击行为）
属性：
  user_id      string  必填   脱敏用户标识
  channel      string  必填   app/h5/mini/api
  app_version  string  必填   客户端版本
  cart_size    int     必填   购物车商品件数
  fail_reason  string  选填   枚举：stock/price/network/other
负责人：  客户端 ____  数据 ____
验收标准：三方对账差异 ≤1%；弱网场景数据可接受
```
