# 消防控制室值班与火警处置（fire-control-room-duty）

消防控制室是单位的消防中枢，**值班这一班不出事，全靠流程不走样**：交接班核得细、火警判得准、设备动得对、记录记得全。

这个技能做四件事：**定制度** → **判火警** → **动设备** → **留记录**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 讲解值班规程与处置流程 | ❌ 替代持证上岗（消防设施操作员职业资格） |
| 梳理交接班核对清单 | ❌ 替代现场火情侦察与统一指挥 |
| 整理火警判别要点与联动顺序 | ❌ 保证处置结果 |
| 生成记录模板与值班处置卡 | ❌ 出具执法或验收结论 |

**遇到以下情况，第一时间拨打 119 并启动现场疏散，不靠在控制室"先看看"：**
- 多人报告同一部位报警或确认有烟、有火光
- 自动喷水、气体灭火等系统已动作
- 商场、医院、地下空间等人员密集场所任何真火警迹象

**永远不要**为了让记录"好看"而事后补填、改写火警处置时间线。控制室记录是执法检查与事故调查的核心证据。

## 二、完整工作流

```
第 1 步  明确场景：日常值班 / 交接班 / 火警处置 / 检查迎检
第 2 步  读规则文件 rules/duty_rules.md
第 3 步  按场景取用：
    - 火警处置 → 走"六步法"（本章第四节）
    - 交接班   → 跑十二项核对清单
    - 记录体检 → python scripts/fire_duty_check.py --file 记录.csv --as-of 今天
第 4 步  按 templates/火警处置记录表.md 输出或补全记录
第 5 步  人工确认联动顺序与现场实际情况
```

## 三、值班制度红线（先背这几条）

| 制度 | 要求 | 违反后果 |
|---|---|---|
| 专人值守 | 每日 24 小时专人值班，**每班不少于 2 人** | 可处责令改正、罚款；火灾时追责 |
| 持证上岗 | 值班人员应持有消防设施操作员职业资格证书 | 无证值班属重大管理缺陷 |
| 不得脱岗 | 控制室不得无人值守，不得以"远程监控"代替人员值守 | 脱岗按违规责令整改 |
| 设备常开 | 火灾自动报警系统、联动控制器保持正常工作状态，不得擅自断电、停用 | 擅自停用消防设施违法 |

> 值班人数、证书等级等具体要求**以现行规范和当地消防救援机构要求为准**；本表为通行管理口径。

## 四、火警处置六步法（核心流程）

```
确认 → 判别 → 处置 → 联动 → 通报 → 记录
```

**第 1 步 确认（60 秒内）**
- 查看报警控制器：报警部位、报警类型（火警/故障/监管）、报警时间
- 通知就近人员或通过视频监控现场核实，**只核实、不擅动**
- 若同一部位反复报警或烟感+温感+手报多信号同报，按真火警对待

**第 2 步 判别**

| 场景 | 特征 | 定性 |
|---|---|---|
| 单点烟感报警，现场无烟无火 | 装修粉尘、蒸汽、蚊虫、探头老化 | 多为误报，核实现场后复位并记录 |
| 两点以上报警或有人证实见烟 | 多信号同报、现场反馈有异常 | **真火警，立即按火警处置** |
| 手动报警按钮被按下 | 有人主动触发 | 一律先按真火警核实 |
| 系统报"故障"而非"火警" | 回路故障、电源故障 | 通知维保，不按火警处置 |

**第 3 步 处置（确认真火警）**
- 立即拨打 119（说清：单位地址、燃烧部位、有无人员被困、自己的姓名电话）
- 通知单位消防安全责任人/管理人，启动灭火和应急疏散预案
- 按预案通知微型消防站、志愿消防队扑救初起火灾、组织疏散

**第 4 步 联动（听指令或按预案，按现场指令优先）**

| 设备 | 操作要点 |
|---|---|
| 应急广播 | 接通着火层及上下相邻层，先播放疏散指令，语气平稳、指令明确 |
| 防排烟系统 | 开启着火层及邻层的排烟口、风机，关闭空调通风 |
| 消防电梯 | 迫降首层，供消防队员专用 |
| 常规电梯 | 联动迫降首层后停用（有燃气泄漏等特殊场景不强行迫降） |
| 防火卷帘 | 按分区两步下降：疏散通道上先降中位、延时后降底；防火分隔部位一次降底 |
| 非消防电源 | 按预案切断（电梯、消防电源除外） |
| 门禁 | 断电释放疏散门禁 |

> 联动设备的投入顺序**以现场指挥和本单位预案为准**；不同建筑预案差异很大，先熟悉自己单位的预案。

**第 5 步 通报**
- 向消防救援机构移交：建筑平面图、系统图、着火部位、已采取的措施
- 向单位负责人持续通报火势与处置进展

**第 6 步 记录**
- 按 `templates/火警处置记录表.md` 逐项填写，时间精确到分钟
- 记录报警时间、确认时间、119 拨打时间、设备动作时间、复位时间、处置人
- 误报也要记录：误报原因、处理方式、探头位置

## 五、交接班十二项核对清单

- [ ] 控制器运行状态（有无未处理火警/故障/屏蔽/监管信息）
- [ ] 未闭环故障与隐患的处理进展
- [ ] 屏蔽/停用设备的审批与期限
- [ ] 主备电源工作状态与主备电切换记录
- [ ] 消防电话、外线电话畅通
- [ ] 应急广播系统正常
- [ ] 消防水箱水位、稳压设施压力（看指示灯或记录）
- [ ] 灭火器、灭火弹等简易器材在位
- [ ] 钥匙、工具、口罩、手电等物品齐全
- [ ] 上级通知、维保预约、来访事宜
- [ ] 双方交接人签字与交接时间
- [ ] 交接不清不接班，记录不闭环不交班

## 六、脚本用法（记录体检）

```bash
python scripts/fire_duty_check.py --file "D:\记录\控制室值班记录.csv" --as-of 2026-10-13
```

| 参数 | 说明 |
|---|---|
| `--file` | 必填。值班/火警记录表（`.csv`，UTF-8 或 GBK 均可） |
| `--as-of` | 核查基准日，默认今天 |
| `--out` | 输出路径，默认打到屏幕 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本检查六类问题：
1. **断档**：日期序列中的值守空白（缺天、缺班）
2. **签名缺失**：交接无双方签字
3. **时长异常**：单班值守时长超过合理上限（默认 12h）
4. **火警未闭环**：有报警无确认时间/无处置记录
5. **时间倒挂**：处置时间早于报警时间等逻辑错误
6. **故障超期**：故障记录超过 7 天无处理进展

> ⚠️ 脚本只做结构与逻辑检查，**不判定记录内容真伪**；标"正常"不等于实际做到。

## 七、人工确认（这步不能省）

- [ ] 本单位预案中联动设备的投入顺序是否与本地实际一致
- [ ] 值班人员是否全部持证、证件是否在有效期内
- [ ] 屏蔽/停用设备是否有审批手续与恢复期限
- [ ] 火警记录的时间线是否与控制器存储记录一致
- [ ] 视频监控、消防电话是否覆盖报警部位
- [ ] 与维保单位的故障响应时限是否写进合同

## 八、输出结构（固定三段）

1. **能不能用** —— 结论先行：制度齐全 / 有缺口 / 有红线问题
2. **核对清单** —— 逐项标合规/缺失/存疑
3. **整改与迎检建议** —— 先后顺序、责任岗位、留存材料

## 九、最常见的坑

**坑一：把"有主机"当"有系统"。**
控制器能亮灯不等于系统完好。备电老化、回路接地、探头积灰都会让系统"看着在、用时装"。

**坑二：误报复位了之。**
不复位记录、不查原因，同一探头一个月误报十几次，最后真报警时没人当回事。

**坑三：广播内容随口说。**
没有预制疏散指令，临场喊"大家快跑"，引发踩踏比火更危险。预案要有标准话术。

**坑四：电梯迫降一刀切。**
有燃气泄漏、火场高温等场景时盲目迫降等于把电梯井变烟道。听现场指挥。

**坑五：记录事后补。**
补填的时间线对不上控制器存储记录，一查就穿帮，还涉嫌伪造证据。

**坑六：交接班只签个字。**
屏蔽信息、未闭环故障不交接，下一班对着满屏屏蔽信息干瞪眼。
