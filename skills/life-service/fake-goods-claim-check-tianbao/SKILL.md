# 买到假货取证与退一赔三核查（fake-goods-claim-check）

买到假货，真正决定结果的不是「它是不是假的」，而是三件事：**能不能证明在这家买的**、**能不能被有权机构认定为假**、**值多少钱**。

这个技能做三件事：**补证据** → **算金额** → **排路径**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 逐项核验证据链是否完整 | ❌ 认定某件商品是真的还是假的 |
| 按公式算退一赔三金额区间 | ❌ 出具鉴定报告或鉴定结论 |
| 列出各类认定路径的成本与分量 | ❌ 承诺一定能赔到三倍 |
| 给出投诉、诉讼的材料清单 | ❌ 代理投诉、代写签名、代起诉 |
| 识别证据缺口并给补救建议 | ❌ 建议删改、补开、伪造凭证 |

**遇到以下情况，务必转交专业机构或当地市场监管部门：**

- 涉及食品、药品、医疗器械、化妆品、婴幼儿用品等关系人身安全的产品
- 金额较大或拟进入诉讼
- 经营者已失联、注销店铺或涉嫌刑事犯罪
- 需要正式鉴定意见作为证据

**绝对不要为了让材料看起来完整，建议用户补开凭证、虚构聊天记录或修改订单截图。**

## 二、完整工作流

```
第 1 步  收集基础信息：订单、价款、渠道、经营者主体、当前物品状态
第 2 步  先读 rules/evidence_chain.md 与 rules/compensation_rules.md
第 3 步  跑脚本做要件扫描与金额核算
         python scripts/fake_check.py --file case.txt --price 1299 --category general
第 4 步  按「保守／合理／争取」三档输出金额，存疑项单独列
第 5 步  逐项人工复核（脚本只做关键词匹配与算术，不做真伪判断）
第 6 步  输出证据缺口清单 + 路径建议 + 陈述材料
```

## 三、金额核算（先看公式，别先看结论）

规则全文在 `rules/compensation_rules.md`，核心公式：

```
退款额    = 已付价款（含你承担的运费）
增加赔偿  = 价款 × 3
法定兜底  = 不足 500 元按 500 元计
法定合计  = 退款额 + max(价款×3, 500)
```

| 商品类别 | 增加赔偿 | 兜底线 |
|---|---|---|
| 一般商品 | 价款 × 3 | 500 元 |
| 食品（不符合食品安全标准） | 价款 × 10 或 损失 × 3（择高） | 1000 元 |
| 药品、化妆品、医疗器械等特殊品类 | 按特别规定执行 | 依特别规定 |

**三倍基数是「实付价款」，不是吊牌价、不是差价、不是你的损失总额。**
运费、鉴定费等直接损失**单列**，不计入三倍基数。

> 具体赔偿口径、兜底标准与适用条件以**现行规定和当地市场监管部门要求为准**。

## 四、欺诈认定的四步顺序（缺一步就降一档）

1. **经营者身份成立** —— 自然人闲置转让一般不认定经营者
2. **存在虚假或引人误解的表述** —— 宣称正品、官方授权等与事实不符
3. **你因此作出购买决定** —— 是否明知而买是关键争点
4. **经营者明知或应知** —— 凭据是否足以推定其主观状态

| 情形 | 判定倾向 |
|---|---|
| 明示「正品」「官方授权」，实际非正品 | 欺诈倾向强 |
| 标题用「原单」「尾货」等模糊表述 | 争议大，需结合聊天记录 |
| 未作任何真伪表述 | 一般按退货退款处理 |
| 职业索赔／知假买假 | 各地裁判口径不一致，不保证支持 |

## 五、脚本用法

```bash
python scripts/fake_check.py --file 案件材料.txt --price 1299 --category general --platform-pledge 10
```

| 参数 | 说明 |
|---|---|
| `--file` | 案件材料文本（`.txt` / `.md`，可从聊天记录、订单页复制） |
| `--price` | 实付价款（元），必填 |
| `--qty` | 数量，默认 1 |
| `--category` | `general`（默认）／ `food` |
| `--platform-pledge` | 平台或店铺承诺倍数，如 `10` 表示「假一赔十」 |
| `--loss` | 有票据的直接损失合计（运费、鉴定费等） |
| `--out` | 输出路径，默认打到屏幕 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本做四件事：
1. **要件扫描** —— 12 项证据要件逐项查有没有
2. **金额核算** —— 退款额、增加赔偿、兜底取值、三档区间
3. **否定词防误伤** —— 检出「未鉴定」「疑似假货」等表述并强制降级为「待认定」
4. **时间线提取** —— 提取关键日期，检查签收日与首次反馈日的间隔

> ⚠️ 脚本只做关键词匹配与算术，**不代表真伪认定**，也不代表最终获赔金额。

## 六、人工确认（这步不能省）

- [ ] 经营者名称是不是**平台公示的主体全称**，不是店铺昵称
- [ ] 实付价款是否与支付流水中**对方账户名**一致
- [ ] 每一笔主张金额后面有没有**凭证编号**
- [ ] 所有定性结论有没有落实为「以……鉴定为准」
- [ ] 「疑似」有没有被写成「确为」
- [ ] 存疑金额是否单独列入争取档，而不是混进合理档
- [ ] 有没有写到「以现行规定和当地市场监管部门要求为准」

**三类高频材料缺陷，见到就退回：**

| 缺陷 | 表现 | 后果 |
|---|---|---|
| 定性先行 | 「肯定是假货」但没有鉴定也没有官方比对 | 全部主张失据 |
| 金额悬空 | 主张三倍却没有价款凭证 | 基数不被采信 |
| 主体不明 | 只有店铺名，没有平台公示主体 | 投诉无对象 |

## 七、输出结构（固定六段）

1. **能不能主张** —— 结论先行：可直接主张／需补证据／暂不具备条件
2. **证据缺口表** —— 12 项逐项标有／缺／存疑，缺的给补救方式
3. **金额核算表** —— 退款额、增加赔偿、兜底取值、三档区间，逐笔跟凭证编号
4. **认定路径建议** —— 平台／官方售后／第三方鉴定，成本与分量对照
5. **推进顺序** —— 平台→12315／12345→市场监管举报→诉讼，每一步的时限与材料
6. **免责与口径** —— 明确以现行规定和当地要求为准

## 八、最常见的坑

**坑一：先把东西用坏了再维权。**
超过必要限度使用、拆掉标签、丢掉包装，即使商品确实有问题，也会因为无法还原原状导致退货与鉴定困难。先保全，再使用。

**坑二：私下加微信沟通。**
平台外的聊天记录在平台介入时往往不被采纳，且难以证明对方身份。沟通要回到平台内置工具，电话后务必用文字复述要求确认。

**坑三：按吊牌价或均价算三倍。**
三倍的基数是**你这一单的实付价款**。标价 5000、实付 800，就按 800 算。

**坑四：忘了 500 元兜底。**
几十块钱的小件，三倍可能只有一百多，但法定兜底是 500 元。不知道这条就少要了一大笔。

**坑五：写「一定是假货」。**
没有鉴定，只能写「涉嫌与正品不符，以鉴定意见为准」。定性过猛会被对方抓住反打。

**坑六：以为退款了就不能再索赔。**
退款退货和增加赔偿是两回事，可以并存。

**坑七：链条只写「保留好证据」。**
笼统的「注意留存」等于没做。要具体到订单号、聊天日期、截图页码、鉴定机构名称与报告编号。

## 九、边界与免责

- 本技能**不代替**任何官方或专业鉴定机构的真伪认定结论
- 赔偿倍数、兜底金额、适用条件以**现行规定和当地市场监管部门要求为准**，各地口径可能不同
- 知假买假、职业索赔的裁判结果因地区而异，**不构成获赔承诺**
- **严禁**用于制作、补开、修改虚假凭证或证据
- 涉及食品、药品等关系人身安全的产品，应同步向监管部门反映
