# 首件检验（FAI）（first-article-inspection）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001 8.5/8.6 与 AS9102，生成首件检验清单：确认触发场景、检验项目与依据、首件报告/标识与偏离处置。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 首件检验
- FAI
- 首件确认
- 首件鉴定
- 换型检验
- 工程变更验证

## 三、工作流
1. 明确首件确认触发场景（换型/材料/工艺变更）
2. 制定检验项目与依据（图纸/BOM）
3. 生成首件检验报告与标识
4. 偏离处置（合格/返工/停线）
5. 记录归档与量产放行

## 四、核心内容（检查清单与判定）
首件检验用于验证生产过程在变更后能稳定产出合格品；触发场景包括新工装、材料变更、停线恢复等，合格后方可批量生产。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未明确首件确认触发场景（换型/材料/工艺变更） | 触发 |
| Q2 | FAIL | 未含检验项目与依据（图纸/BOM） | 检验 |
| Q3 | WARN | 未含首件检验报告/标识 | 报告 |
| Q4 | FAIL | 未含偏离处置（合格/返工/停线） | 处置 |

> 脚本 `first-article-inspection_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python first-article-inspection_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python first-article-inspection_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
