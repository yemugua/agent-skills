# 隐患排查治理体系（hidden-danger-governance）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据《安全生产事故隐患排查治理暂行规定》与GB/T 33000，生成隐患排查治理体系：排查清单、分级（一般/重大）、治理闭环与建档。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 隐患排查
- 隐患治理
- 双重预防
- 隐患台账
- 闭环
- 安全生产标准化

## 三、工作流
1. 建立隐患排查清单（综合/专项/日常）
2. 分级（一般/重大）判定
3. 五定（定人/定时/定责/定标准/定措施）
4. 治理验收与销号
5. 建档与统计分析

## 四、核心内容（检查清单与判定）
《安全生产事故隐患排查治理暂行规定》要求生产经营单位建立隐患排查治理制度；重大隐患治理方案含目标和任务、方法和措施、经费、时限、预案。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未建排查清单或分级标准 | 暂行规定 |
| Q2 | FAIL | 隐患未按五定治理 | 闭环 |
| Q3 | WARN | 重大隐患无方案/挂牌 | 重大 |
| Q4 | FAIL | 未验收销号与建档 | 闭环 |
| Q5 | WARN | 缺统计分析/趋势 | 改进 |

> 脚本 `hidden-danger-governance_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python hidden-danger-governance_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python hidden-danger-governance_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
