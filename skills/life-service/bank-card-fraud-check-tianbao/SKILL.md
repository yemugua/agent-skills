# 银行卡盗刷核查与止损追回

盗刷维权最大的失误是**拖**。发现扣款先找银行理论、想先查清楚是谁干的，几天过去又被刷了几笔——**银行往往以"你未及时采取措施导致损失扩大"为由减轻责任**。这个技能的第一件事永远是止损。

## 什么时候用

- 手机收到银行扣款短信，但卡一直在自己手里
- 几个月没用的卡突然连续被扣款
- 点了陌生短信链接、或装过不明的"清理加速"类 App 后出现异常
- 银行说"可能是你本人授权的"，让你自己举证
- 银行受理了但一直不给结果，或直接拒赔
- 想知道自己到底能主张哪些钱、能通过什么渠道要回来

## 怎么做

**第 1 步**：复制 `templates/银行卡盗刷信息采集表.md` 填写（交易经过、交易渠道、金额与笔数、挂失与报警时间、银行答复是关键项）。

**第 2 步**：跑脚本

```bash
python scripts/bank_fraud_check.py 采集表.md --base 2026-10-05 --out 核查报告.md
```

**第 3 步**：**先照第八段把八条止损动作做完**（挂失、改密、关免密、报警），再按第九段走维权路径。

## 三条最容易决定输赢的规则

1. **发现到挂失的间隔，决定你能要回多少**。银行一般以「你采取措施后发生的交易」划分责任——**发现当日就挂失和拖一周再挂，结果完全不同**。
2. **银行有没有做交易核验和异常监测，是责任归属的核心**。如果银行能证明你把密码交出去过、在公用设备登录过、开通并使用过免密支付，它可能不担责；但**银行仍负有核验与风控义务**，要求其书面说明是否识别、是否拦截。
3. **书面异议，不是电话里说**。电话沟通不留痕，后续投诉和诉讼都拿不出证据。**必须提交书面异议并索取受理回执**。

| | 内容 |
|---|---|
| 输入 | 采集表 Markdown（账户 / 发现日期 / 交易经过 / 交易渠道 / 金额 / 笔数 / 已追回 / 挂失与日期 / 密码与免密处理 / 报警 / 银行核验情况 / 银行答复 / 已有材料） |

| 退出码 | 0 正常；2 关键信息缺失（给提示串，不崩） |

## 边界与纪律

- 依**通用规则**整理，**不替代律师意见**；银行与支付机构的安全义务、举证责任分配，**以监管规定与司法机关认定为准**
- 报告金额按已填信息汇总，**实际损失以银行流水与最终认定为准**
- 不预测公安机关是否立案、银行是否赔偿，也不预测诉讼结果
- **未填的一律不算通过**，只按已填内容判断
- 卡号、身份证号、账号等敏感信息**本地处理，不要外发**
- **任何自称银行、客服、公安打来的电话都是诈骗**，一律挂断后自己打官方渠道核实
