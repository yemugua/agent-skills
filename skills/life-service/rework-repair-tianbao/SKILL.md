# 返工返修管理（rework-repair）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据不合格输出控制与返工返修要求，生成清单：返工与返修的区分、作业指导与授权、返工后重新检验、返修的批准与顾客告知、记录与返工损失统计。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 返工
- 返修
- 返工管理
- 返修审批
- 返工检验

## 三、工作流
1. 区分返工与返修的适用场景
2. 编制返工作业指导并授权
3. 返工后重新检验确认
4. 返修须批准并告知顾客
5. 记录并统计返工损失

## 四、核心内容（检查清单与判定）
返工使产品符合要求，返修可能改变状态需顾客批准；两者都须有作业指导与授权，返工后必须重新检验并记录损失。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含返工与返修区分 | 区分 |
| Q2 | FAIL | 未含作业指导与授权 | 指导 |
| Q3 | WARN | 未含返工后重新检验 | 复检 |
| Q4 | FAIL | 未含返修批准与顾客告知 | 批准 |
| Q5 | WARN | 未含记录与损失统计 | 统计 |

> 脚本 `rework-repair_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python rework-repair_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python rework-repair_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
