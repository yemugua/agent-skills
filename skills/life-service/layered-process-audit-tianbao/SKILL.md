# 分层过程审核 LPA（layered-process-audit）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据分层过程审核（LPA）方法，生成清单：分层设置（班组/车间/厂级）、审核频次与检查项、问题记录与升级、闭环跟踪与看板、有效性评审与优化。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 分层审核
- LPA
- 分层过程审核
- 班组审核
- 车间审核

## 三、工作流
1. 设置分层（班组/车间/厂级）
2. 确定审核频次与检查项
3. 记录问题并分级升级
4. 闭环跟踪并可视化看板
5. 评审有效性并优化

## 四、核心内容（检查清单与判定）
分层过程审核由不同层级按不同频次对关键过程做高频次检查，强调问题快速升级与闭环，是维持过程稳定的日常机制。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含分层设置（班组/车间/厂级） | 分层 |
| Q2 | FAIL | 未含审核频次与检查项 | 频次 |
| Q3 | WARN | 未含问题记录与升级 | 升级 |
| Q4 | FAIL | 未含闭环跟踪与看板 | 闭环 |
| Q5 | WARN | 未含有效性评审与优化 | 评审 |

> 脚本 `layered-process-audit_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python layered-process-audit_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python layered-process-audit_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
