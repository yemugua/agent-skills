# 不合格品控制（nonconforming-control）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001 不合格输出控制要求，生成不合格品控制清单：识别与隔离、评审与处置方式（返工/返修/让步/报废）、记录与追溯、让步接收批准与顾客告知、纠正与防再发。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 不合格品控制
- 不合格品处置
- 返工返修
- 让步接收
- 不合格品隔离

## 三、工作流
1. 识别并隔离不合格品
2. 评审确定处置方式
3. 记录并保持可追溯
4. 让步接收须批准并告知顾客
5. 纠正措施与防再发

## 四、核心内容（检查清单与判定）
不合格输出必须得到识别、隔离与处置；处置方式包括返工、返修、让步接收、报废等，让步接收须经批准并在影响顾客时告知。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含识别与隔离 | 隔离 |
| Q2 | FAIL | 未含评审与处置方式 | 处置 |
| Q3 | WARN | 未含记录与可追溯 | 记录 |
| Q4 | FAIL | 未含让步接收批准与顾客告知 | 让步 |
| Q5 | WARN | 未含纠正措施与防再发 | 纠正 |

> 脚本 `nonconforming-control_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python nonconforming-control_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python nonconforming-control_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
