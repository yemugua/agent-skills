# 消防档案管理与记录合规（fire-safety-archive）

消防档案平时看着不起眼，**检查来了就是第一现场**：巡查断了几个月、检查记录没人签字、隐患整改没闭环，翻三页就见问题。

这个技能做四件事：**建框架** → **定频次** → **填对记录** → **闭闭环**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 讲解档案框架与记录规范 | ❌ 替代单位的法定记录义务 |
| 生成档案目录表与整改台账 | ❌ 出具执法或验收结论 |
| 整理记录填写要点 | ❌ 保证记录真实 |
| 输出体检报告 | ❌ 替代现场核查 |

**永远不要**在检查前集中补记录、代签字、改日期。**补出来的记录时间线对不上、笔体不一样，一查就穿帮，还涉嫌伪造证据。** 记录的真实性是底线，缺了可以补制度、补执行，不能补记录。

## 二、完整工作流

```
第 1 步  明确场景：搭档案体系 / 补记录缺口 / 演练式迎检 / 整改闭环
第 2 步  读规则文件 rules/archive_rules.md
第 3 步  按场景取用：
    - 搭框架 → 两类档案框架（第三节）
    - 定频次 → 更新频次表（第四节）
    - 填记录 → 记录五要素（第五节）
    - 体检表 → python scripts/archive_check.py --file 档案记录.json
第 4 步  按 templates/消防档案目录表.md 输出或补全
第 5 步  人工确认：记录真实性、签字权限、电子化口径
```

## 三、两类档案框架（消防安全重点单位）

依据公安部令第61号，消防档案包括**消防安全基本情况**和**消防安全管理情况**两部分：

**基本情况（9 项）**：单位基本概况和消防安全重点部位情况；建筑物施工、使用或开业前的消防设计审核/验收/安全检查文件资料；消防管理组织机构和各级消防安全责任人；消防安全制度；消防设施、灭火器材情况；专职消防队/义务消防队人员及装备配备；与消防安全有关的重点工种人员情况；新增消防产品、防火材料的合格证明材料；灭火和应急疏散预案。

**管理情况（9 项）**：消防救援机构填发的各种法律文书；消防设施定期检查记录、自动消防设施全面检查测试报告及维修保养记录；火灾隐患及其整改情况记录；防火检查、巡查记录；燃气、电气设备检测（含防雷、防静电）记录资料；消防安全培训记录；灭火和应急疏散预案的演练记录；火灾情况记录；消防奖惩工作情况记录。

> 文书名称随消防执法改革已有调整（如审核/验收改为备案抽查），**具体名目以现行规定和当地消防救援机构要求为准**；非重点单位可参照简化执行。

## 四、更新频次表（硬性节奏）

| 记录类型 | 最低频次 | 依据口径 |
|---|---|---|
| 防火巡查 | **每日/每班**（重点单位） | 消防法、61号令 |
| 防火检查 | **每月至少一次** | 管理实践通行口径 |
| 建筑消防设施全面检测 | **每年至少一次**（委托有从业条件的机构） | GB 25201 等标准 |
| 电气、燃气检测 | 每年至少一次（有相关设施的） | 管理实践通行口径 |
| 消防安全培训 | 重点单位对每名员工**每年至少一次** | 61号令 |
| 预案演练 | 重点单位**每半年至少一次** | 61号令第四十条 |
| 设施维护保养 | 按合同约定（月度/季度） | 维保合同 |

> 频次是"下限"不是"标准"：人流高峰、重大活动前应加密；每次记录之间**不能出现断档**。

---

## 五、记录填写五要素

一份能过关的检查/巡查记录，必须同时有：

1. **时间**——精确到日（巡查精确到班次时段），不接受"近期"
2. **部位**——具体到楼层、防火分区、设备编号，不接受"全场"
3. **内容**——查了什么、结果如何，不接受"正常"
4. **检查人**——签字或盖章，不接受别人代签
5. **被检查负责人**——当场确认签字，**双方签字才算闭环**

**隐患整改记录三要素**：整改措施、整改责任人、完成期限；已整改的还要有复查人和复查日期。写"尽快整改""加强管理"一律视为未闭环。

## 六、脚本用法（档案记录体检）

```bash
python scripts/archive_check.py --file "D:\消防\档案记录.json"
```

| 参数 | 说明 |
|---|---|
| `--file` | 必填。档案记录 JSON |
| `--today` | 核查基准日，默认今天 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本检查五类问题：**档案覆盖缺口、更新频次断档、签字缺失、整改无责任人/期限、日期逻辑倒挂**。

> ⚠️ 脚本只做结构与逻辑检查，**不判定记录内容真伪**；标"正常"不等于实际做到。

---

## 七、人工确认（这步不能省）

- [ ] 记录是否为当时填写，有无集中补写痕迹
- [ ] 签字人是否为本人、是否具备相应权限
- [ ] 电子档案与纸质档案是否一致，签字是否完整
- [ ] 巡查路线是否覆盖所有重点部位
- [ ] 隐患整改是否真正完成（看证据不看表述）
- [ ] 档案更新是否及时（人员、设施、预案变更后）

---

## 八、输出结构（固定三段）

1. **能不能过关**——结论先行：档案齐全 / 有缺口 / 有红线问题
2. **核对清单**——逐项标合规/缺失/存疑
3. **整改与补资料建议**——先后顺序、责任岗位、留存材料

---

## 九、最常见的坑

**坑一：巡查记录"一刀切"全打钩。** 三十天记录一模一样，检查人员一看就知道是补的。

**坑二：只有检查人签字，没有被检查负责人签字。** 单方签字在追责时无效。

**坑三：隐患整改只写"已整改"，无证据无复查。** 等于没整改。

**坑四：档案建完就不更新。** 换了几茬人、改了疏散路线，档案还是三年前的。

**坑五：电子档没签字。** 拍照存档不等于记录，该签字的一个不能少。

**坑六：法律文书乱放。** 消防救援机构填发的文书是档案核心，单独归档、专人保管。

## 十、边界与免责

- 本技能**不替代**单位的法定记录义务；名目与频次**以现行规定和当地消防救援机构要求为准**
- 不得依据本技能伪造、补写、篡改任何记录
- 规程要点为消防管理实践方法论整理，**不构成正式执法或验收结论**
