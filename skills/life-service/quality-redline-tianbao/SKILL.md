# 质量红线与三不原则（quality-redline）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001 与制造企业质量管理实践，生成质量红线与三不原则清单：质量红线清单、三不原则（不接收/不制造/不流出不合格品）、越红线处置、追溯与考核。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 质量红线
- 三不原则
- 不接受不制造不流出
- 不合格品控制
- 质量底线

## 三、工作流
1. 梳理关键质量特性形成红线清单
2. 贯彻三不原则（不接收/不制造/不流出）
3. 明确越红线处置（停线/隔离/上报）
4. 建立可追溯与责任机制
5. 纳入考核与持续改进

## 四、核心内容（检查清单与判定）
三不原则是不合格品控制的基础：不接收不合格来料、不制造不合格品、不流出不合格品；红线为不可逾越的质量底线，越线须立即处置并追溯。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含质量红线清单（关键特性） | 红线 |
| Q2 | FAIL | 未含三不原则（不接收/不制造/不流出） | 三不 |
| Q3 | WARN | 未含越红线处置（停线/隔离/上报） | 处置 |
| Q4 | FAIL | 未含追溯与责任机制 | 追溯 |
| Q5 | WARN | 未含考核与改进 | 考核 |

> 脚本 `quality-redline_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python quality-redline_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python quality-redline_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
