# 邻里纠纷取证与调解核查（neighbor-dispute-evidence）

邻里纠纷打不好，很少是因为道理不对，**绝大多数是证据没留、走错了门、或者自己先违法了**。

这个技能做五件事：**定类型** → **核要件** → **清证据** → **查取证红线** → **算时效与路径**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 判断属于哪类纠纷、对应哪个主管部门 | ❌ 认定邻居一定有错、一定赔偿 |
| 列出四类纠纷的必备要件并标出缺口 | ❌ 代替鉴定机构认定漏水点、噪声值、日照遮挡程度 |
| 核查八项通用证据的覆盖度 | ❌ 建议窃听、偷拍、堵锁眼、断水断电等报复手段 |
| 提示损害赔偿时效参考 | ❌ 断定诉讼时效一定中断、中止 |
| 输出物业协调 / 行政投诉 / 诉讼三条路径 | ❌ 出具正式法律意见书、代理出庭 |

**遇到以下情况，转交律师或相关专业机构：**
- 争议金额较大或涉及房屋结构安全（如拆改承重墙）
- 涉及行政查处决定是否作出、是否属于历史遗留违建
- 需要申请司法鉴定（漏水原因、噪声检测、日照分析）
- 已经起诉或已收到应诉材料
- 存在人身威胁、肢体冲突，应先报警保证人身安全

**永远不要建议在邻居家门口装摄像头对准、窃听、堵锁眼、泼油漆、震楼器报复。** 这些做法取得的证据可能不被采信，且可能反过来构成侵权甚至治安违法。

## 二、完整工作流

```
第 1 步  问清四件事：什么类型的纠纷、什么时候开始、损失是多少、之前找过谁
第 2 步  先读规则文件 rules/dispute_types.md 与 rules/evidence_rules.md
第 3 步  跑核查脚本
    python scripts/neighbor_dispute_check.py --file 案情.txt \
        --occurrence-date 2025-03-12 --as-of 2026-10-08
第 4 步  逐项人工确认（脚本只做关键词匹配，不做事实认定）
第 5 步  按 templates/证据清单表.md 输出核查表，并明确下一条路径
```

## 三、四类纠纷的要件与主管（对照表在 rules/dispute_types.md）

| 类型 | 三个必备要件 | 主管或处置部门 |
|---|---|---|
| **漏水渗漏** | 漏水点与漏水原因、损失范围与金额、与楼上或相邻方的关系 | 物业协调为主；不成则诉讼，漏水原因通常需鉴定 |
| **噪音扰民** | 噪声发生的具体时段、持续时间与频次、干扰程度的客观佐证 | 社会生活噪声找公安机关；工业、建筑施工噪声找生态环境主管部门 |
| **违建加建** | 建设行为的位置与形态、有无审批手续、主管部门查处进展 | 城市管理综合行政执法部门、自然资源主管部门 |
| **采光通风通行** | 遮挡事实与建成时间先后、实际影响程度、是否符合规划与间距要求 | 自然资源主管部门；属违法建设的同步走违建查处 |

> **一个关键区分**：合法建筑造成的遮挡，要看是否违反规划间距与日照标准；若是违法建设造成的遮挡，走违建查处往往比打民事官司更快。

## 四、八项通用证据（脚本逐项核查覆盖度）

| # | 证据 | 为什么重要 |
|---|---|---|
| 1 | 现场照片/视频（含时间水印） | 固定事实与时间，最容易被对方否定 |
| 2 | 物业或社区在场记录 | 中立的第三方在场证明，证明力高 |
| 3 | 报警或公安机关处置记录 | 佐证干扰已严重到需要国家力量介入 |
| 4 | 专业鉴定意见 | 漏水点、噪声分贝、日照分析的核心证据 |
| 5 | 维修报价与发票 | 确定损失金额 |
| 6 | 权属或房屋关系证明 | 确定原告主体资格 |
| 7 | 沟通记录 | 证明曾协商、对方知情且拖延 |
| 8 | 损失清单与修复前照片 | 修复前状态一旦动了就再也补不回来 |

> **取证顺序很重要**：先拍清楚、留下修复前的样子，再动工维修。很多人一上来先修好房子，结果连损失多少都说不清。

## 五、取证合法性红线（脚本会扫）

以下做法取得的材料可能不被采信，还可能反噬自己：

| 红线 | 具体表现 |
|---|---|
| 窃听 | 装监听器、长期在他人门口偷录 |
| 偷拍私密空间 | 摄像头对准他人卧室、卫生间、对窗长期拍摄 |
| 擅自进入 | 撬锁、破门、翻窗进入邻居家中 |
| 报复手段 | 断水断电、堵锁眼、泼油漆、震楼器 |
| 网络曝光 | 公开邻居个人信息、在群里持续辱骂、人肉 |

> 即使在自己家里装摄像头，若**长期对准他人门窗**，同样可能构成侵害隐私权。

## 六、脚本用法

```bash
python scripts/neighbor_dispute_check.py --file "D:\案情\漏水.txt" \
    --occurrence-date 2025-03-12 --as-of 2026-10-08
```

| 参数 | 说明 |
|---|---|
| `--file` | 必填。案情说明、沟通记录或聊天导出（`.txt` / `.md`） |
| `--occurrence-date` | 损害发生日期，用于算时效参考 |
| `--as-of` | 核查基准日，默认今天 |
| `--out` | 输出路径，默认打到屏幕 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本做五件事：
1. **类型判定**：漏水、噪音、违建、采光通风命中哪类
2. **要件核查**：按类型逐条查三个必备要件
3. **证据覆盖**：八项清单逐项标有/未见，并算覆盖度
4. **取证红线**：命中了几条非法取证表述，直接列出
5. **时效参考**：按损害赔偿请求权的一般期间推算并提示是否超期

> ⚠️ 脚本只做关键词匹配，**不代表事实认定**。标"已覆盖"不等于该要件已充分证明。

## 七、人工确认（这步不能省）

- [ ] 照片有没有**原始文件**（含拍摄时间），只有转发过来的截图不行
- [ ] 物业记录是否加盖公章或由经办人签字
- [ ] 损失金额是否有**正式报价单或发票**，自行估算难以获得支持
- [ ] 漏水原因有没有第三方鉴定，还是仅凭"看着像楼上"
- [ ] 噪声有没有**分贝测量记录**，仅凭主观感受很难量化
- [ ] 违建是否已经**向主管部门反映并留痕**（受理编号、回复期限）
- [ ] 所有沟通都发生在正当渠道，没有任何一条见面方式可能反噬

## 八、输出结构（固定六段）

1. **是哪类纠纷** —— 类型与对应主管部门
2. **要件缺口** —— 三个必备要件逐条标已覆盖/待补
3. **证据清单** —— 八项覆盖度总分
4. **取证红线** —— 命中即警告
5. **时效** —— 参考截止日、是否超期、中止中断提示
6. **下一步路径** —— 物业协调 / 行政投诉 / 诉讼，选一条并说明理由

## 九、最常见的坑

**坑一：一上来先修房子。**
漏水后第一时间找人修是对的，但**修复前必须先拍照、录像、留实物**。修完之后损失范围永远说不清。

**坑二：没有漏水原因鉴定，直接告楼上。**
漏水可能是楼上防水层、也可能是公共立管、也可能是自家管道返水。原因不定，告错对象还要赔诉讼费。

**坑三：让物业出一张便签就当证据。**
没盖章、没经办人签字、没注明时间的便签，对方一句"不知道谁写的"就废了。要的是**加盖公章的在场情况说明**。

**坑四：买震楼器报复。**
赢了道德输了官司。一旦对方报警或反诉，你从受害人变成加害人，原纠纷的主张也会被削弱。

**坑五：噪音只凭"我觉得很吵"。**
必须有客观佐证：分贝测量、多次报警记录、邻居联名材料。主观描述在庭审中最容易被攻破。

**坑六：以为所有主张都有三年期限。**
请求停止侵害、排除妨碍、消除危险的，通常不适用诉讼时效规定；**损害赔偿**请求权才受期间限制。以现行规定和受诉法院认定为准。

**坑七：把违建当普通民事纠纷去打。**
违建的查处权在行政部门，自己起诉要求拆除往往不被支持。应先走查处程序，拿到行政认定再谈民事。

- 本技能**不代替**律师的法律意见、司法鉴定机构的鉴定意见、行政主管机关的认定
