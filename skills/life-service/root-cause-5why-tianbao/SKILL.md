# 5Why 根因分析（root-cause-5why）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据根因分析方法论，生成 5Why 分析清单：问题界定、逐层追问（5 层）、验证根因、制定对策与防再发、横向展开。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 根因分析
- 5Why
- 为什么分析
- 问题溯源
- 真因查找

## 三、工作流
1. 准确界定问题与现象
2. 从结果逐层追问「为什么」（≥3 层，通常 5 层）
3. 锁定最可能根因并验证
4. 制定对策与防再发措施
5. 横向展开避免同类问题

## 四、核心内容（检查清单与判定）
5Why 通过连续追问逼近真因，常与鱼骨图配合；根因须经验证而非臆测，对策应聚焦消除根因并横向展开防再发。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含问题界定 | 问题 |
| Q2 | FAIL | 未含逐层追问（≥3 层） | 追问 |
| Q3 | WARN | 未含根因验证 | 验证 |
| Q4 | FAIL | 未含对策与防再发 | 对策 |
| Q5 | WARN | 未含横向展开 | 展开 |

> 脚本 `root-cause-5why_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python root-cause-5why_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python root-cause-5why_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
