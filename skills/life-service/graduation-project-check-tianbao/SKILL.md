# 毕业设计选题与进度核查（graduation-project-check）

毕设出问题，八成不是写不出来，是**题目定得不对**和**进度没人盯**。

这个技能做四件事：**判题目** → **排节点** → **查进度** → **守底线**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 判断题目边界、规模、可行性是否合适 | ❌ 代写论文、代做实验、代跑数据 |
| 给出节点安排与倒排时间表 | ❌ 代替指导教师作出选题与成绩判断 |
| 核查节点剩余天数、状态与完成率 | ❌ 保证通过查重、答辩或抽检 |
| 给出文献综述、开题报告、答辩的组织方法 | ❌ 提供伪造数据、抄袭、代写的任何方法 |
| 提示格式规范与学术诚信红线 | ❌ 认定"这样写一定没问题" |

**遇到以下情况，务必先与指导教师或院系教务确认：**
- 学校对选题范围、字数、格式、查重率有硬性规定
- 涉及涉密数据、人体/动物实验、需要伦理审查
- 进度严重落后，需要考虑延期或更换题目
- 对 AI 使用、署名、成果归属有疑问

**绝对不要**：伪造数据、抄袭、购买代写、把 AI 整篇产出当作自己的作品。这些一旦认定，后果远重于延期。

## 一、什么时候用这个技能

| 用户这样说 | 就用 |
|---|---|
| "毕业论文选题怎么选 / 我的题目是不是太大" | ✅ |
| "开题报告怎么写 / 文献综述怎么写" | ✅ |
| "毕业设计进度怎么安排" | ✅ |
| "中期检查要交什么" | ✅ |
| "查重什么时候做 / 答辩前多久定稿" | ✅ |
| "毕设来不及了怎么办" | ✅ |
| "帮我把论文写出来" | ❌ 不代写 |
| "帮我把数据做出来" | ❌ 不代做、不伪造 |

## 二、选题六项判断标准

| # | 标准 | 不合格表现 |
|---|---|---|
| 1 | 边界清晰 | 题目含多个并列问题，范围无限外延 |
| 2 | 规模适配 | 本科题做成博士题，或一周能做完的题做了半年 |
| 3 | 可行性 | 需要企业内部数据但拿不到，需要昂贵设备 |
| 4 | 有问题意识 | 只描述现象，没有要回答的具体问题 |
| 5 | 有新材料或新方法 | 别人做过十遍，用同样方法再做一遍 |
| 6 | 与专业匹配 | 跨得太远，答辩时无法回应专业问题 |

**题目收窄三招**：加限定（时间、地域、行业、样本范围）、换对象（"产业"→"某类企业"）、定方法（"研究"→"基于 XX 方法的分析"）。

完整对照表见 `rules/topic_selection.md`。

## 三、常见题目毛病

| 毛病 | 例子 | 怎么改 |
|---|---|---|
| 过大 | XX 行业发展问题研究 | 加地域、行业细分、时间范围 |
| 过空 | 浅析 XX / XX 的若干思考 | 补上具体问题与研究对象 |
| 题目即结论 | XX 方法的优越性研究 | 改成"XX 方法在 XX 场景下的适用性研究" |
| 无法获取数据 | 某企业内部风险控制研究 | 换可公开数据的对象 |
| 多个并列问题 | 现状、问题、成因与对策研究 | 聚焦一个，其余作背景 |

## 四、十类标准节点与产出物

| # | 节点 | 产出物 | 常见卡点 |
|---|---|---|---|
| 1 | 选题与任务书 | 选题审批表、任务书 | 题目范围过大 |
| 2 | 文献调研 | 综述初稿、参考文献清单 | 只罗列不分析 |
| 3 | 开题 | 开题报告、开题答辩 PPT | 研究问题不清 |
| 4 | 研究实施 | 实验/调研记录、原始数据 | 数据拿不到、无过程记录 |
| 5 | 中期检查 | 中期报告、已完成部分 | 进度落后却写"按计划进行" |
| 6 | 初稿 | 全文初稿 | 结构缺失 |
| 7 | 查重 | 查重报告 | 引而不注导致重复率偏高 |
| 8 | 修改定稿 | 修改说明、定稿 | 导师意见未逐条回应 |
| 9 | 答辩 | 答辩稿、PPT、演示 | PPT 照搬全文 |
| 10 | 归档 | 最终版、材料袋、源文件 | 格式不符、源文件丢失 |

## 五、从答辩日倒排（默认口径）

| 节点 | 距答辩 | 说明 |
|---|---|---|
| 开题 | 约 70 天 | 之前要完成选题与文献调研 |
| 中期检查 | 约 56 天 | 完成度应在 50% 以上 |
| 初稿 | 约 42 天 | 全文成稿 |
| 查重 | 约 28 天 | **留出修改时间** |
| 定稿 | 约 14 天 | 导师意见逐条改完 |
| 答辩 | 0 | 答辩稿与 PPT 就绪 |

以本校工作日程为准。查重卡在截止前一天几乎必然出问题。

## 六、完成度自评（不要自欺欺人）

| 阶段 | 真实完成度 |
|---|---|
| 只是定了题目 | 5% ~ 10% |
| 文献综述写完 | 20% ~ 25% |
| 开题通过 | 25% ~ 30% |
| 数据/实验做完 | 45% ~ 55% |
| 初稿成稿 | 60% ~ 70% |
| 查重通过 | 75% ~ 80% |
| 定稿完成 | 85% ~ 90% |
| 答辩通过并归档 | 100% |

**判断完成度的唯一标准是有没有可交付的成稿**，不是"看了多少资料"。

## 七、脚本用法

```bash
python scripts/project_check.py --file 进度.json
python scripts/project_check.py --defense-date 2027-05-20 --milestone "开题=2027-03-11:1" --milestone "中期=2027-03-25"
python scripts/project_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 进度 JSON（`milestones`、`defense_date`、`as_of`） |
| `--defense-date` | 答辩日期，用于生成倒排表 |
| `--milestone` | 节点，可重复。格式 `<名称>=<截止日>[:1]`，末尾 `:1` 表示已完成 |
| `--as-of` | 核查基准日，默认今天 |
| `--out` / `--format` | 输出文件与格式（`md` / `json`） |
| `--selftest` | 跑内置自检（14 条断言） |

脚本做三件事：
1. **状态分级**：已完成 / 正常 / 关注（≤14 天）/ 预警（≤7 天）/ 紧急（≤2 天）/ 已逾期
2. **完成率**：已完成节点数 / 总节点数
3. **倒排表**：从答辩日倒推开题、中期、初稿、查重、定稿的建议日期

> ⚠️ 完成率按**节点个数**算，不代表实际写作进度。倒排天数是通行口径，以本校日程为准。

## 八、人工确认（这步不能省）

- [ ] 题目是否通过指导教师与院系审批
- [ ] 数据/样本是否真的拿到了，有没有过程记录
- [ ] 开题报告里"拟采用"的方法，实际采用时有没有变化并说明
- [ ] 引用是否一一对应参考文献表，有没有引而不注
- [ ] 导师意见是否逐条回应并体现在修改说明里
- [ ] 查重报告是否在合格范围，修改是否留够时间
- [ ] 答辩 PPT 是否独立成稿（不是全文复制）
- [ ] 源文件、原始数据、材料袋是否齐备

## 九、最常见的坑

**坑一：题目定得太大，中期才发现做不完。**
"XX 行业发展研究"这类题目没有边界。发现做不完时，收缩题目比硬写更划算。

**坑二：把"资料收集了"当成"写了一半"。**
完成度看成稿，不看阅读量。看过 30 篇文献不等于写了 30%。

**坑三：查重卡在截止前一天。**
重复率不合格还要再来一轮修改，留 28 天不是保守，是必要。

**坑四：开题写的方法，正文换了却不说。**
答辩时第一个问题就是"你为什么用了另一个方法"。

**坑五：文献综述按人罗列。**
"张三认为…李四认为…"是读书报告。要按主题、方法或争议脉络组织，结尾落到"还缺什么、本文做什么"。

**坑六：进度落后写成"按计划进行"。**
中期报告造假，到答辩时必然暴露，还要搭上诚信问题。

**坑七：导师意见收到后没有反馈。**
记录并逐条回应，下次带修改说明去。

**坑八：AI 整篇产出当作自己的作品。**
各校对 AI 使用有明确规定。AI 可用于检索、润色、思路梳理、代码调试辅助，但研究设计、数据、分析结论与最终表述必须是自己的，并按要求如实说明。

## 十、边界与免责

- 本技能只做**选题判断、进度测算与方法整理**，不代写论文、不代做实验、不代跑数据
- 各校在选题范围、字数、格式、查重率、AI 使用、答辩流程上的规定差异较大，**以本校毕业设计（论文）工作管理办法和指导教师要求为准**
- 涉及涉密数据、人体/动物实验、伦理审查的，须先通过学校规定的审批程序
- 本技能不得用于伪造数据、抄袭、购买代写或规避查重
