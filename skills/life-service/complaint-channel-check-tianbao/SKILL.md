# 消费者投诉渠道与流转核查

投错渠道是投诉无果的头号原因：**受理范围不对，材料再全也不会被实质处理**，还可能被退回让你重写。

**本技能与投诉信写作类技能分工不同**：本技能只解决「**投给谁、流转怎么走**」；投诉信本身怎么措辞、怎么组织要素，属于投诉文书写作范畴，本技能只给出必须聚焦事实这一条硬要求。

## 一、硬边界（能做 / 不能做）

| 能做 | 不能做 |
|---|---|
| 按受理范围区分各主管部门的分工 | 代替主管部门受理或作出处理决定 |
| 给出渠道选择逻辑与升级路径 | 承诺投诉一定被受理或一定得到结果 |
| 指出材料被退回的常见原因 | 承诺处理时限（以现行规定和受理机构口径为准） |
| 说明投诉内容应聚焦事实的要求 | 代替投诉人提交或代签文书 |
| 区分投诉、举报、信访、诉讼的流转关系 | 受理跨部门、跨层级的复杂流转 |

**必须转交专业人士或走司法途径的：** 争议金额较大、法律关系复杂；需要申请行政复议或提起诉讼；涉及需要法定程序处理的权益。

## 二、什么时候用

| 用户说法 | 用不用 | 说明 |
|---|---|---|
| 12315 还是 12345 | 用 | 走受理范围区分 |
| 消费者协会管什么 | 用 | 走部门分工表 |
| 举报食品问题去哪 | 用 | 走渠道选择逻辑 |
| 投诉没人管怎么办 | 用 | 走升级路径 |
| 投诉信被退回怎么办 | 用 | 走退回原因清单 |
| 不知道该找哪个部门 | 用 | 走渠道匹配表 |

## 三、完整工作流

### 步骤 1：先判断问题的**领域**（不是情绪）

问题的领域决定了部门：消费交易、市场主体、价格、广告、网络违法、生态、食品药品安全、税务、劳动权益各归不同。

### 步骤 2：按受理范围匹配渠道

见第四节分工表。**先看受理范围，再看是否在线受理**。

### 步骤 3：区分投诉 / 举报 / 调解 / 诉讼四种去向

它们不是同一个流程的不同入口，而是不同性质的处理方式。

### 步骤 4：把内容写成事实陈述

**投诉内容应聚焦事实，不是情绪宣泄。** 这一条决定材料能否被实质处理，见第六节。

### 步骤 5：提交并跟踪，必要时走升级路径

## 四、核心规则（提交前必读）

**先读 `rules/部门受理范围与流转路径.md`，不要凭印象投渠道。**

**所有受理范围、办理流程与时限，一律以现行规定和各受理机构的实际口径为准**，本技能不写死具体天数。

### 主要渠道的受理范围分工

| 渠道 | 主要受理范围 | 注意 |
|---|---|---|
| **12315（市场监管）** | 消费交易纠纷、市场主体登记、价格违法、广告违法、部分假冒伪劣 | 消费者投诉举报的主渠道 |
| **12345（政务服务便民热线）** | 政务咨询与投诉的**统一受理与转办入口** | 通常是转办而非直接处理 |
| **消费者协会（消协调解）** | 消费纠纷的第三方居中调解 | 调解不是裁判，不强制 |
| **税务部门** | 税务征收、发票、税收违法行为 | 与 12315 不同，不处理消费纠纷 |
| **网信部门** | 网络违法有害信息、个人信息违规处理 | 针对网络领域违法行为 |
| **生态环境部门** | 污染排放、环评、环境违法行为 | 与消费纠纷无关 |
| **药品与医疗器械监管** | 药品、医疗器械的质量与经营违法 | 涉药涉械专用渠道 |
| **卫生健康部门** | 医疗纠纷、公共卫生违法行为 | 医疗纠纷走专用路径 |
| **行业主管部门** | 特定行业的经营规范 | 按行业归属 |
| **邮政业申诉** | 快递服务投诉的申诉渠道 | 快递类争议专用 |

### 渠道选择逻辑

```
1. 是不是消费纠纷？
├─ 是 → 12315（投诉解决个人纠纷 / 举报促使查处）
└─ 否 → 2. 属于哪个领域？
         ├─ 税务 → 税务部门
         ├─ 网络违法 → 网信部门
         ├─ 环境污染 → 生态环境部门
         ├─ 药品器械 → 药监部门
         ├─ 医疗 → 卫生健康部门
         └─ 快递服务 → 邮政业申诉渠道
```

**两条实用判断**：

1. **12345 是转办入口，不是处理机构**。投 12345 的材料会被转给对应部门，转办不等于实质处理；能直接投对部门时应直接投。
2. **能同时投诉与举报时，分开提交**：投诉解决你的纠纷，举报促使查处。

### 投诉 / 举报 / 调解 / 诉讼的区别

| 形式 | 指向 | 你的目的 | 结果是否直接给你赔付 |
|---|---|---|---|
| **投诉** | 经营者 | 解决个人纠纷 | 可能 |
| **举报** | 违法行为 | 促使查处 | 不必然 |
| **调解** | 双方争议 | 第三方居中 | 取决于协议是否履行 |
| **诉讼** | 依法审判 | 获得裁判 | 判决后可申请强制执行 |

## 五、投诉无果的升级路径

**升级的前提是前序环节确实走完且留痕。** 没有前序记录直接升级，效果差。

| 阶段 | 动作 | 留痕 |
|---|---|---|
| 1 | 找经营者本身协商 | 工单号、聊天记录 |
| 2 | 对应渠道提交 | 受理编号、提交回执 |
| 3 | 要求书面答复 | 答复文书或超期未答复的记录 |
| 4 | 向上一级或专门机构反映 | 新受理编号 |
| 5 | 申请调解 | 调解申请与协议 |
| 6 | 走司法途径 | 受理通知 |

**判断是否该升级**：材料被退回要看是**受理范围不对**（改渠道）还是**材料不充分**（补材料），两者处理不同。

## 六、投诉内容要聚焦事实（硬要求）

**投诉材料是处理依据，不是情绪表达渠道。**

| 该写 | 不该写 |
|---|---|
| 「本人于某日在某平台购买某商品，实测与描述不符」 | 「这家店太过分了」 |
| 「诉求：退货退款」 | 「必须给个说法」 |
| 按时间顺序陈述可核查的事实 | 夹杂情绪评价与主观猜测 |

**情绪化与威胁性表述的后果**：处理人员会优先跳过实质诉求；威胁性表述可能使诉求被认定为不合理；夹杂无关内容会拖慢流转。

**把不满转化为可核查的事实陈述，本身就是提高处理效率的技巧。**

## 七、脚本用法

脚本：`scripts/complaint_channel_router.py`

```bash
python scripts/complaint_channel_router.py --file 诉求.json
python scripts/complaint_channel_router.py --selftest
```

| 字段 | 说明 |
|---|---|
| `domain` | 问题领域（消费/税务/网络/环境/药品/医疗/快递等） |
| `intent` | 诉求类型（投诉/举报/调解/诉讼） |
| `rejected_before` | 此前已被退回或拒绝的渠道 |
| `content_tags` | 内容标签，用于识别情绪化与诉求不清 |

输出：推荐渠道、备选渠道、是否需要改判领域、情绪化与诉求不清提示、升级建议。

## 八、人工确认清单（不能省）

- [ ] 是否已按**受理范围**而非情绪判断问题领域？
- [ ] 是否区分了 12345（转办入口）与直接主管部门？
- [ ] 投诉与举报是否已分开考虑（目的不同）？
- [ ] 诉求是否明确可执行，而非笼统的「给个说法」？
- [ ] 内容是否**只写可核查事实**，无情绪化与威胁性表述？
- [ ] 前序渠道是否已留痕（受理编号、回执）？
- [ ] 材料被退回的原因是否已区分（受理范围 vs 材料不足）？
- [ ] 是否已核查相关时限要求，避免拖延？

## 九、最常见的坑

1. **把 12345 当处理机构**。它是转办入口，转办不等于实质处理。
2. **投错部门不重投**。受理范围不对会被退回，应改渠道而非反复在同一处提交。
3. **投诉与举报混在一起提交**。目的不同，分开提交更有效。
4. **内容全是情绪**。处理人员跳过实质诉求，材料失去作用。
5. **诉求笼统**。「给个说法」无法执行，应写明具体诉求。
6. **没有前序留痕就要求升级**。升级需要前序记录支撑。
7. **被退回后不分析原因**。受理范围不对与材料不足是两回事。
8. **先投信访再想正规渠道**。信访与投诉举报的定位不同，混用会延误处理。
9. **一次性写几十页**。关键信息淹没在冗长内容中。
10. **没有跟踪是否受理**。「已提交」不等于「已受理」。

## 十、边界与免责

本技能提供渠道受理范围区分、渠道选择逻辑与升级路径，**不代替主管部门受理与处理，不承诺受理结果与办理时限**。各渠道的受理范围、办理流程与时限**以现行规定和受理机构的实际口径为准**，各地存在差异，请勿以本技能的表述为准。需要行政复议、诉讼或涉及金额较大、关系复杂的，请咨询执业律师。
