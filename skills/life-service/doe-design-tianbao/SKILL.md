# 实验设计 DOE（doe-design）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据试验设计方法论，生成 DOE 应用清单：因子与水平确定、设计类型（全因子/部分因子/响应面）、随机化与重复、方差/回归分析、显著性结论。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 实验设计
- DOE
- 因子设计
- 响应面
- 方差分析

## 三、工作流
1. 确定响应变量与可控因子/水平
2. 选择设计类型（全因子/部分因子/响应面）
3. 随机化与设置重复/区组
4. 实施并采集数据
5. ANOVA/回归分析与显著性验证

## 四、核心内容（检查清单与判定）
DOE 通过有计划的试验高效识别关键因子与交互作用；随机化可减少偏差，重复可估计误差，分析常用方差分析(ANOVA)与回归。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未确定因子与水平 | 因子 |
| Q2 | FAIL | 未明确设计类型（全因子/部分因子/响应面） | 设计 |
| Q3 | WARN | 未含随机化与重复/区组 | 严谨 |
| Q4 | FAIL | 未含数据分析（ANOVA/回归） | 分析 |
| Q5 | WARN | 未含显著性结论与验证 | 结论 |

> 脚本 `doe-design_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python doe-design_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python doe-design_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
