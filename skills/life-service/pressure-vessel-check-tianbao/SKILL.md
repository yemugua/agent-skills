# 压力容器使用登记与定期检验核查（pressure-vessel-check）

压力容器的合规，说到底是两件事：**有没有登记**、**检没检、到没到期**。

这个技能做四件事：**定周期** → **算到期** → **判状态** → **出处置**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按安全状况等级推算检验周期与到期日 | ❌ 代替检验机构出具检验结论或定级 |
| 核查台账要素是否齐全、周期是否更新 | ❌ 认定某台设备"实际安全可用" |
| 给出安全附件校验周期与到期预警 | ❌ 代替缺陷评定、强度校核、修理方案设计 |
| 整理使用登记、变更、停用、报废手续清单 | ❌ 代替施工告知与监督检验 |
| 输出超期设备清单与停用处置建议 | ❌ 保证通过特种设备监督检查 |

**遇到以下情况，务必转交具备核准资质的检验机构或有资质的修理单位：**
- 检验结论为"不符合要求"或安全状况等级 4、5 级
- 发现裂纹、鼓包、严重减薄等本体缺陷
- 需要进行强度校核、缺陷评定、修理或改造
- 压力容器发生事故、超压超温等异常工况后
- 涉及介质毒性、易燃易爆、极低温等特殊工况

**永远不要把"年度检查做了"说成"定期检验做了"。** 两者分别考核，混为一谈会让超期设备继续运行，是典型的重大隐患。

## 二、完整工作流

```
第 1 步  建立一台一档台账（铭牌参数、投用日期、上次检验日期、安全状况等级）
第 2 步  先读 rules/inspection_cycle.md，确认周期按等级取值
第 3 步  再读 rules/registration_and_defects.md，核对登记与变更手续
第 4 步  整理成 JSON 台账，跑核查脚本
    python scripts/vessel_check.py --file 台账.json --as-of 2026-10-08 --out 结果.md
第 5 步  逐台人工确认（脚本按等级推算，报告写明日期的以报告为准）
第 6 步  输出超期清单 + 停用挂牌 + 申报检验
```

## 三、三类检查检验不要混淆

| 名称 | 谁来做 | 周期 | 能替代定期检验吗 |
|---|---|---|---|
| 年度检查 | 使用单位自行组织或委托 | 每年至少一次 | ❌ 不能 |
| 定期检验（全面检验） | 有核准资质的检验机构 | 3~6 年（按等级） | — |
| 耐压试验 | 检验机构 | 按规程与检验机构要求 | ❌ 不能 |

---

## 四、检验周期（按安全状况等级）

| 等级 | 一般周期 | 使用限制 |
|---|---|---|
| 1 级 | 一般 6 年 | 正常使用 |
| 2 级 | 一般 6 年 | 正常使用 |
| 3 级 | 一般 3~6 年（**保守按 3 年**） | 监控使用，缩短周期复查 |
| 4 级 | 由检验机构确定，**累计监控使用不超过 3 年** | 必须限期处理缺陷 |
| 5 级 | 不得继续使用 | 处理缺陷后重新检验定级 |

**优先顺序**：检验报告写明下次检验日期的，**以报告为准**；报告没写才按等级推算。

**首次检验**：新压力容器一般应在投入使用后 **3 年内**进行首次全面检验。

---

## 五、安全附件周期（最容易超期）

| 附件 | 周期 |
|---|---|
| 安全阀 | 每年至少校验一次 |
| 压力表 | 每半年至少检定一次 |
| 爆破片装置 | 按制造单位规定定期更换（通常 2~3 年） |
| 液位计、温度计 | 按工况与制造单位要求 |

**安全附件超期未校验，整台设备会被判定为不具备使用条件**，不能当小事。

---

## 六、到期预警分级

| 剩余天数 | 等级 | 动作 |
|---|---|---|
| > 180 | 正常 | 纳入年度计划 |
| 91 ~ 180 | 关注 | 准备停机、清洗、置换方案 |
| 31 ~ 90 | 预警 | 联系检验机构申报，排停机窗口 |
| 1 ~ 30 | 紧急 | 立即申报并确定检验日期 |
| ≤ 0 | **已超期** | **立即停止使用**，挂牌，申报检验 |

## 七、脚本用法

```bash
python scripts/vessel_check.py --file 台账.json --as-of 2026-10-08 --out 核查结果.md
python scripts/vessel_check.py --file 台账.json --format json
python scripts/vessel_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 必填。台账 JSON 文件 |
| `--as-of` | 核查基准日，默认今天（也可用 JSON 里的 `as_of`） |
| `--out` | 结果写入文件 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置自检（16 条断言） |

台账字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` / `code` | ✅ | 设备名称与位号 |
| `commission` | 建议 | 投用日期，用于推首次检验 |
| `last_full` | 建议 | 上次全面检验日期 |
| `grade` | ✅ | 安全状况等级 1~5 |
| `next_full` | 可选 | 报告载明的下次检验日期，**优先于推算** |
| `last_annual` | 建议 | 上次年度检查日期 |
| `last_hydro` | 可选 | 上次耐压试验日期（默认按 10 年核） |
| `safety_valve` | 建议 | 安全阀上次校验日期 |
| `gauge` | 建议 | 压力表上次检定日期 |

脚本对每台设备算五类到期日：全面检验、年度检查、耐压试验、安全阀校验、压力表检定，并给剩余天数与分级，最后汇总整体状态。

> ⚠️ 脚本按等级推算周期，**只要报告写明了下次检验日期就以报告为准**；缺数据的项目标"缺失数据"，需要先补台账。

---

## 八、人工确认（这步不能省）

- [ ] 台账上的安全状况等级是否与最近一次检验报告一致（等级变了周期要改）
- [ ] 报告是否写明了下次检验日期，是否比推算值更早
- [ ] 报告结论为"基本符合要求"的，是否执行了限制条件（降压、缩短周期、监控使用期限）
- [ ] 安全附件校验报告是否在有效期，铅封是否完好
- [ ] 停用设备是否办理停用手续，重新启用前是否已检验
- [ ] 移装、过户、改造后是否办理登记变更，技术档案是否随设备移交
- [ ] 作业人员（安全管理与操作）证书是否在有效期内

## 九、最常见的坑

**坑一：把年度检查当定期检验。**
台账上写着"今年做了年度检查"就以为合规，实际上定期检验已超期两年。监督检查时这两项分开查。

**坑二：把"基本符合要求"当"合格"。**
"基本符合要求"意味着有限制条件——降压使用、缩短周期、监控使用期限不得超过 X 个月。忽略它等于带病运行。

**坑三：安全附件超期不当事。**
安全阀超过一年未校验、压力表超过半年未检定，整台设备就不能用。这类问题整改快，但发现率高。

**坑四：等级降了，台账周期没改。**
上一次是 2 级（6 年），这次定 3 级（3 年），台账还按 6 年排计划，直接导致超期。

**坑五：停用设备直接启用。**
停用超过一年、且期间跨过检验周期的，重新启用前必须检验并办理启用手续。

**坑六：过户只交设备不交档案。**
技术档案缺失，新使用单位无法办理使用登记，设备变成"黑户"。

**坑七：自己延长周期。**
检验周期由检验机构确定，使用单位不得以"生产忙""设备状况好"为由自行延长。

**坑八：私自补焊。**
本体有缺陷私自焊接修补、不告知、不监督检验，属于严重违规，且埋下事故隐患。

## 十、边界与免责

- 本技能只做**周期测算与台账规则整理**，不代替检验机构出具检验结论，不认定设备实际安全状态
- 检验周期、检验项目、缺陷评定口径**以现行安全技术监察规程和检验机构要求为准**，本技能不引用具体条款号
- 登记材料、办理时限、管辖层级**以当地特种设备使用登记部门公示为准**
- 发现超期、4/5 级缺陷或本体异常时，应立即停止使用并向检验机构申报，不以本技能结论替代现场处置
- 本技能不得用于伪造检验记录、检验报告或掩盖设备缺陷
