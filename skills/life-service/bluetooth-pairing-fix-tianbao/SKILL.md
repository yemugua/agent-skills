# 蓝牙耳机连不上与断连排查（bluetooth-pairing-fix）

蓝牙问题最耗时间的不是修不好，而是**按错的顺序排查**。先重装系统、先换耳机、先买新接收器，往往绕了大圈。

这个技能做三件事：**按概率排序** → **给重置步骤** → **划判断线**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按原因概率给出排查顺序 | ❌ 保证重置一次一定解决 |
| 说明 2.4G 与蓝牙的抢占关系 | ❌ 指导刷非官方固件或改动系统核心设置 |
| 给出配对重置步骤 | ❌ 承诺修不好就必须换耳机 |
| 说明音频编码与延迟的关系 | ❌ 代用户操作设备或修改注册表 |
| 给出该修还是该换的判断线 | ❌ 对具体型号的质量做结论 |

**出现以下情况，转售后或换设备：**

- 换过耳机和接收器都复现同样问题
- 重置配对后依然完全无法识别
- 单侧无声或严重失真，且不是设置问题
- 设备有物理损坏、进液、接口松动
- 耳机电池鼓包或异常发热

## 二、排查顺序（按原因概率，从高到低）

```
第 1 步  耳机电量：两只都充满，耳机与充电仓电量都算
第 2 步  多设备抢占：是否同时连着手机、平板、电脑
第 3 步  2.4G 与蓝牙抢占：同一个接收器不能同时用两种连接
第 4 步  配对状态错乱：删除旧配对记录后重新配对
第 5 步  驱动与协议不匹配：换接口、换设备验证
第 6 步  蓝牙版本与设备兼容性
第 7 步  USB 3.0 干扰与省电设置
第 8 步  音频编码与延迟设置
第 9 步  以上都排除仍复现，判定为硬件问题
```

**为什么不先重装系统**：重装系统代价大、见效慢，而且前面几条的概率加起来远高于它。**按顺序走，不要跳步。**

---

## 三、原因概率排序

| 顺序 | 原因 | 典型表现 | 处理 |
|---|---|---|---|
| 1 | **耳机电量不足** | 一只响、续航很短、突然断 | 两只都充满，充电仓也充满 |
| 2 | **多设备连接抢占** | 手机连上又切到电脑 | 断开其他设备的连接 |
| 3 | **2.4G 与蓝牙抢占** | 插上接收器后蓝牙就连不上 | 一个接收器只能用一个连接方式 |
| 4 | **配对记录错乱** | 搜不到设备、配对失败反复 | 删除旧记录重新配对 |
| 5 | **驱动与协议不匹配** | 换台电脑就好、插别的口就好 | 换接口或换设备验证 |
| 6 | **蓝牙版本兼容性** | 老设备只能低版本功能 | 确认双方支持的版本 |
| 7 | **USB 3.0 干扰** | 靠近移动硬盘就断 | 换接口或加延长避开干扰源 |
| 8 | **省电与省电模式** | 闲置后连不上 | 关闭相关省电选项 |
| 9 | **音频编码设置** | 延迟大、音质差 | 调整编码设置 |

**关于第 3 条的重要口径**：**2.4G 接收器和蓝牙用的是同一频段，一个接收器同一时间只能保持一种连接。** 很多「插上就断」的原因是之前连着蓝牙，插上接收器后两条链路互相干扰。**先断开蓝牙再插接收器。**

---

## 四、配对重置步骤

**通用顺序（先做最轻的）：**

```
第 1 步  关掉手机与耳机上的蓝牙，重新打开
第 2 步  在设备端删除该耳机的配对记录
第 3 步  把耳机放回充电仓，长按多功能键进入配对模式
第 4 步  在设备端重新搜索并配对
第 5 步  只连一台设备，观察是否稳定
```

**重置的通用原则**：**先轻后重。** 关蓝牙 → 删记录 → 重启设备 → 耳机恢复出厂设置。跳步会让问题定位不了。

**耳机恢复出厂设置的入口因型号而异**，通常在充电仓里长按多功能键若干秒，具体以说明书为准。

**重置后仍然要做的**：只连一台设备测试。**同时连多台时断连，往往不是坏了，是抢占。**

---

## 五、2.4G 与蓝牙对比

| 维度 | 2.4G 接收器 | 蓝牙 |
|---|---|---|
| 连接方式 | 专用接收器，占一个 USB 接口 | 手机或电脑自带 |
| 延迟 | **通常更低**，适合游戏 | 通常略高，视编码与版本而定 |
| 稳定性 | 稳定，干扰源少 | 受同频段设备影响 |
| 距离 | 受接收器位置限制 | 相对更远 |
| 抢占 | 与蓝牙互斥 | 与 2.4G 互斥 |
| 成本 | 多数耳机附带接收器 | 需设备自带 |

**选择口径**：**打游戏、在固定电脑前使用 → 优先 2.4G；通勤、手机使用 → 蓝牙更方便。** 两者不是替代关系，是场景分工。

## 六、音频编码与延迟

| 编码方向 | 特点 |
|---|---|
| 追求稳定与低延迟 | 选编码支持低延迟模式的方案 |
| 追求音质 | 选高码率编码，代价是延迟与耗电增加 |
| 默认设置 | 兼容性好，但在意延迟时往往不够 |

**口径**：延迟高低与编码、设备性能、传输距离都有关，**不是只由编码决定**。打游戏仍延迟明显时，优先考虑换 2.4G 方案而不是反复调设置。

---

## 七、能修还是该换（判断线）

| 情况 | 建议 |
|---|---|
| 只在一台设备上复现 | **该设备的问题**，先换设备验证 |
| 换设备后正常，原设备有问题 | 原设备的驱动、接口或系统问题 |
| 所有设备都复现，耳机只用过不久 | 耳机本体可能有问题，走售后 |
| 所有设备都复现，已用较久且多处老化 | **该换耳机了** |
| 频繁进水、接口松动、电池异常发热 | 立即停用，直接换 |
| 延迟始终无法接受 | 换 2.4G 方案或换耳机 |

**判断原则**：**先用一台正常的设备交叉验证，把责任分清。** 在没分清是耳机问题还是设备问题之前就买新耳机，很容易白花钱。

## 八、脚本用法

```bash
python scripts/bluetooth_triage.py --symptoms "连不上,总断连"
python scripts/bluetooth_triage.py --file bt.json --out 排查顺序.md
python scripts/bluetooth_triage.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--symptoms` | 逗号分隔的现象关键词 |
| `--context` | 可选场景：`usb3` / `gaming` / `multidevice` / `olddevice` |
| `--file` | 从 JSON 读（自动兼容带 BOM 的文件） |
| `--out` | 结果落盘路径 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本按现象匹配原因，输出**排查顺序、每条对应的验证动作、该修还是该换的判断**。

> 脚本只做规则匹配，**不代表现场判断**。每一步都要实测确认。

## 九、人工确认清单（这步不能省）

- [ ] 两只耳机和充电仓都充满电
- [ ] 确认没有同时连着手机、平板、电脑
- [ ] 确认插上 2.4G 接收器时蓝牙已经断开
- [ ] 删除过旧配对记录并重新配对
- [ ] 换过接口或换过设备验证，定位到哪一侧
- [ ] 确认过蓝牙版本兼容情况
- [ ] 确认过是否靠近 USB 3.0 设备或无线设备
- [ ] 检查过省电相关设置
- [ ] 按顺序走完排查顺序，没有跳步直接换硬件

## 十、最常见的坑

**坑一：耳机没充满就开始排查。**
两只电量不一时经常表现为单侧无声或续航很短。先充满再排查。

**坑二：插上 2.4G 接收器后忘了断开蓝牙。**
同一个接收器同一时间只能保持一种连接，这是「插上就断」的高频原因。

**坑三：一上来就重装系统。**
代价大、见效慢，而前几条原因的概率加起来远高于它。**按顺序走，不要跳步。**

**坑四：同时连着手机和电脑。**
蓝牙会主动切到信号更好的那台，表现成反复断连。先只连一台测试。

**坑五：没删旧配对记录就反复重连。**
配对记录错乱时，重连多少次都还是错的。先删除记录再配对。

**坑六：靠反复调延迟设置解决延迟问题。**
延迟与编码、设备、距离都有关。仍明显时换 2.4G 方案更有效。

**坑七：没分清是耳机问题还是设备问题就买新耳机。**
先用一台正常设备交叉验证，能省掉大部分白花的钱。

**坑八：贴着 USB 3.0 移动硬盘测试。**
USB 3.0 对同频段有干扰，换接口或加延长线往往立竿见影。

**坑九：进液或电池异常发热还继续用。**
这属于硬件安全问题，继续用有风险，直接停用送修或更换。

**坑十：换了耳机但换了另一台也有问题的设备。**
责任方还没定位，换了也白换。先交叉验证。

## 十一、边界与免责

- 本技能**只做排查指引**，不代用户在设备上执行任何操作
- 耳机恢复出厂设置的入口因型号而异，**以产品说明书为准**
- 不承诺重置一次一定能解决，也不承诺修不好就必须换耳机
- 涉及刷非官方固件、修改系统核心设置的，本技能不提供指导
- 进液、电池异常发热、接口松动等硬件安全问题的处置应由售后或专业人员处理
