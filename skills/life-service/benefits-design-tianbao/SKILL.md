# 福利体系设计（benefits-design）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据薪酬福利实践，生成清单：法定福利合规（社保公积金休假）、补充福利项目（商业保险/体检/餐补）、弹性福利与员工选择、福利沟通与感知提升、成本测算与年度迭代。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 福利体系
- 员工福利
- 福利设计
- 弹性福利
- 补充福利

## 三、工作流
1. 确保法定福利合规（社保公积金休假）
2. 设计补充福利项目
3. 提供弹性福利与选择权
4. 加强福利沟通提升感知
5. 测算成本并年度迭代

## 四、核心内容（检查清单与判定）
福利体系以法定福利为底线，补充福利与弹性选择提升感知；关键在沟通让员工感知到价值，并做成本测算与迭代。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含法定福利合规 | 法定 |
| Q2 | FAIL | 未含补充福利项目设计 | 补充 |
| Q3 | WARN | 未含弹性福利与员工选择 | 弹性 |
| Q4 | FAIL | 未含福利沟通与感知提升 | 沟通 |
| Q5 | WARN | 未含成本测算与年度迭代 | 成本 |

> 脚本 `benefits-design_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python benefits-design_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python benefits-design_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
