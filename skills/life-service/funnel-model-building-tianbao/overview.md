# 漏斗模型搭建与转化率核查 · 能力概览

## 你会得到什么

**相邻转化率和总体转化率终于分清了。** 一句话记法：**相邻找病因，总体看疗效**。定位问题必须看相邻转化率（这一步本身做得好不好），对外汇报才用总体转化率（整条链路成不成）。报告里每次写「转化率」都必须带限定词——「下单相邻转化率 10%」而不是「转化率 10%」。

**一条按绝对人数定位问题节点的正确路径。** 大多数人按「流失率最大的一步」去优化，这是错的。第一步流失 92% 通常意味着流量不精准，而不是第一步设计有问题。正确做法是按**流失贡献度**（该步流失人数占总流失的比例）排序：≥30% 优先处理，10%–30% 次优先。脚本会同时给出流失贡献度和「总体提升潜力」（该步流失全部挽回时总体转化率能提升几个百分点）。

**四类口径陷阱的检查清单。** 跨端重复计数、跨天归因、时窗不等长、重复行为分母膨胀——这四类占了漏斗数据对不上的绝大多数原因。尤其**时窗不等长**是最致命的：注册到下单可能跨 30 天，但统计时首步取当日、末步也取当日，同一个人因为跨天被算漏，末步转化率直接低估一半。

**人数不递减的排查顺序。** 多数人第一反应是「数据错了」。其实采用「任意顺序」或跨天归因口径时，人数非递减完全正常。正确排查顺序是：归因方式 → 是否跨天取数 → 跨端去重 → 埋点丢失 → 回退业务逻辑，顺序不能跳。

**小基数警戒线。** 某一步只有 50 人时转化率的标准误约 5.7pp，波动 ±11pp 属正常。团队为这种波动讨论一整天是常见浪费。规则很硬：**任一步人数 < 100，报告中必须标注「不作优化依据」**。

## 典型用法

1. 搭一条新漏斗：先用四要素模板（步骤/时窗/去重单位/归因方式）填全，缺一项就别开始。
2. 转化率跟预期差一倍：查时窗是否等长、是否跨端重复计数。
3. 汇报要改善：先确认结论来自 A/B 实验的对照组，不是漏斗前后对比。
4. 团队规范：把「相邻找病因，总体看疗效」和贡献度阈值表贴进 wiki，统一评审口径。

## 边界

- 漏斗是**描述性**工具，只能说明在哪一步掉，不能解释为什么掉，更不能证明因果
- 各步耗时差异极大（注册到复购跨 60 天）时单一时窗会严重失真，应改用 cohort 分析
- 多触点路径用严格顺序口径会低估，需另建「行为次数分布」视图辅助
- 跨端用户标识合并须遵守本单位数据合规要求，以现行规定和主管部门要求为准
- 步骤的最终定义须与业务方确认，本技能给出结构与判定口径
