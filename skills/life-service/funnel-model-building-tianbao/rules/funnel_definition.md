# 漏斗口径定义与计算规则库

> 生成漏斗方案、解读转化率、或检查漏斗数据可信度前，先读这份规则。

---

## 一、漏斗四要素模板（照抄填写）

```
漏斗名称：  例如「电商 App 下单主链路」
受众：      例如「新注册用户」
去重单位：  用户（统一用户 ID；未登录按设备 ID，且单列口径）
时窗：      各步共用「首次曝光日起 7 天内」
归因方式：  严格顺序（曝光 → 点击 → 加购 → 支付）
步骤定义：  exposure  = 商品详情页曝光且停留 ≥ 1 秒
            click     = 详情页点击加购按钮
            add_cart  = 加购接口返回成功
            order     = 支付回调成功且订单未关闭
剔除规则：  内部测试账号、爬虫 UA、异常设备指纹（漏斗内统一剔除）
```

**四要素任一缺失 → 这条漏斗的数据不可跨期、不可跨漏斗比较。**

---

## 二、转化率三种定义

设第 i 步去重人数为 `n_i`（i = 1..N）：

```
相邻转化率(i) = n_i / n_{i-1}          i = 2..N    衡量第 i 步本身
累计转化率(i) = n_i / n_1               i = 1..N    衡量走到第 i 步还剩多少
总体转化率    = n_N / n_1                         衡量整条链路
```

恒等关系（做交叉校验用）：

```
累计转化率(N) = 总体转化率
相邻转化率的连乘 = ∏(n_i / n_{i-1}) = n_N / n_1 = 总体转化率
```

> **连乘校验**：把相邻转化率连乘，结果应精确等于总体转化率。脚本会做这个校验；对不上说明中间有步骤的人数据取自不同口径。

---

## 三、三类转化率的适用场景

| 指标 | 唯一正确用途 | 禁止用途 |
|---|---|---|
| 相邻转化率 | 定位问题节点、优化某一步 | 对外汇报整体成效 |
| 总体转化率 | 对外汇报、跨期跨漏斗比较 | 定位问题在哪一步 |
| 累计转化率 | 画漏斗图宽度、cohort 比较 | 与相邻转化率混称「转化率」 |

**报告书写规范**：每次出现「转化率」三个字，必须紧跟限定词——
「**下单相邻转化率** 10%」而不是「转化率 10%」。

## 四、流失贡献度与优先级判定

```
第 i 步流失人数        L_i = n_{i-1} − n_i
总流失人数            L   = n_1 − n_N
流失贡献度占比(i)     C_i = L_i / L
总体提升潜力(i)       P_i = L_i / n_1        （该步流失全部挽回时总体转化率可提升的百分点）
```

### 优先级判定阈值

| 判据 | 优先处理 | 次优先 | 暂不处理 |
|---|---|---|---|
| 流失贡献度 C_i | **≥ 30%** | 10%–30% | < 10% |
| 总体提升潜力 P_i | ≥ 2pp | 0.5–2pp | < 0.5pp |

**排序按 C_i 降序，不按相邻转化率升序。** 理由：某一步转化率极低但绝对人数极少，优化它对总体几乎无影响。

### 组合判定表

| C_i | P_i | 判定 | 动作 |
|---|---|---|---|
| 高（≥30%） | 高（≥2pp） | **重点投入** | 立项优化 |
| 高 | 低 | 检查是否上游虚假 | 先查上游流量质量，再决定是否优化 |
| 低 | 高 | 检查时窗 | 大概率是时窗设置问题而非漏斗设计问题 |
| 低 | 低 | 暂缓 | 不投入 |

## 五、小基数警戒线

| 该步人数 | 相邻转化率的 1 个标准误量级 | 建议 |
|---|---|---|
| < 30 | 超过 10pp | 不可作为优化依据，合并步骤 |
| 30–100 | 3–10pp | 需扩时间窗或多期累计后再判|
| > 100 | < 3pp | 可作参考 |
| > 1000 | < 1pp | 可作结论 |

二项比例标准误近似：`SE ≈ √(p(1-p)/n)`。n=50、p=0.2 时 SE ≈ 5.7pp，即 ±11pp 的波动完全正常。

**规则：任一步人数 < 100，报告中必须标注「基数小，波动大，不作为优化依据」。**

## 六、四类口径陷阱检查表

| # | 陷阱 | 检测方法 | 处置 |
|---|---|---|---|
| 1 | 跨端/跨设备重复计数 | 首步人数是否接近日活 × 某系数；App+小程序合计是否 > 日活 | 统一用户 ID 归并；未登录单列口径 |
| 2 | 跨天归因 | 首步与末步是否用同一时间窗；分子是否归因到起点日 | 统一时窗；分子按起点日归集 |
| 3 | 时窗不等长 | 各步骤统计窗口天数是否一致 | 统一或按耗时重设并显式标注 |
| 4 | 重复行为分母膨胀 | 分母是事件数还是去重人数 | 统一用去重单位；重复行为另看人均次数 |

**另两条：**
- **分子分母时间归属必须一致**：都按发生日，或都归因到起点日，混用必然对不上。
- **测试流量与爬虫**：未剔除时首步「访问」被内部流量抬高。剔除规则必须漏斗内统一。

## 七、人数非递减的排查顺序

按顺序查，**不要跳步**：

```
1. 归因方式是不是「任意顺序」？
   → 是：人数非递减属正常，必须改用非严格递减漏斗图
2. 各步是否跨天取数？
   → 是：用户可能周一做A、周二做B，两步各自取数时都会漏他
3. 去重是否跨端归并？
   → 否：首步虚高、末步也可能虚高，方向不定
4. 埋点是否有丢失或重复上报？
   → 检查上报量与端上日志对账
5. 以上都正常仍非递减？
   → 检查是否有「回退」业务逻辑（如取消订单后重新支付），此时需重定义步骤
```

**传统漏斗图（宽度按人数绘制）在人数非递减时视觉失真，必须改用横向条形图或注明。**

## 八、归因窗口取值经验

| 链路类型 | 建议归因窗口 | 说明 |
|---|---|---|
| 站内短链路（浏览→加购→下单） | 7 天 | 超过 7 天多为非本次意图 |
| 搜索→成交 | 1 天（当日）/ 7 天（辅助） | 当日成交占比高，长窗口引入噪声 |
| 内容浏览→转化 | 30 天 | 内容消费周期长 |
| 注册→首次下单 | 7–14 天 | 需与新用户生命周期对齐 |
| 首购→复购 | 30–90 天 | 属留存/cohort 范畴，不宜放在同一条漏斗 |

**跨期对比漏斗时，归因窗口必须一致**，否则转化率变化可能完全来自窗口改动。

---

## 九、漏斗与实验配合的操作顺序

```
1. 漏斗（相邻转化率）      → 定位问题节点
2. 维度下钻               → 缩小假设范围（渠道/端/机型/新老/地区）
3. A/B 实验（保留对照组） → 验证改动是否真的有效
4. 回到漏斗               → 确认整体转化率改善
```

**禁止：**用漏斗改版前后对比替代第 3 步。同期流量结构、季节、活动都会影响结果，漏斗前后对比无法排除这些因素。
