# 绩效管理体系设计（performance-system）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据绩效管理方法论，生成绩效体系清单：战略解码与目标分解、指标库(KPI/OKR)、考核周期与权重、绩效面谈与反馈、结果应用（薪酬/发展/改进）。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 绩效管理
- 绩效考核体系
- 绩效体系设计
- KPI库
- 绩效闭环

## 三、工作流
1. 战略解码并逐层分解目标
2. 建立指标库（KPI/OKR）与权重
3. 明确考核周期与流程
4. 组织绩效面谈与持续反馈
5. 结果应用于薪酬/发展/改进

## 四、核心内容（检查清单与判定）
绩效管理体系应承接战略、层层分解，并通过面谈反馈与结果应用形成闭环；指标须可衡量、可达成，避免考核流于形式。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含战略解码与目标分解 | 解码 |
| Q2 | FAIL | 未含指标库(KPI/OKR)与权重 | 指标 |
| Q3 | WARN | 未含考核周期与流程 | 周期 |
| Q4 | FAIL | 未含绩效面谈与反馈 | 面谈 |
| Q5 | WARN | 未含结果应用 | 应用 |

> 脚本 `performance-system_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python performance-system_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python performance-system_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
