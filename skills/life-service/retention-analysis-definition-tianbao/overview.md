# 留存分析口径定义与核查 · 能力概览

## 你会得到什么

**一句话就能解释「留存率为什么对不上」。** 留存是唯一一个「不同人算出不同数」的指标：运营报的 40% 可能是「7 日内留存（区间）」，数据报的 22% 是「第 7 日留存（当日）」，两个都对，但混用能吵到天昏地暗。这个技能把四种定义（当日/区间/加权/滚动）并列写清，并要求每次引用都带限定词。

**回访窗口取值表与队列成熟度规则。** 「7 日留存」到底含不含第 7 天？含不含第 6 天上午？回访窗口不写进指标字典，三个月后没人说得清。另外队列未满期被填成 0 是留存图最常见的**假异常**——昨天注册的队列算「30 日留存」，实际只跑了两天，曲线尾部断崖，看着像大量流失。规则很硬：未满期必须留空或标注「未成熟」。

**注册日 cohort 与活跃日 cohort 必须并行出。** 只报一套就等于蒙住一只眼：评估渠道拉新质量要用注册日，评估运营活动效果要用活跃日（日活）。同一份数据，两种分组能得出方向相反的结论。

**「曲线平坦了」经常被当成好消息，但它不是。** 平坦只说明「不再继续流失」，不说明「留得够多」——D7 稳定在 3% 的产品曲线同样平坦。技能给出曲线形态判读表（断崖/陡降后平坦/持续陡降/台阶/二次上扬/平坦）和 D7 绝对值参照量级，并强调**必须同时对标同类产品或自身历史值**，通用阈值不能用来下业务结论。

**加权留存率与流失率换算，含交叉校验规则。** 报告必须注明按队列规模加权还是按日活加权；校验规则是加权结果应落在各队列留存率的最小值到最大值之间，超出范围就说明权重用错了。

## 典型用法

1. 有人报了个留存数，核不上：先查是当日还是区间，再查队列是否满期。
2. 留存曲线掉了但不知道为什么：先排未成熟队列（假异常），再排跨端未归并，最后才看业务。
3. 做渠道效果评估：注册日 cohort 对比各渠道 D7。
4. 团队规范：把口径八字段、单调性校验规则贴进指标字典。

## 边界

- 留存是**同期指标**，受拉新渠道、季节、活动、版本发布共同影响，单期变化不能直接归因于产品改动
- 早期队列反映旧版本产品，跨期对比前须确认产品是否实质变化
- D7 绝对值参照量级是**通用经验值非行业标准**，品类差异极大，须以同类对标或自身历史为准
- 跨端用户标识合并须遵守本单位数据合规要求，以现行规定和主管部门要求为准
- 留存事件（什么算活跃）的最终定义须与业务方确认
