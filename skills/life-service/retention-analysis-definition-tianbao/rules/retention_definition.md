# 留存口径定义与核查规则库

> 生成留存报告、解读留存曲线、或与他人对数前，先读这份规则。

---

## 一、N 日留存定义（四种，必须显式声明）

设队列 `C(t)` 为第 t 天的队列用户数。

| 定义 | 公式 | 报告写法 |
|---|---|---|
| 当日留存 | `R_dayN(t) / C(t)`，仅算第 N 天当天 | 「D7 留存（当日）」 |
| 区间留存 | 第 0~N 天内至少来过一次的用户 / `C(t)` | 「7 日内留存（区间）」 |
| 加权留存 | `Σ(逐日留存 × 当日队列规模) / Σ(当日队列规模)` | 「加权 D7 留存」 |
| 滚动留存 | 第 t 到 t+N 天内累计来过 | 「7 日滚动留存」 |

**禁止**：不加限定词地写「N 日留存」。

## 二、回访窗口取值

| 业务类型 | 建议首个回访窗口 | 说明 |
|---|---|---|
| 工具/效率类 | D1、D3 | 使用可能隔天发生 |
| 社交/内容类 | D7、D30 | D1 天然低，参考价值有限 |
| 电商/消费类 | D1、D7、D30 | D1 看冲动复购，D30 看习惯 |
| 金融/理财类 | D7、D30 | 低频但客单高 |
| 订阅制 | D7（试用期内）、D30 | 以订阅周期为对齐单位 |
| 企业服务 | D30、D90 | 使用周期以月计 |

**窗口内必须写明**：是否含第 N 天当天、是否含第 0 天（当天）、时区如何取整。

## 三、按注册日 vs 按活跃日对照

| 场景 | 按注册日 | 按活跃日 | 应选 |
|---|---|---|---|
| 评估渠道拉新质量 | ✅ | ❌ | 注册日 |
| 评估运营活动效果 | ❌ | ✅ | 活跃日 |
| 评估新手引导改动 | ✅ | ❌ | 注册日 |
| 看公司整体留存趋势 | ❌ | ✅ | 活跃日 |
| LTV 测算 | ✅ | ❌ | 注册日 |
| 存量用户健康度 | ❌ | ✅ | 活跃日 |

**规则：两套并行出数，缺一套就等于蒙住一只眼。**

## 四、加权留存率

```
加权 D_N 留存 = Σ(d_i × s_i) / Σ(s_i)
    d_i = 第 i 天队列的 D_N 留存率
    s_i = 第 i 天队列的用户规模
加权流失率     = 1 − 加权 D_N 留存
```

### 交叉校验规则

| 校验项 | 规则 | 不通过说明 |
|---|---|---|
| 加权 vs 逐日 | 加权结果应落在各队列留存率的 [最小值, 最大值] 内 | 超出范围说明权重用错 |
| 同口径一致性 | 同一种权重算法下，两次计算的加权值应完全一致 | 权重口径漂移 |
| 权重声明 | 每份报告必须注明按 `s_i`（队列规模）加权 | 未注明视为不合格 |

**禁止**：把「按队列规模加权的留存」与「按日活加权的活跃留存」放在同一张表里对比。

## 五、留存曲线形态判读阈值

| 形态 | 量化特征 | 含义 |
|---|---|---|
| 断崖式 | D1 < 20% | 首次体验或流量精准度问题 |
| 陡降后平坦 | D1–D3 下降 >10pp，之后单日变化 <1pp | 已触底，触底值即真实水平 |
| 持续陡降 | 到 D30 仍在下降，单日降幅 >1pp | 使用习惯未形成 |
| 台阶状 | 相邻两日留存差 >5pp | 存在周期性因素，勿误判为流失 |
| 二次上扬 | D7 后回升 >2pp | 回访型产品的正常形态 |

### D7 绝对值参照量级（通用经验值，非行业标准）

| D7 绝对值 | 判读 |
|---|---|
| ≥ 25% | 多数消费/社交类可接受 |
| 15%–25% | 正常区间，看获客成本能否覆盖 |
| 8%–15% | 偏低，需评估 LTV |
| < 8% | 触底位置过低，价值主张可能不成立 |

> **必须同时对标同类产品或自身历史值。** 品类差异极大，不得用通用阈值下业务结论。

## 六、队列成熟度检查

```
队列成熟条件：当前日期 ≥ 队列日期 + N 天
未成熟时：该单元格必须留空或标注「未成熟」
禁止：填 0、填上一期值、用小样本估计值填充
```

### 常见假异常

| 现象 | 真实原因 | 处置 |
|---|---|---|
| 曲线尾部断崖式下跌 | 队列未满期被填 0 | 留空并标注 |
| 最近几列突然上升 | 用不同窗口定义的列混入 | 核对每列的 N 值与窗口 |
| 某一天留存 >1（>100%） | 去重口径错误（重复计数） | 查去重 |
| D7 > D1 | 窗口定义不一致 | 核对窗口 |

---

## 七、单调性校验

在同一回访窗口定义下：

```
D1 ≥ D2 ≥ D3 ≥ ... ≥ D30
```

**若出现 `D_N+1 > D_N`：**
1. 检查是否混用了「当日」与「区间」两种定义
2. 检查去重是否失效（重复计数导致分子大于分母）
3. 检查窗口是否逐列不一致

---

## 八、口径字段完整性检查（每次出数必填）

| 字段 | 示例 | 缺失后果 |
|---|---|---|
| `起点事件` | 注册成功 / 首次下单 | 队列含义不明 |
| `留存事件` | 打开 App / 登录 / 完成下单 | 「活跃」不可比 |
| `回访窗口` | 第 N 天当天 / 第 0~N 天内 | 与他人对不上数 |
| `分组基准` | 注册日 / 活跃日 | 结论方向可能相反 |
| `去重单位` | 用户（统一 ID）/ 设备 | 人数不可比 |
| `跨端处理` | 已归并 / 未归并（仅设备 ID） | 留存被低估 |
| `加权方式` | 按队列规模 / 按日活 | 平均值不可比 |
| `口径版本` | v2.1，断点 2026-01-01 | 跨期对比失真 |

## 十、六类口径陷阱速查

| 陷阱 | 检测 | 处置 |
|---|---|---|
| 当日 vs 区间混用 | 同一数据两数相差近一倍 | 每次带限定词 |
| 回访窗口未定义 | 指标字典无此字段 | 补进字典 |
| 跨端未归并 | 队列人数接近日活 × 异常系数 | 统一 ID 归并 |
| 活跃事件过宽 | 「打开即活跃」且 D1 异常高 | 改用核心行为 |
| 队列未满期 | 最近几列数值异常 | 留空标注 |
| 加权方式不一致 | 同一数据两个平均值 | 固定算法并注明 |
