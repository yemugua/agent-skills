# 顾客投诉处理（customer-complaint）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001 顾客沟通与不满意处理要求，生成顾客投诉处理清单：受理与登记、根因分析（8D/5Why）、围堵与纠正措施、顾客回复与关闭确认、趋势分析与防再发。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 顾客投诉
- 客户投诉处理
- 投诉处理流程
- 8D投诉
- 投诉闭环

## 三、工作流
1. 受理投诉并登记信息
2. 开展根因分析（8D/5Why）
3. 实施围堵与纠正措施
4. 回复顾客并确认关闭
5. 趋势分析并防再发

## 四、核心内容（检查清单与判定）
顾客投诉须及时受理、分析根因并回复关闭；围堵措施先止住影响，纠正措施消除根因，趋势分析用于系统性防再发。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含受理与登记 | 受理 |
| Q2 | FAIL | 未含根因分析（8D/5Why） | 根因 |
| Q3 | WARN | 未含围堵与纠正措施 | 围堵 |
| Q4 | FAIL | 未含顾客回复与关闭确认 | 回复 |
| Q5 | WARN | 未含趋势分析与防再发 | 趋势 |

> 脚本 `customer-complaint_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python customer-complaint_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python customer-complaint_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
