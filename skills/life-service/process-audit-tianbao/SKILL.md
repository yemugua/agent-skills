# 过程审核 VDA 6.3（process-audit）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 VDA 6.3 与 IATF 16949，生成过程审核清单：审核范围与过程识别（P2~P7）、提问表与评分（0/4/6/8/10）、现场证据收集、审核报告与分级（A/B/C）、整改与再验证。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 过程审核
- VDA6.3
- 过程审核提问表
- 审核评分
- 过程审核分级

## 三、工作流
1. 界定审核范围与过程（P2~P7）
2. 使用提问表并按0/4/6/8/10评分
3. 现场收集客观证据
4. 形成审核报告与A/B/C分级
5. 跟踪整改并再验证

## 四、核心内容（检查清单与判定）
VDA 6.3 按项目管理、开发、量产等过程要素提问评分，强调现场客观证据；结果分级（A/B/C）反映过程成熟度并驱动整改。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含审核范围与过程识别 | 范围 |
| Q2 | FAIL | 未含提问表与评分规则 | 评分 |
| Q3 | WARN | 未含现场客观证据收集 | 证据 |
| Q4 | FAIL | 未含审核报告与分级 | 报告 |
| Q5 | WARN | 未含整改与再验证 | 整改 |

> 脚本 `process-audit_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python process-audit_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python process-audit_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
