# 卓越绩效模式（GB/T 19580）（performance-excellence）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 GB/T 19580《卓越绩效评价准则》与 GB/Z 19579，生成卓越绩效自评清单：领导/战略/顾客/测量/员工/运营/结果七大类、关键绩效与评分系统。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 卓越绩效
- 质量奖
- 市长质量奖
- GB/T 19580
- 绩效自评
- 成熟度评价

## 三、工作流
1. 搭建七大类评价框架（领导/战略/顾客/测量/员工/运营/结果）
2. 建立关键绩效测量（KPM）
3. 采用过程ADLI+结果LeTCI评分
4. 标杆/对比数据收集
5. 改进与创新机制固化

## 四、核心内容（检查清单与判定）
GB/T 19580 以七大类目评价组织成熟度；过程类条目用 ADLI（方法-展开-学习-整合），结果类条目用 LeTCI（水平-趋势-对比-整合）评分。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未覆盖七大类框架（领导/战略/顾客/测量/员工/运营/结果） | 19580 |
| Q2 | WARN | 未含关键绩效测量（KPM） | KPM |
| Q3 | FAIL | 未含评分系统（过程/结果成熟度） | 评分 |
| Q4 | WARN | 未含标杆/对比数据 | 标杆 |
| Q5 | FAIL | 未含改进与创新机制 | 改进 |

> 脚本 `performance-excellence_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python performance-excellence_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python performance-excellence_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
