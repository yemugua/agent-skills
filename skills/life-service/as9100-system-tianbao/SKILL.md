# 航空航天质量管理体系（as9100-system）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 AS9100 系列与航空航天特殊要求，生成清单：产品安全关键特性识别、首件检验 FAI 与控制、不合格品 MRB 处置、防护物流与 Suspect 零件控制、特殊过程 NADCAP 认可。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- AS9100 体系
- 首件检验报告
- 关键特性控制
- 不合格品 MRB
- 特殊过程认可

## 三、工作流
1. 识别产品安全关键特性
2. 执行首件检验与再合格验证
3. 规范不合格品评审处置
4. 控制防护物流与可疑件
5. 完成特殊过程外部认可

## 四、核心内容（检查清单与判定）
航空领域对可追溯与防假冒零件要求极严。关键特性必须标识受控，可疑件一旦隔离不得随意放行，超差件须经评审处置而非自行放行。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含关键特性识别与标识 | 关键特性 |
| Q2 | FAIL | 未含首件检验与再验证 | 首件检验 |
| Q3 | FAIL | 未含不合格品评审处置 | 评审 |
| Q4 | WARN | 未含防护物流与可疑件控制 | 可疑件 |
| Q5 | WARN | 未含特殊过程认可 | 特殊过程 |

> 脚本 `as9100-system_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python as9100-system_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python as9100-system_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
