# 消防控制室远程监控管理（fire-control-room-remote）

> 领域：消防 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据《消防控制室通用技术要求》GB 25506 与建筑消防设施的维护管理 GB 25201，生成消防控制室清单：设施接入、24h持证值班、火警处置流程、故障/离线管理与通讯联络。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 消防控制室
- 消控室
- 远程监控
- 控制室值班
- 火警处置
- 消防设施联网

## 三、工作流
1. 明确接入的消防设施（报警/联动/水系统/防排烟）
2. 落实24h持证值班（中级建构筑物消防员）
3. 建立火警处置流程（确认-上报-联动）
4. 故障/离线监测与报修闭环
5. 应急广播与通讯联络保障

## 四、核心内容（检查清单与判定）
GB 25506 要求消防控制室实行每日24h专人值班并持证；接到火警信号后应立即确认、启动应急程序并报警，消防设施故障应及时维修并记录。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未明确接入的消防设施类型（火灾报警/联动/水系统） | 接入要求 |
| Q2 | FAIL | 未含24h持证值班（中级建构筑物消防员） | 值守 |
| Q3 | WARN | 未含火警处置流程（确认-上报-联动） | 处置 |
| Q4 | FAIL | 未含设施故障/离线管理 | 运维 |
| Q5 | WARN | 未含应急广播/通讯联络 | 通讯 |

> 脚本 `fire-control-room-remote_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python fire-control-room-remote_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python fire-control-room-remote_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
