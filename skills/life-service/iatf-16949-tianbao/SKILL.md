# IATF 16949 汽车质量管理体系（iatf-16949）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 IATF 16949:2016 与 ISO 9001:2015，生成汽车供应链 QMS 清单：过程方法、顾客特殊要求、五大核心工具、体系/过程/产品审核与管理评审。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- IATF 16949
- 汽车质量体系
- 五大工具
- APQP
- PPAP
- 顾客特殊要求

## 三、工作流
1. 采用过程方法/乌龟图识别过程
2. 管理顾客特殊要求（CSR）清单
3. 应用五大核心工具（APQP/PPAP/FMEA/MSA/SPC）
4. 开展体系/过程/产品审核
5. 管理评审与KPI监视

## 四、核心内容（检查清单与判定）
IATF 16949 在 ISO 9001 基础上增加汽车行业要求，强调过程方法、顾客特殊要求与 APQP/PPAP/FMEA/MSA/SPC 五大工具的应用。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未采用过程方法/乌龟图 | 过程方法 |
| Q2 | FAIL | 未含顾客特殊要求（CSR）管理 | CSR |
| Q3 | WARN | 未含核心工具（APQP/PPAP/FMEA/MSA/SPC） | 五大工具 |
| Q4 | FAIL | 未含内审/制造过程审核 | 审核 |
| Q5 | WARN | 未含管理评审与KPI | 评审 |

> 脚本 `iatf-16949_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python iatf-16949_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python iatf-16949_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
