# 投诉信撰写与投诉路径核查（complaint-letter-check）

一封管用的投诉信，解决三件事：**交给谁**、**写全了没有**、**说完之后怎么跟**。

这个技能做四件事：**选渠道** → **查要素** → **清措辞** → **定跟进**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 核查投诉信要素是否齐全、诉求是否可执行 | ❌ 代替主管部门受理或作出处理决定 |
| 按事项推荐受理渠道与管辖层级 | ❌ 保证投诉一定被受理或一定退到钱 |
| 扫描情绪化、威胁性、无证据定性的表述并给出改写 | ❌ 代你提交投诉、代签文书、代收退款 |
| 给出送达留痕与时间管理清单 | ❌ 认定对方"构成欺诈""一定违法" |
| 提示投诉与诉讼、仲裁、信访的衔接 | ❌ 出具法律意见书或代理案件 |

**遇到以下情况，务必转交执业律师或走司法程序：**
- 争议金额较大（通常数万元以上）或法律关系复杂
- 对方已失联、注销、跑路，或涉嫌诈骗
- 已经或即将超过诉讼时效（普通 3 年）
- 涉及人身伤害、医疗纠纷、劳动争议的实体权利主张
- 需要申请财产保全、强制执行的

**永远不要把"已提交投诉"当成"权利已保全"。** 投诉处理流程一般不产生确定的诉讼时效中断效力，大额或临近届满的，应通过起诉、仲裁或取得对方书面确认等更稳妥的方式处理。

## 二、完整工作流

```
第 1 步  明确诉求性质：要回钱（投诉/诉讼）还是要对方被罚（举报）
第 2 步  先读 rules/complaint_channels.md，选定渠道与管辖层级
第 3 步  按 rules/complaint_elements.md 的十二项要素起草
第 4 步  跑核查脚本扫要素缺失与风险词
    python scripts/complaint_check.py --file 投诉信.txt --out 核查结果.md
第 5 步  改写情绪化表述，逐项人工确认事实与证据编号对应
第 6 步  提交并索取受理编号，按时间管理表跟进
```

## 三、先分清楚四条路（选错会白跑）

| 路径 | 干什么 | 结果能不能直接拿回钱 |
|---|---|---|
| **投诉** | 解决自己的权益争议，组织调解 | ✅ 能促成退款赔偿 |
| **举报** | 要求主管部门查处违法行为 | ❌ 罚的是对方，不直接赔你 |
| **信访** | 向政府反映情况、提出请求 | ❌ 一般不处理民事纠纷 |
| **诉讼/仲裁** | 司法或准司法程序主张权利 | ✅ 有强制执行力 |

想退钱走**投诉或诉讼**；想让对方被罚走**举报**。可以同时进行，但要分开提交，不要混在一份材料里。

## 五、十二项必备要素

规则全文在 `rules/complaint_elements.md`，核心十二项：

| # | 要素 | 缺了会怎样 |
|---|---|---|
| 1 | 受理单位名称 | 材料被转来转去 |
| 2 | 投诉人姓名 | 无法核实身份 |
| 3 | 联系方式 | 无法回访，直接搁置 |
| 4 | 被投诉方全称 | 无法锁定主体 |
| 5 | 事实时间线（≥3 个时间点） | 看不出经过 |
| 6 | 具体诉求 | 无法办理 |
| 7 | 争议金额与计算 | 退费类无法调解 |
| 8 | 凭证编号（订单号/合同号） | 无法调取记录 |
| 9 | 已协商情况 | 被要求先自行协商 |
| 10 | 证据清单 | 证据被忽略 |
| 11 | 签名/落款 | 形式要件缺失 |
| 12 | 落款日期 | 无法判断时序 |

## 六、措辞：只写事实和证据

| 要这样写 | 不要这样写 |
|---|---|
| "3 月 8 日商品出现故障，与页面承诺的 XX 不符" | "这破东西三天就坏了，明显是垃圾货" |
| "商家于 4 月 2 日明确表示不予退换" | "商家态度极其恶劣，拒不处理" |
| "请求协调退还货款 1,280 元" | "必须给我一个说法，否则没完" |

三类会被扣分的表述：

| 类别 | 典型词 |
|---|---|
| 情绪化 | 垃圾、骗子、黑心、无良、坑人、血汗钱 |
| 威胁性 | 曝光个人信息、人肉、上门找你、没完 |
| 无证据定性 | 故意、恶意、串通、收了好处费、内幕 |

**原则**：每一句事实后面跟一个证据编号；不写推测和动机；不写没有证据支撑的定性词。

## 七、脚本用法

```bash
python scripts/complaint_check.py --file "D:\投诉\退款投诉信.txt"
python scripts/complaint_check.py --file 投诉信.txt --out 核查结果.md
python scripts/complaint_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 必填。投诉信草稿文本（`.txt` / `.md`，UTF-8） |
| `--out` | 核查结果写入文件 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置自检（11 条断言） |

脚本做三件事：
1. **要素扫描**：十二项逐项查有没有，时间点要求不少于 3 个
2. **风险词扫描**：情绪化、威胁性、无证据定性三类
3. **结论判定**：可以提交 / 补正后可提交 / 不建议提交 / 修改措辞后再提交

> ⚠️ 脚本只做关键词匹配，命中"有"不等于写得对，必须逐项人工复核。

## 八、人工确认（这步不能省）

- [ ] 被投诉方全称是否与营业执照或平台店铺信息一致
- [ ] 事实时间线每个节点是否都有证据支撑
- [ ] 诉求是否可执行、金额是否明确、计算过程是否说清
- [ ] 是否已先与对方协商，协商记录是否留存
- [ ] 附件清单与正文证据编号是否一一对应
- [ ] 渠道选择是否正确（不是这个部门管的事就换）
- [ ] 是否涉及刑事、劳动争议、医疗损害等需走专门程序的情形

## 九、最常见的坑

**坑一：没拿到受理编号就以为交上去了。**
任何渠道都要当场索取工单号、受理编号或回执。没有编号，等于没提交，也无法催办。

**坑二：被投诉方只写"那家店"。**
受理机关无法锁定主体，材料只能搁置。全称可在企业信用信息公示系统或平台店铺信息页核对。

**坑三：满篇情绪，事实只有两句。**
"骗子""黑心"这类词不会加分，还会让受理方质疑材料可信度。删掉定性，换成带日期的事实。

**坑四：诉求写成"给个说法"。**
不可执行的诉求无法调解。要写成"退还货款 1,280 元""更换同型号新机"。

**坑五：把举报写成投诉（或反过来）。**
想要回钱却在材料里只写"请严查"，处理结果是被罚了款，你的钱还是没回来。

**坑六：同一件事同时投八个渠道。**
会被合并处理、互相等待，反而更慢。先走一个渠道拿编号，超期不办再升级。

**坑七：靠投诉拖着不诉讼。**
投诉处理流程一般不产生确定的诉讼时效中断效力，拖着拖着就过了 3 年。

## 十、边界与免责

- 本技能只做**文书核查与路径规则整理**，不代替主管部门受理，不承诺处理结果
- 受理范围、管辖层级、办理时限**以当地主管部门公示为准**，本技能不引用具体条款号
- 本技能不得用于伪造证据、虚构事实、诽谤他人或恶意重复投诉
- 涉及金额较大、对方失联或涉嫌违法犯罪的，请及时向公安机关报案或咨询执业律师
