# 堡垒机部署、权限与审计核查规则表

本文件是 `bastion-host-deploy` 的核心资产。**做部署方案、定权限模型、核审计能力之前，先读本文件，不要凭印象。**

---

## 一、部署形态选型表

| 形态 | 原理 | 适用规模 | 优点 | 局限 | 安全前提 |
|---|---|---|---|---|---|
| 旁路模式 | 运维先登堡垒机再连目标 | < 数百台 | 部署简单，不改网络 | **目标侧仍可被直连** | **必须封堵目标侧直连** |
| 网关模式 | 流量强制经堡垒机转发 | 中大规模 | 可关闭直连端口，强制审计 | 需改网络，故障面大 | 网络层强制 |
| 代理模式 | 堡垒机代理 SSH/RDP/DB 协议 | 多协议需求 | 支持 RDP、数据库 | 每协议需适配 | 应用侧配置配合 |
| 云原生方案 | 云控制台 + 云审计 | 全在云上 | 与云 IAM 打通 | 跨云割裂 | 云侧策略 |

**选型要点：**

1. 旁路模式的**唯一安全前提是目标侧封堵直连**。不封堵等于没上。
2. 网关模式能真正强制，但改造成本与风险最高，**核心生产系统优先考虑**。
3. 云上优先用云原生审计，自建堡垒机常是重复建设。

## 二、账号权限核查项

| # | 核查项 | 通过标准 | 不通过的后果 |
|---|---|---|---|
| 1 | 个人账号 | 堡垒机账号数 ≥ 运维人数 | 无法追责 |
| 2 | 共享账号 | **= 0** | 审计归零 |
| 3 | root 直登 | `PermitRootLogin no` | root 被暴力破解风险 |
| 4 | 认证方式 | 禁用项已落到配置 | 密钥被爆破后仍可密码登录 |
| 5 | 资产范围 | 按业务/环境/集群分账号 | 越权面过大 |
| 6 | 命令范围 | 角色级白名单 | 权限等同 root |
| 7 | 时间范围 | 高危系统临时授权 + 自动回收 | 永久权限堆积 |
| 8 | 数据范围 | 库/表/行级别授权 | 数据越权 |
| 9 | 提权范围 | sudo 白名单，无 `su`/`bash`/`-i` | **命令审计整体失效** |
| 10 | 临时权限回收 | 有自动回收机制 | 应急权限永久化 |

## 三、职责分离必须项

| 必须分离 | 说明 | 违反后果 |
|---|---|---|
| 权限授予 vs 权限使用 | 授权由管理岗执行 | 运维自行提权 |
| 审计 vs 操作 | 审计管理员 ≠ 日常运维管理员 | 痕迹可被掩盖 |
| 生产 vs 测试变更 | 权限不自动继承 | 测试账号误操作生产 |
| 应用账号 vs 人工账号 | 数据库连接账号与运维账号分开 | 无法追到具体人 |
| 备份执行 vs 备份删除 | 能删的不等于唯一能恢复的 | 数据不可恢复 |

> 三权分立（系统管理员 / 安全管理员 / 审计管理员分设）在现行规定要求的场景必须落实，具体以现场合规要求为准。

## 四、sshd_config 关键项核查表

| 项 | 推荐值 | 不合规后果 |
|---|---|---|
| `PermitRootLogin` | `no` | root 可被暴力破解 |
| `PasswordAuthentication` | 与 `PubkeyAuthentication` 至少收紧一项 | 两种方式同时开放，弱密码被爆破 |
| `PubkeyAuthentication` | `yes`（若用密钥） | — |
| `MaxAuthTries` | 3–6 | 0 或过大 = 不限速 |
| `X11Forwarding` | `no` | 攻击面增大 |
| `LoginGraceTime` | 30–60 | 半开连接占用资源 |
| `ClientAliveInterval` / `CountMax` | 300 / 2 | 死连接堆积 |
| `Include /etc/ssh/sshd_config.d/*.conf` | 注意加载顺序 | 片段覆盖主文件，主文件改了不生效 |
| 来源限制 | **防火墙或网络分层** | `AllowUsers` 不限制来源 |

**「误以为 AllowUsers 能限制来源」的核查提示：**

| 配置 | 实际作用 | 误解后果 |
|---|---|---|
| `AllowUsers alice` | 只有 alice 能登录 | 以为「从哪登录都管住了」→ 直连没封 |
| `DenyUsers bob` | bob 不能登录 | 同上 |
| `Match Address` | 可按来源限制（需谨慎配置） | 不是所有版本/场景都可靠 |
| **防火墙 `iptables -A INPUT -s <堡垒机IP> -p tcp --dport 22 -j ACCEPT`** | **真正限制来源** | ✅ 正确做法 |

## 五、高危命令清单与防护

| 类别 | 命令 | 风险 | 防护手段 | 绕过可能 |
|---|---|---|---|---|
| 数据销毁 | `rm -rf /`、`rm -rf *` | 不可恢复 | 黑名单 + 参数识别 | 别名、脚本 |
| 数据销毁 | `dd if=/dev/zero of=/dev/sda` | 磁盘覆写 | 黑名单 | base64 后执行 |
| 数据销毁 | `mkfs.*`、`fdisk` | 分区破坏 | sudo 白名单排除 | — |
| 数据篡改 | `truncate`、`> /path/表` | 数据清空 | 黑名单 | — |
| 历史清除 | `history -c`、`rm ~/.bash_history` | 销毁线索 | 中心侧记录，不依赖目标 history | — |
| 权限变更 | `chmod 777`、`chown -R root` | 权限失控 | 白名单排除或限参 | — |
| 账号变更 | `useradd`、`passwd`、`visudo` | 留后门 | sudo 白名单不含 | — |
| **提权** | `sudo su -`、`sudo -i`、`sudo bash` | **命令过滤失效** | **必须拦截** | **不可绕过** |
| 后门 | `nc -e`、`bash -i >& /dev/tcp/...` | 反向 shell | 出站审计 + 黑名单 | 变形 |
| 关审计 | `systemctl stop auditd` | 关审计 | 中心侧记录 | 目标侧拦不住 |
| 网络 | `iptables -F`、`stop firewalld` | 关防火墙 | sudo 白名单排除 | — |
| 审计库 | `DELETE FROM audit_log` | 销毁审计 | 审计表独立写入账号，查询只读 | — |

### 拦截层次对照

| 层次 | 手段 | 可绕过性 | 评价 |
|---|---|---|---|
| 1 | 文档规定不许执行 | **完全可绕过** | 不算管控 |
| 2 | 命令黑名单 | 可绕过（别名/eval/脚本） | 需实测 |
| 3 | 命令白名单 | 较难绕过 | 推荐 |
| 4 | sudo 白名单 + 目标侧无 root | 需目标侧配合 | 最强 |
| 5 | 容器/沙箱 + 只读挂载 | 环境上杜绝 | 最彻底 |

**致命漏洞：`sudo` 白名单含 `su`、`bash`、`sh`、`-i`、`zsh`** → 进入新 shell 后命令过滤完全失效，整套命令审计形同虚设。

## 六、审计能力核查表

| # | 核查项 | 通过标准 | 缺失后果 |
|---|---|---|---|
| 1 | 登录成功记录 | 有 | 无法确认访问主体 |
| 2 | **登录失败记录** | 有 | 无法发现爆破尝试 |
| 3 | 命令输入日志 | 有 | — |
| 4 | **命令输出日志** | 有 | 只记输入会漏掉管道后的实际执行 |
| 5 | 会话录像 | 可按人/时间检索回放 | 无法还原界面操作 |
| 6 | 文件传输记录 | 文件名、大小、方向 | 数据外泄无痕迹 |
| 7 | 日志防篡改 | 运维无写权限 | **日志不构成证据** |
| 8 | 日志集中收集 | 已集中 | 本地日志会被删 |
| 9 | 删除权限分离 | 管理员不能删他人日志 | 痕迹可被掩盖 |
| 10 | 容量告警与归档 | 有 | **满盘后新日志写不进去，系统性失效** |
| 11 | 到期清理机制 | 有 | 同上 |
| 12 | 目标侧独立审计 | `auditd` 等独立保留 | 堡垒机被绕过则无痕 |

## 七、VPN / 堡垒机 / 零信任职责边界

| 维度 | VPN | 堡垒机 | 零信任 |
|---|---|---|---|
| 解决什么 | 外部接入内网 | 运维操作审计与管控 | 按身份与设备逐次授权 |
| 控制粒度 | 网络可达（粗） | 会话与命令（细） | 单资源单次（最细） |
| 审计能力 | 通常仅登录日志 | **完整会话审计** | 有，偏访问决策 |
| 能否替代其他 | 不能替代堡垒机 | 不能替代 VPN 接入 | 理念覆盖部分，落地仍需审计手段 |
| 典型误用 | 当审计手段用 | 当唯一网络接入用 | 概念包装无落地策略 |

**推荐组合：**

```
远程接入 → 零信任网关 / VPN（接入 + 身份核验 + 设备状态）
运维操作 → 堡垒机（会话审计 + 命令管控）
资源授权 → 零信任策略在会话内做细粒度授权
```

**一句话结论**：**VPN 通了不代表访问有审计；堡垒机上了不代表网络受控。**

## 八、fail-open vs fail-close

| 模式 | 堡垒机故障时 | 安全性 | 适用 |
|---|---|---|---|
| fail-open（放行） | 允许运维直连 | ❌ 等于现成绕过通道 | 仅非生产 |
| fail-close（拒绝） | 拒绝所有运维访问 | ✅ 安全性高 | **生产必选** |

**必须确认**：堡垒机自身不可用时，运维访问是被阻断还是被放行。默认放行是重大设计缺陷。

## 九、部署验收清单（摘要版）

### 网络
- [ ] 目标 22 端口只对堡垒机网段开放
- [ ] 从非堡垒机网段 `telnet <目标> 22` 失败
- [ ] 堡垒机不直接暴露公网

### 权限
- [ ] 共享账号 = 0
- [ ] `PermitRootLogin no`
- [ ] sudo 白名单无 `su`/`bash`/`sh`/`-i`
- [ ] 临时权限有自动回收

### 审计
- [ ] 登录成功与失败都记录
- [ ] 命令日志含输出
- [ ] 录像可检索回放
- [ ] 文件传输有记录
- [ ] 运维对审计存储无写权限
- [ ] 有容量告警与归档
- [ ] 留存到期有清理机制

### 管控
- [ ] 高危命令**实测拦截成功**（非仅配置界面）
- [ ] 别名/eval/脚本/sudo su 绕过均被拦
- [ ] 应急通道有审批与事后复核
- [ ] 目标侧审计独立于堡垒机
- [ ] 堡垒机故障时 fail-close

## 十、反误判清单

| 现象 | 常见误判 | 真实情况 | 正确做法 |
|---|---|---|---|
| 堡垒机上线 | 直连已堵 | 旁路模式未封堵 | 防火墙限制来源 IP |
| 配了 AllowUsers | 限制了来源 | 只限制了用户 | 用防火墙或网络分层 |
| 配了命令黑名单 | 高危命令拦住了 | 别名/eval 可绕 | 实测 + 改用白名单 |
| sudo 白名单里有 bash | 权限受控 | 命令过滤已失效 | 移除所有交互 shell 提权路径 |
| 日志有记录 | 审计合规 | 可能被删、可能没输出 | 查存储权限与日志内容 |
| 日志量大 | 审计完善 | 可能是存储满后的重复写失败 | 查容量与写入状态 |
| 用了 VPN | 访问可追溯 | 只有登录记录 | 审计必须用堡垒机 |
| 紧急用过通道 | 事后再补就行 | 补审缺失则等于无审计 | 审批 + 时限 + 事后复核 |
