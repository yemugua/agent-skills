# 小程序个人信息保护合规核查

## 用途

对微信小程序的个人信息保护合规状况做逐项核查，定位阻断项与风险项，给出可落地的整改清单。适合：

- 上线前隐私合规自查（任何小程序都该过一遍）
- 被平台通报/接口被拦截后的整改定位
- 不确定「隐私协议怎么写、授权弹窗怎么接、SDK 要不要申报」

## 输入

一份 Markdown 采集表（表格 `| 字段 | 值 |` 或 `字段：值` 冒号行均可），字段见
`templates/隐私合规采集表.md`。核心字段：

| 字段 | 说明 |
|------|------|
| 主体类型 | 企业 / 个体工商户 / 个人 |
| 小程序是否已上线 | 是 / 否 |
| 是否收集个人信息 | 是 / 否 |
| 收集的信息类型 | 如「手机号、位置、相册」；含敏感信息会触发单独同意核查 |
| 是否配置用户隐私保护指引 | 后台设置-服务内容声明里的隐私指引 |
| 隐私协议是否列明目的范围期限 | 目的、方式、种类、保存期限 |
| 是否在使用隐私接口前取得同意 | 隐私授权弹窗（先同意后调用） |
| 拒绝授权后是否仍可用基础功能 | 不得强制退出 |
| 是否使用第三方SDK或插件 | 统计/推送/地图/支付等 |
| 是否已申报SDK与共享清单 | 后台第三方设置申报 |
| 是否收集敏感个人信息 / 敏感信息是否单独同意 | PIPL 第 28/29 条 |
| 是否提供账号注销 / 是否支持查阅复制更正删除 | 用户权利 |
| 是否加密传输与存储 | HTTPS/TLS + 存储加密 |
| 是否落实未成年人监护人同意 | 14 岁以下监护人同意 |
| 是否有违规收集或通报整改历史 | 监管通报/平台处罚 |

## 输出

多段 Markdown 报告：

1. **结论摘要**：总体结论（通过 / 有风险 / 不通过）+ 阻断/风险计数 + 处置建议
2. **分项核查**：隐私协议与告知 / 授权与同意 / 第三方 SDK 与共享清单 / 敏感信息 / 用户权利 / 数据安全与未成年人
3. **阻断项与风险/待办**：逐条列出，阻断项说明平台后果
4. **整改操作指引**：标准 8 步隐私合规清单
5. **边界与纪律**：依据 PIPL / 数据安全法 / GB/T 35273-2020 与微信平台公开规则，不替代监管规定与法律意见

## 使用

```bash
python3 scripts/miniprogram_privacy_compliance.py <采集表.md>
```

退出码：`0` 正常；`2` 未读取到有效字段（打印待补正提示）。

## 判定口径

- **不通过（阻断）**：未配置用户隐私保护指引、未在隐私接口前取得同意、SDK 未申报、敏感信息无单独同意、无账号注销。
- **有风险**：协议内容不完整、拒绝授权后不可用、无查阅/复制/更正/删除、未加密、未成年人未落实、有违规整改历史。
- **通过**：全部核查项满足。

## 红线（本技能不会做的）

- 不代写规避监管的「表面合规」文本；不虚构整改结论。
- 不替代微信平台审核结论与正式法律意见。
