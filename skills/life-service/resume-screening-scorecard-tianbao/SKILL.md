# 招聘简历筛选评分卡（resume-screening-scorecard）

招聘质量的坑，八成在**筛选标准**这一步：JD 写一套、心里想一套、打分校一套，最后招进来的人自然对不上。

这个技能做四件事：**定维度** → **打分排序** → **判红线** → **备面试**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 设计岗位评分维度与权重 | ❌ 基于性别、年龄、地域、婚育等做筛选 |
| 对简历材料做结构化打分 | ❌ 替代背景调查与用人决策 |
| 生成针对性面试问题 | ❌ 编造候选人材料 |
| 输出邀约优先级与排序表 | ❌ 保证候选人胜任或留存 |

**评分只依据与岗位相关的材料与信息。** 涉及个人隐私、与岗位胜任无关的因素一律不作为评分项；拿不准的信息标注"待面试验证"，不脑补。

---

## 一、什么时候用这个技能

| 用户这样说 | 就用 |
|---|---|
| "收到一堆简历，怎么筛" | ✅ |
| "招聘评分表怎么做" | ✅ |
| "这个候选人约不约面试" | ✅ |
| "面试该问什么" | ✅ |
| "招的人为什么总留不住" | ✅ |
| "帮我查查这个人的底" | ❌ 背景调查需授权与合规渠道 |

## 二、完整工作流

```
第 1 步  对齐岗位：JD、必需要素、团队阶段（初创/成熟）
第 2 步  读规则文件 rules/scoring_rubric.md，确定七维度与权重
第 3 步  逐份打分，跑脚本汇总排序
    python scripts/score_calc.py --file 评分明细.csv --weights default
第 4 步  红线筛查：一票否决项先过
第 5 步  按邀约优先级安排面试，生成针对性问题
第 6 步  面试后回填实际表现，校准评分标准
```

## 三、七维度评分框架（100 分制）

| # | 维度 | 建议权重 | 看什么 |
|---|---|---|---|
| 1 | 硬性资质 | 15% | 学历、职业资格、上岗证（岗位必需项） |
| 2 | 专业经验 | 25% | 同岗位/同行业年限、项目规模、职责匹配度 |
| 3 | 专业能力证据 | 20% | 作品、案例、处理过的复杂问题、成果数据 |
| 4 | 稳定性 | 10% | 职业连续性、跳槽频率、空窗期合理性 |
| 5 | 动机与匹配 | 10% | 求职原因、职业规划、对岗位/行业的认知 |
| 6 | 沟通与协作 | 10% | 表达清晰度、跨部门协作、团队角色证据 |
| 7 | 成长潜力 | 10% | 学习轨迹、新技能习得、自我驱动证据 |

> 权重是通用基线。**技术岗加重 2/3，管理岗加重 5/6，初创岗加重 7**——在评分表里写死本岗位权重，避免每次现编。

**每维度按 0-5 分打分，再按权重折算：**

```
维度得分 = 原始分(0-5) / 5 × 100 × 权重
总分    = Σ 维度得分
```

## 四、S/A/B/C/D 五级分档

| 档位 | 总分区间 | 含义 | 动作 |
|---|---|---|---|
| **S** | ≥90 | 显著超出岗位要求 | 优先面试，可适当放宽薪酬谈判节奏 |
| **A** | 80-89 | 超出要求 | 正常面试，重点验证匹配度 |
| **B** | 70-79 | 符合要求 | 批量面试，比价择优 |
| **C** | 60-69 | 部分符合，有缺口 | 备选池，缺岗位关键要素则不约 |
| **D** | <60 | 明显不符 | 归档，进入人才库长期跟踪 |

**分档是"动作分档"不是"人品分档"——**D 档只是当前岗位不匹配，不是对候选人的否定。

---

## 五、硬性红线（一票否决）

- 岗位**法定必需证书缺失**（如消防值班岗无消防设施操作员证）
- 简历关键信息**造假**（任职时间、职务、证书编号）
- 涉及竞业限制且无法规避
- 基本到岗条件无法满足（工作地、班次、出差要求）
- 有与岗位职责冲突的利益关系

> 红线项必须在 JD 发布前写清楚，**不能秋后算账**。

## 六、脚本用法

```bash
python scripts/score_calc.py --file 评分明细.csv --weights default --min-grade B
```

| 参数 | 说明 |
|---|---|
| `--file` | 必填。评分明细 CSV（UTF-8/GBK），列：`name, dim1..dim7, redline, note` |
| `--weights` | 权重方案：`default`（通用）/ `tech`（技术岗）/ `mgmt`（管理岗）/ `startup`（初创岗） |
| `--min-grade` | 只输出该档位及以上的候选人，默认 B |
| `--out` | 输出路径 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

## 七、邀约优先级矩阵

| 分档 | 简历质量 | 到岗紧迫度 | 动作 |
|---|---|---|---|
| S/A | 高 | 高 | 48 小时内首约，面试官档期优先 |
| S/A | 高 | 低 | 正常约，同步储备 |
| B | 中 | 高 | 集中批量面，控制单场成本 |
| B | 中 | 低 | 人才库储备 |
| C | 有缺口 | 高 | 只约关键要素达标的 |
| 红线 | — | — | 不约，归档说明原因 |

## 八、面试问题生成（按低分维度提问）

| 低分维度 | 针对性问题示例 |
|---|---|
| 经验 | "请讲一个你从头负责的同类项目，你在其中的决策点是什么？" |
| 能力证据 | "这个成果里，哪部分是你个人贡献？怎么证明？" |
| 稳定性 | "你每次换岗位的触发因素是什么？这次为什么看机会？" |
| 动机 | "你对这个岗位最担心的一点是什么？" |
| 沟通 | "请用三句话向非专业的同事解释你的工作。" |
| 潜力 | "过去一年你新学会了什么？怎么学的？" |

**提问原则：问行为不问观点**（"你会怎么想"换成"你上次怎么做的"）；每个问题预设一个"好答案长什么样"，面试当场比对。

## 九、人工确认（这步不能省）

- [ ] JD 与评分维度一一对应（JD 没写的别偷着扣分）
- [ ] 红线项发布前公示，标准统一
- [ ] 两名以上评估人独立打分后校准，避免单人偏差
- [ ] 面试后回填实际表现，每季度复盘分档校准
- [ ] 涉及证书、任职信息的，入职前走合规核验渠道

---

## 十、输出结构（固定三段）

1. **候选人排序表** —— 总分、分档、各维度得分、亮点/疑点
2. **邀约优先级清单** —— 顺序、理由、建议面试官
3. **定制面试问题** —— 按每人低分维度生成 3-5 问

---

## 十一、最常见的坑

**坑一：JD 和评分表两张皮。**
JD 写"注重团队协作"，评分表全是硬技能——招进来的人会干活不会共事，团队天天擦火花。

**坑二：唯证书/唯大厂论。**
证书是门槛不是能力；大厂背景可能是平台能力不是个人能力。要看"离开平台他还做成过什么"。

**坑三：一人打分说了算。**
面试官的个人偏好（校友、同乡、聊得来）会系统性地扭曲结果。多人独立打分+校准是纠偏的唯一机制。

**坑四：红线项秋后算账。**
发 JD 时不写"需持 X 证"，面试到终面才说，候选人体验极差，还可能惹投诉。

**坑五：C/D 档简历直接删。**
岗位在变、人在成长。今天 D 档的人，半年后可能就是 S 档。人才库的成本是零，收益是复利。

**坑六：只筛不反馈校准。**
招的人留不住，永远怪"候选人不行"。不把留存结果回灌到评分维度，筛选标准就永远漂着。
