# 薪资谈判策略与Offer对比核算（salary-negotiation）

谈薪最常见的两个错误：**第一个是只比月薪**，把 13 薪、公积金比例、期权、加班强度全漏掉；**第二个是只问「能给多少」**，把谈判变成了乞讨。

这个技能做三件事：**定锚** → **谈价** → **按全成本横向比 Offer**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出报价区间与锚定策略 | ❌ 保证拿到某个数字 |
| 按全成本口径横向对比多个 Offer | ❌ 提供虚假在职证明、流水或薪资信息 |
| 折算公积金、福利、期权与真实时薪 | ❌ 代替劳动合同条款的审阅 |
| 给出常见谈判场景的话术脚本 | ❌ 建议同时持有多份已签署的 Offer 施压 |
| 提示试用期、竞业、违约金等条款风险 | ❌ 提供税务筹划或规避社保的方案 |

**必须停下来做专业确认的情形：**
- Offer 里有**竞业限制、服务期、违约金、培训费用返还**条款 —— 签约前请专业人士审阅
- 涉及**股权、期权**的行权条件、退出机制、税负 —— 以协议文本与专业意见为准
- 薪资结构涉及**异地社保、第三方代缴、现金发放** —— 存在合规风险，需核实
- 个税与社保基数、专项附加扣除**以现行规定与当地主管部门要求为准**
- 试用期工资标准**以现行劳动法律法规与当地最低工资标准为准**

**绝对不做的事**：不伪造收入证明、银行流水、在职证明；不虚构竞品 Offer 抬价。这类行为一旦被发现，代价是失去 offer 并影响行业口碑。

## 二、完整工作流

```
第 1 步  先读 rules/negotiation_rules.md，建立价格区间认知（市场分位 + 现薪 + 目标）
第 2 步  定锚：按 §3 算出「报价下限 / 目标值 / 报价上限」三个数
第 3 步  先出价还是后出价：按 §3.2 判定，写好一句话脚本
第 4 步  收集每个 Offer 的七项参数（月薪、发薪月数、奖金、签字费、公积金比例、期权、福利）
第 5 步  跑脚本对比：python scripts/offer_compare.py --file offers.json
第 6 步  看四个数：年度到手现金、年度综合到手、真实时薪、相对现薪涨幅
第 7 步  折算期权与试用期：按 §5 折价，别把不确定收入当确定收入
第 8 步  签约前核条款：竞业、服务期、违约金、奖金发放条件、试用期标准
```

## 三、锚定：三个数（不是一个数）

### 3.1 报价区间怎么定

```
报价下限 = 你的底线（低于此不去），通常 = 现薪 × 1.10
目标值   = 市场同岗位中位偏上，通常 = 现薪 × 1.20 ~ 1.30
报价上限 = 有依据的最高值，通常 = 目标值 × 1.10 ~ 1.15
对外只报「目标值 ~ 报价上限」这个区间，不报下限。
```

**区间而不是单点**：报单点数字，等于把谈判压缩成「成或不成」；报区间，对方会在区间内取数，且保留了「区间底部也接受」的回旋余地。

### 3.2 先出价还是后出价

| 情形 | 做法 | 一句话脚本 |
|---|---|---|
| 你掌握市场价、对方没给范围 | **先出价**，报区间上沿 | 「结合这个岗位的职责和我过往在 XX 上的结果，我的期望是 XX 到 XX，具体看整体 package」 |
| 对方已给出明确薪资范围 | **后出价**，落在范围上 1/3 | 「我了解到范围是 XX-XX，结合我的经验，我希望能落在偏上的位置」 |
| 现薪明显低于市场价 | **避免回答现薪**，转向期望 | 「我更希望按这个岗位的市场水平和我的能力来谈，我的期望是 XX」 |
| 对方坚持要现薪数字 | 报**全成本口径**，不报月薪 | 「我现在的年度总包大概是 XX（含奖金与公积金），期望有 XX% 的提升」 |

> 被问现薪时，**报年度总包而不是月薪**——这是把锚从「月薪 +20%」抬到「总包 +20%」的关键一步。

### 3.3 三个不能说的话

| 不能说 | 为什么 | 改成 |
|---|---|---|
| 「我现在的工资是 XX 万」 | 把锚定权交给对方 | 报年度总包口径 |
| 「多少都行，看公司安排」 | 主动放弃定价权 | 报区间 |
| 「我手里还有个 XX 万的 offer」 | 虚构即失格；真的也不宜当筹码反复用 | 「我这边时间上希望本周内确认」 |

## 四、全成本对比：七项构成（只比月薪一定比错）

```
① 年度现金   = 月薪 × 发薪月数 + 年度奖金 + 签字费
② 五险一金个人扣除 = 月薪 × 个人缴纳比例 × 12     （默认合计约 22.5%）
③ 年度个税   = 按年度综合所得七级超额累进计算（以现行税法为准）
④ 年度到手现金 = ① - ② - ③
⑤ 公积金双边  = 月薪 × 公积金比例 × 12 × 2        ← 公司缴的部分也是你的钱
⑥ 福利折现   = 餐补、体检、商保、培训、通讯等年度合计
⑦ 期权年化   = 期权总授予价值 ÷ 归属年限 × 折价系数

年度综合到手 = ④ + ⑤ + ⑥ + ⑦
真实时薪     = 年度综合到手 ÷ (每月投入小时 × 12)
每月投入小时 = 工作日数 × 日均在岗小时 + 每周加班小时 × 4.33 + 日均通勤小时 × 工作日数
```

**公积金双边是最常被漏掉的一项。** 月薪 3 万、公积金 12% 的公司，一年双边就是 8.64 万——相当于多了一个月多的工资。

**真实时薪是最后的裁判。** 两个 offer 年收入差 5 万，但一个每周多加班 15 小时,算完时薪可能反而是低的。

## 五、期权与试用期：不确定收入要打折

| 项 | 折价规则 | 说明 |
|---|---|---|
| 上市公司股票 | 不折价（按市价） | 流动性好 |
| 成熟期未上市公司期权 | 按 **50%** 折价 | 归属与退出都有不确定性 |
| 早期创业公司期权 | 按 **0-30%** 折价，保守取 0 | 行权价、稀释、退出条件都未知 |
| 年度奖金（写进合同） | 不折价 | 有约定即可主张 |
| 年度奖金（未写进合同） | 按 **50%-70%** 折价 | 与绩效、公司经营挂钩 |
| 试用期工资 | 按规定不低于本岗位最低档或合同约定工资的 80%，且不低于当地最低工资标准 | **以现行规定为准** |

**红线**：期权占年度综合到手的比例**超过 30%** 时，说明这份 offer 的实际现金吸引力有限，谈判时应优先争取现金部分。

## 六、跳槽涨幅阈值

| 相对现薪涨幅 | 判定 | 说明 |
|---|---|---|
| ≥ 30% | 值得跳 | 能覆盖风险与适应成本 |
| 20% - 30% | 可以考虑 | 看平台、成长与团队 |
| 10% - 20% | 谨慎 | 除非有明确的成长或团队因素 |
| < 10% | 不建议 | 覆盖不了跳槽的风险与成本 |
| ≤ 0 | 不跳 | 除非有极强的非金钱理由 |

> 跳槽的真实成本包括：试用期风险、适应期、人脉重建、可能的年终奖损失。**低于 10% 的涨幅，通常覆盖不了这些。**

## 七、脚本用法

```bash
python scripts/offer_compare.py --file offers.json --out offer对比.md
python scripts/offer_compare.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 输入 JSON，含 `current_annual` 与 `offers` 列表 |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 结果写入文件，默认 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON：

```json
{
  "current_annual": 380000,
  "offers": [
    {"name": "A 公司", "monthly_gross": 30000, "months": 13, "bonus": 60000,
     "housing_fund_rate": 0.12, "welfare_year": 6000,
     "equity_total": 400000, "vesting_years": 4, "equity_discount": 0.5,
     "probation_months": 3, "probation_ratio": 0.8,
     "workdays_per_month": 21.75, "daily_hours": 9,
     "overtime_hours_per_week": 10, "commute_hours_per_day": 1.0},
    {"name": "B 公司", "monthly_gross": 34000, "months": 12, "bonus": 30000,
     "housing_fund_rate": 0.07, "welfare_year": 3000,
     "overtime_hours_per_week": 20, "commute_hours_per_day": 2.0}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `monthly_gross` / `months` / `bonus` / `sign_on` | 税前月薪、发薪月数、年度奖金、签字费 |
| `housing_fund_rate` | 公积金缴存比例（个人侧，公司同比例计入双边） |
| `welfare_year` | 年度福利折现（餐补、体检、商保、培训） |
| `equity_total` / `vesting_years` / `equity_discount` | 期权总价值、归属年限、折价系数（默认 0.5） |
| `overtime_hours_per_week` / `commute_hours_per_day` | 用于折算真实时薪 |
| `social_rate` | 五险一金个人合计比例，默认 0.225 |
| `special_deduction_monthly` | 专项附加扣除月额，默认 0 |

脚本输出：每个 offer 的年度现金、五险一金、个税、到手现金、公积金双边、期权年化、年度综合到手、真实时薪、相对现薪涨幅、试用期折损，横向排名与判定，以及涨幅过低、期权占比过高、试用期打折过低、时薪与总收入排名背离等提醒。

> 个税按**奖金并入综合所得**的简化口径估算，实际以公司计税方式与现行税法为准；社保基数上限、专项附加扣除、 지역 政策差异未完全覆盖。

- [ ] 个税与社保以现行规定与当地主管部门要求为准

## 九、最常见的坑

**坑一：只比月薪，不看发薪月数与公积金比例。**
错误做法：A 公司月薪 3 万、B 公司月薪 3.2 万，选 B。正确做法：算全成本。A 是 13 薪 + 公积金 12%（双边一年 8.64 万），B 是 12 薪 + 公积金 7%，A 的年度综合到手可能反过来更高。**月薪差两千，年度总包可能差出五六万。**

**坑二：被问现薪就老实报月薪。**
错误做法：「我现在月薪 2 万」。正确做法：报年度总包——「我现在的年度总包大概 30 万（含奖金和公积金）」，把锚从月薪抬到总包。对方按总包 +20% 给，比按月薪 +20% 多出一大截。

**坑三：先出价时报了底线数字。**
错误做法：底线 25 万，开口就报 25 万。正确做法：报区间上沿（目标值到上限），区间下沿是底线，永远不说出口。**谈判的成交价通常在开价与对方预算之间，开价低了没救。**

**坑四：把期权按 100% 算进收入。**
错误做法：期权 40 万，一年 10 万，觉得收入很高。正确做法：未上市公司期权按 50% 折价，早期创业公司按 0-30% 甚至 0 折。**期权没到手之前，都是纸面数字。**

**坑五：不算真实时薪。**
错误做法：年收入高 5 万就选它。正确做法：把加班和通勤折进去算时薪。每周多加班 15 小时、通勤多 1 小时，一年多投入近 900 小时——**换算成时薪，可能比低收入的那个还低。**

**坑六：年终奖没写进合同。**
错误做法：口头说「一般发 3 个月」。正确做法：写进 Offer 或合同，明确发放条件与计算口径。没写进的奖金属于公司自主决定事项，年底缩水无从主张。

**坑七：忽略试用期折损。**
错误做法：按 12 个月满薪算第一年收入。正确做法：试用期 3 个月打 8 折，第一年实际少了一个月工资的 20%。**第一年现金流才是你真正要过的日子。**

**坑八：为了涨薪跳槽，涨幅却只有 8%。**
错误做法：涨 8% 就跳。正确做法：涨幅低于 10% 通常覆盖不了试用期风险、适应成本与人脉重建。低于 20% 的跳槽，必须有明确的成长或团队理由。

**坑九：用虚构的竞品 offer 抬价。**
错误做法：编造一个不存在的 offer 施压。正确做法：用时间压力代替虚假筹码——「我这边希望本周内确认」。虚构背景一旦被核实，offer 会直接撤回。
