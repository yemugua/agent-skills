# 商业计划书撰写与投资人关注点核查（business-plan-writing）

BP 不是产品说明书。投资人看完只有三个问题：**这门生意能不能做大、能不能赚钱、为什么是你**。

这个技能做三件事：**按六大模块搭骨架并逐章答题** → **把三年财务表的勾稽关系理清** → **提前拆掉投资人高频提问里的陷阱**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出 BP 结构、每章必答问题与模板 | ❌ 预测融资成功概率或投资回报率 |
| 给出三年财务预测表科目与勾稽规则 | ❌ 代替会计师审计或出具财务意见 |
| 给出市场规模测算方法与口径 | ❌ 编造市场数据、竞争对手数据或经营数据 |
| 给出投资人高频提问清单与应答思路 | ❌ 代替律师出具法律意见或尽调结论 |
| 核查章节缺失、因果链断裂、财务不勾稽 | ❌ 指导包装虚假数据或规避披露义务 |
| 给出数据来源引用规范 | ❌ 指导隐瞒重大风险或关联关系 |

**必须先停下来确认的情形：**
- 涉及**发行、上市、融资披露** —— **以现行证券监管法律法规和披露规则为准**，本技能不替代专业机构意见
- 涉及**税务与会计处理** —— 由持证会计师与税务师把关，**以现行财税规定为准**
- 涉及**股权、期权池、对赌条款** —— 由律师起草，**以现行公司法和合同约定为准**
- 涉及**个人信息与用户数据** —— 遵守现行个人信息保护规定，BP 中不得出现可识别的用户明细
- 引用第三方数据 —— 必须标注来源，**不得使用未公开或未经授权的数据**

## 二、完整工作流

```
第 1 步  先定一句话：这门生意解决谁的什么问题，靠什么赚钱
第 2 步  按 rules/bp_modules.md 排六大模块，逐章答必答问题
第 3 步  市场模块：用 rules/market_sizing.md 的口径做自上而下与自下而上两套测算
第 4 步  财务模块：按 rules/finance_model.md 列三年预测表，做勾稽校验
第 5 步  跑脚本体检：python scripts/bp_check.py --file bp.json
第 6 步  看四个数：章节完整度、财务勾稽通过率、数据来源标注率、高风险项数
第 7 步  按 rules/investor_questions.md 逐条预演二十个高频提问
第 8 步  定稿前按 §八 人工确认，涉及披露义务的部分请专业机构审核
```

**顺序不能颠倒**：市场没算清就写财务，财务一定编。**先有自下而上的收入测算，再有自上而下的市场空间。**

## 三、六大模块与每章必答问题

| # | 模块 | 一句话要回答 | 必答问题 |
|---|---|---|---|
| 1 | **问题** | 谁在什么场景下遇到什么麻烦，代价是多少 | 目标用户是谁？痛点有多痛？现在怎么解决？现有方案的代价是什么？ |
| 2 | **方案** | 你做了什么，让痛点消失或大幅减轻 | 产品形态是什么？核心功能是哪几个？为什么用户会换？ |
| 3 | **市场** | 这门生意能做多大 | 市场多大？怎么算出来的？未来 3 年能拿到多少？ |
| 4 | **商业模式** | 怎么赚钱，赚得对不对 | 谁付钱？付多少？一次赚多少？获客成本多少？回本周期多长？ |
| 5 | **竞争** | 你凭什么赢 | 竞争对手有谁？他们的强项弱项？你在哪一维领先？壁垒是什么？ |
| 6 | **财务** | 三年后长什么样 | 收入、成本、毛利、费用、现金流分别是多少？什么时候打平？ |

**附：融资与团队**。融资轮次、金额、用途、估值依据、团队构成。这两项很多 BP 漏掉，但投资人一定会问。

### 模块之间的因果链

BP 不是六个独立模块，而是一条链：

```
问题（存在真实痛点）
  → 方案（能解决这个痛点）
    → 市场（解决的人足够多）
      → 商业模式（他们愿意付钱且我能赚）
        → 竞争（我能持续拿到份额）
          → 财务（以上假设的量化结果）
```

**任何一环断了，整条链就断了。** 写完后逐环检查：方案解决的是这个问题吗？市场算的是这类用户吗？收入是不是用户数 × 付费率 × 客单价？

## 四、市场规模测算（三种口径，都要写）

| 口径 | 算法 | 用途 | 常见错误 |
|---|---|---|---|
| **TAM**（总可及市场） | 目标人群数 × 年均消费 | 讲天花板 | 把整个行业都算进来，虚高 |
| **SAM**（可服务市场） | TAM × 可触达比例（地域、品类、渠道限制） | 讲现实空间 | TAM 直接当 SAM 用 |
| **SOM**（可获市场） | SAM × 三年可获取份额（保守） | 讲三年目标 | 份额拍脑袋给 30% |

### 自上而下与自下而上（两套都要有）

```
自上而下：行业规模 × 你的细分占比
自下而上：客户数 × 付费率 × 客单价 × 复购次数

两套结果的差异是投资人会追问的点。
差异小于 2 倍，BP 里说明取哪套及原因；差异大于 2 倍，必须解释。
```

**每个数字都要标注来源与时点**，例如「据 XX 报告（2025 年）数据测算」。没有来源的数字等于没写。

## 五、商业模式：单位经济模型

**投资人不看利润表，先看单位经济模型（UE）。** 一个客户的完整账：

```
单位经济模型（单客户/单次）
  客单价 ARPPU        = 元/单
  变动成本           = 元/单   （履约、带宽、退款、按量成本）
  毛利 = 客单价 - 变动成本
  毛利率 = 毛利 ÷ 客单价

  获客成本 CAC        = 元
  单客户毛利贡献 LTV  = 毛利 × 复购次数

  LTV / CAC  ≥ 3      才算基本跑通（行业不同标准不同，写明所用标准）
  回本周期 = CAC ÷ 单客户月毛利   （越短越好）
```

**必须写清的三点**：
1. 你的 CAC 是多少，**怎么算出来的**（渠道单价、转化率、人力成本怎么摊）
2. 你的留存/复购曲线长什么样（第 1 个月、第 6 个月、第 12 个月留存率）
3. 现金流最紧的月份是哪个月，账上钱够烧多久

**一条常见致命问题**：BP 里收入预测从第 1 年 1000 万跳到第 2 年 8000 万，却没解释用户从哪来。**收入增速必须能拆成「用户数 × 付费率 × 客单价」的乘积，每一项都要有增长依据。**

## 六、三年财务预测表必备科目

| 类别 | 科目 |
|---|---|
| **收入** | 营业收入、其中产品收入、订阅收入、一次性收入、其他收入 |
| **成本** | 营业成本、履约成本、服务器/带宽成本、退款与坏账 |
| **毛利** | 毛利、毛利率 |
| **费用** | 研发费用、销售费用、市场推广费用、管理费用 |
| **利润** | 经营利润、净利润、净利率 |
| **现金流** | 经营性现金流、资本开支、自由现金流、期末现金余额 |
| **规模指标** | 用户数、付费用户数、ARPU、获客成本 CAC、客单价 |
| **资产负债** | 总资产、总负债、净资产 |

### 三条勾稽关系（写完必须核一遍）

```
1. 毛利 = 营业收入 - 营业成本
   → 毛利率 = 毛利 ÷ 营业收入

2. 经营利润 = 毛利 - 研发费用 - 销售费用 - 管理费用
   → 净利润 = 经营利润 - 所得税 ± 其他损益

3. 期末现金余额 = 期初现金 + 经营性现金流 + 投资活动现金流 + 筹资活动现金流
   → 融资到账后现金余额必须等于 融资额 + 原有现金 + 累计经营性现金流
```

**违反任意一条，财务表就是编的。** 投资人或会计师一眼就能看出勾稽不上。

### 融资额怎么定

```
建议融资额 = 达到下一个里程碑所需月数 × 月度净消耗 ÷ 安全系数
安全系数取 1.3-1.5（留出超支空间）

例：月度净消耗 120 万，到下一个里程碑需 18 个月
  基础额 = 120 × 18 = 2160 万
  建议融资 = 2160 × 1.3 ≈ 2800 万
```

**同时写明融资用途的比例**，例如「研发 55%、市场 30%、运营 10%、储备 5%」。

## 七、投资人高频提问（20 题）与陷阱

| # | 提问 | 陷阱 | 应答要点 |
|---|---|---|---|
| 1 | 这个项目解决的真问题是什么？ | 痛点描述停留在行业焦虑 | 具体到谁在什么场景下损失了什么 |
| 2 | 不用你产品，这个问题怎么解决？ | 忽略已有替代方案 | 列出 3-5 个现有方案及其代价 |
| 3 | 用户为什么非用你不可？ | 「体验更好」这类主观描述 | 给切换成本、可验证指标 |
| 4 | 市场规模怎么算的？ | 引用来源不明的大数字 | 明确口径、来源、时点，两套算法 |
| 5 | 你的第一批用户从哪来？ | 「投放」两个字 | 给出具体渠道、成本、转化率 |
| 6 | CAC 怎么算的？ | 只算投放费用不算人力 | 渠道费 + 销售人力 + 工具分摊 |
| 7 | 留存数据有吗？ | 编留存曲线 | 有就给真实数据，没有就给可验证的小样本 |
| 8 | 收入预测的依据是什么？ | 从 1000 万跳到 8000 万 | 拆成用户数 × 付费率 × 客单价 |
| 9 | 毛利率为什么是这个数？ | 拍一个行业平均 | 按自己的实际履约成本算 |
| 10 | 什么时候能打平？ | 只给单年利润 | 给月度现金曲线与最紧月份 |
| 11 | 账上钱够烧多久？ | 说「充足」 | 给具体月数与依据 |
| 12 | 你的壁垒是什么？ | 把「团队」当唯一壁垒 | 产品、渠道、数据、关系至少一项可累积 |
| 13 | 竞争对手会怎么反击？ | 从不考虑被反击 | 给出对手的优势与你的应对 |
| 14 | 大厂进场怎么办？ | 一味回避 | 给「即使大厂做，你的最小可行优势」 |
| 15 | 团队凭什么做这件事？ | 只讲履历不讲匹配 | 过往是否做过同类事、结果如何 |
| 16 | 之前做过什么项目？为什么结束？ | 隐瞒失败经历 | 如实说 + 复盘 + 与本项目的关系 |
| 17 | 关键人离职怎么办？ | 无答案 | 关键岗位冗余安排 |
| 18 | 这轮钱花完的里程碑是什么？ | 「继续增长」 | 具体到可验收的产品或收入节点 |
| 19 | 创始团队股权怎么分？ | 说不清或过于集中 | 说明结构与 Vesting 安排 |
| 20 | 有哪些风险是你没解决的？ | 说「没有风险」 | 列 3 个真实风险 + 应对方案 |

**最忌讳的三种回答**：
- 「这个数据是公开的」（追问：哪个来源、什么时点、什么口径）
- 「我们的团队很优秀」（追问：体现在哪件事上）
- 「目前没有收入，但我们有资源」（追问：什么资源，多久能变现）

## 八、数据来源与引用规范

| 规范 | 要求 |
|---|---|
| 标注来源 | 每个引用的外部数字都要写来源名 + 时点 |
| 标注口径 | 「市场规模」要说明是收入口径还是数量口径 |
| 区分自有与引用 | 自有经营数据与第三方数据分别标注 |
| 数据可追溯 | 投资人要求时能提供原始出处 |
| 不夸大 | 第三方报告数据注明是否为预测值 |
| 敏感处理 | 用户数据、个人信息、未公开数据不得出现在 BP 中 |

**BP 中引用格式示例**：

```
√「据 XX 研究机构 2025 年报告，2024 年我国该品类零售规模为 X 亿元，
   同比 +Y%，预计 2027 年达 Z 亿元。」
×「据权威数据显示，市场前景广阔。」
```

## 九、脚本用法

```bash
python scripts/bp_check.py --file bp.json --out BP体检.md
python scripts/bp_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | BP 内容 JSON，见下方结构 |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 输出文件，默认 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON：

```json
{
  "title": "XX 项目商业计划书",
  "sections": [
    {"module": "problem", "name": "问题", "present": true, "answered_questions": 4, "total_questions": 4},
    {"module": "solution", "name": "方案", "present": true, "answered_questions": 2, "total_questions": 3},
    {"module": "market", "name": "市场", "present": true, "answered_questions": 2, "total_questions": 3},
    {"module": "business", "name": "商业模式", "present": true, "answered_questions": 1, "total_questions": 4},
    {"module": "competition", "name": "竞争", "present": true, "answered_questions": 3, "total_questions": 3},
    {"module": "finance", "name": "财务", "present": true, "answered_questions": 3, "total_questions": 4},
    {"module": "team", "name": "团队", "present": false, "answered_questions": 0, "total_questions": 3},
    {"module": "funding", "name": "融资", "present": true, "answered_questions": 2, "total_questions": 3}
  ],
  "finance": {
    "years": [2026, 2027, 2028],
    "revenue": [1000, 8000, 30000],
    "cost": [800, 4800, 16500],
    "gross_profit": [200, 3200, 13500],
    "rd_expense": [300, 1600, 4500],
    "sales_expense": [200, 1800, 5400],
    "admin_expense": [100, 400, 900],
    "op_profit": [-400, -600, 2700],
    "net_profit": [-400, -600, 2400],
    "begin_cash": [800, 2400, 1800],
    "end_cash": [2400, 1800, 4500],
    "op_cash_flow": [0, 600, 3300]
  },
  "ue": {"arppu": 200, "variable_cost": 80, "cac": 150, "repeat_times": 4,
         "churn_monthly": 0.08},
  "data_sources": [
    {"item": "市场规模", "source": "", "year": ""},
    {"item": "自有用户数", "source": "内部后台", "year": "2026"}
  ],
  "risks": ["政策变动", "大厂入场", "获客成本上升"]

```

| 字段 | 说明 |
|---|---|
| `sections[].answered_questions` | 已回答的必答问题数 |
| `finance.*` | 三年财务各科目 |
| `ue.*` | 单位经济模型参数 |
| `data_sources[].source` | 数据来源，空字符串视为未标注 |
| `risks` | 已识别的风险条数 |

脚本输出：章节完整率、必答题回答率、三条财务勾稽校验结果、单位经济指标（LTV/CAC、回本周期、毛利率）与 LTV/CAC 判定、数据来源标注率、风险披露条数，以及整改建议。

> 脚本只做结构与算术核查，**不判断商业计划的可信度，也不预测融资结果**。

## 十、人工确认清单（这步不能省）

- [ ] 六大模块 + 团队 + 融资共八部分齐全
- [ ] 每章的必答问题已逐条回答，未答的已写明原因
- [ ] 模块之间的因果链已逐环检查
- [ ] TAM / SAM / SOM 三层口径清晰，未混用
- [ ] 市场同时给了自上而下与自下而上两套测算，差异有解释
- [ ] 每个外部数据都标了来源与时点
- [ ] 单位经济模型已算，且 CAC 算法写清
- [ ] 收入预测已拆成「用户数 × 付费率 × 客单价」，每项有增长依据
- [ ] 三年财务表三条勾稽关系全部核通
- [ ] 融资额按「月净消耗 × 月数 × 安全系数」推导，用途有比例
- [ ] 已如实披露主要风险（不少于 3 条）与应对
- [ ] 用户个人信息、未公开数据已从 BP 中移除
- [ ] 涉及披露义务的内容已请专业机构审核

## 十一、最常见的坑

**坑一：BP 写成了产品说明书。**
错误做法：通篇讲产品功能和技术架构。正确做法：六个模块各回答一个问题，产品只是方案模块的一部分。**投资人不关心你的技术栈，关心这门生意能不能赚钱。**

**坑二：市场规模引用来路不明的大数字。**
错误做法：「据权威数据显示，市场前景广阔」。正确做法：写清来源、时点、口径，并给自上而下与自下而上两套测算。**没有来源的数字等于没写，一追问就穿。**

**坑三：TAM 直接当 SOM 用。**
错误做法：把整个行业规模当作自己三年能拿到的市场。正确做法：TAM → SAM（可触达比例）→ SOM（保守份额）。**投资人对「你三年内实际能拿多少」更感兴趣。**

**坑四：收入预测从 1000 万跳到 8000 万。**
错误做法：只给总数，不给拆解。正确做法：拆成用户数 × 付费率 × 客单价，每项都有增长依据。**数字跳得太快但没有路径，是 BP 里最常见的致命伤。**

**坑五：CAC 只算投放费用。**
错误做法：「投放花了 200 万，带来 1000 个用户，CAC 是 2000」。正确做法：CAC 要含销售人力、工具、佣金分摊。**只算投放费用的 CAC 会显著偏低，回本周期算出来也不可信。**

**坑六：财务表勾稽不上。**
错误做法：毛利数字跟收入减成本对不上，经营利润跟费用加总对不上。正确做法：写完先核三条勾稽关系（毛利、经营利润、期末现金）。**会计师一眼就能看出勾稽不上。**

**坑七：融资额拍脑袋。**
错误做法：「我们打算融资 3000 万」。正确做法：按「月净消耗 × 到下个里程碑所需月数 × 安全系数」推导，并写明用途比例。**融资额和里程碑对不上，说明创始人自己没算清要多久。**

**坑八：竞品分析靠贬低对手。**
错误做法：竞品都是老古董、体验差、市占率低。正确做法：客观写对手强项与弱项，写清自己在哪一维领先、壁垒是什么。**只贬低对手会让人怀疑你不了解市场。**

**坑九：说「没有风险」。**
错误做法：BP 里只讲机会。正确做法：列 3 条真实风险 + 应对方案。**说没有风险的人，通常是没想清楚。**

**坑十：团队部分缺失或只讲履历。**
错误做法：BP 里根本没有团队模块。正确做法：说明过往是否做过同类事、结果如何、关键人离职怎么办。**同品类的项目，团队往往比产品更能决定能不能做成。**
