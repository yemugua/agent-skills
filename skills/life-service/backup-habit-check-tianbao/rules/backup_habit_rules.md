# 数据备份核查规则库

> 做核查、出检查表、写交接清单之前，先读这份文件，不要凭印象写。

---

## 一、3-2-1 逐项核查表

| 要素 | 达标口径 | 不达标典型 |
|---|---|---|
| 3 份副本 | 原始 + 两份独立副本 | 只有两份，或第二份是同步 |
| 2 种介质 | 副本在不同物理设备或不同服务 | 同一台电脑的两个目录 |
| 1 份异地 | 至少一份不在同地、不同账号体系 | 全在家里，或全在同一账号 |

**计数要点**：同一设备上的多个目录只算一份；同一账号下的本地目录与云端，要看账号本身失效时的风险。

---

## 二、备份方式对比表

| 方式 | 自动性 | 异地性 | 多版本 | 局限 |
|---|---|---|---|---|
| 云盘 | 高 | 是 | 取决于版本保留设置 | 受配额影响 |
| 移动硬盘 | 低，需手动触发 | 否，需另备一份 | 否 | 未跑完等于没备 |
| NAS | 高 | 否，需异地同步 | 可配置 | 配置门槛较高 |
| 电脑自动备份 | 高 | 否 | 取决于保留设置 | 只覆盖本机 |

**选型顺序建议**：先把重要小文件放进云盘，再把大体量归档到移动硬盘并定期跑，最后再考虑是否需要 NAS。

---

## 三、假备份坑清单（逐条对照）

| 坑 | 判断方法 |
|---|---|
| 同步当备份 | 在回收站里找另一个时间点的版本 |
| 没开自动备份 | 看设置是否为自动触发 |
| 同步未完成 | 看完成状态、文件数与大小是否一致 |
| 历史版本被覆盖 | 看版本保留天数 |
| 备份同设备 | 检查物理设备是否相同 |
| 同账号体系 | 检查账号与平台是否相同 |
| 从未恢复演练 | 见演练方案 |
| 被清理规则删掉 | 检查清理规则是否覆盖备份目录 |

---

## 四、恢复演练方案（最小可行版）

| 步骤 | 动作 | 合格标准 |
|---|---|---|
| 1 | 随机挑 5-10 个重要文件 | 不挑最好打开的 |
| 2 | 取回到另一个目录 | 不覆盖原文件 |
| 3 | 逐个打开 | 图片可显示、文档可编辑、视频可播放、压缩包可解压 |
| 4 | 比对大小与时间 | 对得上 |
| 5 | 记录结果 | 有成功/失败计数 |

**节奏**：重要数据至少每季度一次。**判定**：演练失败即视为备份不成立，先修再谈备份完成。

## 六、加密与口令管理

| 规则 | 说明 |
|---|---|
| 应加密的数据 | 证件、合同、财务、医疗、他人隐私 |
| 口令存放 | 与数据分开存放，至少两处 |
| 口径失效的情况 | 口令与数据在同一设备或同一云账号 |
| 人员变动 | 离职或换机时确认谁持有口令 |

---

## 七、离职 / 换机数据交接清单

| 项目 | 要点 |
|---|---|
| 在职产出文件 | 交到团队位置，不留在个人电脑 |
| 账号与权限 | 该移交的移交，该注销的注销 |
| 设备个人数据 | 清空前先备份 |
| 外接介质 | 逐个清点 |
| 合作方资料 | 按合同与保密要求处理 |

**否定项提醒**：「交上去了」不等于「存好了」，交接完成后仍要确认备份状态。

---

## 八、优先级排序规则

额度有限时按下列顺序补齐：

1. 不可再生资料（证件、合同、记录）
2. 家庭影像（孩子成长记录）
3. 工作产出与项目资料
4. 大体量影音归档
