# 数据备份习惯与有效性核查（backup-habit-check）

「我备份了」和「我能恢复回来」之间，隔着一次没做过的恢复演练。**这个技能的重点不是教你多备份，而是帮你确认备份真的有效。**

这个技能做四件事：**列数据** → **按 3-2-1 核对** → **排假备份坑** → **做演练**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按 3-2-1 逐项核对现状 | ❌ 代替用户访问、读取或传输其数据 |
| 对比不同备份方式的适用范围 | ❌ 保证任何方式都能恢复全部数据 |
| 识别「以为在备份其实没备上」的坑 | ❌ 修改用户的账号密码或安全相关设置 |
| 给出恢复演练方案 | ❌ 推荐具体商业产品或给出价格判断 |
| 提供备份检查表与交接清单模板 | ❌ 处理加密、涉密或受监管的数据 |

**遇到以下情况，先停下来说清楚：**

- 数据涉及他人隐私、公司核心资产或受合同与监管约束
- 备份介质已经损坏，或加密口令已经遗失
- 需要在涉密环境或单位统一策略之外自行处理
- 需要解密他人数据

## 二、完整工作流

```
第 1 步  列数据清单：哪些东西丢了会真的难受
第 2 步  盘现状：现在有几份副本、分别在什么介质、异地了吗
第 3 步  先读规则文件 rules/backup_habit_rules.md（3-2-1 逐项表 + 假备份坑 + 方式对比）
第 4 步  跑核查脚本，输出逐项判定与缺口
    python scripts/backup_321_audit.py --file backup.json --out 核查结论.md
第 5 步  补齐缺口：先补最要命的那一类数据，不是先买设备
第 6 步  做一次真恢复演练（见第六步），把文件真的取回来打开
第 7 步  设定期复查节奏，写成检查表
```

## 三、3-2-1 原则（照着数，别估）

| 要素 | 要求 | 常见不符 |
|---|---|---|
| **3 份副本** | 原始数据算一份，另有两份副本 | 只有两份，其中一份还是同步的 |
| **2 种介质** | 不能都放在同一台设备或同一个服务上 | 电脑 + 同一账号的另一个目录 |
| **1 份异地** | 至少一份不在同一地点、不在同一账号体系 | 全在家里，失窃或火灾一起没 |

**计数要点**：同一台电脑上的两个文件夹**只算一份**；同一账号下的「本地 + 云端」是否安全，要看账号本身失效时的风险。

**重要数据优先原则**：先补证件、合同、孩子照片、财务记录这几类，再考虑体积大的影音。备份额度有限时，**优先级比完整性更重要**。

## 四、备份方式对比

| 方式 | 优点 | 局限 | 适合 |
|---|---|---|---|
| 云盘 | 自动、异地、可保留多版本 | 受配额与同步策略影响，删除同步即消失 | 照片、文档、小体量关键数据 |
| 移动硬盘 | 大容量、可离线、成本可控 | **必须真的插上并跑完**，否则等于没备 | 大体量、归档类数据 |
| NAS | 自动、可做多版本、可被多设备访问 | 初始配置门槛高，单点故障要靠两块盘 | 家庭与小团队的高频变动数据 |
| 电脑自动备份 | 无感、按版本保留 | 只覆盖本机，换机前要确认已导出 | 工作文档 |

**关键提醒**：移动硬盘的备份只在「跑完」之后才算。**同步没完成就拔盘、断网关机，等于备了个空。**

---

## 五、假备份坑（逐条对照，这是本技能的核心）

| 坑 | 表现 | 怎么确认 |
|---|---|---|
| 同步当备份 | 云盘删了，本地也跟着没了 | 在回收站里找**另一个时间点**的版本 |
| 备份软件没开自动备份 | 平时看着在跑，其实是一次性复制 | 看设置里是不是「每次/每天自动」 |
| 同步没完成就拔盘 | 目录看着在变，其实断了 | 看是否显示完成状态，文件数与大小是否一致 |
| 历史版本被覆盖 | 同步机制把旧版本清理掉了 | 看是否开启版本保留、保留多少天 |
| 备份放在同一台设备上 | 设备坏了，备份一起没 | 检查副本是否在不同物理设备上 |
| 备份在同一账号体系 | 账号出问题导致全部不可用 | 检查是否跨账号、跨平台 |
| 备份了但没试过恢复 | 从没打开过备份里的文件 | 见第六步，做一次真演练 |
| 备份目录被清理规则扫掉 | 脚本或清理软件把备份当垃圾删 | 检查清理规则是否覆盖备份目录 |

**否定项提醒**：「备份任务显示成功」只说明任务跑完了，**不说明数据完整、能打开**。

---

## 六、恢复演练（比备份本身更重要）

**为什么更重要**：备份是一个没被验证过的承诺。硬盘会坏、文件会损坏、账号会失效、格式可能不认。**只有真的取回来一次，才知道这份备份值不值钱。**

**最小可行演练步骤：**

1. 随机挑 5-10 个重要文件（**不要挑最好打开的那几个**）
2. 从备份里取回到**另一个目录**，不要覆盖原文件
3. 逐个打开：图片能显示、文档能编辑、视频能播放、压缩包能解压
4. 比对文件大小与修改时间是否对得上
5. 记录结果：几个成功、几个失败

**多久做一次**：重要数据至少每季度一次。全年不做演练，等于没有备份。

**演练失败的常见原因**：备份不完整、文件被后续版本覆盖、格式不兼容、介质本身已损坏、根本没备到这一类数据。

---

## 七、备份加密与交接

**加密要不要做**：涉及身份证件、合同、财务、医疗与他人隐私的数据应当加密。加密后**口令必须另存在与数据不同的地方**，否则等于把数据锁死。

**离职 / 换机的数据交接清单：**

| 项目 | 要点 |
|---|---|
| 在职期间的产出文件 | 交接到团队位置，不是留在个人电脑 |
| 账号与权限 | 该移交的移交，该注销的注销 |
| 设备上的个人数据 | 清空前先备份，确认工作数据已剥离 |
| 外接硬盘与介质 | 逐个清点，别把别人的东西带走 |
| 客户或合作方资料 | 按合同与保密要求处理 |

**提醒**：交接不等于备份，别以为「交上去了」就等于存好了。

## 八、脚本用法

```bash
python scripts/backup_321_audit.py --file backup.json --out 核查结论.md
python scripts/backup_321_audit.py --text "copies=2;media=1;offsite=no;auto=no;tested=no"
python scripts/backup_321_audit.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 备份现状 JSON（自动兼容带 BOM 的文件） |
| `--text` | 直接写现状，用分号分隔 `键=值` |
| `--out` | 结果落盘路径 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

JSON 字段：`copies`（副本数）、`media`（介质种类数或列表）、`offsite`（是否有异地）、`auto`（是否自动）、`tested`（是否演练过）、`encrypted`（是否加密）。

脚本逐项输出 3-2-1 判定，缺口按严重度排序，并给出补齐顺序建议。

> 脚本只做规则判定，**不接触用户数据**。输入必须由用户自己填写。

## 九、人工确认清单（这步不能省）

- [ ] 列出了「丢了会真的难受」的数据清单
- [ ] 副本数、介质种类、异地三项分别数过，不是估的
- [ ] 确认过备份不是「同步当备份」
- [ ] 确认过备份软件确实开了自动备份
- [ ] 确认过备份不在同一台设备、同一个账号体系里
- [ ] 检查过历史版本保留设置
- [ ] 检查过定期清理规则不会扫到备份目录
- [ ] 做了一次真恢复演练，文件真的取回来打开过
- [ ] 加密数据的口令另存在与数据不同的地方
- [ ] 设定了下次演练时间

## 十、最常见的坑

**坑一：把同步当备份。**
同步是镜像，云端删了本地一起没。备份要有独立时间点，能取回旧版本。

**坑二：移动硬盘当摆设。**
插上没跑完就拔，等于没备。必须确认任务状态是完成。

**坑三：备份软件设成手动。**
默认「不自动备份」比想象中常见，很多人以为它一直在跑。

**坑四：备份放同一台电脑的两个文件夹。**
设备坏了全没，这不算两份副本。

**坑五：历史版本被自动清理覆盖。**
同步客户端按保留天数清理旧版本，真出事时能取回的只有最近一个点。

**坑六：从没试过恢复。**
备份是承诺，不是结果。不演练就不知道能不能用。

**坑七：备份被清理软件当成垃圾删掉。**
定期清理脚本连备份目录一起扫，事后才发现。

**坑八：备份和加密口令放一起。**
加密的意义就没了，数据等于被锁死。

**坑九：只备大文件，不备小文件。**
合同、证件、记录这类小文件最容易漏，却最要紧。

**坑十：换机时只带走数据没交接账号。**
数据在、账号没，工作衔接不上。

## 十一、边界与免责

- 本技能**只做核查与方案设计**，不代用户访问、读取或传输任何数据
- 不涉及他人隐私、公司核心资产或受监管约束数据的处理
- 加密与解密操作由用户自行完成，本技能不提供破解
- 备份介质的选择、容量与投入规模由用户根据实际情况决定，本技能不做产品推荐与价格判断
- 演练结果只反映当时状态，恢复能力会随版本更新与介质老化变化
