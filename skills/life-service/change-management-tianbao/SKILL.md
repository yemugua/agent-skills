# 变更管理（4M 变更）（change-management）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 IATF 16949 与变更管理要求，生成清单：变更类型识别（人/机/料/法/环）、变更申请与评审、验证确认与批准、客户通知与 PPAP 再提交、变更点记录与追溯。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 变更管理
- 4M变更
- 工程变更
- 变更评审
- 变更通知

## 三、工作流
1. 识别变更类型（人/机/料/法/环）
2. 提交变更申请并评审
3. 开展验证确认并批准
4. 必要时通知客户并再提交PPAP
5. 记录变更点并保持追溯

## 四、核心内容（检查清单与判定）
人、机、料、法、环任一变化都可能影响质量；变更须评审、验证并批准，影响顾客特性时要通知并重新提交，变更点须留痕可追溯。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含变更类型识别 | 类型 |
| Q2 | FAIL | 未含变更申请与评审 | 评审 |
| Q3 | WARN | 未含验证确认与批准 | 验证 |
| Q4 | FAIL | 未含客户通知与再提交 | 通知 |
| Q5 | WARN | 未含变更点记录与追溯 | 记录 |

> 脚本 `change-management_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python change-management_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python change-management_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
