# 应急预案编制（emergency-plan-preparation）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据《生产安全事故应急预案管理办法》与 GB/T 29639，生成清单：风险评估与应急资源调查、预案体系（综合/专项/现场处置）、组织职责与响应程序、评审备案、演练与动态修订。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 应急预案
- 应急预案编制
- 综合应急预案
- 专项应急预案
- 现场处置方案

## 三、工作流
1. 开展风险评估与应急资源调查
2. 构建预案体系（综合/专项/现场处置）
3. 明确组织职责与响应程序
4. 组织评审并备案
5. 定期演练并动态修订

## 四、核心内容（检查清单与判定）
应急预案须以风险评估与资源调查为基础，形成综合、专项与现场处置方案体系，评审备案后定期演练并动态修订。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含风险评估与资源调查 | 评估 |
| Q2 | FAIL | 未含预案体系（综合/专项/现场处置） | 体系 |
| Q3 | WARN | 未含组织职责与响应程序 | 职责 |
| Q4 | FAIL | 未含评审与备案 | 备案 |
| Q5 | WARN | 未含演练与动态修订 | 演练 |

> 脚本 `emergency-plan-preparation_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python emergency-plan-preparation_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python emergency-plan-preparation_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
