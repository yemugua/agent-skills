# 批记录审核与产品放行（batch-release-review）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 GB/T 19001 与 GMP 放行控制思路，生成清单：批记录完整性与签名留痕、关键参数符合性、偏差与变更闭合、检验结果合格性、放行授权与时限。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 批记录审核
- 批放行
- 产品放行审核
- 批数据完整性
- 放行授权

## 三、工作流
1. 核查批记录完整性与签名留痕
2. 核对关键参数符合性
3. 核查偏差与变更已闭合
4. 确认检验结果合格
5. 执行放行授权并控制时限

## 四、核心内容（检查清单与判定）
批放行是最后一道闸口，任何未闭合的偏差、未解释的异常数据或缺失签名都应阻止放行；放行授权人须经书面任命且权限明确。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含批记录完整性与签名留痕 | 完整性 |
| Q2 | FAIL | 未含关键参数符合性核对 | 参数 |
| Q3 | FAIL | 未含偏差与变更闭合核查 | 偏差 |
| Q4 | FAIL | 未含检验结果合格确认 | 检验 |
| Q5 | WARN | 未含放行授权与时限控制 | 授权 |

> 脚本 `batch-release-review_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python batch-release-review_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python batch-release-review_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
