# 手机存储清理与空间核查（phone-storage-cleanup）

空间满了不要一上来就清缓存。**先分清是谁吃掉了空间，再决定清哪一类。** 缓存清了马上又涨回来，说明问题根本不在缓存。

这个技能做四件事：**分类** → **定风险** → **选动作** → **复查**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按占用类别给出清理方案与风险等级 | ❌ 承诺清完能恢复多少空间 |
| 标出删除后无法找回的项目 | ❌ 建议清理系统核心文件或未知目录 |
| 说明各类占用的清理顺序 | ❌ 指导绕过系统保护或卸载预装应用 |
| 给出清理前的备份要求 | ❌ 代用户在设备上执行任何删除 |
| 说明给老人孩子清理的边界 | ❌ 修改设备的安全与定位相关设置 |

**出现以下情况，先停下来说清楚：**

- 占用列表里出现看不懂的目录名，或体积异常大的分区
- 手机频繁死机、重启、存储提示时好时坏（可能是硬件或系统问题）
- 重要数据（证件、合同、孩子照片）尚未备份就打算清理
- 读写本身异常（读写速度忽快忽慢、文件校验对不上）

| 用户这样说 | 就用 |
|---|---|
| "手机空间满了 / 存储不足" | ✅ |
| "手机变卡、发热、更新失败" | ✅ |
| "其他占用怎么这么大" | ✅ |
| "该清缓存还是删文件" | ✅ |
| "删了照片能找回来吗" | ✅ |
| "微信聊天记录能不能删" | ✅ |
| "给爸妈的手机清理要注意什么" | ✅ |
| "手机突然死机重启" | ❌ 先排查硬件与电池 |
| "想把手机格式化" | ❌ 必须先确认备份到位 |

## 二、完整工作流

```
第 1 步  先看系统自带的存储分析，读出各类别占用（不要凭印象删）
第 2 步  分类归档：照片视频 / 应用本体 / 应用缓存 / 聊天记录 / 下载目录 / 系统文件
第 3 步  先读规则文件 rules/phone_storage_rules.md（分类表 + 风险等级 + 红标项）
第 4 步  跑占用诊断脚本，按体积排序并标出不可恢复项
    python scripts/phone_storage_audit.py --file usage.json --out 清理方案.md
第 5 步  补齐备份（重要项必须先备份再清）
第 6 步  按风险从低到高执行：先清缓存，再清下载目录，最后才动聊天记录和照片
第 7 步  复查：隔两天再看一次，增长快的类别才是真问题
```

## 三、占用分类（清理前必须先分类）

| 类别 | 典型来源 | 清理风险 | 关键提示 |
|---|---|---|---|
| 应用缓存 | 社交、短视频、浏览器 | 低 | 可再生成，清了会重新下载 |
| 应用本体 | 已不用的 App | 低 | 卸载可再装，但应用数据会一起丢 |
| 下载目录 | 安装包、收到的文件、离线视频 | 低 | 确认没用的再删 |
| 系统日志与临时文件 | 系统自身 | 低 | 一般会自行清理 |
| 聊天记录（文字） | 微信、QQ | **中** | 可选清空，但很多选项会连媒体一起删 |
| 聊天记录（媒体） | 群里的图片、视频、文件 | **中** | 比文字更占空间，多数不可恢复 |
| 照片视频 | 相机、其他 App 保存 | **高** | 误删后很多机型无法从回收站恢复 |
| 应用数据 | 游戏存档、笔记、文档 | **高** | 删除会丢内容 |
| 系统核心文件 | 系统分区 | ❌ 不清 | 不要动 |

**关键提醒**：「其他」是个筐，里面什么都有。**没看清里面是什么之前，不要整类清空。**

---

## 四、不可恢复项（必须先备份再动）

以下操作删除后通常无法找回，**先确认已备份**：

- 相机胶卷里的照片和视频
- 聊天软件里的图片、视频、语音、文件
- 备忘录、录音机、文档 App 里的内容
- 游戏存档与进度
- 通讯录、短信（部分系统删除后不可恢复）
- 下载目录里别人发来但没备份的文件

系统回收站通常只保留几天，且部分机型根本不留。**备份没做就清，等于赌。**

---

## 五、空间不足引发的系统异常

| 现象 | 是否可能由空间不足引起 |
|---|---|
| 相机无法拍照、提示存储不足 | ✅ 直接相关 |
| 系统更新失败或反复卡在安装 | ✅ 直接相关 |
| 应用频繁闪退 | ✅ 可能相关 |
| 手机变卡、发烫 | ⚠️ 可能相关，也可能是电池老化或系统版本 |
| 应用找不到、图标消失 | ⚠️ 可能与安装不完整有关 |
| 通知不推送 | ⚠️ 可能是后台被系统清理 |
| 反复自动重启、死机 | ❌ 多数不是空间问题 |

**不要把死机、重启一律归因于空间不足。** 反复死机更多是电池、系统版本或硬件问题，清理空间不解决，误判会耽误真正的排查方向。

---

## 六、清理顺序（风险从低到高）

```
1. 应用缓存        风险最低，可放心清
2. 下载目录        确认没用的安装包、离线视频
3. 不再使用的 App  卸载前确认账号数据不在里面
4. 聊天记录媒体    先备份，再按会话或按年份清理
5. 照片视频        必须先备份到外部或云端
6. 应用数据        谨慎，逐个确认内容
```

**每清一类，隔一天再看占用变化。** 清完立刻涨回来的，说明它会自动重新生成，不是真问题。

---

## 七、给老人孩子清理的操作边界

| 不可做 | 原因 |
|---|---|
| 动他们的通讯录、照片、常用 App | 误删后他们找不到也不会自己恢复 |
| 清理正在进行的聊天 | 可能涉及需要留存的内容 |
| 动系统安全、定位、支付相关设置 | 风险高，且他们无法察觉异常 |
| 代替他们做账号密码相关操作 | 涉及支付与账号安全 |
| 不告知就批量删除 | 事后无法弥补 |

| 应当做 | 原因 |
|---|---|
| 清理前先把占用报告给对方看 | 知情是前提 |
| 大批量操作前先做一次备份 | 老人很少自己留副本 |
| 一次只清一类，便于确认 | 出问题好定位 |

## 八、脚本用法

```bash
python scripts/phone_storage_audit.py --file usage.json --out 清理方案.md
python scripts/phone_storage_audit.py --text "wechat:20G photo:30G other:12G"
python scripts/phone_storage_audit.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 占用数据 JSON（自动兼容带 BOM 的文件） |
| `--text` | 直接写类别与体积，用空格分隔，如 `photo:30G cache:2G` |
| `--total` | 设备总容量（GB），用于算占比 |
| `--out` | 结果落盘路径 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本按体积排序，输出**每一类的可清理比例、风险等级、是否需要先备份、清理后是否会长回来**，并把「其他」这类不明类别单独标记为「先看清再动」。

> 脚本只做分类与排序，**不读取设备数据**。输入必须由用户自己从系统设置里读出后提供。

## 九、人工确认清单（这步不能省）

- [ ] 读过系统自带的存储分析，不是凭印象
- [ ] 每一类占用都归了档，知道谁最大
- [ ] 重要照片、聊天记录、文档已确认备份
- [ ] 清楚哪些操作删除后无法找回
- [ ] 「其他」这一类已看清内容，而不是整类清空
- [ ] 按风险从低到高执行，没有一上来就删聊天记录
- [ ] 清理后隔天复查，看哪一类又长回来了
- [ ] 给老人孩子清理时，对方已知情

## 十、最常见的坑

**坑一：一上来清全部缓存。**
缓存清了马上又生成，等于什么都没做，还把登录状态和离线内容清掉了。

**坑二：把「其他」整类清空。**
「其他」是个筐，里面可能混着重要文件。先打开看是什么，再决定删哪几项。

**坑三：以为删聊天记录只删文字。**
很多清理选项会连同图片、视频、文件一起删，且多数不可恢复。

**坑四：没备份就删照片。**
系统回收站通常只留几天，部分机型不留。先备份，再删本地。

**坑五：把卡顿死机都算到空间头上。**
反复死机更多与电池、系统版本或硬件有关，清理空间不解决，误判会耽误真正的排查。

**坑六：删了不用的 App 就完事。**
很多 App 的账号数据、笔记、游戏进度在卸载后一起丢失，卸载前要确认。

**坑七：清完不复查。**
不看过几天占用怎么变，就不知道哪一类是真正持续增长的。

**坑八：给老人手机批量删文件不告知。**
他们不会自己恢复，也说不清哪些重要，事后很难补。

**坑九：把系统分区当清理对象。**
系统核心文件不要动，清不动还可能出问题。

**坑十：以为清理能延长手机寿命。**
存储空间与电池老化是两回事，该换电池还是得换。

## 十一、边界与免责

- 本技能**只做占用分析与清理指引**，不代用户在设备上执行任何操作
- 各品牌系统的存储分析与清理入口位置不同，**以设备自带说明为准**
- 数据备份责任在使用者本人，本技能不代为备份
- 清理前若出现反复死机、重启或读写异常，应先按硬件问题排查，不要靠清空间试
- 涉及他人设备时，须取得设备使用者知情同意
