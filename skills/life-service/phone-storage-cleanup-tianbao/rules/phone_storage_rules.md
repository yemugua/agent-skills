# 手机存储占用与清理规则库

> 生成清理方案、给别人写操作指引之前，先读这份文件，不要凭印象写。

---

## 一、占用分类表（含风险等级）

| 类别 | 典型来源 | 可清理比例（经验） | 风险 | 清完会不会涨回来 |
|---|---|---|---|---|
| 应用缓存 | 社交、短视频、浏览器 | 大部分 | 低 | 会 |
| 应用本体 | 已不用的 App | 全部 | 低 | 不会 |
| 下载目录 | 安装包、收到的文件、离线视频 | 大部分 | 低 | 不会 |
| 系统日志与临时文件 | 系统自身 | 大部分 | 低 | 会 |
| 聊天记录（文字） | 微信、QQ | 全部 | 中 | 不会 |
| 聊天记录（媒体） | 群里的图片视频 | 大部分 | 中 | 会（继续聊天又涨） |
| 照片视频 | 相机、其他 App 保存 | 大部分 | 高 | 会（继续拍又涨） |
| 应用数据 | 游戏存档、笔记、文档 | 按项 | 高 | 不会 |
| 系统核心文件 | 系统分区 | 不清 | — | — |

**可清理比例为经验值，实际以设备读数为准。**

---

## 二、不可恢复项清单（先备份再动）

| 项目 | 备注 |
|---|---|
| 相机胶卷里的照片与视频 | 部分机型有回收站，但通常只留几天 |
| 聊天记录里的图片、视频、语音、文件 | 比文字更占空间，多数不可恢复 |
| 备忘录、录音机、文档 App 内容 | 同上 |
| 游戏存档与进度 | 很多游戏卸载即丢 |
| 通讯录 | 部分系统删除后不可恢复 |
| 下载目录里别人发来的文件 | 没有第二份 |
| 应用内登录状态 | 清理应用数据会掉登录 |

**否定项提醒**：「先删着试试」不是可接受的方案，不可恢复项没有补救路径。

---

## 三、「其他」这一类的处理规则

| 步骤 | 动作 |
|---|---|
| 1 | 先打开看具体条目，不要整类清空 |
| 2 | 判断是否属于应用残留、下载文件、系统临时目录 |
| 3 | 只删能明确判断用途的条目 |
| 4 | 删完观察几天，看是否重新出现 |

**风险**：未知来源的大体积目录可能是某个应用正在使用的数据，整类清掉可能让应用异常或丢数据。

## 四、空间不足引发的系统异常对照

| 现象 | 与空间不足的关系 |
|---|---|
| 相机无法拍照、提示存储不足 | 直接相关 |
| 系统更新失败或卡在安装 | 直接相关 |
| 应用频繁闪退 | 可能相关 |
| 手机变卡、发烫 | 可能相关，也可能与电池或系统版本有关 |
| 应用找不到、图标消失 | 可能与安装不完整有关 |
| 通知不推送 | 可能与后台被清理有关 |
| 反复自动重启、死机 | **通常无关**，优先排查电池、系统版本、硬件 |

**判定原则**：能直接解释「装不下」的算直接相关；「变卡」「死机」属多因症状，不能直接归因。

## 五、清理执行顺序（风险从低到高）

| 顺序 | 类别 | 执行前置条件 |
|---|---|---|
| 1 | 应用缓存 | 无 |
| 2 | 下载目录 | 确认无未备份的重要文件 |
| 3 | 不再使用的 App | 确认账号数据与进度可接受丢失 |
| 4 | 聊天记录媒体 | 已备份 |
| 5 | 照片视频 | 已备份到外部或云端 |
| 6 | 应用数据 | 逐项确认内容 |

**每清一类，隔一天再观察**，看是否重新增长。持续增长的类别才是真正需要长期管理的对象。

---

## 六、给老人孩子清理的操作边界

| 不可做 | 原因 |
|---|---|
| 删通讯录、照片、常用 App | 误删后他们无法自行恢复 |
| 清正在进行的聊天 | 可能涉及需要留存的内容 |
| 改系统安全、定位、支付设置 | 风险高且他们无法察觉 |
| 代替做账号与密码操作 | 涉及支付与账号安全 |
| 不告知就批量删除 | 事后无法弥补 |

| 应当做 | 原因 |
|---|---|
| 先出占用报告并让其知情 | 知情是前提 |
| 大批量操作前先备份 | 老人很少自己留副本 |
| 一次只清一类，便于确认 | 出问题好定位 |

## 八、常见误判清单

| 说法 | 是否成立 |
|---|---|
| 清缓存能让手机变快 | 部分成立，仅在缓存确实异常时 |
| 清理能延长手机寿命 | 不成立，属电池与硬件问题 |
| 死机就是空间不足 | 不成立，要排查其他方向 |
| 删聊天记录只删文字 | 不成立，多数会连媒体一起删 |
| 系统文件可以清理 | 不成立，不应清理 |
| 「其他」可以整类清空 | 不成立，需先看清内容 |
