# 管理评审组织与报告（qms-management-review）

管理评审是体系的"年终体检+战略会"：**输入材料七拼八凑、会议开成汇报会、决议没人跟踪**，评审就白开。

这个技能做四件事：**备输入** → **开好会** → **写报告** → **跟决议**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 讲解评审组织方法与材料准备 | ❌ 替代最高管理者的管理决策 |
| 生成输入材料清单与报告模板 | ❌ 保证决议落实 |
| 整理评审输出与跟踪口径 | ❌ 出具认证结论 |

**永远不要**把管理评审开成"念材料会"——没有数据、没有比较、没有决策的评审，不如不开。

---

## 一、什么时候用这个技能

| 用户这样说 | 就用 |
|---|---|
| "管理评审要准备什么" | ✅ |
| "评审输入材料有哪些" | ✅ |
| "评审报告怎么写" | ✅ |
| "评审决议怎么跟踪" | ✅ |
| "管理评审多久开一次" | ✅ |
| "评审就是走个形式" | ❌ 输入不实则决策无据 |

## 二、完整工作流

```
第 1 步  明确场景：年度评审准备 / 材料编制 / 会议组织 / 报告撰写 / 决议跟踪
第 2 步  读规则文件 rules/review_rules.md
第 3 步  按场景取用：
    - 备输入 → 输入清单（第三节）
    - 开好会 → 会议流程（第四节）
    - 写报告 → 报告要素（第五节）
    - 跟决议 → 跟踪机制（第六节）
第 4 步  按 templates/管理评审报告.md 输出
第 5 步  人工确认：数据真实性、决议可执行性
```

---

## 三、评审输入清单（九项）

1. **内审结果**——方案执行、不符合分布、整改闭环情况
2. **顾客反馈**——满意度、投诉、交付表现
3. **过程绩效与产品符合性**——质量目标达成、一次合格率、准时交付率
4. **不符合与纠正措施**——趋势分析、重复发生的问题
5. **监视测量结果**——关键指标趋势（同比/环比）
6. **供方绩效**——来料质量、交付、服务
7. **变更与风险**——内外部环境变化、重大变更、风险机遇应对
8. **改进机会**——创新提案、标杆对比
9. **资源需求**——人员、设备、资金缺口

> 输入材料的要求：**有数据、有趋势、有比较**；只有文字没有数字的材料退回重做。

---

## 四、会议组织流程

1. **会前 2 周**：发出议程与材料包，预审数据
2. **会议议程**：体系运行总评 → 逐项输入汇报（数据先行）→ 专题讨论 → 决议
3. **主持**：最高管理者主持并做决策；管理者代表汇报体系运行
4. **决议要求**：可执行、有责任人、有期限、可验证
5. **记录**：签到、发言要点、决议逐条记录

---

## 五、评审报告要素

- 评审目的、时间、地点、参加人
- 输入材料逐项评述（含数据摘要）
- 体系适宜性/充分性/有效性结论
- 质量目标达成与调整
- 改进机会、变更需求、资源需求（**输出三件套**）
- 决议清单（措施、责任部门、完成期限）
- 上次评审决议落实情况回顾

---

## 六、决议跟踪机制

```
决议 → 责任人 → 完成期限 → 证据 → 管理者代表验证 → 下次评审回顾
```

- 决议完成率纳入下年度管理评审输入
- 跨年未完成的决议要有原因说明和调整
- 决议与内审不符合整改、改进项目打通管理

---

## 七、人工确认（这步不能省）

- [ ] 输入数据是否真实、口径是否一致
- [ ] 顾客反馈是否来自多渠道而非单一渠道
- [ ] 质量目标是否 SMART、是否随战略调整
- [ ] 决议是否可执行、有资源保障
- [ ] 上次评审决议是否先回顾再开新会

---

## 八、输出结构（固定三段）

1. **体系什么状态**——结论先行：有效运行 / 有缺口 / 有系统性风险
2. **决议清单**——逐条可跟踪
3. **跟踪安排**——责任人、期限、验证方式

---

## 九、最常见的坑

**坑一：输入材料凑数。** 各部门交上来的都是"正常"两个字。

**坑二：会议开成汇报会。** 每人念一遍 PPT，最高管理者只听不决策。

**坑三：决议没有责任人。** "加强培训""提高意识"——谁都负责等于没人负责。

**坑四：只开年会。** 一年一次评审，平时的问题堆到年底一次性爆。

**坑五：上次决议没人回顾。** 同样的问题连续三年出现在评审报告里。
