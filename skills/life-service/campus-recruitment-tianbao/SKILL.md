# 校园招聘组织（campus-recruitment）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：生成校园招聘全流程组织方案：目标院校与专业、宣讲会、笔试面试、录用与offer管理、雇主品牌与转化追踪。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 校园招聘
- 校招
- 应届生招聘
- 宣讲会
- 管培生
- 校招行程

## 三、工作流
1. 锁定目标院校/专业与人数需求
2. 制定行程与宣讲物料
3. 笔试/群面/终面设计
4. 录用决策与offer发放
5. 入职转化与雇主品牌复盘

## 四、核心内容（检查清单与判定）
校招周期性强（秋招/春招），需提前锁定院校与HC；关注录用转化率与入职留存，管培生应配套轮岗与发展计划。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未锁院校/专业与需求人数 | 规划 |
| Q2 | WARN | 无宣讲/行程与物料 | 宣讲 |
| Q3 | FAIL | 笔面流程未设计 | 筛选 |
| Q4 | WARN | 无录用与offer管理 | 录用 |
| Q5 | WARN | 缺转化追踪/雇主品牌 | 复盘 |

> 脚本 `campus-recruitment_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python campus-recruitment_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python campus-recruitment_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
