# 消防应急预案演练策划与评估（fire-emergency-drill）

演练不是"演"给检查看，是把预案从纸上练成手上的动作。**频次是底线、方案是骨架、评估是灵魂、整改是闭环**——四样缺一样，演练就白搞。

这个技能做四件事：**定频次** → **编方案** → **做评估** → **抓整改**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 讲解演练法规要求与策划方法 | ❌ 替代单位的法定演练义务 |
| 生成方案要点清单与评估表 | ❌ 替代现场指挥与演练安全管理 |
| 整理问题整改台账 | ❌ 保证演练效果与处置结果 |
| 输出记录模板 | ❌ 出具执法或验收结论 |

**以下情况，方案必须报单位消防安全责任人或管理人批准，并办理相应审批手续：**
- 实战灭火演练、夜间演练
- 模拟疏散需临时封闭通道、停电梯、断电源
- 动用消防设施联动（应急广播、防火卷帘、防排烟）

**永远不要**为了"效果好看"把问题清单写虚、把整改时限写成"尽快"、把评估结论写成"基本通畅"。演练记录是执法检查与事故调查的核心材料。

## 二、完整工作流

```
第 1 步  明确场景：排年度计划 / 策划单次演练 / 演练后评估 / 迎检补资料
第 2 步  读规则文件 rules/drill_rules.md
第 3 步  按场景取用：
    - 定计划 → 频次红线表（第三节）
    - 编方案 → 方案九要素（第四节）
    - 定形式 → 类型选择矩阵（第五节）
    - 做评估 → 评估四维度与整改闭环（第六节）
    - 体检表 → python scripts/drill_plan_check.py --file 演练记录.json
第 4 步  按 templates/演练评估表.md 输出或补全记录
第 5 步  人工确认：审批手续、安全保障、联动影响
```

## 三、频次红线（法定底线）

| 单位类型 | 法定最低要求 | 依据 |
|---|---|---|
| 消防安全重点单位 | 灭火和应急疏散预案演练**至少每半年一次** | 公安部61号令第四十条 |
| 其他单位 | **至少每年一次** | 公安部61号令第四十条 |
| 高层民用建筑 | 另有更高要求的从其规定（全要素综合演练等） | 高层民用建筑消防安全管理规定 |
| 医院、养老院、学校、幼儿园、托儿所等 | 通行管理口径建议提高频次，并安排夜间时段 | 管理实践通行口径 |

> **"每半年一次"指两次演练间隔不超过 6 个月。** 年度计划要倒排：间隔 5 个月左右办一次最稳，别把两次都排在上半年、下半年空 8 个月。

## 四、方案九要素（缺一项就是一处问题）

1. **演练目的**——检验什么：预案可行性 / 人员响应 / 设施联动 / 疏散能力，写具体
2. **演练依据**——所依据的预案名称与版本号、法规条款
3. **时间与地点**——精确到起止时刻，具体到楼层、部位
4. **组织机构**——总指挥、指挥长、各行动组及人员分工（报警、疏散引导、灭火行动、医疗救护、安全防护、通信联络）
5. **情景设定**——起火部位、燃烧物、报警方式、人员被困假设
6. **实施步骤**——精确到分钟的时间线：何时模拟报警、何时广播、何时疏散、何时集结清点
7. **保障措施**——医疗、交通、通信、后勤、警戒、恶劣天气预案
8. **评估安排**——谁评估、用什么表、计时点设在哪
9. **整改要求**——问题收集口径、责任分工、复查时限

> 要素写得不具体（如"加强组织领导"不落到人名）等于没写；"尽快整改""进一步加强"这类表述在检查中一律视为未闭环。

---

## 五、演练类型选择矩阵

| 类型 | 适用场景 | 规模 | 成本 |
|---|---|---|---|
| 桌面推演 | 预案评审、指挥人员训练、新员工熟悉流程 | 小 | 低 |
| 功能演练 | 单一环节强化：报警、疏散、灭火、广播单项练 | 中 | 中 |
| 疏散演练 | 人员密集场所首选，检验疏散与清点能力 | 中 | 中 |
| 专项演练 | 薄弱环节补强：夜间疏散、地下空间、燃气、化学品 | 中 | 中高 |
| 综合演练 | 多环节联动全流程检验 | 大 | 高 |

**年度组合建议**：至少 1 次综合演练或疏散演练 + 1 次桌面推演或专项演练；单位改扩建、人员大幅变动、发生火警后应加练。

## 六、评估四维度与整改闭环

**评估四维度**（每个维度至少设一个可计量观测点，计时精确到分钟）：

| 维度 | 观测点示例 |
|---|---|
| 时间 | 报警响应时间（模拟报警→现场确认）、疏散用时（警报→集结清点完毕）、设施联动到位时间 |
| 人员 | 参演率、各行动组到位率、关键岗位持证情况、员工逃生路线知晓率 |
| 设施 | 应急广播、防排烟、应急照明、防火卷帘、灭火器、消火栓是否按预案动作 |
| 管理 | 预案与实际偏差、指挥流畅度、记录完整性 |

**整改闭环五步法**：

```
发现问题 → 定措施定责任人 → 定期限 → 整改销项 → 复查验证并归档
```

每一步都要落到纸面：问题清单、责任人、完成期限、复查人、复查日期。**没有问题发现的演练，大概率是评估没做，不是真的没问题。**

## 七、脚本用法（演练记录体检）

```bash
python scripts/drill_plan_check.py --file "D:\消防\演练记录.json"
```

| 参数 | 说明 |
|---|---|
| `--file` | 必填。演练记录/方案要素 JSON |
| `--today` | 核查基准日，默认今天 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本检查五类问题：**频次间隔超标、方案九要素缺失、评估必填项缺失、整改无责任人/期限、日期逻辑倒挂**。

> ⚠️ 脚本只做结构与逻辑检查，**不判定演练实际效果**；标"正常"不等于真做到。

## 八、人工确认（这步不能省）

- [ ] 演练是否影响营业/生产秩序，动火、断电、封路等审批是否办理
- [ ] 安全保障是否到位：警戒范围、医疗备勤、消防车通道预留
- [ ] 联动设备投入是否事先通知维保单位，避免设备损伤
- [ ] 疏散路线是否与实际一致（通道堆物、安全出口上锁）
- [ ] 参演人数统计口径是否全口径（含外包、驻场单位）
- [ ] 夜间演练的照明与人员集合点是否明确

---

## 九、输出结构（固定三段）

1. **能不能过关**——结论先行：频次合规 / 有缺口 / 有红线问题
2. **核对清单**——逐项标合规/缺失/存疑
3. **整改与补资料建议**——先后顺序、责任岗位、留存材料

## 十、最常见的坑

**坑一：半年一次排成"年初年尾各一次"。** 两次间隔超过 6 个月，一查一个准。倒排计划，间隔控制在 5 个月左右。

**坑二：方案写"加强组织领导"。** 没有具体人名和分工，等于没有组织机构。

**坑三：演练不计时，评估写"基本通畅"。** 没有时间数据的演练评估等于没评估。

**坑四：发现问题不登记。** 明年演练原样再犯，检查时连续两年同类问题从轻变从重。

**坑五：整改期限写"尽快"。** 没有期限就没有闭环，复查无记录等于没整改。

**坑六：记录只有签到表和照片。** 没有时间线、没有评估结论、没有问题清单，资料不成体系。

## 十一、边界与免责

- 本技能**不替代**单位的法定演练义务；频次等要求**以现行规定和当地消防救援机构要求为准**
- 实战灭火、夜间演练等高风险科目，必须制定专项安全措施并履行审批手续
- 涉及真实火警时，一切以现场指挥和消防救援机构指令为准
- 规程要点为消防管理实践方法论整理，**不构成正式执法或验收结论**
