# 职业病危害因素检测管理（hazard-detection）

检测是职业健康的"眼睛"：**不检测就不知道危害有多大，不超标整改就等于白测**。管理闭环三件事——按期测、布对点、用好结果。

这个技能做四件事：**定周期** → **选机构** → **核布点** → **用结果**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 讲解检测组织与结果运用方法 | ❌ 替代法定检测与评价结论 |
| 生成检测台账与整改清单 | ❌ 出具检测报告 |
| 整理告知与公示口径 | ❌ 判定危害程度 |

**涉及职业病危害事故的检测，按应急检测程序组织，不等年度周期。**

**永远不要**拿到超标报告当"存档文件"——超标的每一天，员工都在暴露中。

## 二、完整工作流

```
第 1 步  明确场景：排检测计划 / 选机构 / 核报告 / 超标处置 / 迎检
第 2 步  读规则文件 rules/detection_rules.md
第 3 步  按场景取用：
    - 定周期 → 检测类型与周期（第三节）
    - 选机构 → 机构能力核验（第四节）
    - 核布点 → 布点原则（第五节）
    - 用结果 → 超标处置与告知（第六节）
    - 体检表 → python scripts/detection_check.py --file 检测.json
第 4 步  按 templates/检测结果运用表.md 输出
第 5 步  人工确认：危害因素辨识、岗位匹配、整改证据
```

---

## 三、检测类型与周期

| 类型 | 周期/触发 | 用途 |
|---|---|---|
| 定期检测 | **每年至少一次** | 掌握常态危害水平 |
| 建设项目评价检测 | 建设期（预评价/控制效果评价） | 三同时 |
| 防护设施效果检测 | 设施改造/投用后 | 验证设施有效性 |
| 应急检测 | 事故或异常时 | 应急处置 |

> 周期要求**以《工作场所职业卫生管理规定》等现行规定为准**。

---

## 四、检测机构能力核验

1. **资质**：具备职业卫生技术服务资质（资质范围覆盖检测项目）
2. **能力**：检测方法在资质能力表内，仪器设备满足要求
3. **人员**：检测人员经培训考核
4. **报告要素**：机构章、检测依据、布点图、数据表、结论、签发人
5. **数据逻辑**：检测日期、气象条件、流量记录与结果自洽

---

## 五、布点原则

- 覆盖**所有存在职业病危害因素的作业岗位**
- 劳动者呼吸带高度（劳动者作业位置）
- 重点岗位/高风险岗位加密
- 不同工种、不同班次分别布点
- 记录检测时的生产状态（满负荷/常态）

---

## 六、结果运用（闭环核心）

```
出报告 → 判读（对照职业接触限值）→ 超标：整改+复查 → 达标：保持控制
→ 结果告知劳动者 → 公示/存入档案 → 纳入下次检测计划
```

- **超标整改**：工程控制（优先）→ 管理控制 → 个体防护；定责任人、期限
- **复查**：整改完成后复测，数据支撑关闭
- **告知**：结果书面告知相关劳动者（隐私岗位单独告知）
- **档案**：检测报告、布点图、整改记录归入职业卫生档案

---

## 七、脚本用法（检测台账体检）

```bash
python scripts/detection_check.py --file "D:\EHS\检测.json"
```

脚本检查四类问题：**周期超期、点位覆盖缺口、超标无整改闭环、告知缺失**。

> ⚠️ 脚本只做结构与逻辑检查，**不判定检测数据与危害程度**。

---

## 八、人工确认（这步不能省）

- [ ] 危害因素辨识是否覆盖所有原辅料与工艺
- [ ] 检测机构资质范围是否覆盖本项目
- [ ] 布点是否覆盖所有危害岗位
- [ ] 超标整改是否以工程控制为主
- [ ] 复查数据是否支撑关闭
- [ ] 结果是否告知劳动者并归档

---

## 九、输出结构（固定三段）

1. **检测状态**——结论先行：按期合规 / 有缺口 / 有超标未闭环
2. **核对清单**——周期、机构、布点、结果运用逐项
3. **整改与补资料建议**——先后顺序、责任岗位、留存材料

---

## 十、最常见的坑

**坑一：只测不超标处置。** 报告放档案室，超标岗位继续生产。

**坑二：布点漏岗位。** 实验室、仓库、临时作业点没人测。

**坑三：机构资质对不上。** 检测项目不在能力范围内，报告无效。

**坑四：结果不告知。** 员工连自己岗位的危害水平都不知道。

**坑五：赶生产不配合检测。** 检测时降负荷，数据好看但不真实。
