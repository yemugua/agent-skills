# 婚宴桌次安排与席位排布（wedding-banquet-seating）

婚宴排桌做不好，**问题几乎都出在「桌数算错」和「圈子混排」**：要么人来了没座，要么一桌十个人互相不认识，全程尬坐。

这个技能做五件事：**核人数 → 算桌数 → 分区域 → 排座次 → 做引导**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按人数与分区规则核算桌数与桌次排布 | ❌ 替代酒店宴会厅的现场摆台与疏散安排 |
| 给出座次原则、禁忌与引导口径 | ❌ 判断场地承重、消防通道、最大容纳人数 |
| 输出可复制的桌次表、席位卡与清单 | ❌ 代为决定涉及家庭关系的敏感安排（谁与谁同桌） |
| 提示需要提前确认的关键时间点 | ❌ 承诺现场一定不出差错 |

**以下事项必须以酒店宴会厅的现场条件为准，不要自行决定：**

- 宴会厅最大容纳桌数、消防通道宽度、疏散要求
- 主桌舞台位置、上菜通道、音响与灯光位置
- 是否能加桌、加桌后的通道是否仍满足疏散要求
- 备用桌摆放位置（不能占用通道）

**涉及家庭关系的安排（如离异父母、关系不和的亲属），必须由新人及双方家庭确认，本技能只给出处理原则，不代为决定。**

## 二、完整工作流

```
第 1 步  核人数：统计"占座人数"（不含抱在怀里的婴儿），分出大人/儿童
第 2 步  定每桌座数：常见 10 人/桌，主桌可 12 人；按酒店桌型确认
第 3 步  算桌数：基础桌数 = ceil(占座人数 / 每桌座数)
第 4 步  加备用桌：按 5%-8% 加机动桌（上限一般 2 桌），放边缘不占通道
第 5 步  分区域：主桌 / 男方亲属 / 女方亲属 / 同事 / 同学 / 朋友 / 机动
第 6 步  排座次：按座次原则与禁忌清单逐桌落实
第 7 步  出清单：桌次表、席位卡、桌号牌、签到台引导
第 8 步  跑脚本核对：python scripts/seating_plan.py --file guests.json
第 9 步  提前 3 天再确认一次人数，当天留 1-2 桌机动
```

**顺序不能颠倒**：人数没核准就订桌数，是「人来了没座」和「空两桌难看」的共同根源。

---

## 三、人数到桌数的换算规则

| 项 | 口径 |
|---|---|
| 占座人数 | 抱在怀里的婴儿可不占座（需提前与酒店确认是否提供宝宝椅）；**3 岁以上儿童一般占座** |
| 每桌座数 | 常规 10 人/桌；主桌 10-12 人（按酒店桌型） |
| 基础桌数 | `ceil(占座人数 / 每桌座数)` |
| 备用桌 | 按基础桌数的 5%-8% 加，**总桌数 10 桌以下加 1 桌，10-25 桌加 1-2 桌，25 桌以上不超过 2 桌** |
| 机动桌 | 备用桌当天不用时，可作为机动桌安置临时加人 |
| 工作人员 | 摄影、摄像、主持、婚庆督导一般不计入宾客桌，按酒店工作餐安排，需提前确认 |

**示例**：占座 168 人，每桌 10 人 → 基础 17 桌 → 备用 1-2 桌 → 报给酒店 18-19 桌。

**不要按"大概多少人"订桌。** 提前 2 周定名单，提前 3 天二次确认，这是唯一有效的办法。

## 四、六区分区口径

| 区域 | 人员 | 位置原则 | 桌数算法 |
|---|---|---|---|
| 主桌 | 新人、双方父母、祖父母（如需）、证婚人/主婚人 | 居中、正对舞台、最靠近主舞台 | 1 桌（人数多可分主桌 + 副主桌） |
| 男方亲属 | 男方直系与旁系亲属 | 主桌左侧靠前区域 | `ceil(男方亲属人数 / 每桌座数)` |
| 女方亲属 | 女方直系与旁系亲属 | 主桌右侧靠前区域 | 同上 |
| 同事 | 新人双方同事、领导 | 中段区域，领导桌相对靠前 | 同上 |
| 同学 | 双方同学、同乡 | 中段偏后 | 同上 |
| 朋友 | 朋友、邻居、其他 | 靠后区域，近出口与音响 | 同上 |

**左右分区的通用做法**：以新人面向舞台的方向为准，男方亲属在左、女方亲属在右（或按当地习俗调整），**关键是两侧都要靠前，不能一前一后**。

**不能在最后一桌安排长辈。** 最后一排通常靠近上菜口、音响与出口，嘈杂且进出频繁。

---

## 五、主桌怎么坐

**标准主桌（10-12 人）人员构成：**

1. 新人（新郎、新娘）
2. 双方父母（4 人）
3. 祖父母（如需，双方各 1-2 人）
4. 证婚人 / 主婚人（如需）
5. 伴郎伴娘（不坐主桌时另设伴郎伴娘桌，靠近主桌）

**座次原则：**

- 新人居中、面向舞台与宾客
- 双方父母分坐新人两侧，按「男左女右」或当地习俗
- 长辈、证婚人安排在父母旁边，**不要安排在桌端（上菜位）**
- 主桌不留空位给「可能来的人」，人没到就空着比临时加座体面

**人数多时的处理**：设主桌 + 副主桌（第二桌安排祖辈、重要长辈、证婚人），副主桌紧邻主桌。

## 六、脚本用法

```bash
python scripts/seating_plan.py --file guests.json --out 桌次方案.md
python scripts/seating_plan.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 输入 JSON：总人数、每桌座数、各分区人数、是否含儿童、备用桌比例 |
| `--out` | 结果写入指定文件，默认写 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON 示例：

```json
{
  "total": 168,
  "seats_per_table": 10,
  "children": 8,
  "main_table_seats": 12,
  "zones": {
    "groom_family": 46,
    "bride_family": 42,
    "colleague": 38,
    "classmate": 24,
    "friend": 18
  },
  "buffer_rate": 0.06
}
```

脚本输出：基础桌数、备用桌数、建议总桌数、各分区桌数与桌号区间、主桌构成建议、以及「人数与分区不匹配」等提醒（各分区人数之和 + 主桌人数 ≠ 总人数时会报警）。

> 脚本只做数量核算与分区编号，**不替代现场摆台与家庭关系判断**。分区人数与实际名单务必人工核对。

## 七、人工确认清单（这步不能省）

- [ ] 占座人数已按「3 岁以上占座」口径核准，且提前 3 天二次确认
- [ ] 每桌座数与酒店桌型核对过（圆桌 10 人还是 12 人）
- [ ] 备用桌数量已定，摆放位置不占用消防通道
- [ ] 主桌人员构成已与双方父母确认
- [ ] 双方亲属左右分区已确认，两侧都靠前
- [ ] 领导、长辈未安排在最后一桌、门口、上菜口
- [ ] 关系不和的人员未安排在同一桌（**由新人及家庭确认**）
- [ ] 桌号牌、席位卡、签到台引导已准备
- [ ] 当天有 1-2 桌机动，并指定了负责人处理临时加人

## 八、最常见的坑

**坑一：按「大概人数」订桌数。**
错误做法：觉得「差不多 15 桌」就报 15 桌。正确做法：提前 2 周定名单算出占座人数，提前 3 天二次确认，再按 `ceil(人数/每桌座数)` 算基础桌数并加备用桌。人数没核准，必然出现「人来了没座」或「空两桌难看」。

**坑二：备用桌不加，或加太多。**
错误做法：一分不加，或者怕不够加 3-4 桌。正确做法：按基础桌数的 5%-8% 加，且总桌数 25 桌以上不超过 2 桌。备用桌多了空着难看，且通常也要计入最低消费。

**坑三：把不认识的人硬凑一桌。**
错误做法：某区剩 3 个人，就塞进别的区的桌。正确做法：余数并入同区域的其他桌（该桌坐 11-12 人），或单设「机动桌」安置各区余数；把三个圈子的人塞一桌，全程无人说话。

**坑四：把长辈或领导安排在最后一桌。**
错误做法：谁最后确认就安排在哪。正确做法：长辈、领导靠前居中，最后一排留给朋友和年轻人——后排靠近上菜口、音响、出口，嘈杂且进出频繁。

**坑五：主桌塞满，把伴郎伴娘和工作人员也安排进去。**
错误做法：主桌坐 14 个人，挤得转不开身。正确做法：主桌只坐新人、双方父母、祖辈与证婚人；伴郎伴娘另设桌并紧邻主桌；摄影摄像主持按工作餐安排。

**坑六：桌号从 1 编到 20，但没有引导。**
错误做法：只有桌号牌，宾客到场自己找。正确做法：签到台放总桌次图（含分区色块），每桌立桌号牌，重要桌（主桌、亲属、领导）加席位卡；有条件的安排 1-2 名引导人员。

**坑七：忽略关系禁忌。**
错误做法：按名单顺序一排了之，把关系不和的亲属排在同一桌。正确做法：排座前先把「不能同桌」的组合列出来（离异父母、有过节的亲属、前任同事等），**由新人及双方家庭确认后**再落表。

**坑八：备用桌占通道。**
错误做法：备用桌摆在过道上，临时启用时堵住疏散通道。正确做法：备用桌摆在宴会厅边缘不影响通行的位置，且**以酒店现场条件与消防要求为准**。
