# 机械硬盘掉盘与数据抢救（hdd-dropping）

**硬盘出现咔哒声或刮擦声，立刻断电停用。** 反复通电可能让本来还能救的数据变成救不回来。这条比任何技巧都重要。

这个技能做四件事：**辨征兆** → **读预警** → **定顺序** → **判放弃**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 区分掉盘征兆与可自愈的临时问题 | ❌ 承诺数据一定能救回来 |
| 解读 SMART 关键预警项的含义 | ❌ 指导开盘、拆磁头或动手修 |
| 给出抢救流程与顺序 | ❌ 建议反复通电试机 |
| 说明备份优先于修复的原则 | ❌ 替代专业数据恢复机构 |
| 给出该放弃数据的判定线 | ❌ 代用户操作硬盘或读取其数据 |

**必须转交专业数据恢复机构的：**

- 需要开盘处理（拆外壳、进洁净室）才能救的
- 异响伴随数据重要且无任何有效备份的
- 企业级阵列、多盘系统中的单盘故障
- 涉及合约、账务、研发等不可再生数据
- 已经尝试过多次通电读取的

**永远不要为了试试看而反复通电。** 磁头在失效盘上反复寻道会持续损伤盘面，可救范围越来越小。

## 二、完整工作流

```
第 1 步  辨征兆：异响、不识别、掉盘频繁，读第 3 节对照表
第 2 步  有异响就直接进入停用结论，不再做后续测试
第 3 步  无异响但告警，读 SMART 关键项（第 4 节）
第 4 步  先读规则文件 rules/hdd_recovery_rules.md（征兆表 + 预警项 + 抢救顺序 + 放弃判定）
第 5 步  跑状态评估脚本，按征兆组合输出处置级别
    python scripts/hdd_drop_triage.py --symptoms "异响,读取报错"
第 6 步  按抢救流程执行：镜像优先于恢复
第 7 步  对照放弃判定线做最终取舍
```

## 三、掉盘征兆对照表

| 征兆 | 含义 | 紧急度 |
|---|---|---|
| 咔哒声、咔咔响、刮擦声 | 磁头无法正常寻道，机械部分在动 | **立即停用** |
| 完全不识别、BIOS 里看不到 | 可能是供电、接口、盘体或控制器 | 高 |
| 时好时坏、反复掉线 | 盘体不稳定或线缆接触不良 | 高 |
| 拷贝大文件到某个百分比就断 | 该区域不可读 | 高 |
| SMART 报属性异常 | 见第四节 | 高 |
| 启动时咔一下然后正常 | 磁头复位，可能已到寿命末期 | **立即停用** |
| 打开文件很慢但能读 | 可能是坏道或缓存问题 | 中，先备份 |
| 电脑偶尔认不到盘，重插就好 | 可能是接口或供电，先换线换口验证 | 中 |

**判断口径**：**异响是最强信号**。只要有异响，无论其他指标多好，都按最坏情况处理。

---

## 四、SMART 关键预警项解读

| 预警项 | 含义 | 严重度 |
|---|---|---|
| 重新分配扇区数持续增长 | 已有扇区无法使用，靠备用区顶替 | **高** |
| 待映射扇区数不为零 | 有扇区还没完成重映射，随时可能读不出 | **高** |
| 无法校正扇区数不为零 | 已尝试多次仍读不出 | **高** |
| 通电超时计数增长 | 磁头寻道时间异常 | 高 |
| 寻道错误率异常 | 机械寻道不稳定 | 中高 |
| 温度告警 | 长期高温会加速盘体老化 | 中 |
| 出厂校准计数异常 | 厂商自检没通过 | 中 |
| 通电小时数很高 | 老盘，各项性能同步下降 | 中 |
| 底层数据错误率上升 | 盘面读出数据本身就有误 | **高** |

**注意**：「SMART 全绿」不等于盘健康。**异响盘即使 SMART 全绿也应停用。** SMART 是趋势指标，突然的机械故障往往来不及反映到这些数值上。

**否定项提醒**：「SMART 没报警所以没事」是误判。机械故障有相当一部分不会先反映在 SMART 数值里。

## 五、抢救流程（顺序不能乱）

```
第 1 步  停止使用：不再往这块盘写任何数据
第 2 步  固定环境：断电、静置、必要时降温，避免震动与高温
第 3 步  做镜像：把能读到的部分做整盘或分区镜像到健康介质
第 4 步  从镜像上做恢复：在镜像件上跑恢复工具，不动原盘
第 5 步  核对：把镜像件里的文件与原记录比对，确认完整性
```

**为什么镜像优先于恢复**：

| 直接恢复 | 先镜像 |
|---|---|
| 反复读原盘，风险累积 | 原盘只读一次，风险最小 |
| 中途失败没有退路 | 镜像件可以重复操作 |
| 恢复软件可能写回原盘 | 不动原盘，随时可重来 |

**绝对不要做**：把恢复出来的文件直接写回故障盘、格式化故障盘「试试看还能不能用」、继续往故障盘拷新数据。

## 六、什么情况该放弃数据

**这些情况建议停止自行尝试，转专业机构或接受损失：**

| 情况 | 理由 |
|---|---|
| 有异响且数据无任何有效备份 | 自己操作会持续损伤盘面，专业机构也只能在洁净条件下处理 |
| 已反复通电多次仍读不出 | 可救范围已大幅缩小 |
| 需要开盘才能读 | 家庭与办公环境不具备条件 |
| 盘片有明显物理变形或液体痕迹 | 属于硬件损坏，自行处理无意义 |
| 数据量大且分散多块盘 | 需要专业工具与经验 |

**判定原则**：**数据价值高于成本时，找专业机构；数据可再生或价值不高时，直接换盘。** 备份到位的情况下，换盘往往比抢救更省钱省心。

**核心顺序**：**备份优先于修复。** 任何一次「抢救」之前，先回答一个问题：这块盘上的数据有没有第二份？没有的话，慎重再慎重的理由就是它不可再生。

## 七、脚本用法

```bash
python scripts/hdd_drop_triage.py --symptoms "异响,读取报错"
python scripts/hdd_drop_triage.py --file case.json --out 处置建议.md
python scripts/hdd_drop_triage.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--symptoms` | 逗号分隔的征兆关键词 |
| `--smart` | SMART 报警项，逗号分隔 |
| `--file` | 从 JSON 读（自动兼容带 BOM 的文件） |
| `--out` | 结果落盘路径 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本按征兆组合输出**处置级别**（立即停用 / 高优先处理 / 先备份 / 继续观察）、**风险提示**与**该做什么不该做什么**。命中异响类征兆时直接输出停用结论。

> 脚本只做征兆与预警项的规则判定，**不接触硬盘、不读取数据**。

## 八、人工确认清单（这步不能省）

- [ ] 确认有没有异响（这一条决定后面所有动作）
- [ ] 有异响的话，已经断电停用，没有继续通电试
- [ ] 确认最近有没有往这块盘写过数据
- [ ] 确认数据有没有第二份，值不值得冒险
- [ ] 读了 SMART 关键项，而不是只看一个总状态
- [ ] 明确了抢救顺序是先镜像后恢复
- [ ] 确认恢复出来的数据没有写回原盘
- [ ] 核对过恢复出来的文件是否完整可用
- [ ] 需要开盘或专业处理时，已经转交专业机构

## 九、最常见的坑

**坑一：异响了还反复通电试。**
这是最伤数据的一件事。每通电一次，磁头寻道都可能进一步损伤盘面，可救范围持续缩小。

**坑二：SMART 全绿就继续用。**
机械故障常常来不及反映在 SMART 数值上。**异响 + SMART 全绿 = 照样停用。**

**坑三：直接恢复不先镜像。**
恢复软件要反复读写原盘，中途失败没有退路。先镜像，原盘只被动读一次。

**坑四：把恢复出来的数据写回故障盘。**
刚落地的数据又进入不可靠的介质，等于白做。

**坑五：格式化一下看看还认不认。**
格式化是写操作，会破坏仅存的残余可读区域，把唯一的机会也毁掉。

**坑六：继续往这块盘拷新数据。**
盘已经在失效边缘，新写入的数据很可能既写不完整又覆盖了残留内容。

**坑七：以为拷贝到一半断掉的文件完全没了。**
已拷贝的部分通常还在，重点是别从头再来、别覆盖目标盘。

**坑八：忽略线缆和接口。**
时好时坏有时是线缆或接口接触不良。换线换口验证的成本极低，应该先排除。

**坑九：把「还能识别」当成「还健康」。**
能识别只说明通电和通信正常，不代表盘面可读。

**坑十：等坏了才想起没备份。**
抢救是补救，不是常态。**备份优先于修复。**

## 十、边界与免责

- 本技能**只做征兆判断与流程指引**，不代用户操作硬盘或读取其数据
- 涉及开盘、拆磁头、进洁净室的处理，一律转交专业数据恢复机构
- 无法承诺数据一定能恢复，**可恢复性取决于损伤类型、损伤程度与是否已反复通电**
- SMART 数值的解读口径以设备厂商说明与实际工具输出为准
- 涉及合约、账务、研发等不可再生数据，建议直接委托专业机构
