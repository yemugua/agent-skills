# 候选人体验管理（candidate-experience）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据候选人旅程管理方法，生成清单：触点点位与关键环节、响应时效与沟通话术、面试环境与接待标准、反馈闭环与拒信管理、净推荐值测量与改进。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 候选人体验
- 候选人旅程
- 招聘响应时效
- 面试接待标准
- 招聘 NPS

## 三、工作流
1. 梳理触点点位与关键环节
2. 统一响应时效与沟通话术
3. 制定面试环境与接待标准
4. 落实反馈闭环与拒信管理
5. 测量净推荐值并持续改进

## 四、核心内容（检查清单与判定）
多数负面口碑来自「投简历后没回音」。即使不录用，及时告知结果也会显著提升雇主形象；未被录用的优质候选人仍是未来的人才库资源。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含触点点位与关键环节 | 触点 |
| Q2 | FAIL | 未含响应时效与沟通话术 | 时效 |
| Q3 | WARN | 未含面试环境与接待标准 | 接待 |
| Q4 | WARN | 未含反馈闭环与拒信管理 | 闭环 |
| Q5 | WARN | 未含净推荐值测量与改进 | 测量 |

> 脚本 `candidate-experience_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python candidate-experience_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python candidate-experience_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
