# APQP 先期产品质量策划（apqp）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 AIAG APQP 手册与 IATF 16949，生成 APQP 策划清单：五个阶段（计划/产品设计/过程设计/验证/反馈）、跨职能小组、里程碑、输出物（控制计划/PFMEA/作业指导书）。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- APQP
- 先期产品质量策划
- 产品质量先期策划
- 新产品质量策划
- 阶段门

## 三、工作流
1. 组建跨职能小组并制定计划
2. 产品设计开发与 DFMEA
3. 过程设计与 PFMEA/试生产
4. 产品与过程验证确认
5. 反馈评定与持续改进（含 CP）

## 四、核心内容（检查清单与判定）
APQP 将新产品开发划分为五个阶段，强调跨职能协同与阶段门评审；输出 PFMEA、控制计划、作业指导书等，确保量产前风险受控。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含跨职能小组与计划 | 计划 |
| Q2 | FAIL | 未含产品设计阶段（DFMEA） | 设计 |
| Q3 | FAIL | 未含过程设计（PFMEA/试产） | 过程 |
| Q4 | WARN | 未含验证确认阶段 | 验证 |
| Q5 | WARN | 未含反馈改进（含控制计划） | 改进 |

> 脚本 `apqp_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python apqp_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python apqp_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
