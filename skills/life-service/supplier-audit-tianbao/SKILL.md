# 供应商审核（supplier-audit）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001 外部提供控制与 VDA 6.3，生成供应商审核清单：审核策划与检查表、体系与过程审核、问题分级与整改要求（CAPA）、审核报告与分级、整改验证与复审。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 供应商审核
- 供方审核
- 二方审核
- 供应商现场审核
- 供方评审

## 三、工作流
1. 策划审核并准备检查表
2. 实施体系与过程审核
3. 问题分级并提出CAPA要求
4. 出具审核报告与供方分级
5. 验证整改并安排复审

## 四、核心内容（检查清单与判定）
供应商审核（二方审核）用于控制外部提供过程的风险；应基于检查表客观取证，问题分级后闭环CAPA并验证有效性。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含审核策划与检查表 | 策划 |
| Q2 | FAIL | 未含体系与过程审核 | 审核 |
| Q3 | WARN | 未含问题分级与CAPA要求 | CAPA |
| Q4 | FAIL | 未含审核报告与供方分级 | 报告 |
| Q5 | WARN | 未含整改验证与复审 | 验证 |

> 脚本 `supplier-audit_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python supplier-audit_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python supplier-audit_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。

## 九、免责声明
本技能为辅助参考工具，输出不构成法律/行政意见。最终合规责任由使用单位与责任人承担。引用标准以官方发布为准。
