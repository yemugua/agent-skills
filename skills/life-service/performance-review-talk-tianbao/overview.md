# 绩效面谈准备与结果异议沟通核查

## 你会得到什么

**面谈前先做自评三件套**，而不是列一堆做了什么。数据表：5-8 项关键成果，每项给目标值、实际值、变化幅度、数据来源和证据编号——每个数都能追到系统或台账，每条成果都有一个上级能访问到的证据编号（存在个人网盘的成果等同于不存在）。归因表：2-3 个未达项，每项写根因、是否可控、已做动作、下期改进，并配一张「归因句改写对照表」，把「因为需求变更频繁」「团队人不够」这类句子换成落在自己动作上的版本。

**面谈中分三类话术，不即兴组织语言。** 认可类：接住认可但归到具体动作，用方法论换取下周期的资源与授权。改进类：五步结构——先接住结论停两秒（「这个结果我接受」），再把差距定位到一个环节，然后根因落在可控项，接着给可验收的改进计划，最后当场复述共识。申诉类：六步顺序不可颠倒，**先索取各维度得分与扣分原因**，再摆事实只问「是否计入」「为什么」，然后把争议收敛成口径差异，接着提一个明确诉求，再问清制度规定的时限，最后结束确认。配一份「四句禁语对照」：动机指控、人比人、威胁告公司、拿资历当业绩。

**对结果有异议时，走有留痕的五步路径。** 索取判定依据 → 核对口径列「已计入/未计入」清单 → 与直属上级复核一次 → 按制度期限提交书面申诉 → 不认可时申请二次复核。**不要跳过第一步直接写申诉**，很多异议在拿到依据后就消失了，直接申诉容易因依据不足被程序性退回。给了申诉信的完整格式（请求 / 事实与证据编号 / 争议焦点 / 已沟通记录 / 附件清单 / 承诺）、措辞红线对照表，以及超期未回复时的书面催办函模板。

**还有一张僵局破法话术库。** 对方讲旧账、拒绝给依据、你被问到没准备的点、自己情绪上来了、对方提出无法承受的改进目标——八种僵局各给一句可直接说出口的话。其中「这个我需要回去确认，不现场给不确定的答案」是最该背下来的一句。

## 典型用法

- 绩效结果出来前一个月，按数据表 + 归因表把材料准备好
- 面谈当天记不下细节，用开场记录模板 10 分钟内记完要点
- 面谈结束 24 小时内发纪要邮件，把共识与不同意见写清楚
- 对结果不服气，先索取依据再决定要不要写申诉信

## 脚本

`scripts/review_talk_prep.py` 读入自评材料 JSON，输出自评证据覆盖率、量化覆盖率、证据可见率、口径一致性、程序完整率，以及证据不在上级可见位置、根因写到他部门、权重不等于 1、申诉期限临近四类提醒。支持 `--file` / `--text` / `--out` / `--format`，带 `--selftest`。

## 边界

本技能提供面谈准备、话术与申诉沟通方法论，不构成对考核结果公平性的任何认定，也不承诺申诉被受理或结果被调整。评价维度、权重、评级规则、申诉期限与受理范围以本单位绩效制度为准。涉及劳动争议、违法解除或严重歧视的，请咨询劳动法律专业人士。脚本只做材料与口径的形式核查，不预测申诉成功率。
