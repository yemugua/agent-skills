# 绩效面谈准备与结果异议沟通核查（performance-review-talk）

绩效面谈是**一年里唯一一次当面解释自己价值**的场合。准备得好，是定改进项；准备得差，是被当成一个「解释不清的人」。

这个技能做三件事：**把自评准备成证据链** → **把面谈话术分三类背熟** → **把异议走成有留痕的五步路径**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出面谈前准备清单与三类话术脚本 | ❌ 代替人力部门解释考核制度 |
| 给出异议处理五步路径与书面申诉格式 | ❌ 承诺申诉一定被受理或改分 |
| 核查自评证据链完整性与口径一致性 | ❌ 对考核结果是否公平作法律认定 |
| 给出改进计划写法与目标设定口径 | ❌ 代替本人与直属上级确认目标 |
| 给出僵局破法与措辞红线 | ❌ 提供攻击性、威胁性或造假的表达 |
| 检查程序合规性（是否有反馈、有无申诉渠道） | ❌ 判断某单位制度的具体合法性 |

**必须先停下来确认的情形：**
- 单位已发布绩效管理制度与申诉办法 —— **以本单位制度为准**，申诉期限、受理范围、提交对象按制度执行
- 涉及薪酬调整结果 —— 属个人敏感信息，按公司保密要求处理，不写入任何书面材料外传
- 涉及他人绩效、他人违规的举报 —— 不在绩效申诉中处理，走公司合规或纪检渠道
- 疑似违法解除或严重歧视 —— 建议咨询劳动法律专业人士，本技能不替代

## 二、完整工作流

```
第 1 步  查本单位制度：确认评价维度、权重、申诉期限、受理范围、提交对象
第 2 步  跑证据链体检：python scripts/review_talk_prep.py --file review.json
第 3 步  看四个数：自评证据覆盖率、量化覆盖率、口径一致性、程序完整率
第 4 步  按 rules/talk_scripts.md 背熟三类话术（认可 / 改进 / 申诉）
第 5 步  按 templates/review_talk_prep.md 填自评三件套：数据表 + 归因表 + 证据索引
第 6 步  预演三条最难的问题（见 §五），每条准备 60 秒版本
第 7 步  面谈中只做三件事：确认事实、提出异议、约定改进项，不辩论动机
第 8 步  面谈后 24 小时内发一封书面纪要邮件确认共识（留痕）
第 9 步  若对结果仍有异议，按五步路径走书面申诉，注意期限
```

**顺序不能颠倒**：第 1 步不查制度就准备，后面所有话术都可能用在错误的程序里。

## 三、面谈前准备清单（照着做）

### 3.1 自评三件套

| 件 | 内容 | 最低要求 |
|---|---|---|
| **数据表** | 周期内 5-8 项关键成果，每项给「目标值 / 实际值 / 变化幅度 / 数据来源」 | 每个数都能追到系统或台账 |
| **归因表** | 2-3 个未达项，每项写「根因 → 是否可控 → 已做动作 → 下期改进」 | 根因不写「其他部门」 |
| **证据索引** | 关键成果的证据链接（文档编号、工单号、发布记录、评审结论） | 每条成果至少 1 个可核查证据 |

**关键判断：证据必须在上级能看到的地方。** 存在个人网盘的成果，在绩效材料里等同于不存在。提前把关键产出同步到共享位置或抄送相关人。

### 3.2 四类问题预判

| 类型 | 典型问题 | 你的准备 |
|---|---|---|
| 事实类 | 「你周期内的核心产出是什么？」 | 数据表逐条，一句话一项 |
| 归因类 | 「为什么这项没达成？」 | 归因表：根因 + 可控性 + 已做动作 |
| 评价类 | 「为什么同事 A 比你高？」 | 回到评价维度，不用人比人 |
| 未来类 | 「下周期打算怎么做？」 | 改进计划：目标值 + 三项动作 + 时间点 |

**最容易翻车的是评价类问题。** 回答「我比 A 强」是输家开局，无论事实如何。把话题拉回「按评价维度，我在这个维度的实际结果是 X」。

### 3.3 面谈前 24 小时检查

- [ ] 已读本单位绩效制度，确认评价维度、权重、申诉期限
- [ ] 5-8 项关键成果，每项有目标值/实际值/来源
- [ ] 未达项已写根因，且根因句主语是自己的动作
- [ ] 关键成果已同步到上级可见的位置，并留有记录
- [ ] 团队成果已注明人数、分工与自己承担的部分
- [ ] 已准备三条最难问题的 60 秒版本，各录音一次自查语气
- [ ] 已确认改进计划的目标值是本人认可的
- [ ] 面谈地点与时长已知晓（少于 15 分钟通常无法深入）

## 四、三类话术脚本（可直接改后照读）

### 4.1 认可类（结果高于预期）

```
1. 接住认可，但归到具体动作上
   「谢谢。我自己复盘，这块确实超出预期的地方在 XX——当时我把 XX 环节前移了，
    单均耗时从 A 降到 B。这条经验我在 XX 场景又用了一次。」
   意图：让认可有具体锚点，也暴露方法论，而不是只说「谢谢」。

2. 主动认领下一步的更大目标
   「如果下周期要冲更高目标，我建议从 XX 入手，因为它同时影响 X 和 Y。
    需要您确认优先级。」
   意图：把一次好评换成下一周期的资源与授权。

3. 不说
   「我本来就是干这个的」「主要靠我 A 带着」——把一次好结果变成个人英雄叙事。
```

### 4.2 改进类（结果低于预期）

```
1. 先接住结论，不辩解
   「这个结果我接受。」
   （停两秒。不接这句，接下来任何解释都会被听成辩解。）

2. 说清差距的具体位置
   「从数据看，我的问题主要在 XX 环节：目标是 A，实际 B，差距 C。
    根因是我在 XX 时间点才介入 X，错过了 XX 窗口。」
   意图：差距要能定位到一个动作，而不是一种能力。

3. 把根因落在可控项
   「这部分是我能改的。下一阶段我改成 XX 机制，具体是……」
   （不接「因为需求变更」「因为资源不足」作为主因句。）

4. 提出可验收的改进计划
   「下周期我的目标是：X 指标达到 Y（当前 B）。三项动作：1. … 2. … 3. …
    希望在 X 月中旬做一次中途对齐。」
   意图：改进计划要能被检验，不是「以后加强」。

5. 结束时确认
   「我理解的改进项是这三个，有遗漏您指出来；下次对齐时间定在 X 月中旬对吗？」
   意图：把口头共识当场复述一遍，防止事后口径不一致。
```

### 4.3 申诉类（对结果有异议）

**面谈中先异议，不要在面谈中直接跳到申诉。** 顺序是：先确认事实依据 → 再表达异议 → 看对方是否愿意调整 → 不能调整再走书面。

```
第 1 步  请对方给依据
  「我想先理解一下判定依据。这个分数是由哪几个维度构成的？
   每一项的具体得分和扣分原因能给我看一下吗？」
  意图：很多异议在拿到依据后就消失了，因为确实是自己不知道的扣分项。

第 2 步  摆事实，只摆事实
  「关于 XX 维度，我有三条记录：X 月 X 日完成 A（工单 T123），
   X 月 X 日完成 B（文档 D456，已评审），X 月 X 日处理 C 共 N 件。
   这些是否被计入？如果没有计入，原因是什么？」
  意图：不评价对方对错，只问「是否计入」「为什么」。

第 3 步  说明自己认可的口径不同在哪
  「我理解的口径是 XX，贵方采用的口径是 XX。差异导致我的得分是 A 而非 B。
   如果以贵方口径为准，我认可结果；如果以我方口径为准，我希望重新核算。」
  意图：把争议收敛成「口径差异」，而不是「你评错了」。

第 4 步  提出明确的诉求（一次只提一个）
  「我的诉求是：请复核 XX 维度的计分依据，并把复核结论书面反馈给我。」
  意图：诉求越具体，越可能被执行。「请给我一个公正的评价」无法执行。

第 5 步  约定下一步与时限
  「如果本轮无法调整，我按公司制度在 X 日前提交书面申诉，
   受理人按制度是 XX。我会在 X 日前收到回复吗？」
  意图：把时限问出来。制度里通常有回复时限，记住它。

第 6 步  结束确认
  「我理解今天达成的共识是：XX、XX、待办是 XX。我会后发一封纪要邮件，
   如果有不准确的地方请您指正。」
  意图：当场发纪要邮件，是最有效的留痕方式。
```

**申诉面谈的四句禁语：**

| 禁语 | 为什么禁 | 替换 |
|---|---|---|
| 「你这是故意针对我」 | 动机指控，无法举证，且终止对话 | 「我想理解这个判定的口径」 |
| 「凭什么他就有我没有」 | 变成人比人，偏离评价体系 | 「关于这个维度，我的记录是……」 |
| 「我不服，我要告你们」 | 把沟通变成对抗，对方只剩防御选项 | 「我按公司制度提交书面申诉」 |
| 「我在公司干了 X 年」 | 资历不等于绩效，会强化印象偏差 | 「过去三个周期，我的 X 指标分别是 A、B、C」 |

## 五、三条最难问题的 60 秒版本（预演用）

| 问题 | 60 秒版本骨架 |
|---|---|
| 「你觉得你为什么是这个等级？」 | 「我理解这个等级对应的是 X 维度未达标。从数据看我在 A 达标（数值）、B 未达标（数值）。我认可结论，改进项是 B。」 |
| 「有没有你觉得评价不公平的地方？」 | 「有一处想请复核：XX 成果我在 X 月完成，依据是 X（工单/文档编号），但这一项似乎未计入。我请求复核该维度的计分依据。」 |
| 「下周期你打算怎么改进？」 | 「三项动作：一、XX 环节提前两周介入；二、每周做一次 X 指标跟踪；三、在 X 月中旬做一次对齐检查。目标值是 Y。」 |

**预演方法**：三条各录一遍，回放只听三件事——有没有报数字、有没有说「我不知道」、有没有超过 90 秒。

## 六、异议处理五步路径（书面）

| 步 | 动作 | 时限 | 留痕方式 |
|---|---|---|---|
| 1 | 索取判定依据（各维度得分与扣分原因） | 面谈当场 | 纪要邮件 |
| 2 | 核对口径，列出「已计入 / 未计入」清单 | 面谈后 2 个工作日内 | 自己的清单 |
| 3 | 与直属上级复核一次（带证据） | 制度规定期限内 | 会议纪要 |
| 4 | 提交书面申诉 | **以制度规定的申诉期限为准** | 邮件 + 提交回执 |
| 5 | 复核反馈不认可时，按制度申请二次复核或第三方复核 | 按制度 | 邮件 |

**不要跳过第 1 步直接写申诉。** 直接申诉而不索取依据，很容易因为「依据不足」被程序性退回，反而错过真正能解决问题的信息。

**申诉后无回应怎么办**：按制度规定的时限到期后仍未回复，发送一次书面催办（邮件，注明首次提交日期与制度条款依据），抄送制度规定的主管部门或人力资源对口人。**催办是正当程序，不是施压。**

## 七、书面申诉的正式表达格式

```
标题：关于 [周期] 绩效考核结果的申诉（申请人：[姓名]/[工号]/[部门]）

一、申诉请求
   1. 请求复核 [维度名称] 的计分依据
   2. 请求将 [成果名称]（证据编号 XX）计入考核统计范围
   3. 请求出具书面复核结论

二、事实与依据（逐条列，每条附证据编号）
   1. [日期] [成果名称]，证据：工单号 T123 / 文档 D456（附件 1）
   2. [日期] [成果名称]，证据：发布记录 R789（附件 2）
   3. [周期内该维度相关成果合计 N 项，均未见计入说明

三、争议焦点
   我方口径：[说明]
   现有口径：[说明]
   差异导致的结果：得分 [A] 与 [B] 的差距

四、已沟通记录
   [日期] 与 [对象] 面谈，已于 [日期] 发送纪要邮件（邮件主题：……）
   [日期] 复核一次，结论为 ……

五、附件清单
   附件 1：[名称]  附件 2：[名称]  ……

六、承诺
   本人所提交证据真实有效，如有不实愿承担相应责任。

申请人：[姓名]    联系方式：[电话/邮箱]
日期：[YYYY 年 MM 月 DD 日]
```

**申诉材料的措辞红线：**

| 禁止 | 原因 | 改为 |
|---|---|---|
| 「贵司/公司评价不公」 | 结论性指控，无法举证 | 「请求复核 XX 维度的计分依据」 |
| 「这明显是有人针对我」 | 涉及他人动机，无证据 | 删掉，只列事实 |
| 「我已经提供了全部证据，你们不看」 | 对抗语气 | 「已提交的证据编号为 X-Y-Z，请复核」 |
| 通篇形容词（很优秀、非常不满） | 无法验证 | 换成日期、编号、数值 |

**申诉的三条硬要求**：只列事实与证据编号；一次只提一个核心诉求；每条主张都能指向一个附件。

## 八、僵局破法（面谈僵住了怎么办）

| 僵局表现 | 破法话术 | 说明 |
|---|---|---|
| 对方开始讲个人情绪或旧账 | 「我理解。我们能不能先把这次考核的 XX 维度对齐，其他的我另找时间单独聊。」 | 把话题拉回评价维度 |
| 对方拒绝给依据 | 「我理解现在不方便给。那我按流程提交书面申诉，并在其中列明我的依据请求。可以吗？」 | 不硬顶，改走程序 |
| 你被问到完全没准备的点 | 「这个我需要回去确认，不现场给不确定的答案。我 X 日前书面回复您。」 | 不硬编。**不确定就说不确定** |
| 你情绪上来了 | 「我需要十分钟。」然后离开现场。 | 情绪在场内无法沟通，事后书面更有效 |
| 对方提出你无法接受的改进项 | 「这个方向我认同，具体目标值我需要核算后 X 日回复，我先记录下来。」 | 不当场答应无法承受的目标 |
| 双方对事实都无异议，只对结论有分歧 | 「我们对事实没分歧，分歧在评价结论。结论以公司制度为准，我按申诉流程走。」 | 收敛争议范围 |

**最有效的一句收尾**（任何僵局都适用）：

> 「今天的信息我记下来了。我会在 X 日前发一封纪要邮件，写明我们的共识和我的不同意见。如果有不准确的地方，请您指正。」

这句话同时完成三件事：留痕、保留异议权、给对方一个低成本的回应通道。

## 九、脚本用法

```bash
python scripts/review_talk_prep.py --file review.json --out 面谈准备体检.md
python scripts/review_talk_prep.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 自评材料 JSON，见下方结构 |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 输出文件，默认 `scripts/_last_result.txt` |

## 十一、最常见的坑

**坑一：把绩效面谈当成被审判，全程解释。**
错误做法：从头讲一遍做了什么，堆工作量。正确做法：先接住结论（「这个结果我接受」），再定位差距到具体环节，再给改进计划。**面谈的目标是定改进项，不是赢辩论。**

**坑二：拿资历和工作年限当业绩。**
错误做法：「我干了 X 年，付出很多」。正确做法：「过去三个周期，我的 X 指标分别是 A、B、C」。**资历不进入评价体系，用它会强化印象偏差。**

**坑三：拿同事作比较。**
错误做法：「为什么 A 就有我没有」。正确做法：把话题拉回评价维度——「关于这个维度，我的记录是 X，是否被计入？」。**人比人会让对话从评价体系滑到人际比较，双方都输。**

**坑四：只问不给依据，直接进入申诉。**
错误做法：面谈一结束就写申诉信。正确做法：先索取各维度得分与扣分原因——**很多异议在拿到依据后自然消失**（因为确实是自己不知道的扣分项）。直接申诉容易因依据不足被程序性退回。

**坑五：申诉材料写成情绪宣泄。**
错误做法：满篇「很不满」「明显不公」。正确做法：逐条列事实 + 证据编号 + 一句话争议焦点 + 明确诉求。**申诉信是证据材料，不是投诉信。**

**坑六：面谈中当场答应无法承受的改进目标。**
错误做法：「好，下季度提升 50%」。正确做法：「方向我认同，目标值我需要核算后 X 日回复」。**当场答应做不到的目标，等于自己设了一个必然失败的坑。**

**坑七：面谈后不留痕。**
错误做法：谈完就散，双方各记各的。正确做法：24 小时内发一封纪要邮件，写明共识与不同意见，请对方指正。**口头共识在绩效争议中约等于零证据。**

**坑八：证据存在个人网盘。**
错误做法：成果都在自己电脑上，绩效材料里写「已完成」。正确做法：把关键产出同步到共享位置或抄送相关人，并在材料里给出可访问的编号。**上级看不到的证据，等于不存在。**

**坑九：申诉超期才发现期限。**
错误做法：面谈后拖着不写申诉，一个月后才发现已过期。正确做法：面谈当天就问清制度规定的申诉期限与受理对象，写进纪要邮件。**期限是硬门槛，问一句的成本是零。**

**坑十：把申诉当情绪出口，说完就散。**
错误做法：在申诉信里写「明显有人针对我」，不列证据。正确做法：删掉所有动机推断，只列事实、编号、诉求。**带指控的申诉会让复核者先处理你的态度问题，而不是你的诉求。**
