# 短视频运镜（short-video-camera-move）

每个运镜镜头都是三段：**起幅（固定）→ 运镜段（运动）→ 落幅（固定）**。

绝大多数「剪出来看着晕」的问题，根源不是运镜手法选错了，而是**镜头从头动到尾、没有干净的入点和切点**。

这个技能做三件事：**分三段 → 核硬约束 → 控整片节奏**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出八种运镜手法的适用与取舍 | ❌ 讲解剪辑软件的具体操作与转场特效 |
| 按三段结构核查每个镜头的时长 | ❌ 推荐稳定器、滑轨、摇臂等器材的品牌型号 |
| 核查整片的运镜种类与节奏 | ❌ 提供调色、卡点、配乐的具体做法 |
| 给出运镜目的清单 | ❌ 替代摄影师在现场的判断 |

**遇到以下情况，按各自渠道处理：**

- 需要**剪辑软件操作、转场、卡点、调色** → 不在本技能范围
- 需要**选购或调试稳定器、滑轨、摇臂** → 以器材说明与厂商指导为准
- **设备防抖能力与可实现的运镜方式**因机型差异很大 → 以自己设备的说明为准
- 涉及**他人肖像**的内容 → 发布前应取得本人同意

**安全提示**：拍摄时请注意人身与设备安全，**不要在移动中操作设备**，不要在危险位置或影响他人的场所拍摄。

## 二、完整工作流

### 第一步：先定目的（说不出就别运）

| 目的 | 推荐手法 |
|---|---|
| 引入主体，把注意力收进来 | 推 |
| 交代环境，展示主体在哪 | 拉、摇 |
| 强调某个细节 | 推（慢推） |
| 跟随正在运动的主体 | 跟拍、横移 |
| 展示高度或层次 | 俯仰、升降 |
| 展示产品全貌 | 环绕 |
| 情绪递进或收束 | 推、拉 |
| 转场 | 拉、摇 |

**「觉得不动有点单调所以晃两下」不是目的，是干扰。**

### 第二步：定总时长

**运镜镜头不短于 1.5 秒；环绕镜头不短于 2 秒。**

短于这个时长，起幅、运镜段、落幅塞不下，运镜必然显得抽搐。

### 第三步：分三段

**起幅 0.5 秒 → 运镜段 → 落幅 0.5 秒**

- 运镜段不少于 0.5 秒
- 推拉的运镜段不少于 0.8 秒

**记忆法：动之前先稳 0.5 秒，动完之后再稳 0.5 秒。**

### 第四步：匀速走完

**起手缓 → 中间匀 → 收手缓 → 停稳再结束录制。**

忽快忽慢是新手最明显的特点。

### 第五步：控整片节奏

- 运镜种类**不超过 3 种**
- **不要连续 3 个以上镜头用同一种运镜**
- **20 秒以上的片子必须有固定镜头穿插**

### 第六步：填 JSON 跑自查

把每个镜头的运镜类型、总时长、起幅落幅、速度、目的填进去，脚本一次给出逐镜头判定、整片节奏问题与整改顺序。

## 三、核心规则（生成结论前先读规则文件）

**必须先读 `rules/运镜手法与自查表.md`，不要凭印象写。** 规则文件里有：

- 三段式结构各段的作用与建议时长
- 八种运镜手法的画面效果、适用内容、常见错误与建议时长
- 五条硬约束与四条使用约束
- 运镜目的清单（说不出就别运）
- 判定顺序说明与八条高频坑
- 拍一个运镜镜头的四步

**判定顺序不能颠倒**：先看严重项（镜头太短、缺起幅、缺落幅、运镜段太短、时长自相矛盾），再看可改进项，最后才看信息是否完整。

**为什么这条重要**：若先判信息完整度，会出现「镜头只有 1 秒、运镜根本做不完，却因为没填目的而被判成待确认」——把问题说轻了，比漏判更糟。

## 四、八种运镜手法速查

| 手法 | 画面效果 | 适用内容 | 运镜段下限 |
|---|---|---|---|
| **推** | 画面靠近主体，注意力收紧 | 开场引入、强调细节、情绪递进 | 0.8 秒 |
| **拉** | 画面远离，交代环境 | 结尾收束、揭示场景、转场 | 0.8 秒 |
| **摇** | 镜头左右转动 | 展示横向空间、跟随横向运动 | 0.5 秒 |
| **俯仰** | 镜头上下转动 | 展示高度、从脚到头介绍人物 | 0.5 秒 |
| **横移** | 机身整体左右平移 | 跟随并排行走、展示侧面层次 | 0.5 秒 |
| **跟拍** | 跟着主体同速移动 | 走路、跑步、骑行 | 0.5 秒 |
| **升降** | 机身垂直升高或降低 | 展示高度层次、从低处揭示场景 | 0.5 秒 |
| **环绕** | 围绕主体转 | 展示产品、突出人物（**单镜不短于 2 秒**） | 0.5 秒 |
| **固定** | 镜头不动 | 穿插在运镜之间做呼吸点 | 不适用 |

## 五、脚本用法

```bash
python scripts/camera_move_check.py --file shots.json --out 运镜核查.md
python scripts/camera_move_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 输入 JSON：`shots` 为镜头列表，每个填 `move` / `duration_s` / `start_static_s` / `end_static_s` 等 |
| `--out` | 结果写入指定文件，默认写 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检（60 条断言，含 BOM 两条路径） |

输入 JSON 示例：

```json
{
  "total_duration_s": 30,
  "shots": [
    {
      "name": "开场推镜",
      "move": "push",
      "duration_s": 3.0,
      "start_static_s": 0.6,
      "end_static_s": 0.8,
      "speed": "const",
      "purpose": "intro"
    },
    {
      "name": "呼吸点",
      "move": "static",
      "duration_s": 2.0
    }
  ]
}
```

`move` 取 `push` / `pull` / `pan` / `tilt` / `truck` / `follow` / `pedestal` / `arc` / `static`；
`purpose` 取 `intro` / `context` / `detail` / `follow_action` / `height` / `product` / `emotion` / `transition`；
`speed` 填 `const`（匀速）或其他值（会提示变速）；
`arc_turn_ratio` 为环绕转过的圈数比例（1.0 表示转满一圈）。
`total_duration_s` 为片长，不填则按各镜头时长求和。

脚本输出：总体判定、整片层面的问题（运镜种类、连续重复、缺固定镜头）、逐镜头判定表（含三段时长与不合格原因的 why）、整改顺序、八种手法表、目的清单、阈值表、人工确认清单。

## 六、人工确认清单（这步不能省）

- [ ] 每个运镜镜头都有起幅与落幅，各不少于 0.5 秒
- [ ] 运镜过程是匀速的，起手缓、收手缓
- [ ] 每个运镜都能说出目的
- [ ] 一个片子运镜种类不超过 3 种
- [ ] 长片有固定镜头穿插做呼吸点
- [ ] 拍摄时人身与设备安全，没有在移动中操作设备

## 七、最常见的坑

**坑一：从头动到尾，没有起幅落幅。**
错误做法：开机就开始推，推完立刻停录。正确做法：**起幅 0.5 秒 → 运镜 → 落幅 0.5 秒**。没有起幅落幅，剪辑时找不到干净的入点和切点，接上去就是抖一下接抖一下。

**坑二：镜头只有 1 秒却做了推镜。**
错误做法：1 秒的镜头里塞进推镜，运镜段只剩 0.2 秒。正确做法：**运镜镜头不短于 1.5 秒**，扣掉起幅落幅后运镜段至少还有 0.5 秒。

**坑三：环绕只转了四分之一圈就切。**
错误做法：绕了 30 度就切走，看着像手抖。正确做法：**环绕单镜不短于 2 秒，且要转完整**。环绕是转速最慢的运镜。

**坑四：一个 30 秒的片子用了六种运镜。**
错误做法：推、拉、摇、环绕、升降、跟拍全用一遍。正确做法：**运镜种类不超过 3 种**，否则风格不统一，观众觉得杂乱。

**坑五：全程都在动，没有一个固定镜头。**
错误做法：每个镜头都在运镜，三分钟看下来头晕。正确做法：**20 秒以上的片子必须有固定镜头穿插**做呼吸点。

**坑六：运镜速度忽快忽慢。**
错误做法：起手猛地一动，中间慢下来，最后又加速。正确做法：**匀速**，起手缓、中间匀、收手缓。

**坑七：为了「不单调」而晃镜头。**
错误做法：觉得画面不动有点无聊，就左右晃两下。正确做法：**没有目的的运镜是纯粹的干扰**。对照目的清单，说不出目的就别运。

**坑八：跟拍时贴太近。**
错误做法：跟拍走路的人，镜头贴到一米内，人一出画就找不回来。正确做法：**留出余量，让主体保持在画面中部**，跟丢了还能找回来。
