# 纠正预防措施与 8D 报告（capa-8d）

质量问题不可怕，可怕的是**同一个问题第二次来**。CAPA 的核心就一句：找到根因、做对措施、验证有效、推广固化。

这个技能做四件事：**先围堵** → **找根因** → **做措施** → **验效果**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 讲解 CAPA 流程与 8D 方法 | ❌ 替代组织自身的质量管理决策 |
| 生成 8D 报告模板与闭环体检 | ❌ 保证措施有效 |
| 整理根因分析与验证口径 | ❌ 判定责任归属 |

**涉及安全、法规、顾客重大影响的问题，围堵措施必须当天启动，不等根因分析完成。**

**永远不要**把"加强培训""加强检查"当根因措施——人是会累的，系统才是可靠的。

## 二、完整工作流

```
第 1 步  明确场景：内外部质量问题 / 审核不符合 / 顾客投诉
第 2 步  读规则文件 rules/capa_rules.md
第 3 步  按场景取用：
    - 先围堵 → 围堵与纠正区分（第三节）
    - 找根因 → 根因工具（第四节）
    - 做措施 → 8D 九步（第五节）
    - 验效果 → 有效性验证（第六节）
    - 体检表 → python scripts/capa_check.py --file 8D报告.json
第 4 步  按 templates/8D报告.md 输出
第 5 步  人工确认：根因是否触系统、验证窗口是否够
```

## 三、围堵 vs 纠正 vs 预防

| 类型 | 目的 | 例子 |
|---|---|---|
| **围堵（临时措施）** | 防止问题继续流出 | 全检库存、暂停发货、加 100% 检查 |
| **纠正（永久措施）** | 消除已发生的根因 | 更改工装、修订参数、优化流程 |
| **预防（横向展开）** | 防止同类问题在别处发生 | 同工艺线、同供方、同型号排查 |

> 围堵不是"长期方案"：加了全检就要有退出机制，写清楚何时取消、谁批。

## 四、根因分析工具

**5Why**：连续追问为什么，直到触到系统层面（流程缺失、设计缺陷、标准不清）。

| 层 | 问题 | 回答 |
|---|---|---|
| 现象 | 尺寸超差 | — |
| Why1 | 为什么超差 | 装夹不到位 |
| Why2 | 为什么装夹不到位 | 定位销磨损 |
| Why3 | 为什么磨损没发现 | 没在点检表里 |
| Why4 | 为什么没在点检表 | 点检表三年没修订 |
| Why5（根因） | 为什么没修订 | 无文件定期评审机制 |

**倒因为果的典型**：根因写"员工疏忽"——这是把现象当根因；往下问"为什么会允许疏忽发生"。

**鱼骨图/树图**：多因耦合问题（人机料法环测）用鱼骨；系统失效用树图。

## 五、8D 九步

1. **D0 准备**：立项、组队（跨部门）、紧急响应
2. **D1 小组**：成员、职责、组长
3. **D2 问题描述**：对象、现象、数量、时间、地点、5W2H + IS/IS NOT
4. **D3 围堵**：临时措施 + 验证 + 库存处置
5. **D4 根因**：5Why/鱼骨，区分发生原因与流出原因
6. **D5 纠正**：永久措施、验证、更新文件（FMEA/作业指导书/控制计划）
7. **D6 预防**：横向展开、类似过程排查
8. **D7 防再发**：标准化、培训、纳入日常控制
9. **D8 结案**：小组祝贺、关闭、经验沉淀

---

## 六、有效性验证

- **验证窗口**：措施实施后连续观察 ≥ 3 个批次或 ≥ 1 个月（按问题频率定）
- **验证证据**：后续数据、审核记录、现场检查记录
- **未通过**：重新分析根因，升级小组
- **横向展开证据**：排查记录、整改记录

## 七、脚本用法（闭环体检）

```bash
python scripts/capa_check.py --file "D:\质量\8D报告.json"
```

脚本检查五类问题：**要素缺失、根因深度不足（停在人的层面）、围堵无退出机制、无验证窗口、无横向展开**。

> ⚠️ 脚本只做结构与逻辑检查，**不判定根因分析质量**。

---

## 八、人工确认（这步不能省）

- [ ] 根因是否触到系统层面（文件/流程/设计）
- [ ] 围堵措施是否临时、有无退出计划
- [ ] 永久措施是否更新了相关文件（不然会退回去）
- [ ] 验证窗口是否覆盖足够样本
- [ ] 横向展开是否查了同类过程/供方
- [ ] 顾客是否知情（外审外问题按沟通要求）

---

## 九、输出结构（固定三段）

1. **问题状态**——结论先行：已闭环 / 进行中 / 有缺口
2. **8D 完整性**——逐项核对
3. **验证与推广**——证据、横向展开、标准化

## 十、最常见的坑

**坑一：围堵变长期。** 加了全检不撤，成本翻倍还掩盖了真问题。

**坑二：根因写"员工疏忽"。** 倒因为果，明年同一位员工再犯。

**坑三：措施不改文件。** 口头说换新参数，作业指导书还是旧的，新人一翻就退回去。

**坑四：验证走过场。** 实施完第二天就结案，没看后续数据。

**坑五：不横向展开。** A 线的问题不查 B 线，两周后 B 线照样爆。
