# 组织结构设计（org-structure-design）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据组织设计方法论，生成清单：战略与业务对组织的要求、部门划分与职能定位、管理幅度与层级、汇报关系与权责划分、编制配置与运行评估。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 组织结构设计
- 组织架构
- 部门设置
- 汇报关系
- 权责划分

## 三、工作流
1. 明确战略与业务对组织的要求
2. 划分部门并定位职能
3. 确定管理幅度与层级
4. 明确汇报关系与权责
5. 配置编制并评估运行

## 四、核心内容（检查清单与判定）
组织结构应服务战略，部门职能清晰、层级合理、权责对等；设计后须评估运行效率并随业务调整。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含战略与业务要求 | 战略 |
| Q2 | FAIL | 未含部门划分与职能定位 | 部门 |
| Q3 | WARN | 未含管理幅度与层级 | 幅度 |
| Q4 | FAIL | 未含汇报关系与权责划分 | 权责 |
| Q5 | WARN | 未含编制配置与运行评估 | 评估 |

> 脚本 `org-structure-design_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python org-structure-design_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python org-structure-design_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
