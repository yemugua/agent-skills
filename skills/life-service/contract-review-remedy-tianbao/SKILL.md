# 合同条款审查与违约救济核查（contract-review-remedy）

一份合同能不能保住你，**签之前看条款，出事之后看救济**。

签之前看三件事：主体对不对、必备条款全不全、有没有藏着毒条款。
出事之后也看三件事：到底有没有违约、能选哪种救济、证据够不够。

这个技能做五件事：**审条款** → **识风险** → **算金额** → **定救济** → **列证据**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 核查必备条款是否齐全 | ❌ 认定合同有效或无效 |
| 标注高风险条款并给出修改方向 | ❌ 代替律师出具法律意见书 |
| 测算违约金与定金的通行口径 | ❌ 预测法院或仲裁机构的具体裁判结果 |
| 梳理救济路径与证据清单 | ❌ 代为起草诉讼文书或代理诉讼 |
| 提示时效与程序节点 | ❌ 保证胜诉或保证执行到位 |

**遇到以下情况，务必转交执业律师：**
- 争议金额较大，或涉及股权、不动产、知识产权等重大权益
- 合同涉及特许经营、金融、建设工程、涉外等特殊领域
- 需要出具正式法律意见、起草诉讼文书、参与谈判或出庭
- 已经进入诉讼、仲裁程序，或收到法院/仲裁机构文书
- 涉及刑事风险（如合同诈骗）的线索

**永远不要为了让合同"看起来对我有利"而建议隐瞒、删改关键事实或伪造证据。** 这类操作在诉讼中被发现会直接导致主张不被支持，甚至产生新的责任。

## 二、完整工作流

```
第 1 步  拿到合同全文（含附件、补充协议、订单、报价单）
第 2 步  先读规则文件 rules/clause_review.md 与 rules/breach_remedy.md
第 3 步  跑审查脚本
    python scripts/contract_review.py --file 合同.txt \
        --amount 1000000 --liquidated 500000 --loss 200000 --deposit 300000
第 4 步  逐项人工通读复核（脚本只做关键词检索，不做法律判断）
第 5 步  输出审查意见：必备条款表 + 风险条款表 + 金额测算 + 修改建议
第 6 步  已发生违约的，按救济决策路径走，并同步固定证据
```

## 三、九项必备条款（缺一项就留隐患，详见 `rules/clause_review.md`）

| # | 条款 | 缺失后果 |
|---|---|---|
| 1 | 当事人的姓名或名称、住所 | 主体不明，起诉时连被告都列不清 |
| 2 | 标的 | 合同可能不成立 |
| 3 | 数量 | 无法判断履行是否完全 |
| 4 | 质量 | 验收标准缺失，扯皮 |
| 5 | 价款或者报酬 | 计费依据缺失 |
| 6 | 履行期限、地点和方式 | 无法判断逾期与违约 |
| 7 | 违约责任 | 救济路径不清，维权成本高 |
| 8 | 解决争议的方法 | 管辖不明，增加诉讼成本 |

另有六项**建议条款**：通知与送达、不可抗力、验收、变更与解除、保密、知识产权归属。

> **不要一上来就抠措辞。** 见过太多合同写了二十页违约责任，却没写清楚交付时间——违约根本无从判断。

## 四、十类高风险条款（见到就标红）

| 风险条款 | 典型表述 | 风险 |
|---|---|---|
| **单方变更权** | 「甲方有权随时调整价格」 | 对价失衡，履约成本不可控 |
| **无限免责** | 「任何损失均不负责」 | 可能被认定无效，但会诱导对方轻率履约 |
| **排除对方主要权利** | 「乙方不得主张任何权利」 | 格式条款中此类约定可能无效 |
| **自动续约** | 「期满未提异议自动续期一年」 | 被动续期，退出成本高 |
| **背靠背付款** | 「甲方收到第三方款项后再付」 | 第三方不付款的风险被转嫁 |
| **单方指定管辖** | 「由甲方所在地法院管辖」 | 增加己方诉讼成本 |
| **无限连带责任** | 「对甲方一切债务承担连带责任」 | 责任范围不可控 |
| **口头变更** | 「变更一律口头」 | 举证困难 |
| **仲裁条款不明确** | 「提交当地仲裁委员会仲裁」 | 未选定明确仲裁委员会，可能导致仲裁协议无效 |
| **违约金与定金并用** | 同时约定两者 | 一般只能择一适用 |

## 五、违约金与定金的三条硬口径

| 问题 | 通行口径 |
|---|---|
| 违约金过分高于损失 | 约定的违约金过分高于造成的损失的，可以请求人民法院或者仲裁机构**适当减少**；司法实践中常以**超过造成损失的 30%** 作为判断过分高于的参考 |
| 违约金低于损失 | 可以请求**予以增加**，但需举证损失数额与因果关系 |
| 定金上限 | 定金数额**不得超过主合同标的额的 20%**，超过部分不产生定金的效力 |
| 定金罚则 | 给付方不履行无权请求返还；收受方不履行应**双倍返还** |
| 违约金与定金 | 既约定违约金又约定定金的，一方违约时对方**可以选择适用**，一般不能并用 |

**这三条口径的共同前提：以"实际损失"为基准，不是以合同金额或对方获利为基准。**

## 六、五种救济，别只会要钱（详见 `rules/breach_remedy.md`）

| 救济 | 适用 |
|---|---|
| **继续履行** | 仍有履行可能且己方要货不要钱 |
| **采取补救措施** | 质量不符，要求修理、更换、重作、退货、减价 |
| **赔偿损失** | 有实际损失，需证明损失与因果关系 |
| **支付违约金** | 合同有约定，过高或过低可请求调整 |
| **定金罚则** | 有定金约定且已实际交付 |

**选择救济前先想清楚自己要什么**：要货、要钱，还是要解除关系脱身。三种目标的举证重点完全不同。

## 七、脚本用法

```bash
python scripts/contract_review.py --file "D:\合同\采购合同.txt" \
    --amount 1000000 --liquidated 500000 --loss 200000 --deposit 300000
```

| 参数 | 说明 |
|---|---|
| `--file` | 合同文本（`.txt` / `.md`，支持从 Word、PDF 复制出来的纯文本） |
| `--amount` | 合同标的额，用于定金 20% 上限测算 |
| `--liquidated` | 约定违约金数额 |
| `--loss` | 实际损失数额，用于违约金是否过分高于的测算 |
| `--deposit` | 约定定金数额 |
| `--out` / `--format` | 输出文件路径 / `md` 或 `json` |
| `--selftest` | 跑内置自检（13 条断言） |

脚本做四件事：
1. **必备条款扫描**——九项逐项查有没有
2. **建议条款扫描**——六项查有没有
3. **高风险条款抽取**——十类风险按关键词命中并给修改建议
4. **金额测算**——违约金与损失倍数、定金 20% 上限与超出部分、定金罚则、违约金与定金并用提示

> ⚠️ 脚本只做关键词检索，**命中不等于条款合规，缺项也不等于合同无效**。必须人工通读复核。

## 八、人工确认清单（这步不能省）

**签约前：**

- [ ] 主体名称与登记一致，签约人有授权，印章类型正确
- [ ] 标的、数量、质量标准可验证，而不是靠主观评价
- [ ] 价款是否含税、发票类型与开具时间明确
- [ ] 支付节点与可验证的交付/验收节点挂钩
- [ ] 验收标准与验收期限明确，有逾期未验收视为通过的约定
- [ ] 违约情形是**列举**的，而不是一句「违约应承担责任」
- [ ] 违约金可以算出来，计算基数明确
- [ ] 未同时约定违约金与定金
- [ ] 仲裁条款三要素齐全（请求仲裁的意思表示、仲裁事项、选定的仲裁委员会）
- [ ] 通知与送达条款写明了地址与变更通知义务

**违约后：**

- [ ] 义务已经到期（先确认履行期限届至、付款条件成就）
- [ ] 已固定违约证据（交付凭证、验收单、聊天原始记录）
- [ ] 已发书面催告并**保留送达凭证**（EMS + 签收回执）
- [ ] 已采取减损措施（未采取措施致使损失扩大的，扩大部分不予赔偿）
- [ ] 时效未过（普通诉讼时效一般为 3 年）
- [ ] 解除合同的已发出解除通知（不通知不解除）

## 九、最常见的坑

**坑一：没写违约情形，只写"违约应承担责任"。**
无法判断什么叫违约，对方一句"我没违约"就能拖很久。

**坑二：违约金写得越高越好。**
过分高于损失的部分会被调减，写了也拿不到，还可能被认定不合理加重责任。

**坑三：违约金和定金一起主张。**
一般只能择一适用，主张两项会被驳回一项。

**坑四：定金超过标的额 20% 还按定金罚则算。**
超过部分不产生定金效力，只能按预付款或损失处理。

**坑五：对方违约后自己放任损失扩大。**
扩大部分拿不到赔偿，因为违反了减损义务。

**坑六：以为对方违约合同就自动解除。**
不通知不解除，白白错过止损窗口，还可能反过来被主张违约。

**坑七：仲裁条款没选定明确的仲裁委员会。**
可能导致仲裁协议无效，最后还是回法院，白花时间。

**坑八：催告只打电话不留痕。**
无法证明催告过，迟延履行解除的条件就成就不了。

**坑九：只保存聊天截图不保存原始记录。**
截图证明力弱，原始载体与时间戳保全才是可靠做法。

**坑十：拖过诉讼时效。**
3 年看着长，一忙起来就过了；时效抗辩一旦提出，实体权利就很难通过法院强制实现。

## 十、输出结构（固定五段）

1. **结论先行** —— 条款是否齐全、有几项风险、金额测算结论
2. **条款核查表** —— 九项必备 + 六项建议，逐项标有/缺
3. **风险条款清单** —— 风险名称、命中表述、修改建议
4. **金额测算** —— 违约金与损失倍数、定金上限与超出部分、罚则数额
5. **救济路径与证据清单** —— 要货/要钱/要解除三种目标的举证重点

## 十一、边界与免责

- 本技能**不代替**执业律师的法律意见，不构成法律意见书
- 条款效力、违约金调整与赔偿范围**以现行法律规定、司法解释与争议处理机构的认定为准**，本技能只提供通行口径，不引用具体条款号
- **不代写诉讼文书、不代理诉讼、不预测裁判结果**
- 涉及重大金额、复杂交易或已进入程序的争议，应咨询执业律师或专业法律服务机构
- 不得用于伪造、篡改证据或隐瞒关键事实
