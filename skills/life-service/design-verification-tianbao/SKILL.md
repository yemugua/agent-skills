# 设计开发验证与确认（design-verification）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001 设计与开发控制要求，生成设计验证与确认清单：设计输入与输出、设计评审、验证（试验/计算/对比）、确认（试用/客户确认）、设计更改控制。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 设计验证
- 设计确认
- 设计评审
- 设计输入
- 设计更改

## 三、工作流
1. 明确设计输入与输出
2. 组织设计评审
3. 开展设计验证（试验/计算）
4. 进行设计确认（试用/顾客确认）
5. 控制设计更改并评审影响

## 四、核心内容（检查清单与判定）
设计验证证明输出满足输入要求，设计确认证明产品满足预期用途；两者不可互相替代，设计更改须评审、验证并留痕。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含设计输入与输出 | 输入输出 |
| Q2 | WARN | 未含设计评审 | 评审 |
| Q3 | FAIL | 未含设计验证（试验/计算） | 验证 |
| Q4 | FAIL | 未含设计确认（试用/顾客确认） | 确认 |
| Q5 | WARN | 未含设计更改控制 | 更改 |

> 脚本 `design-verification_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python design-verification_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python design-verification_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
