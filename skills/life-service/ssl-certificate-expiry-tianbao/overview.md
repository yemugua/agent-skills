# SSL证书到期更换与配置核查 · 能力概览

## 你会得到什么

一套把「证书到期」和「证书配置」分开处理的完整核查路径——这两类问题的排查手段完全不同，到期看日期，配置看内容，混在一起查必然绕路。

**到期层面**：按剩余天数给出五级分级（>45 天正常 / 16–45 天关注 / 8–15 天告警 / 1–7 天紧急 / ≤0 已过期），并把「notBefore 在未来」单独列为「未生效」——这种情况 `notAfter` 看起来还很长，监控不会报警，但证书实际不可用。Linux 一行命令算天数、Python 跨平台写法、以及批量巡检的写法都给齐。

**配置层面**：证书链三层校验法（叶子 / 中间 / 根，谁该下发、谁不该下发、顺序错了会怎样）、SAN 通配符完整匹配表（`*` 只匹配一级、不跨点、不匹配裸域、IP 必须写进 iPAddress）、签名算法与密钥强度禁用清单（SHA-1、MD5、RSA 1024 一律重签）、Nginx 与 Apache 各十条常见错误写法逐条对照。

**脚本**：`scripts/cert_expiry_check.py` 用纯标准库解析 PEM 证书文本（自建最小 DER 解析，不依赖第三方库），输出剩余天数与分级、算法强度判定、SAN 覆盖判定、链结构判定与换证验证清单，支持 Markdown 与 JSON。

## 典型用法

1. 监控报「N 天后到期」：先分级，确认该走哪个响应节奏，而不是每次都紧急处理。
2. 某个客户端报 `certificate has expired` 但证书看着没到期：先核客户端时钟——续签也解决不了时钟漂移。
3. 新机器/新手机访问某站点报错，其他设备正常：查中间证书是否下发，这类问题「本机测是好的」极具迷惑性。
4. 域名报不匹配：`openssl x509 -ext subjectAltName` 逐条核 SAN，别只看 CN——现代客户端已完全忽略 CN 字段。
5. 换证后彻底验证：十四条清单，含「必须从外部访问」「集群逐台都换」「CDN 边缘与源站都换」这些最常被漏掉的项。

## 边界

- 只做**证书状态核查与配置指引**，不代替现场签发、替换与 reload
- 脚本读的是**证书文本，不是线上端口**。它能告诉你这张证书还剩多少天、SAN 里有没有你的域名，但不能告诉你服务器现在发的是不是这张证书、reload 有没有生效——那两件事必须用在线命令验证
- 任何在线检查**必须带 `-servername`**，否则拿到的是默认站点证书，结论不可信
- **不建议用 `-k` / `verify=False` / `check_hostname=False`「解决」问题**，那只是把问题藏起来
- 证书有效期长度、算法要求、是否需要公共 CA，涉及合规要求时**以现行规定、浏览器与操作系统厂商的根证书要求、以及所在行业的具体规范为准**，各 CA 策略会持续变动
- 私钥疑似泄露必须吊销重签，只换证书文件是不够的
