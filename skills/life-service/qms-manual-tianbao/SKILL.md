# 质量手册编写（qms-manual）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 GB/T 19001-2016 文件化信息要求，生成清单：组织环境与范围界定、过程框架与相互关系、方针目标与职责权限、引用程序文件、版本控制与发布。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 质量手册
- 手册编写
- 质量手册改版
- 手册与程序文件
- 手册范围界定

## 三、工作流
1. 界定组织环境与体系范围
2. 搭建过程框架与相互关系
3. 明确方针目标与职责权限
4. 建立与程序文件的引用关系
5. 落实版本控制与发布审批

## 四、核心内容（检查清单与判定）
质量手册须界定体系范围并对不适用的条款说明理由；常见问题是手册与程序文件、实际运行三张皮，以及删减条款不作说明导致外审开不符合。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含范围界定与不适用说明 | 范围 |
| Q2 | FAIL | 未含过程框架与相互关系 | 过程 |
| Q3 | WARN | 未含方针目标与职责权限 | 职责 |
| Q4 | FAIL | 未含引用程序文件清单 | 引用 |
| Q5 | WARN | 未含版本控制与发布审批 | 版本 |

> 脚本 `qms-manual_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python qms-manual_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python qms-manual_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
