# 质量追溯与批次管理（traceability-batch）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 ISO 9001 标识与可追溯性要求，生成追溯与批次管理清单：批次编号规则、物料标识与流转卡、过程记录（人/机/料/法/环）、正向与反向追溯、追溯演练与时效。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 质量追溯
- 批次管理
- 可追溯性
- 批次追溯
- 追溯演练

## 三、工作流
1. 制定批次编号规则
2. 落实物料标识与流转卡
3. 记录过程要素（人/机/料/法/环）
4. 实现正向与反向追溯
5. 定期演练并考核时效

## 四、核心内容（检查清单与判定）
可追溯性要求能还原产品历史与去向；批次编号与流转记录是基础，应定期做正向/反向追溯演练并验证完成时效。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含批次编号规则 | 编号 |
| Q2 | FAIL | 未含物料标识与流转卡 | 标识 |
| Q3 | WARN | 未含过程记录（人/机/料/法/环） | 记录 |
| Q4 | FAIL | 未含正向与反向追溯 | 追溯 |
| Q5 | WARN | 未含追溯演练与时效 | 演练 |

> 脚本 `traceability-batch_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python traceability-batch_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python traceability-batch_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
