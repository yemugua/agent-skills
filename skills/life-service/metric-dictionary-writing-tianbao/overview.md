# 指标字典编写与口径对齐 · 能力概览

## 你会得到什么

**九个必备字段，每项写明最低标准和缺失后果。** 指标名、业务定义、计算公式、统计维度、时间窗口、数据来源、负责人、更新频率、口径变更记录——其中最常被省略也最致命的是**第九项口径变更记录**：没有它，一年后没人说得清某个数字变化是业务变化还是口径变化。

**命名规范七要素加缩写表。** `业务域_业务对象_统计动作_口径修饰_时间周期`，四条硬规则（不用空泛词、比率型显式标记、累计型必标注、周期必写），以及一份必须随字典发布的缩写表。没有缩写表的命名规范等于没有规范。

**同义词重复建设的识别与合并决策。** `order_cnt`、`order_count`、`order_num`、`order_total` 四个字段并存是最典型的情况。技能给出识别方法（提取「业务对象+统计动作」二元组，出现 ≥2 次进排查）和四种情形的分流处置，其中**同名不同口径**被标为危险项。

**口径变更三段式流程。** 登记 → 影响面评估 → 历史数据处置 → 双跑期 → 通知切换。历史数据处置只有两个合法选项：**全量重算**或**标注断点且两侧不可比**。「不重算也不标断点」被明确列为最危险的一种。

**废弃指标下线的四个前置条件。** 无活跃引用（近 90 天血缘）、已提前 30 天通知、有替代指标、历史数据归档。直接删条目被禁止——删掉之后半年后有人问「以前那个报表的日活是怎么算的」就无解了。

## 典型用法

1. 建字典：从业务域划分（交易域/用户域/内容域/履约域），按模板填满九字段。
2. 「同一个指标三个部门三个数」：先查分子分母，再查时间窗口，最后查口径变更记录，通常三步内能定位。
3. 指标口径要改：走三段式流程，变更记录必须写清是否重算历史。
4. 字典清理：跑脚本查必备字段缺失与同义词重复，废弃项按四条件核对。

## 边界

- 给出的是字段结构、命名规范与流程；指标的**业务含义必须由业务方确定**
- 涉及对外披露、财务结算、法务口径的指标须经相应部门正式确认，以现行规定和主管部门要求为准
- 历史数据重算成本与必要性需评估，不可逆的数据订正应谨慎操作并保留原始数据
- 指标平台的技术实现（血缘采集、自动同步、影响面分析）超出本技能范围
