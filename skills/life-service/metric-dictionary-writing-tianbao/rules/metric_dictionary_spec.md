# 指标字典编写规范

> 建字典、写条目、评审指标口径前，先读这份规范，不要凭印象写。

---

## 一、九项必备字段与最低标准

| # | 字段 | 最低标准 | 反例 |
|---|---|---|---|
| 1 | 指标名 | 业务语言；同名指标全公司唯一 | 「活跃数」（谁活跃？） |
| 2 | 业务定义 | 一句话说明回答什么问题 | 「就是活跃用户」 |
| 3 | 计算公式 | 精确到字段；比率型写明分子分母 | 「大概算一下」 |
| 4 | 统计维度 | 至少一个可拆分维度 | 只有总计 |
| 5 | 时间窗口 | 自然日/滚动 + 时区 + 边界规则 | 「按天」 |
| 6 | 数据来源 | 来源表 + 关键字段 | 「数仓里查」 |
| 7 | 负责人 | 业务 owner + 数据 owner，各一名具体角色 | 「增长部」 |
| 8 | 更新频率 | 频率 + 具体产出时间 | 「T+1」（几点？） |
| 9 | 口径变更记录 | 版本 + 日期 + 内容 + 是否重算 | 空 |

## 二、指标条目模板

```
指标 ID：        trade_order_paid_gmv_1d
指标名称：       支付订单成交额（日）
英文规范名：     trade_order_paid_gmv_1d
业务定义：       用于衡量每日真实发生资金收付的交易规模，不含测试与
                 内部订单。用于日报与经营看板。
计算公式：       SUM(order.pay_amount)
                 WHERE order.pay_status = 'PAID'
                   AND order.is_test = 0
                   AND order.pay_time >= 当日 00:00:00
                   AND order.pay_time < 次日 00:00:00
                 时区：Asia/Shanghai
统计维度：       可拆：支付渠道、终端、新老用户、商品类目、地区
时间窗口：       自然日 00:00:00 ~ 23:59:59（含起不含止），时区
                 Asia/Shanghai
数据来源：       dws.order_detail（字段 pay_amount, pay_status,
                 is_test, pay_time）
业务负责人：     交易产品负责人（角色）
数据负责人：     交易数据 owner（角色）
更新频率：       T+1，每日 09:00 前产出
使用场景：       交易日报、经营看板「结果指标」区
口径变更记录：
  v1.0  2025-01-01  初始口径
  v2.0  2026-03-15  排除测试订单（is_test=0）；历史自 2025-01-01 起全量重算
状态：           active
```

## 三、命名规范七要素

```
业务域_业务对象_统计动作_口径修饰_时间周期
```

| 要素 | 说明 | 示例 |
|---|---|---|
| 业务域 | 归属域 | trade / user / content |
| 业务对象 | 度量实体 | order / user / goods |
| 统计动作 | 做了什么 | paid / active / refund / avg / cnt / sum / ratio |
| 口径修饰 | 包含或排除规则 | all / new / valid / excl_refund |
| 时间周期 | 窗口长度 | 1d / 7d / 30d / mtd / lifetime |

### 四条命名硬规则

| 规则 | ❌ | ✅ |
|---|---|---|
| 不用空泛词 | `order_total` | `trade_order_paid_cnt_1d` |
| 比率型显式标记 | `order_paid_rate` | `trade_order_paid_ratio_1d` |
| 累计型必标注 | `gmv` | `trade_order_paid_gmv_mtd` |
| 周期必写 | `daily_active_user` | `user_active_device_dau_1d` |

### 缩写表（必须随字典发布）

| 缩写 | 全称 | 备注 |
|---|---|---|
| dau | daily active users | 日活 |
| mau | monthly active users | 月活 |
| gmv | gross merchandise value | 成交总额 |
| aov | average order value | 客单价 |
| arpu | average revenue per user | 每用户平均收入 |
| ctr | click through rate | 点击率 |
| cvr | conversion rate | 转化率 |
| mt | metric | 指标 |
| mtd | month to date | 月累计 |
| ytd | year to date | 年累计 |
| ltv | lifetime value | 生命周期价值 |

> 没有缩写表的命名规范等于没有规范。缩写新增必须登记到表里。

## 四、同义词与重复建设识别

| 情形 | 判断 | 处置 |
|---|---|---|
| 同名同口径 | 完全重复 | 保留一个，其余登记为别名 |
| **同名不同口径** | **危险** | 合并决策，或改名区分后并存 |
| 不同名同口径 | 别名泛滥 | 选主名，别名全部登记 |
| 不同名不同口径 | 正常 | 各自建条目，描述里写清区别 |

### 重复建设扫描方法

1. 提取每个指标的「业务对象 + 统计动作」二元组
2. 二元组出现 ≥2 次 → 进入重复排查
3. 逐个对比计算公式，分流为「同口径」与「不同口径」
4. 同口径 → 收敛主名；不同口径 → 改名区分

## 五、口径变更三段式流程

```
① 登记   版本号 + 变更日期 + 变更内容 + 变更人 + 审批人
② 评估   列出所有引用方（报表/看板/API/下游任务）
③ 处置   A 全量重算：以新口径回溯，标注重算区间
         B 断点处理：不重算，标注断点日，两侧不可比
④ 双跑   涉及对外披露或结算时，并行产出 ≥1 个完整周期
⑤ 切换   更新字典 → 通知引用方 → 切换下游 → 下线旧口径
```

### 变更记录写法

```
v1.0  2025-01-01  初始口径：支付订单数 / UV
v2.0  2026-03-15  排除测试订单；历史自 2025-01-01 起全量重算
v3.0  2026-09-01  分子改为支付成功且未退款；历史未重算，断点 2026-09-01
```

**规则**：每条变更记录必须能回答「是否重算历史」。答不上来就是记录不合格。

## 六、废弃指标下线流程

### 四个前置条件

| # | 条件 | 判定标准 |
|---|---|---|
| 1 | 无活跃引用 | 近 90 天血缘中无任何引用 |
| 2 | 已通知 | 提前 ≥30 天通知并确认无人使用 |
| 3 | 有替代 | 明确指向现行指标 |
| 4 | 历史保留 | 已产历史归档，不删除 |

### 废弃条目写法

```
状态：       deprecated
废弃日期：   2026-06-30
废弃原因：   口径与 trade_order_valid_cnt_1d 重复
替代指标：   trade_order_valid_cnt_1d（见字典条目）
最后引用方： 已确认（2026-05-20 通知，6 个使用方全部回复迁移）
历史数据：   已归档至 dwm_archive.order_cnt_legacy，保留 3 年
```

**禁止**：直接从字典删除条目。删除会使历史报表失去出处。

## 七、字典评审检查清单

**字段完备性**
- [ ] 九项必备字段齐全
- [ ] 比率型指标写明分子与分母
- [ ] 时间窗口含时区与边界规则
- [ ] 至少一个可拆分维度
- [ ] 业务定义回答「用来回答什么问题」

**命名与去重**
- [ ] 英文规范名符合七要素
- [ ] 所有缩写在缩写表内
- [ ] 同义词已扫描并做合并决策
- [ ] 无同名不同口径

**变更与废弃**
- [ ] 变更记录能回答「是否重算历史」
- [ ] 断点已标注且两侧不可比
- [ ] 废弃项满足四个前置条件
- [ ] 废弃项指向替代指标

**责任与产出**
- [ ] 业务 owner 与数据 owner 均已指定到具体角色
- [ ] 更新频率含具体产出时间
- [ ] 使用场景写明「谁在何时用它」

## 八、常见反例与改法

| 反例 | 问题 | 改法 |
|---|---|---|
| 指标名「日活数」 | 无业务域、无口径修饰 | `user_active_device_dau_1d` |
| 定义「统计每日活跃用户」 | 只说怎么算不说回答什么 | 「衡量每日有多少设备发生有效访问，用于评估产品黏性」 |
| 公式「COUNT(DISTINCT user_id)」 | 无过滤条件、无时间边界 | 补 WHERE 条件与时间窗口 |
| 频率「T+1」 | 不知几点产出 | 「T+1，每日 09:00 前产出」 |
| owner「增长部」 | 部门不是人 | 写具体角色并设备份 |
| 变更记录空 | 无法追溯口径断点 | 补版本、日期、内容、是否重算 |
| 废弃项直接删除 | 历史报表失去出处 | 标记 deprecated + 替代指标 |
| 定义了没人用 | 维护成本高，最终腐化 | 补使用场景，写不出就不建 |
