## 计算公式写法要求

**计数型：**
```
COUNT(DISTINCT user_id)
WHERE stat_date = 'YYYY-MM-DD'
  AND is_test = 0
```

**金额型：**
```
SUM(pay_amount)
WHERE pay_status = 'PAID'
  AND pay_time >= 'YYYY-MM-DD 00:00:00'
  AND pay_time <  'YYYY-MM-DD+1 00:00:00'
```

**比率型（分子分母必须分列）：**
```
分子：COUNT(DISTINCT paid_order_id)
      WHERE pay_status = 'PAID' AND is_test = 0
分母：COUNT(DISTINCT user_id)
      WHERE event_name = 'checkout_page_view'
口径：分子分母必须来自同一时间窗口与同一用户去重口径
```

## 口径变更记录格式

```
v1.0  YYYY-MM-DD  初始口径：______
v2.0  YYYY-MM-DD  变更内容：______
                  是否重算历史：是，自 YYYY-MM-DD 起全量重算
                  / 否，断点 YYYY-MM-DD，两侧不可直接比较
                  变更人：______  审批人：______  通知范围：______
```

> 每条变更记录必须能回答「是否重算历史」。答不上来即为不合格记录。

## 提交前自检

- [ ] 九项必备字段齐全，无空值
- [ ] 业务定义说明「回答什么问题」，不只是「怎么算」
- [ ] 比率型指标写明分子、分母、同一时间窗口
- [ ] 时间窗口含时区与边界含否规则
- [ ] 至少一个可拆分维度
- [ ] 两位负责人写到具体角色，各有备份
- [ ] 更新频率含具体产出时间
- [ ] 使用场景写明谁在何时用
- [ ] 英文规范名符合七要素，缩写已在缩写表登记
- [ ] 已扫描同义词，无同名不同口径
- [ ] 口径变更记录可回答「是否重算历史」
