# 岗位竞聘演讲稿撰写与结构核查（job-competition-speech）

竞聘演讲不是述职——**述职是证明你做过什么，竞聘是证明你能胜任还没做的事**。

这个技能做三件事：**按四段搭结构** → **把胜任证据写成 STAR 化升级路径** → **卡住时长与扣分点**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出演讲稿结构、时长分配与模板 | ❌ 预测竞聘成功概率或评分结果 |
| 给出 STAR 化胜任证据写法 | ❌ 帮你虚构未经历过的项目或成果 |
| 给出扣分点清单与改写对照 | ❌ 代替单位人事部门的评价标准 |
| 给出问答环节应答结构 | ❌ 指导攻击其他竞聘者或打探内部信息 |
| 核查时长与结构完整度 | ❌ 保证演讲通过 |

**必须先停下来确认的情形：**
- 竞聘岗位的**任职条件、职级要求与选拔程序** —— **以本单位竞聘实施方案和人事部门公布的条件为准**
- 涉及需要**公示、回避或组织考察**的环节 —— 按本单位制度执行
- 演讲时长限制 —— **以主办方通知为准**，本技能的时长分配为通用参考
- 材料中不得包含单位保密信息、他人生日与身份信息

## 二、完整工作流

```
第 1 步  读竞聘方案：确认演讲时长、是否脱稿、是否有问答、评分维度
第 2 步  按 rules/speech_structure.md 排四段结构，定各段字数上限
第 3 步  把 2-3 个真实经历按 rules/competence_evidence.md 写成 STAR 三层升级
第 4 步  写上任打算：按 30/60/90 天分阶段，每阶段给可验收标准
第 5 步  跑脚本体检：python scripts/competition_speech_check.py --file speech.json
第 6 步  看四个数：总时长与目标差、各段时长占比、STAR 完整度、扣分表述命中数
第 7 步  按 §七 改掉八类扣分点，重点是「表态式」表达
第 8 步  掐表预演三遍：录音回放，检查语速、卡顿与结尾
```

**顺序不能颠倒**：第 3 步的证据没准备好，第 2 步的结构再漂亮也是空架子。

## 三、四段结构与时长分配

### 结构与配比（以 10 分钟为例）

| 段 | 占比 | 时长 | 字数（语速 240 字/分） | 写什么 |
|---|---|---|---|---|
| **自我介绍** | 10% | 1 分钟 | 220-260 字 | 姓名、现岗位、与本岗位相关的三个标签 |
| **岗位认知** | 20% | 2 分钟 | 440-520 字 | 这个岗位要解决什么、难点在哪、我的理解 |
| **胜任证据** | 45% | 4.5 分钟 | 1000-1100 字 | 2-3 段 STAR，含一次失败复盘 |
| **上任打算** | 25% | 2.5 分钟 | 560-640 字 | 30/60/90 天计划 + 需要的支持 |

### 不同总时长的分配表

| 总时长 | 自我介绍 | 岗位认知 | 胜任证据 | 上任打算 |
|---|---|---|---|---|
| 5 分钟 | 0.5 分钟 | 1 分钟 | 2.5 分钟 | 1 分钟 |
| 8 分钟 | 0.8 分钟 | 1.5 分钟 | 3.6 分钟 | 2.1 分钟 |
| 10 分钟 | 1 分钟 | 2 分钟 | 4.5 分钟 | 2.5 分钟 |
| 15 分钟 | 1.5 分钟 | 3 分钟 | 7 分钟 | 3.5 分钟 |

**语速换算**：中文演讲舒适语速约每分钟 **220-260 字**，准备时按 **240 字/分钟** 折算字数。语速过快（>280 字/分）听不清，过慢（<200 字/分）显得拖沓。

### 四个关键判断

| 问题 | 判定 |
|---|---|
| 自我介绍能不能省？ | 不能。**这是评委第一次听到你的声音**，且决定了后面所有内容的信任基数 |
| 岗位认知能不能只讲职责？ | 不能。只复述岗位职责等于没讲，**要讲这个岗位真正的难点在哪** |
| 胜任证据要不要讲失败？ | 要。**一次真实的失败复盘比三次成功更能证明可托付**，但要控制在 30 秒内 |
| 上任打算要不要承诺数字？ | 要，但**只承诺能控制的部分**（流程、机制、协同节奏），不承诺超出权限的业绩数字 |

## 四、岗位认知怎么写才有分量

**三步结构**：

```
第 1 步：这个岗位当下最难的一件事是什么（不是职责，是难点）
第 2 步：难点的根因是什么（往机制、人、流程层面找，不停留在表面）
第 3 步：我认为破解路径是什么（给方向，不给完整方案，留给上任后展开）
```

### 示例对照

```
✗ 「这个岗位主要负责团队管理与业务推进，要求有较强的沟通能力和责任心。」
  （复述 JD，任何人都能说）

✓ 「这个岗位当下最难的不是业绩目标，而是跨三个交付线的资源冲突。
   过去半年我观察过类似情况，冲突的根因不是资源不足，
   而是需求排期没有统一入口，各线各自抢产能。
   我的思路是先建立一张统一的排期视图，让优先级在一个地方决定。
   具体怎么做，我会在上任后第一个月落地。」
  （有观察、有根因、有方向、留了空间）
```

**加分点**：说出**这个岗位的真实难点**，通常来自你的实际观察，而不是从 JD 推导。这需要事先做功课：找在岗人员聊、看近半年的相关数据。

## 五、胜任证据的 STAR 三层写法

### 标准 STAR

| 要素 | 写什么 | 常见问题 |
|---|---|---|
| **S 情境** | 当时是什么情况 | 铺垫太长，占掉一半时间 |
| **T 任务** | 你要解决什么 | 写成团队任务，看不出你的角色 |
| **A 行动** | 你具体做了什么 | 写成「我们」，看不出个人贡献 |
| **R 结果** | 造成了什么变化 | 缺数字，或把团队成果写成个人成果 |

### 关键升级：把「经历」讲成「能力的三级台阶」

```
一级：做过什么        —— 我负责过 X 项目的 A 模块
二级：怎么做的更好    —— 我在其中改了 B 环节，结果从 C 变成 D
三级：为什么是我能做  —— 这段经历里我形成了 E 方法，它正好对应本岗位的 F 要求
```

**第三级最关键。** 多数人只讲到二级，评委听到的是履历；讲到三级，评委听到的是**岗位匹配度**。

### 示例

```
✗ 「我之前负责过 XX 系统的开发，带了 3 个人按时上线了。」
  （只有一级，且「带了 3 个人」可能被追问是不是真带）

✓ 「三年前我们的对账流程要人工核对，每月两天。
    当时没人知道问题出在哪，我把三个月的数据全跑了一遍，
   定位到差异集中在跨月的三类订单上。
   我做了两件事：一是把对账口径写成了规则文档，
    二是推动财务和技术各出一个人做交叉校验。
    结果次月起月度对账从两天缩短到四小时，
   差错率从 3% 降到 0.2%。
   这件事让我形成了一个习惯：先定位根因，再动手改流程。
   竞聘这个岗位，我认为需要的正是这种先定位、后落地的做法。」
  （三级台阶齐全，最后一句明确指向岗位）
```

### 没有直接经验怎么办

**不要硬凑，要做迁移。** 用「可迁移能力 + 部分证据 + 学习计划」三段：

```
1. 我没有直接做过 X，但我做过 Y，两者在 A 维度上方法相同
2. 在 Y 中我取得的可核查结果是 Z
3. 对 X 中我没有把握的部分，我的做法是在前 30 天跟着做，快速补齐
```

**承认没有直接经验，比编一段假经历安全得多。** 编的经历在追问下会露馅，而承认差距并给出补齐路径，反而显示可信度。

## 六、上任打算怎么写（30/60/90）

| 阶段 | 做什么 | 可验收标准 | 需要的支持 |
|---|---|---|---|
| **前 30 天** | 摸清现状、梳理关键关系、识别主要矛盾 | 出一份现状清单，明确 3 个最需要解决的问题 | 与在岗人员沟通的时间安排 |
| **30-60 天** | 抓最急的一件事做出来，形成正反馈 | 有一项可量化的改善落地 | 必要的授权与跨部门协调支持 |
| **60-90 天** | 固化机制，纳入常态 | 形成一个可重复运行的机制 | 机制落地的流程与制度安排 |

### 写法要求

| 要求 | 说明 |
|---|---|
| 只承诺可控的 | 流程、机制、协同节奏可承诺；业绩数字超出权限的不承诺 |
| 每阶段只抓一件 | 三个阶段各一件重点，不是九件事 |
| 每阶段有验收标准 | 「建立排期视图」要落到「每周输出一次排期表，各线认领」 |
| 说明需要的支持 | 不要说「请组织支持」，要说清具体支持是什么 |

### 空话对照

```
✗ 「我将尽全力履行职责，带领团队实现目标，不辜负组织的信任。」
  （无信息量，谁都能说）

✓ 「前 30 天我会产出一份现状清单，明确最需要解决的三个问题。
    其中优先解决 XX，因为它是另外两个问题的上游。
    60 天内把 XX 做成可量化的改善。
    我需要的支持是：每月一次跨部门协调会的排期，以及对 Y 流程的授权。」
  （有时间、有重点、有验收、有具体支持）
```

## 七、八类扣分点

| # | 扣分点 | 错误写法 | 正确写法 |
|---|---|---|---|
| 1 | **表态式空话** | 「我将尽全力」「不辜负信任」 | 删掉，换成 30 天做什么 |
| 2 | **复述 JD** | 「这个岗位要求有 X 能力」 | 「这个岗位当下最难的是 X」 |
| 3 | **只讲一级** | 「我做过 X 项目」 | 补二级（怎么做得更好）+ 三级（对应岗位什么） |
| 4 | **没有数字** | 「提升了效率」 | 「从两天缩短到四小时」 |
| 5 | **全是「我们」** | 「我们完成了 X」 | 写清团队人数、分工与我承担的那段 |
| 6 | **过度承诺** | 「一年内让业绩翻三倍」 | 承诺可控的机制与流程改进 |
| 7 | **攻击竞聘者** | 「某些人做事不力所以需要我」 | 删掉，只讲岗位与做法 |
| 8 | **否定前人** | 「原来那套方法不行」 | 「现有做法在 X 场景下有效，在 Y 场景下需要补充」 |

### 三个现场禁忌

| 禁忌 | 后果 |
|---|---|
| 超时被打断 | 内容再好，听不全也扣分。**宁可少讲 30 秒，不要超时** |
| 逐字念稿 | 评委能听出来，一听出来就是准备不足的印象 |
| 结束后说「以上是我的演讲，谢谢大家」 | 无信息量，且占时间。可以改成一句收尾观点 |

## 八、问答与无领导小组环节

### 结构化问答的四步应答

```
1. 复述问题（确认没听错，也给自己争取 3 秒思考时间）
2. 给结论（先说答案，不要先讲背景）
3. 给依据（1-2 条，数字或事实）
4. 收尾（回到岗位，说明这意味着什么）
```

**模板**：

> 「您问的是 [复述问题]。我的看法是 [结论]。依据有两点：一是 [事实/数字]，二是 [事实/数字]。落到这个岗位上，意味着我会 [与岗位相关的行动]。」

### 答不出来的时候

```
「这个问题我没有实践过，不想给不确定的答案。
 如果是我来处理，我会先 [拆解思路]，用 [什么方式] 验证。
 我需要 [X] 时间能给出初步判断。」
```

**承认不知道 + 给出思路，远好于编一个。** 编的会在第二个追问崩掉。

### 无领导小组的三个动作

| # | 动作 | 说明 |
|---|---|---|
| 1 | 前 2 分钟表态并提出框架 | 抢的不是发言权，是定义问题的权利 |
| 2 | 认真接别人的观点并推进 | 「顺着 A 的思路补充一点……」比另起炉灶更受欢迎 |
| 3 | 收尾时做总结而不是重复 | 把讨论过的点归纳成结构，这是最容易展示全局视角的时刻 |

**不要**：抢话、否定所有人、长时间沉默、最后重复别人说过的话。

## 九、脚本用法

```bash
python scripts/competition_speech_check.py --file speech.json --out 演讲稿体检.md
python scripts/competition_speech_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 演讲稿信息 JSON，见下方结构 |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 输出文件，默认 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON：

```json
{
  "title": "竞聘 XX 岗位演讲稿",
  "owner": "本人",
  "target_minutes": 10,
  "speech_rate": 240,
  "sections": [
    {"name": "自我介绍", "text": "各位评委好，我是……"},
    {"name": "岗位认知", "text": "这个岗位当下最难的是……"},
    {"name": "胜任证据", "text": "三年前我们的对账流程……"},
    {"name": "上任打算", "text": "前 30 天我会……"}
  ],
  "evidence": [
    {"label": "对账流程优化",
     "has_situation": true, "has_task": true, "has_action": true,
     "has_result": true, "has_number": true,
     "links_to_job": true, "we_only": false}
  ],
  "risks": ["每年业绩翻三倍", "现在的做法根本不行"]
}
```

| 字段 | 说明 |
|---|---|
| `target_minutes` | 主办方规定的演讲时长 |
| `speech_rate` | 每分钟字数，默认 240 |
| `sections[].text` | 段落正文，脚本会算时长 |
| `evidence[]` | 胜任证据的 STAR 要素与升级层 |
| `risks` | 疑似扣分表述原文 |

脚本输出：总字数与折算时长、各段时长与目标占比偏差、STAR 完整度、证据升级层（第三级占比）、八类扣分词命中清单，以及整改建议。

> 脚本只做结构与时长核查，**不预测竞聘结果，也不评价你的经历是否胜任**。

## 十、人工确认清单（这步不能省）

- [ ] 已读竞聘方案，确认时长、是否脱稿、有无问答、评分维度
- [ ] 四段结构齐全，各段时长在目标区间
- [ ] 总时长留 5-10% 余量，宁可少讲不要超时
- [ ] 岗位认知讲了真实难点，不是复述 JD
- [ ] 胜任证据 2-3 段，每段 STAR 齐全
- [ ] 至少一段证据讲到第三级（为什么是我能做）
- [ ] 至少一段证据含失败复盘，控制在 30 秒内
- [ ] 每个证据结果都有数字
- [ ] 团队成果已写清人数、分工与自己承担的部分
- [ ] 无直接经验的部分已用迁移法处理，未编造经历
- [ ] 上任打算分 30/60/90，每阶段有验收标准
- [ ] 承诺的都在权限范围内
- [ ] 八类扣分点已逐条删改
- [ ] 未攻击其他竞聘者、未否定前人做法
- [ ] 材料不含单位保密信息与他人个人信息

## 十一、最常见的坑

**坑一：把竞聘演讲写成述职。**
错误做法：通篇讲自己过去一年做了什么。正确做法：述职证明做过什么，**竞聘要证明能胜任还没做的事**。多花时间在「这个岗位难在哪、我会怎么做」上。

**坑二：自我介绍写成简历。**
错误做法：「本人 X 年经验，历任 A、B、C 岗位，获 X 奖。」正确做法：姓名 + 现岗位 + **与本岗位相关的三个标签**。**这是评委第一次听到你的声音**，也是后面所有内容的信任基数。

**坑三：岗位认知复述 JD。**
错误做法：「这个岗位要求有较强的沟通能力和管理能力。」正确做法：说出这个岗位当下真正的难点，往机制层面找根因。**谁都能念 JD，说出难点需要真观察过。**

**坑四：胜任证据只讲到一级。**
错误做法：「我负责过 X 项目。」（只有经历，没有能力提炼）正确做法：补二级（怎么做得更好、结果从 C 变 D）+ 三级（这形成了什么方法，正好对应岗位什么要求）。**第三级是岗位匹配度，评委只听这个。**

**坑五：没有数字。**
错误做法：「提升了效率、获得了好评」。正确做法：「从两天缩短到四小时，差错率从 3% 降到 0.2%」。**数字是可信度的唯一载体。**

**坑六：表态式空话占篇幅。**
错误做法：「我将尽全力履行职责，不辜负组织的信任」。正确做法：删掉，换成 30 天要做什么。**谁都能说的话不占评委的记忆容量。**

**坑七：过度承诺业绩数字。**
错误做法：「一年内让业绩翻三倍」。正确做法：承诺可控的机制与流程改进，业绩承诺留到有数据支撑时。**超出权限的承诺一旦没做到，比不承诺更伤。**

**坑八：攻击竞聘者或否定前人。**
错误做法：「某些人做事不力」「原来的方法根本不行」。正确做法：「现有做法在 X 场景有效，在 Y 场景需要补充」。**攻击同行是减分项，评委会记得很清楚。**

**坑九：没有直接经验就硬凑。**
错误做法：把做过的相似事情包装成直接经验。正确做法：用「可迁移能力 + 部分证据 + 补齐计划」三段。**编的经历在追问下会露馅，承认差距反而显示可信度。**

**坑十：超时或逐字念稿。**
错误做法：稿子写到超时，或照着念。正确做法：总时长留 5-10% 余量，只写关键词卡不写全稿。**内容再好，被打断就听不全。**
