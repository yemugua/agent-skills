# RAG 文档切分规则库

> 设计切分策略、调整参数、或排查召回问题前，先读这份规则。

---

## 一、四类策略对照表

| 策略 | 做法 | 适用 | 优点 | 缺点 |
|---|---|---|---|---|
| 固定长度 | 按字符/token 硬切 | 长叙述文本 | 简单、均匀 | 破坏语义完整性 |
| 按结构 | 按标题/段落/条目切 | 制度、手册、技术文档 | 保留语义边界 | 依赖结构规整 |
| 语义 | 按相似度断点切 | 无结构长文本 | 语义完整 | 成本高、块大小不可控 |
| 父子块 | 小块检索、大块入上下文 | 超长文档 | 兼顾精度与上下文 | 实现复杂 |

**选择顺序**：有结构 → 按结构切；无结构长叙述 → 语义或固定长度；既要精度又要上下文 → 父子块。

---

## 二、chunk size 与 overlap 经验区间

| 文档类型 | chunk size（中文） | overlap | 说明 |
|---|---|---|---|
| FAQ / 短问答 | 150–300 字 | 10% | 一个问答落在一块 |
| 制度 / 手册 | 300–600 字 | 15%–20% | 对齐章节 |
| 技术 / API 文档 | 400–800 字 | 15% | 代码块单独处理 |
| 论文 / 报告 | 600–1000 字 | 10%–15% | 太大稀释主题 |
| 对话记录 | 200–400 字 | 20% | 按轮次切 |

### token 估算

```
中文：1 字 ≈ 0.7–1.2 token（保守按 1:1）
英文：1 词 ≈ 1.3 token
混合：按中文占比加权
```

**必须按 token 设定，不要按字符。** embedding 模型上下文上限常见为 512 / 8192 token。

### overlap 规则

| 区间 | 判定 |
|---|---|
| < 5% | 边界风险高，答案易被切开 |
| 10%–20% | **推荐区间** |
| > 25% | 存储成本上升，收益递减 |

**优先按句子/段落边界切，而不是靠 overlap 补救。**

## 三、特殊内容处理

| 类型 | 正确做法 |
|---|---|
| 表格 | 整体成块或「表头+数据行」，**每块重复表头** |
| 代码 | 按函数/类边界切，保证括号配对 |
| 公式 | 独立成块，保留 LaTeX 原文 |
| 多级标题 | 保留完整标题路径 |
| 列表 | 整体成块，保留列表符号 |
| 页眉页脚 | **清洗时删除** |

**表格每块带表头的示例：**

```
❌ chunk1: | 地区 | 销售额 |      chunk2: | 北京 | 100 |
✅ chunk1: | 地区 | 销售额 |      chunk2: | 地区 | 销售额 |
           | 北京 | 100    |                  | 北京 | 100    |
```

## 四、切分质量四项校验

| 校验项 | 方法 | 合格标准 |
|---|---|---|
| 入库完整性 | 原文字数 vs chunk 总字数 | 差异 < 1% |
| 块大小分布 | 最大/最小/均值 | 无超上限 1.5 倍的块；无大量 < 50 字碎块 |
| 重叠有效性 | 相邻块重叠率 | 10%–20% |
| 结构完整性 | 标题路径、表头 | 标题路径完整；表格块含表头 |

**必须先做完这四项再讨论召回率。**

---

## 五、召回下降五步排查顺序

```
1. 入库完整性  → 原文与 chunk 总字数是否对得上
2. 切分参数    → size/overlap 最近是否改过
3. 检索参数    → top_k、相似度阈值、查询改写
4. embedding 一致性 → 索引模型与查询模型是否同一版本
5. 数据更新    → 文档更新后索引是否同步、旧 chunk 是否清理
```

**第 4 步最隐蔽：换 embedding 模型不重建索引，会导致召回率断崖式下跌。**

## 六、三个权衡杠杆

| 杠杆 | 调大效果 | 代价 |
|---|---|---|
| top_k | 召回率↑ | 精确率↓，噪声干扰生成 |
| overlap | 边界召回↑ | 存储与索引重复↑ |
| chunk size | 小→精确率↑ | 上下文不完整→回答质量↓ |

### 调整方向

```
召回不足 → 先加大 chunk size → 再加大 top_k → 最后 overlap 提到 20%
精确率不足 → 先减小 top_k → 再减小 chunk size → 最后加相似度阈值
答案不完整 → 父子块（检索小块，入上下文大块）
```

**top_k 越大不一定越好。建议检索候选后重排，取 top 3–5 条。**

## 七、常见坑对照

| 坑 | 错误做法 | 正确做法 |
|---|---|---|
| 无基线调参 | 凭感觉改 | 先建 20–50 题评测集与基线 |
| 结构化文档固定切 | 40 页制度按 500 字硬切 | 按标题层级切 |
| 表格硬切 | 数据块无表头 | 每块重复表头 |
| 换模型不重建 | 索引与查询不在同一空间 | 换模型必重建全量索引 |
| overlap=0 | 答案被切成两半 | ≥10% 或按句切 |
| chunk 过小 | 答案跨块 | 加大或用父子块 |
| 无限加 top_k | 塞 20 条噪声 | rerank 后取 3–5 条 |
| 入库不完整 | 调参数无用 | 先查入库完整性 |
| 页眉页脚残留 | 稀释主题向量 | 清洗时删除 |
| 按字符设 token | 超出模型上限 | 按 token 设定 |
