# 消防设施维护保养（fire-facility-maintenance）

> 领域：消防 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据《建筑消防设施的维护管理》GB 25201，生成消防设施维保清单：维保对象、周期（月/季/年）、功能性试验、维保记录与故障报修闭环。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 消防设施维保
- 消防维保
- 检测维保
- 灭火器送检
- 喷淋试水
- 报警主机维保

## 三、工作流
1. 列出维保对象（灭火器/消火栓/报警/喷淋/排烟）
2. 明确维保周期（月/季/年）与依据
3. 开展检测与功能性试验
4. 形成维保记录与双方签字确认
5. 故障报修闭环与档案留存

## 四、核心内容（检查清单与判定）
GB 25201 规定建筑消防设施应明确巡查、检测、维修、保养周期；设有自动消防设施的单位应与有资质机构签订维保合同并留存记录。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未列维保对象（灭火器/消火栓/报警/喷淋/排烟） | 维保对象 |
| Q2 | FAIL | 未明维保周期（月/季/年）与依据（GB 25201） | 周期 |
| Q3 | WARN | 未含检测/功能性试验（如喷淋末端试水） | 检测 |
| Q4 | FAIL | 未含维保记录与签字确认 | 记录 |
| Q5 | WARN | 未含故障报修闭环 | 闭环 |

> 脚本 `fire-facility-maintenance_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python fire-facility-maintenance_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python fire-facility-maintenance_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
