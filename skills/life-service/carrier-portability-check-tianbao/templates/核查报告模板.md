# 携号转网核查报告模板

> 报告由 `scripts/carrier_check.py` 自动生成。此模板供人工复核时对照使用。

## 报告结构（11 段）

| 段 | 标题 | 回答什么问题 |
|---|---|---|
| 一 | 结论摘要 | 能不能办？卡在哪？共几项不通过/有风险/待补正 |
| 二 | 资格条件逐项核查 | 120 天够不够、在网状态、合约与赠品是否干净 |
| 三 | 不可携情形核查 | 是否属于政企/物联网/宽带捆绑/主副卡/靓号 |
| 四 | 号码与账户风险 | 银行、验证码、第三方绑定、骚扰登记 |
| 五 | 时限倒计时 | 资格届满日、24 小时激活窗口、受理时效 |
| 六 | 拒绝情形与申诉阶梯 | 拒绝理由属于哪一类、有没有书面依据 |
| 七 | 投诉渠道与受理 | 工单、工信部、12345、12315 走没走 |
| 八 | 证据清单与缺口 | 六类证据齐不齐、缺什么 |
| 九 | 办理与申诉路径排序 | 第 1 步到第 7 步按什么顺序做 |
| 十 | 证据缺口速查 | 每个缺口对应的补法 |
| 十一 | 待办补正动作 | 可直接照着做的动作清单 |
| — | 边界与纪律 | 免责与口径说明 |

## 四态判定口径

| 状态 | 含义 | 处理方式 |
|---|---|---|
| **通过** | 该项已满足要求 | 无需动作 |
| **有风险** | 可争取但有隐患 | 按说明提前处理 |
| **不通过** | 明确不满足或属于不可携情形 | 必须先解决硬门槛 |
| **待补正** | 信息未填或填了但无法判断 | **未填一律不算通过** |

## 复核要点

1. **入网日期**是否真实（影响 120 天计算）
2. **合约到期日**是否已过（决定能否受理）
3. **携出通知日期**与今天是否相差超过 1 天（决定 24 小时窗口是否已过）
4. **银行与免密绑定**是否已清理（决定停机后是否扣费失败）
5. 报告里所有"不通过"项是否已在第九段路径中有对应动作
