# 七日无理由退货与例外核查

## 你会得到什么

把七日无理由拆成两道独立门槛——**商品类别例外**与**商品完好**——逐项核查。这通常是商家最常用的两个拒绝理由。

**一、例外清单，以现行规定列举为准。** 定制品、鲜活易腐、拆封的音像制品与计算机软件、交付的报纸期刊、消费者已确认的与商品性能不符的瑕疵、定制礼物、网络下载或已拆封的数字化商品。**具体列举范围以现行规定为准**，各地与不同商品类别的执行口径可能存在差异，不作扩张解释。

**最容易搞错的一条**：拆封类例外只针对**特定品类**（音像制品、计算机软件、数字化商品），不是所有商品。拆封一双鞋、拆开食品包装**不因为「拆封了」就构成例外**。商家拿「已拆封」拒绝一切退换，是需要驳斥的。

**二、商品完好的判断标准**，核心判据是「是否因查验或使用而影响二次销售」。给了包装、配件、吊牌、使用痕迹、商品本体五个要素的影响对照。关键界线是**查验 vs 使用**：为确认质量而试穿试听属查验，穿着出门、日常使用属使用，后者可能影响完好认定。

**三、起算时点的实操确认方法**：不要与商家争从哪天算，直接要求商家在订单系统中出示该笔订单的退货截止日期——系统数据对双方都有约束力。

**四、举证责任分配，这是最有力的一条**：例外情形的适用与商品不完好，**均由经营者举证**；消费者只需证明收到商品且完好、在期限内提出。

**五、退货与换货的法律性质不同**。七日无理由对应退货（解除合同），换货通常按质量问题路径走且不当然适用无理由。

**六、运费承担与运费险对比**：一般规则是谁主张谁承担；退货运费险是保险产品可能限额赔付需按条款理赔，商家包退是单方承诺，两者不冲突，先看商家承诺能否覆盖。

所有时限、运费标准与列举范围一律以现行规定和受理机构口径为准，不写死天数与金额。

## 典型用法

- 「拆封了还能退吗」：先确认商品类别，拆封例外只针对特定品类。
- 「商家说是定制品」：定制的举证责任在商家，要求其证明。
- 「商品完好怎么认定」：五要素对照加查验与使用的界线。
- 「七天从哪天算」：让商家出示系统退货截止日期。
- 「运费谁出」：无理由退货通常消费者承担；商家问题则相反。

## 脚本

`seven_day_judge.py` 读入商品 JSON，输出例外命中、完好判定、举证责任归属与运费方向提示，带 `--selftest`。

## 边界

不写死具体天数、金额与条款编号，不承诺退成与否。例外列举范围、商品完好的最终认定与运费标准以现行规定和受理机构口径为准。实质争议请通过平台、监管部门或司法途径解决。
