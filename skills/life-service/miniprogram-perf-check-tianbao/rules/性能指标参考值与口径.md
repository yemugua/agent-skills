# 性能指标参考值与测量口径

> 通用参考值，用于快速定位量级问题。最终以官方文档、真机实测与目标机型表现为准。

## 一、参考阈值

| 指标 | 达标 | 需优化 | 严重超标 |
| --- | --- | --- | --- |
| 主包体积 | < 1.5 MB | 1.5–2 MB | > 2 MB（超限无法上传） |
| 总包体积 | < 20 MB | — | > 20 MB |
| 冷启动耗时 | < 3000 ms | 3000–5000 ms | > 5000 ms |
| 首屏渲染耗时 | < 2000 ms | 2000–3500 ms | > 3500 ms |
| 页面切换耗时 | < 500 ms | > 500 ms | — |
| 单次 setData 数据量 | < 256 KB | 256–1024 KB | > 1024 KB |
| setData 调用频率 | < 20 次/秒 | > 20 次/秒 | — |
| 接口平均响应 | < 500 ms | 500–1500 ms | > 1500 ms |
| 图片平均大小 | < 100 KB | 100–300 KB | > 300 KB |
| 首屏请求数 | <= 5 个 | > 5 个 | — |

## 二、测量口径（很重要，否则数据不可比）

- **冷启动**：杀掉小程序进程后首次打开，取多次测量的**中位数**，不要用单次值。
- **真机优先**：开发者工具的数值与真机差异很大，不能作为验收依据。
- **目标机型**：以你的用户主力机型为准，低端机达标才算达标。
- **首屏渲染**：以用户看到有效内容为准，不是页面 onLoad 的时间。
- **setData 数据量**：指单次调用传输的数据序列化后大小，不是界面显示条数。

## 三、包体积硬限制

- 主包与单个分包存在体积上限（常见为 2 MB），超限**无法上传**，必须拆分。
- 总包也有整体上限，超限同样无法发布。
- 上限数值以官方当前规定为准。

## 四、常见误判

- 把开发者工具的数据当真机数据 → 结论偏乐观。
- 只测高端机 → 低端机用户实际体验被忽略。
- 只看启动耗时不看包体积 → 找不到根因。
- 一次改多项并只复测一次 → 无法定位哪项改动生效。
