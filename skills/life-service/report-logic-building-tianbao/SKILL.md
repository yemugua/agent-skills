# 汇报逻辑搭建与表达核查（report-logic-building）

汇报没重点，九成不是内容不够，而是**层级错了**：把并列的三件事当成「第一、第二、第三」，它们却不是同一个分类标准下的三个分支。

这个技能做三件事：**用金字塔四条原则搭骨架** → **用 MECE 检查分组** → **按对象调表达**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出金字塔结构与自检方法 | ❌ 替你做事实判断或数据核实 |
| 给出 SCQA 引入模板 | ❌ 保证汇报一定被接受 |
| 给出 MECE 检查清单 | ❌ 代替业务判断决定分类标准 |
| 给出图表选配规则 | ❌ 生成可能误导的图表 |
| 给出分对象的表达调整表 | ❌ 代替对方的决策与判断 |

**必须先停下来确认的情形：**
- 数据来源不明或未经核实 —— **先核实再汇报**
- 涉及未公开信息、个人评价、人事变动 —— 按公司保密要求处理
- 需要对方立即决策的紧急事项 —— 先给结论与选项，不要先铺垫背景
- 结论涉及他人责任 —— 只讲事实与依据，不评价人

## 二、完整工作流

```
第 1 步  先定一句话结论：这封汇报如果只留一句，留哪句
第 2 步  按 rules/pyramid_rules.md 排金字塔：顶句 + 3 个分支 + 各分支支撑
第 3 步  用 SCQA 引入开场（S 情境 / C 冲突 / Q 问题 / A 答案）
第 4 步  用 rules/mece_checklist.md 逐项检查每个分组的分类标准
第 5 步  跑脚本体检：python scripts/logic_check.py --file logic.json
第 6 步  看四个数：论点收敛率、分类 MECE 通过率、层级一致率、图表匹配率
第 7 步  按 rules/audience_adjust.md 调整表达：同一内容，五种说法
第 8 步  按 §九 做十类逻辑病自查，改完再发
```

**顺序不能颠倒**：第 1 步的结论没定，第 2 步的分支一定散。**没有结论的汇报，本质是信息堆。**

## 三、金字塔四条原则

```
                    ┌─────────────┐
                    │  顶句（结论）│  ← 全文唯一核心观点
                    └──────┬──────┘
            ┌──────────────┼──────────────┐
        ┌───┴───┐      ┌───┴───┐      ┌───┴───┐
        │ 分支1 │      │ 分支2 │      │ 分支3 │  ← 同一层级、同一维度
        └───┬───┘      └───┬───┘      └───┬───┘
          支撑           支撑             支撑    ← 论据与数据
```

### 四条原则

| # | 原则 | 说明 | 自检方法 |
|---|---|---|---|
| 1 | **结论先行** | 开头就给结论，不从背景讲起 | 把第一段遮住，能看出结论吗 |
| 2 | **以上统下** | 每一层的意思能概括下一层 | 试着用一个字概括三个分支 |
| 3 | **归类分组** | 同一层的分支必须同维度 | 三个分支能用同一个问句回答吗 |
| 4 | **逻辑递进** | 分支之间按时间/程度/因果排序 | 顺序打乱后读者会不会困惑 |

### 顶句怎么写

顶句必须满足三条：

```
1. 是一句完整的判断，不是话题（「关于 X 的分析」不是顶句）
2. 能被下层论证（如果分支撑不住顶句，顶句写错了）
3. 包含对方关心的信息（不是自我表达）
```

| ✗ 不是顶句 | ✓ 是顶句 |
|---|---|
| 「关于用户流失的分析」 | 「流失集中在首月未完成引导的用户，建议把引导前置到注册当次」 |
| 「本次汇报三个部分」 | 「建议暂停渠道 B 的投放，把预算转到渠道 C」 |
| 「现状与问题」 | 「问题不在需求，在交付节奏」 |

## 四、SCQA 引入模板

```
S 情境（Situation）：大家都认可的事实，一两句带过
C 冲突（Complication）：出现了什么变化，打破了原有判断
Q 问题（Question）：因此需要回答的核心问题
A 答案（Answer）：你的结论，直接接金字塔顶句
```

### 示例

```
S：这个项目的交付节奏一直是每月一个版本，上线后没出过问题。
C：这个月客户临时加了三个需求，我们发现交付周期被压到了原来的一倍。
Q：接不接这批需求？接的话怎么排期才不拖累后续版本？
A：建议接，但把三个需求拆到下两个版本，本版本只做其中最紧急的一个。
   理由有三条……（进入金字塔）
```

**S 不能超过两句。** 情景铺垫长了，读者就抓不到冲突。

## 五、MECE 检查清单

| # | 检查项 | 判定方法 |
|---|---|---|
| 1 | 分支是否互斥 | 任两个分支能否同时属于一类？ |
| 2 | 分支是否穷尽 | 明确说一句「除此之外不属于这类」，试试能否找到反例 |
| 3 | 分类标准是否单一 | 同一层有没有用两个不同标准分类 |
| 4 | 同层是否同粒度 | 有没有「A 小项」和「B 大类」并列 |
| 5 | 分支数量是否可控 | 是否超过 5 个（超过要合并或下沉） |
| 6 | 名称是否同一句式 | 有没有一个是动词短语、一个是名词短语 |
| 7 | 层级是否一致 | 每个分支下面是不是同一级的内容 |
| 8 | 是否与顶句同维度 | 分支是不是在论证顶句，而不是另起话题 |
| 9 | 顺序是否有逻辑 | 时间/程度/因果是否说得通 |
| 10 | 空分支是否存在 | 是否列了「其他」占位 |

### 最常见的 MECE 错误

| 错误 | 问题 | 改法 |
|---|---|---|
| 「线上渠道、线下渠道、社交媒体」 | 线上和社交媒体重叠 | 改成「自建渠道、投放渠道、代理渠道」 |
| 「成本、费用、管理费用」 | 费用包含成本 | 改成同层级的三项 |
| 「大客户、中小客户、其他」 | 「其他」是占位，不是分类 | 找出第三类的实际特征 |
| 「收入增长、成本下降、效率提升」 | 三个不同维度（结果/原因） | 拆成两层 |

## 六、同一内容对五种对象的表达调整

| 对象 | 关心什么 | 开头给什么 | 省略什么 | 举例 |
|---|---|---|---|---|
| **直属上级** | 进度、风险、需要他做什么 | 结论 + 需要决策的点 | 过程细节 | 「三件事，其中 B 卡住了需要你协调」 |
| **隔级领导** | 方向、影响面、资源 | 结论 + 对整体的影响 | 执行细节 | 「B 卡住会影响下季度目标，已启动替代方案」 |
| **平级同事** | 接口、时点、责任人 | 我要做的事 + 需要你配合的 | 我的内部进展 | 「我这周三要交付 X，需要你 Y 部门周三前给 Z」 |
| **下属** | 目标、边界、反馈 | 目标 + 他要做的部分 | 我为什么这么做 | 「你这周只做 X，做完不用管 Y」 |
| **外部客户/合作方** | 他的利益、交付承诺 | 对他的承诺 + 时间 | 内部流程与分工 | 「我们保证 X 日交付，质量标准是 Y」 |

**原则**：对谁说，就把对方关心的那个变量放到第一句。**不要用同一份材料讲给所有人。**

## 七、图表选配规则

| 想表达的关系 | 用什么图 | 不要用 |
|---|---|---|
| 随时间的趋势 | 折线图 | 柱状图（时间序列用柱状会误读趋势） |
| 类目之间的比较 | 柱状图 | 饼图（超过 5 个扇区就难比较） |
| 构成占比（≤4 项） | 饼图/环形图 | 多层饼图 |
| 两个变量的关联 | 散点图 | 双轴柱状图（容易制造假相关） |
| 流程与阶段 | 流程图 | 表格 |
| 时间跨度对比 | 甘特图 | 柱状图 |
| 分布 | 直方图 / 箱线图 | 饼图 |

### 图表四条通则

```
1. 一个图只说一件事
2. 标题写结论，不写「XX 数据图」
3. 坐标轴从 0 开始（截断会夸大差异）
4. 数据点不超过 7 个，多了看不清
```

### 图表标题写法

```
✗ 「2026 年销售数据」
✓ 「销售连续两季度下滑，Q4 环比 -12%」
```

## 八、论点收敛三步法

论点太多时按顺序做：

```
第 1 步  筛：只留与顶句直接相关的，其余下沉为附录
第 2 步  合：同维度的分支合并，控制在 3-5 个
第 3 步  排：按重要性排，不按时间顺序排
```

**常见误区**：把 5 个论点并成 3 个，但合并后的分类标准不统一。**合并前先确认能用同一个问句回答。**

## 九、十类逻辑病与改法

| # | 病 | 表现 | 改法 |
|---|---|---|---|
| 1 | 无结论 | 通篇背景与过程 | 第一段给顶句 |
| 2 | 论点无上级 | 列了三点但不知属于什么 | 补一个能概括三点的顶句 |
| 3 | 分类重叠 | 「线上渠道、社交媒体」 | 换一个单一标准重分 |
| 4 | 标准不一 | 同层用了两个维度 | 统一成一个标准 |
| 5 | 粒度不齐 | 大类和小项并列 | 把小的合并进大的 |
| 6 | 分支过多 | 列了 8 条 | 合并到 3-5 条，其余下沉 |
| 7 | 「其他」占位 | 「其他 XX」 | 找出这类实际特征 |
| 8 | 顺序无逻辑 | 想到哪写到哪 | 按重要性或时间排 |
| 9 | 论据不支撑 | 论点很大，数据很小 | 补论据或缩小论点 |
| 10 | 层级跳跃 | 顶层与底层差两级 | 补中间层 |

## 十、脚本用法

```bash
python scripts/logic_check.py --file logic.json --out 逻辑体检.md
python scripts/logic_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 汇报逻辑 JSON，见下方结构 |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 输出文件，默认 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON：

```json
{
  "title": "季度复盘汇报",
  "audience": "直属上级",
  "lead_sentence": "建议暂停渠道 B 投放，把预算转到渠道 C",
  "conclusion_first": true,
  "scqa": {"s": "三个渠道按月投放", "c": "B 渠道连续两月 ROI 下降",
           "q": "是否调整预算分配", "a": "建议转向 C"},
  "branches": [
    {"name": "渠道 B ROI 持续下降", "dimension": "渠道表现", "granularity": "same",
     "covered": true, "overlaps": [], "placeholder": false, "supports_top": true},
    {"name": "渠道 C 转化率提升", "dimension": "渠道表现", "granularity": "same",
     "covered": true, "overlaps": [], "placeholder": false, "supports_top": true},
    {"name": "其他渠道待观察", "dimension": "渠道表现", "granularity": "same",
     "covered": false, "overlaps": [], "placeholder": true, "supports_top": true}
  ],
  "charts": [
    {"type": "line", "purpose": "trend", "conclusion_title": true, "items": 6,
     "axis_from_zero": true}
  ],
  "wording": ["先说一下背景", "众所周知"]
}
```

| 字段 | 说明 |
|---|---|
| `branches[].dimension` | 分类标准，同层必须一致 |
| `branches[].granularity` | `same` 同粒度 / `mixed` 粒度不齐 |
| `branches[].overlaps` | 与其他分支重叠的分支名 |
| `branches[].placeholder` | 是否为「其他」占位 |
| `branches[].supports_top` | 是否支撑顶句 |
| `charts[].type` | `line` / `bar` / `pie` / `scatter` / `table` / `gantt` / `hist` |
| `charts[].purpose` | `trend` / `compare` / `compose` / `correlate` / `flow` / `schedule` / `distribution` |
| `charts[].items` | 数据点数量 |

脚本输出：论点收敛率、分类标准一致性、互斥性与穷尽性、层级一致率、图表匹配率与超载提示、冗余表述命中，以及整改建议。

> 脚本只做结构与形式核查，**不判断你的结论是否正确，也不替你做数据核实**。

## 十一、人工确认清单（这步不能省）

- [ ] 顶句是一句完整判断，不是话题
- [ ] 结论在第一段，不从背景讲起
- [ ] 三个分支能概括成一个问句
- [ ] 同层分类标准单一，没有两个维度混用
- [ ] 分支互斥：任两个不能同时成立
- [ ] 分支穷尽：没有「其他」占位
- [ ] 分支数控制在 3-5 个
- [ ] 粒度一致，没有大类与小项并列
- [ ] 每个分支都支撑顶句
- [ ] 顺序按重要性或逻辑，不按想到的顺序
- [ ] 论据能支撑论点的大小
- [ ] 图表达配正确，一个图只说一件事
- [ ] 图表标题写的是结论不是话题
- [ ] 坐标轴从 0 开始
- [ ] 已按对象调整表达，把对方关心的放第一句
- [ ] 所有数据来源清楚且已核实
- [ ] 涉及未公开信息与个人评价的内容已按保密要求处理

## 十二、最常见的坑

**坑一：从背景讲起。**
错误做法：先讲半年来的行业变化、公司环境，再讲结论。正确做法：第一段就是顶句，背景放 SCQA 的 S 里，一两句带过。**读者读第一段时不知道你要说什么，就会直接停。**

**坑二：论点没有上级概念。**
错误做法：列出第一、第二、第三，但说不出这三点在论证什么。正确做法：补一个能概括三点的顶句。**三五个没有归属的论点等于没有论点。**

**坑三：分类标准不统一。**
错误做法：「收入增长、成本下降、效率提升」——前两个是结果，第三个是原因，维度不同。正确做法：把三者归到「经营改善」下面，再往下分。**同一层的分支必须能用同一个问句回答。**

**坑四：分类重叠。**
错误做法：「线上渠道、线下渠道、社交媒体」——社交媒体属于线上。正确做法：改成「自建、投放、代理」这种互斥的标准。**重叠的分类会让读者怀疑你的严谨度。**

**坑五：用「其他」占位。**
错误做法：列了 A、B、其他。正确做法：找出第三类的实际特征再命名。**「其他」说明你自己也没想清楚。**

**坑六：分支太多。**
错误做法：一页列 8 条。正确做法：合并到 3-5 条，其余下沉为附录。**超过 5 个分支，读者会直接放弃记忆。**

**坑七：一份材料讲给所有人。**
错误做法：对隔级领导和平级同事发同一份汇报稿。正确做法：把对方关心的变量放到第一句，其余省略。**对方关心什么，你的开头就该是什么。**

**坑八：图表选错类型。**
错误做法：用饼图做时间趋势，用柱状图比较 8 个类目。正确做法：趋势用折线，类目比较用柱状，构成占比（≤4 项）用饼图。**图表选错会直接导致误读。**

**坑九：图表标题写话题。**
错误做法：图标题写「2026 年销售数据」。正确做法：写「销售连续两季度下滑，Q4 环比 -12%」。**图表标题就是结论，读者只扫标题。**

**坑十：坐标轴不从 0 开始。**
错误做法：柱状图从 90 开始，让 3% 的差异看起来像翻倍。正确做法：从 0 开始，差异小就诚实地说差异小。**截断坐标轴是误导，即使数据是真的。**
