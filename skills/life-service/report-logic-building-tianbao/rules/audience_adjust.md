# 分对象表达调整表

> 同一件事，五种说法。**对方关心什么，你的开头就该是什么。**

---

## 一、五类对象的表达调整

| 对象 | 关心什么 | 开头给什么 | 省略什么 | 示例 |
|---|---|---|---|---|
| 直属上级 | 进度、风险、需要他做什么 | 结论 + 需要决策的点 | 过程细节 | 「三件事，其中 B 卡住了需要你协调」 |
| 隔级领导 | 方向、影响面、资源 | 结论 + 对整体的影响 | 执行细节 | 「B 卡住会影响下季度目标，已启动替代方案」 |
| 平级同事 | 接口、时点、责任人 | 我要做的事 + 需要你配合的 | 我的内部进展 | 「我这周三要交付 X，需要你 Y 部门周三前给 Z」 |
| 下属 | 目标、边界、反馈 | 目标 + 他要做的部分 | 我为什么这么做 | 「你这周只做 X，做完不用管 Y」 |
| 外部客户/合作方 | 他的利益、交付承诺 | 对他的承诺 + 时间 | 内部流程与分工 | 「我们保证 X 日交付，质量标准是 Y」 |

---

## 二、同一件事的五种说法示例

**事实**：某个功能上线后，用户的重复提交率从 12% 降到 4%。

| 对象 | 说法 |
|---|---|
| 直属上级 | 「重复提交率从 12% 降到 4%，功能已全量上线，本周内不会再有变更」 |
| 隔级领导 | 「功能上线后重复提交率降了三分之二，这个高频投诉点基本解决」 |
| 平级同事 | 「我们今天上线了防重复提交，你们那边如果还有重试问题请直接提」 |
| 下属 | 「下次你接这个功能时，把防重提交做成默认校验，不要靠前端拦」 |
| 外部客户 | 「您反馈的重复提交问题已修复，从今天起不会再出现，建议刷新后使用」 |

**原则：同一件事，同一个数字，不同的落点。数字不因对象改变，落点要改。**

---

## 三、四种不该出现的说法

| 说法 | 问题 | 改法 |
|---|---|---|
| 对下属讲「我为什么这么做」 | 占用他的注意力 | 直接讲目标与边界 |
| 对平级讲内部进展 | 他不需要知道你的内部困难 | 只讲接口与时点 |
| 对上级讲过程细节 | 他要的是结论与决策点 | 过程放备份页 |
| 对外部讲内部流程 | 暴露内部分工 | 只讲对外承诺 |

---

## 四、表达调整四步

```
1. 确认对方在这件事上的角色（决策者/执行者/合作方/旁观者）
2. 确认对方最关心的一个变量（钱/时间/风险/关系/责任）
3. 把那个变量放到第一句
4. 其余内容按对方需要程度删减，细节进备份页
```

---

## 五、敏感场景的表达边界

| 场景 | 边界 |
|---|---|
| 涉及他人责任 | 只讲事实与依据，不评价人 |
| 涉及未公开信息 | 按公司保密要求处理，不写入材料 |
| 涉及人事变动 | 按公司人事管理规定告知，不提前扩散 |
| 涉及未核实的数据 | 先核实，或明确标注「初步，待核实」 |
| 紧急事项 | 先给结论与选项，不先铺垫背景 |
