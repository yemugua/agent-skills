# 汇报逻辑搭建与表达核查

## 你会得到什么

**金字塔四条原则 + 可操作的自检方法。** 结论先行（遮住第一段还能看出结论吗）、以上统下（试着用一个问句概括三个分支）、归类分组（三个分支能用同一个问句回答吗）、逻辑递进（打乱顺序读者会困惑吗）。**汇报没重点，九成是层级错了**——把并列的三件事当成「第一第二第三」，它们却不是同一个分类标准下的分支。

**顶句的三条标准**与对照表。顶句必须是完整判断而非话题（「关于用户流失的分析」不是顶句，「流失集中在首月未完成引导的用户，建议把引导前置到注册当次」才是）、必须能被下层论证（分支支撑不住顶句说明顶句写错了）、必须包含对方关心的信息。

**SCQA 引入模板**：S 情境（一两句带过，不超过两句）、C 冲突、Q 问题、A 答案（直接接顶句）。配一个完整示例。**铺垫长了读者抓不到冲突。**

**MECE 十条检查项**与最常见四类错误的改法：「线上渠道、线下渠道、社交媒体」（社交媒体属于线上，重叠）→ 改成「自建、投放、代理」；「成本、费用、管理费用」（费用包含成本）→ 改成同层级三项；「收入增长、成本下降、效率提升」（前两个是结果、第三个是原因，维度不同）→ 归到「经营改善」下再分；「大客户、中小客户、其他」（「其他」是占位不是分类）。附修复三问。

**图表选配规则**给死：趋势用折线、类目比较用柱状、构成占比（≤4 项）用饼图、两变量关联用散点、流程用流程图、跨度对比用甘特、分布用直方图。每条都写明「不要用」和原因（如双轴柱状图容易制造假相关）。四条通则：**标题写结论不写「XX 数据图」、坐标轴从 0 开始、一个图只说一件事、数据点不超过 7 个**。

**同一件事对五类对象的表达调整表**（直属上级/隔级领导/平级同事/下属/外部合作方），各给关心什么、开头给什么、省略什么、示例。再给一个具体示例：同一个「重复提交率 12%→4%」的五种说法。**同一件事、同一个数字，不同的落点——数字不因对象改变，落点要改。**

另有论点收敛三步法（筛→合→排）、分支数量控制区间（3-5 个合适、≥8 个必须收敛）、十类逻辑病对照表。

## 典型用法

- 汇报材料定稿前排一次金字塔，确认结论先行
- 分支列了七八条，收敛到 3-5 条
- 分类重叠或不穷尽时，用 MECE 十条逐项过
- 同一份内容要给不同人看，按调整表改开头第一句

## 脚本

`scripts/logic_check.py` 读入汇报逻辑 JSON，输出论点收敛率、分类标准一致性、互斥性与穷尽性、层级一致率、图表匹配率与超载提示、冗余表述命中与整改建议。支持 `--file` / `--text` / `--out` / `--format`，带 `--selftest`。

## 边界

本技能提供汇报逻辑搭建方法与结构核查规则，不替你做事实判断或数据核实，也不判断结论是否正确。数据来源不明或未经核实的应先核实再汇报；涉及未公开信息、个人评价与人事变动的内容按公司保密要求处理。图表选择以准确表达为准，不生成可能误导的图表。表达调整以对方公开的关注点为依据，不揣测他人立场。
