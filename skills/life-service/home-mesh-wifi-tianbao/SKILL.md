# 家庭组网与无线覆盖排查（home-mesh-wifi）

覆盖差和网速慢是两回事。**隔墙掉线是覆盖问题，要靠拓扑解决；满格还慢是干扰问题，要靠频段与信道解决。** 选错拓扑会把两个问题叠在一起，买再多设备也没用。

这个技能做四件事：**选拓扑** → **算节点** → **排分工** → **验覆盖**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 按面积、承重墙、楼层给拓扑选型建议 | ❌ 保证换 Mesh 后全屋无死角 |
| 估算节点数与回程带宽下限 | ❌ 修改运营商光猫的注册与认证参数 |
| 说明 2.4G 与 5G 的分工与取舍 | ❌ 建议刷第三方固件或提高发射功率 |
| 给出摆放、回程与漫游方案 | ❌ 替代运营商装维与有线施工 |
| 定位常见组网错误 | ❌ 替代企业级多 AP 的信道规划与认证设计 |

**遇到以下情况，停止自行操作，转交运营商装维或专业网络人员：**

- 有线直连光猫也慢（是宽带或线路问题，与无线无关）
- 光猫亮红灯、频繁掉注册、入户光衰异常
- 需要新增网线、面板、POE 供电、天花板内布线
- 需要改动光猫的桥接、VLAN 或认证参数
- 涉及强电改造、登高安装、穿承重墙打孔
- 商铺、办公、公寓等商业场所的多 AP 统一规划

**永远不要修改光猫的注册与认证参数。** 改错直接断网，通常需要装维上门重新下发数据。

## 二、完整工作流

```
第 1 步  定性：有线直连测速，排除宽带与线路问题
第 2 步  分清覆盖与干扰：信号格数 + 实测速率一起看
第 3 步  量户型：面积、承重墙数量、楼层、弱电箱位置、能否布线
第 4 步  先读规则文件 rules/home_mesh_rules.md（拓扑决策表 + 回程换算 + 漫游对比）
第 5 步  跑选型脚本，拿拓扑、节点数与回程带宽下限
    python scripts/home_mesh_planner.py --area 128 --walls 6 --floors 2 --devices 22
第 6 步  分配 2.4G 与 5G 的职责，决定 SSID 是否分开
第 7 步  按摆放表放节点，逐点测速验收（覆盖与速率分开测，取三次中位数）
```

## 三、三种拓扑怎么选（选型主线）

| 拓扑 | 什么时候选 | 硬前提 | 主要风险 |
|---|---|---|---|
| 单台无线路由器 | 面积小、承重墙少、无多层 | 路由器位置能居中且不被弱电箱困住 | 覆盖死角，调位置也无效 |
| 路由 + 多个 Mesh 子节点 | 面积大、承重墙多、要漫游 | **回程要够**，优先有线 | 无线回程吞吐腰斩 |
| 路由 + 有线 AP | 已有布线或能布线的户型 | 每个 AP 要有网线到位 | 布线成本与施工 |

**按顺序问这四个问题：**

1. **能不能拉网线？** 能 → 有线 AP 最稳；不能 → Mesh 或无线回程。
2. **面积与承重墙多少？** 100 ㎡ 以内、承重墙少 → 单台可能就够。
3. **要不要漫游？** 手机在房间之间走动不断流才算漫游。双频合一反而常导致漫游失败。
4. **弱电箱在什么位置？** 弱电箱是金属封闭空间，**主节点塞进去等于把天线包住**。

## 四、2.4G 与 5G 的分工

| 维度 | 2.4GHz | 5GHz |
|---|---|---|
| 穿透能力 | **强**，穿墙衰减相对小 | 弱，穿一两堵墙明显掉速 |
| 速率上限 | 低 | **高** |
| 干扰 | 大（蓝牙、微波炉、无绳电话同频段） | 小 |
| 覆盖半径 | 大 | 小 |
| 典型用途 | 智能家居、摄像头、门锁、老设备 | 手机、平板、电脑、电视 |
| 是否做回程 | 可以，不推荐 | **推荐专用** |

**分工原则**：**能拉线就用线；不能拉线就把 5G 留给回程**，别让回程和数据抢同一个频段。

**双频合一**：图省事，但常让智能家居设备找不到网、手机在两个频段间反复跳。**建议分开 SSID**，漫游也更可控。

> 信道怎么选、宽度设多少，那部分转到 `wifi-channel-selection` 技能。两个技能配合，一个管拓扑一个管频段。

## 五、回程带宽要多少

回程就是子节点到主节点之间的链路。**回程带宽不够，前面所有选型都白做。**

| 入户实测速率 | 有线回程下限 | 无线回程可行性 |
|---|---|---|
| ≤ 300Mbps | 100Mbps | 可用，注意实测折损 |
| 500Mbps | 200Mbps | 可用但折损明显，多节点慎用 |
| 1000Mbps | 500Mbps | **不建议无线回程**，多节点优先有线 |
| > 1000Mbps | 全千兆有线 | 无线回程撑不住 |

**无线回程折损口径**：同频段做回程时，链路占用本机收发能力的一半左右，**实测通常只有直连速率的一半左右**；跨楼层还要再打折。这是经验值，会因设备与现场不同而变化，**只作估算，必须实测**。

## 六、漫游机制对比

| 机制 | 说明 | 常见问题 |
|---|---|---|
| 双频合一 | 只发一个 SSID，设备自行选频 | 智能家居找不到 2.4G；手机反复跳频 |
| 各节点发同名 SSID | 靠系统自动切换 | 老设备切不过来，黏在弱节点上 |
| 802.11r 快速漫游 | 切换前先认证，衔接更顺 | 老设备不兼容，需双方支持 |
| 802.11k/v 邻居信息 | 告知设备邻居有哪些、哪个更好 | 需 AP 与客户端都支持 |

**验收方法**：拿手机从弱节点走到强节点，看连接是不是真切过去了。**只有信号格数变化而连接没切，说明漫游没生效。**

---

## 七、摆放与测速验收

**摆放要点：**

- 节点放在开阔、居中、离地 1-1.5 米的位置
- 避开承重墙、金属柜、鱼缸、镜面、微波炉
- **不要把主节点塞进弱电箱**，要么把线引出来外放，要么把 AP 挪到箱外
- 一个节点覆盖不到的区域就加第二个节点，别靠调一个节点硬撑
- 有线回程时 AP 跟着网线走，不再受插座位置限制

**测速验收（覆盖与速率分开测）：**

| 测什么 | 怎么做 | 判据 |
|---|---|---|
| 有线基线 | 电脑网线直连主节点测速 | 这是上限，WiFi 不可能超过它 |
| 覆盖点 | 每个房间测信号格数 | 每间房至少一个可用点 |
| 速率点 | 每个房间连 5G 测速 | 与有线基线差距在合理范围 |
| 分频段 | 分别连 2.4G 与 5G 各测三次 | 5G 应明显快于 2.4G |
| 分时段 | 白天与晚高峰各测三次 | 晚高峰不塌陷 |

**测速取三次中位数**，单次结果没有可比性。

## 八、脚本用法

```bash
python scripts/home_mesh_planner.py --area 128 --walls 6 --floors 2 --devices 22
python scripts/home_mesh_planner.py --file plan.json --out 选型结果.md
python scripts/home_mesh_planner.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--area` | 建筑面积（平方米） |
| `--walls` | 主要承重墙数量 |
| `--floors` | 楼层数 |
| `--devices` | 同时在线的无线设备数 |
| `--link-mbps` | 入户实测速率，默认按 500 计 |
| `--wire` | 能否布网线：`yes` / `no`，默认 `no` |
| `--file` | 从 JSON 读参数（自动兼容带 BOM 的文件） |
| `--out` | 结果落盘路径 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本输出**推荐拓扑、节点数估算、回程带宽下限、2.4G 与 5G 分工、摆放禁忌与验收清单**，并对满格还慢的情形提示去查信道。

> 脚本只按输入参数估算，**不代表现场判断**。节点数最终以逐点实测为准。

## 九、人工确认清单（这步不能省）

- [ ] 有线直连测过速，确认不是宽带本身慢
- [ ] 分清是覆盖问题还是干扰问题，不是靠猜
- [ ] 量过户型：面积、承重墙数量、楼层、弱电箱位置
- [ ] 确认能不能布网线，能布线优先有线 AP 或有线回程
- [ ] 主节点没有塞在弱电箱里
- [ ] 2.4G 与 5G 职责分清，SSID 是否分开了
- [ ] 无线回程时，5G 是否留给回程而非业务数据
- [ ] 每个房间都测过覆盖与速率，取三次中位数
- [ ] 漫游是否真的切换，有实测证据而不是只看设置页

## 十、最常见的坑

**坑一：覆盖不好就买 Mesh。**
先分清是覆盖还是干扰。满格还慢是干扰，加 Mesh 只会更挤；隔墙掉线才是覆盖。

**坑二：把主节点塞进弱电箱。**
弱电箱是金属封闭空间，天线被包住，信号出不来。很多户型网速差的根源就在这里，不是设备不行。

**坑三：多节点全用无线回程。**
回程占本机收发能力的一半，实测吞吐常只有直连的一半左右，且节点之间互相抢。千兆入户尤其撑不住。

**坑四：双频合一图省事。**
智能家居设备常常找不到 2.4G，手机也会在两个频段间反复跳，分开 SSID 更稳。

**坑五：光猫模式没弄清就改。**
桥接与路由模式的区别影响地址分配归属与端口映射，改错会出现能上网但某些服务打不开。要改先弄清现状，并保留改回去的路径。

**坑六：只看参数表选设备不看回程。**
标称速率是单节点直连的能力，多节点场景要问清回程方式。

**坑七：把 AP 塞进弱电箱当分线器用。**
AP 需要稳定供电与网线到位，塞进弱电箱往往导致供电不稳或只能走无线回程。

**坑八：用一个节点硬撑全屋。**
覆盖是靠节点数量堆出来的，不是靠调一个节点的位置。死角该加节点就加。

**坑九：漫游没验证就以为成功了。**
手机从弱节点走到强节点，连接没切过去就没有漫游，只是信号变强了。

**坑十：只测一次就下结论。**
单次测速受时段与占用影响，差距明显时才说明问题。

## 十一、边界与免责

- 本技能**不替代**运营商装维与企业级无线规划
- 频段、发射功率与信道使用**以当地无线电管理规定与设备核准情况为准**
- 不得修改光猫注册与认证参数，不得刷第三方固件，不得超出发射功率的合规范围
- 涉及网线布设、POE 供电、天花板内布线与登高的，应由专业人员施工
- 商业场所、多 AP、高密度场景应做专业网规、信道规划与认证设计
