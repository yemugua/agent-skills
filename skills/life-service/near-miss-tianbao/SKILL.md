# 未遂事件管理（near-miss）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据事件管理与风险前置理念，生成未遂事件管理清单：未遂事件定义与上报渠道、无责/鼓励报告机制、分级与调查分析、整改与经验反馈、趋势分析与预防。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 未遂事件
- 险肇事件
- near miss
- 无责上报
- 事故苗头

## 三、工作流
1. 明确未遂事件定义与上报渠道
2. 建立无责或鼓励报告机制
3. 分级并调查分析原因
4. 落实整改与经验反馈
5. 做趋势分析并前置预防

## 四、核心内容（检查清单与判定）
未遂事件（险肇）是事故的前兆，管理关键在于鼓励上报而非追责，通过分析整改与经验反馈把风险消灭在成灾之前。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含定义与上报渠道 | 上报 |
| Q2 | FAIL | 未含无责/鼓励报告机制 | 机制 |
| Q3 | WARN | 未含分级与调查分析 | 分析 |
| Q4 | FAIL | 未含整改与经验反馈 | 整改 |
| Q5 | WARN | 未含趋势分析与预防 | 趋势 |

> 脚本 `near-miss_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python near-miss_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python near-miss_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
