# 安全风险分级管控（risk-classification）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据双重预防机制与《安全风险分级管控体系通则》，生成风险分级管控清单：风险点辨识、评价分级（红橙黄蓝）、管控措施与四色图。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 风险分级管控
- 四色图
- 红橙黄蓝
- 风险点辨识
- 风险评价
- 双重预防

## 三、工作流
1. 辨识风险点/危险源
2. 评价分级（重大/较大/一般/低，红橙黄蓝）
3. 制定管控措施与责任层级
4. 绘制风险四色图与公告
5. 建立动态更新机制

## 四、核心内容（检查清单与判定）
双重预防机制包括风险分级管控与隐患排查治理；风险按重大/较大/一般/低四级以红橙黄蓝四色公告，落实分级管控责任。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未辨识风险点/危险源 | 辨识 |
| Q2 | FAIL | 未评价分级（重大/较大/一般/低，红橙黄蓝） | 分级 |
| Q3 | WARN | 未含管控措施与责任 | 管控 |
| Q4 | FAIL | 未绘制风险四色图/公告 | 四色图 |
| Q5 | WARN | 未含动态更新机制 | 更新 |

> 脚本 `risk-classification_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python risk-classification_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python risk-classification_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
