# OKR 目标管理（okr）

> 领域：招聘 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据 OKR（目标与关键结果）方法论，生成 OKR 推行清单：目标(O)设定原则、关键结果(KR)量化、对齐与拉通、周期与复盘、与考核解耦。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- OKR
- 目标与关键结果
- 目标管理
- OKR推行
- 目标对齐

## 三、工作流
1. 设定鼓舞性且聚焦的目标(O)
2. 编写可量化的关键结果(KR)
3. 上下左右对齐拉通
4. 确定周期并跟踪进度
5. 周期末复盘并与考核解耦

## 四、核心内容（检查清单与判定）
OKR 以「目标+可量化关键结果」驱动聚焦与对齐，强调挑战性与透明；通常与绩效考核解耦，以鼓励挑战性目标。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含目标(O)设定原则 | 目标 |
| Q2 | FAIL | 未含关键结果(KR)量化 | KR |
| Q3 | WARN | 未含对齐拉通 | 对齐 |
| Q4 | FAIL | 未含周期与进度跟踪 | 周期 |
| Q5 | WARN | 未含复盘与考核解耦 | 复盘 |

> 脚本 `okr_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python okr_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python okr_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
