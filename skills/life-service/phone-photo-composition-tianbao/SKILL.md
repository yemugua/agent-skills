# 手机摄影构图（phone-photo-composition）

构图问题的本质是：**观众第一眼看哪里，你说了不算，画面说了算。**

主体放正中间、地平线歪 2 度、头顶空一大片——这三件事单独看都不致命，凑在一起就是「看着别扭但说不出哪别扭」。

这个技能做三件事：**定构图法 → 核坐标 → 分级整改**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 给出七种构图法的适用题材与主体落点坐标区间 | ❌ 评判照片的艺术价值或好坏 |
| 核查水平、地平线、留白、占比、杂物六项自查 | ❌ 讲解具体机型的相机功能与菜单操作 |
| 按严重度排出整改顺序 | ❌ 提供后期修图的具体操作步骤 |
| 说明构图规则可被有意识打破的前提 | ❌ 替代摄影师在现场的取景判断 |

**遇到以下情况，按各自渠道处理：**

- 需要把照片用于**商业宣传、出版、赛事投稿** → 涉及著作权与肖像授权，应取得权利人许可
- 拍摄内容是**他人肖像** → 发布前应取得本人同意
- 拍摄地点涉及**军事设施、涉密单位、明确禁拍标识的场所** → 不在本技能范围，且不得拍摄
- 相机/App 的具体开关位置、专业模式参数 → 以自己手机的官方说明为准

## 二、完整工作流

### 第一步：拍之前先定构图法

先看题材，从七种里选一种（详见 `rules/构图方法与自查表.md`）：

| 题材 | 首选 |
|---|---|
| 风景、人像、街拍（拿不准时） | 三分法 |
| 建筑正面、强对称场景 | 中心构图或对称构图 |
| 有道路、栏杆、河流、台阶 | 引导线构图 |
| 有门窗、树枝可做前景 | 框架构图 |
| 大面积天空、雾、极简 | 留白构图 |
| 特写、美食、花卉 | 填充构图 |

**定完构图法，心里先有个数：主体大概落在哪个坐标区间。**

### 第二步：打开参考线

在手机相机设置里打开**网格线（参考线）**。这一步能一次性解决水平、地平线、三分落点三个问题。

### 第三步：按快门前扫四角

扫一遍画面四个角和主体头顶：垃圾桶、电线杆、路人手臂、横穿头顶的树枝。

**改机位（蹲下、抬高、左右挪半步）比后期裁剪可靠得多。**

### 第四步：拍完填 JSON 跑自查

把每张照片的主体坐标、水平倾斜、留白比例填进去，脚本一次给出逐张判定与整改顺序。

### 第五步：按严重度改

- **严重项**（水平超差、主体位置不合、引导线没指向主体）→ 这个场景得重拍
- **可改进项**（留白、杂物、地平线居中、占比过小）→ 换机位或换角度再补一张

---

## 三、核心规则（生成结论前先读规则文件）

**必须先读 `rules/构图方法与自查表.md`，不要凭印象写。** 规则文件里有：

- 七种构图法的要点、适用题材、常见错误
- 六种构图法各自的主体落点坐标表（三分法、中心、对称、引导线、框架、填充）
- 六项自查的阈值与不合格原因
- 判定顺序说明
- 八条高频坑

**判定顺序不能颠倒**：先看真实缺陷（严重项），再看可改进项，最后才看信息是否完整。

**为什么这条重要**：如果先判信息完整度，会出现「水平已经差 3 度，却因为没填留白比例而被判成待确认」的情况——把问题说轻了，比漏判更糟。

---

## 四、六项自查速查

| 项目 | 阈值 | 严重度 |
|---|---|---|
| 水平倾斜 | 不超过 1.0 度（对称构图 0.5 度） | 严重 |
| 主体位置 | 按所选构图法的坐标区间 | 严重 |
| 引导线指向主体 | 线条终点必须落在主体上 | 严重 |
| 地平线位置 | 避开 0.45-0.55（对称构图例外） | 可改进 |
| 头顶留白 | 0.05-0.20 | 可改进 |
| 主体占比 | 不低于 0.15（留白构图不高于 0.35，填充构图不低于 0.5） | 可改进 |
| 画面杂物 / 边缘穿帮 | 无 | 可改进 |

## 五、脚本用法

```bash
python scripts/composition_check.py --file shots.json --out 构图自查.md
python scripts/composition_check.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 输入 JSON：`shots` 为照片列表，每张填 `method` / `subject_x` / `subject_y` 等 |
| `--out` | 结果写入指定文件，默认写 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检（44 条断言，含 BOM 两条路径） |

输入 JSON 示例：

```json
{
  "shots": [
    {
      "name": "湖边风景",
      "method": "thirds",
      "subject_x": 0.33,
      "subject_y": 0.33,
      "horizon_tilt_deg": 0.4,
      "horizon_y": 0.33,
      "headroom": 0.10,
      "subject_ratio": 0.40
    }
  ]
}
```

可选字段：`method` 取 `thirds` / `center` / `symmetry` / `leading` / `frame` / `negative` / `fill`；
`subject_x` / `subject_y` 为必填的主体归一化坐标（0 到 1）；
`horizon_tilt_deg`（水平倾斜度数）、`horizon_y`（地平线高度）、`headroom`（头顶留白）、
`subject_ratio`（主体占比）、`clutter`（有杂物）、`edge_cut`（边缘切到主体）、
`leading_lines`（引导线指向主体）。

脚本输出：总体判定、逐张判定表（含不合格原因的 why）、整改顺序、七种构图法速查表、阈值表、人工确认清单。

## 六、人工确认清单（这步不能省）

- [ ] 打开手机参考线，地平线压在网格横线上
- [ ] 按快门前扫过画面四个角，没有杂物
- [ ] 主体头顶与画面上边缘留白合适，没有被切
- [ ] 拍人像时眼睛的水平位置在画面高度 0.3 到 0.5 之间
- [ ] 拍完放大到百分之百再看一次水平
- [ ] 涉及他人肖像的照片，发布前已取得本人同意

## 七、最常见的坑

**坑一：以为「放中间就是三分法」。**
错误做法：人放画面正中间，还觉得自己用了三分法。正确做法：三分法的交点在 **0.33 和 0.67** 附近，正中间是 0.5，两者差了半条线。要么真的放交点，要么坦诚用中心构图。

**坑二：拍倒影时水平差 1 度。**
错误做法：水面倒影，觉得差一点点没关系。正确做法：对称构图的全部美感建立在「两边一样」上，**差 0.5 度就能毁掉整张**。拍倒影必须开参考线并把水平压死。

**坑三：地平线正好在画面中间。**
错误做法：天一半地一半，觉得挺平衡。正确做法：地平线落在 0.45 到 0.55 之间，观众不知道该看天还是看地。**想表现晚霞就压到 0.33，想表现水面纹理就抬到 0.67。** 例外是完整倒影，那本来就该居中。

**坑四：拍人像头顶留一大片天空。**
错误做法：人只占画面下三分之一，上面全是天。正确做法：头顶留白控制在 **0.05 到 0.20**。留太多人显得小、画面散；留太少顶得压抑，像被裁掉额头。

**坑五：引导线尽头没有主体。**
错误做法：一条很有感觉的路，通向画面外面。正确做法：引导线的作用是**把视线送到主体上**，终点必须落在主体。线再好看，把人带出画面就是失败。

**坑六：只盯着主体，没扫四角。**
错误做法：对焦在人脸，按快门，回家才发现电线杆「长」在人头上。正确做法：按快门前扫一遍四角与头顶。**改机位比后期裁剪可靠。**

**坑七：手机广角主摄把边缘的人拉变形。**
错误做法：一群人合影，站在最边上的两位脸被拉宽。正确做法：主摄是广角，边缘畸变明显，**主体尽量落在画面中间 0.3 到 0.7 区域**，或者退远一点用 2 倍镜。

**坑八：主体太小，自己觉得有氛围。**
错误做法：站得远远的拍一个小人，说是留白构图。正确做法：留白构图要的是**有意义的留白**（大面积天空、雾、纯色墙），否则就是没走近。占比低于 0.15 观众看不出你在拍什么。
