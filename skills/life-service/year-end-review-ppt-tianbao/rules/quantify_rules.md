# 量化口径与表述边界规则库

> 填指标前先读本文件。**算不出数的指标，说明它本来就不该进述职。**

---

## 一、指标表模板

| 指标 | 单位 | 本期值 | 上年同期 | 上周期 | 目标值 | 方向 | 权重 | 来源 |
|---|---|---|---|---|---|---|---|---|
| [指标1] | [万元] | [1200] | [950] | [1110] | [1150] | up | 0.4 | [系统] |
| [指标2] | [次] | [18] | [25] | [22] | [20] | down | 0.3 | [监控] |
| [指标3] | [天] | [15] | [18] | [16] | [12] | down | 0.3 | [工单] |

| 项 | 建议 |
|---|---|
| 指标数 | 5-8 项 |
| 权重合计 | 1 |
| 基线 | 每项都要有上年同期值 |
| 来源 | 系统 / 台账 / 抽样（抽样注明样本量与区间） |
| 方向 | 标明 up / down，决定达成率公式 |

## 二、四象限判定表

| 同比 | 达成率 | 真实情况 | 述职怎么写 |
|---|---|---|---|
| ↑ | ≥100% | 真增长真达成 | 重点写，给关键动作 |
| ↑ | <100% | 增长但没够到目标 | 说明目标定得高，或增长集中在后半段 |
| ↓ | ≥100% | **目标定低了** | **必须主动说明**，否则被追问很被动 |
| ↓ | <100% | 下滑 | 写根因与止损动作，不解释客观原因了事 |

> 「同比下降但达成率 104%」是最容易被抓的一栏。**自己先说出来，比被问出来好。**

---

## 三、方向与达成率公式

```
up（越大越好）：达成率 = 本期值 ÷ 目标值
down（越小越好）：达成率 = 目标值 ÷ 本期值
```

| 指标类型 | 常见例子 | 方向 |
|---|---|---|
| 产出类 | 销售额、项目数、处理量 | up |
| 质量类 | 故障次数、缺陷数、投诉量 | down |
| 效率类 | 处理时长、交付周期、响应时长 | down |
| 人员类 | 离职人数、编制数 | down |

### 反例

```
故障次数 25 → 18，目标 20
✗ 18 ÷ 20 = 90%（越算越差）
✓ 目标 ÷ 实际 = 20 ÷ 18 = 111%
```

**算反了会把一笔漂亮的成绩写成未达标。**

---

## 四、人均效能

```
人均效能 = 本期产出 ÷ 本期平均在岗人数
本期平均在岗人数 =（期初在岗人数 + 期末在岗人数）÷ 2
```

| 情况 | 处理 |
|---|---|
| 中途入职 | 按实际在岗月数折算 |
| 中途离职 | 同上 |
| 兼职/借调 | 按实际投入折算，写明口径 |

**分母口径不写明，这个数没有意义。** 口径写在页脚小字也可以，但必须写。

## 五、口径操纵的红线

| 行为 | 定性 | 正确做法 |
|---|---|---|
| 目标年中调过只报调整后 | **口径操纵** | 写明「年初 X，因 Y 调整为 Z，实际 W，调整后达成 D%」 |
| 只报达成率不报同比 | 选择性呈现 | 同比与达成率一起给，方向不一致时主动解释 |
| 抽样样本量不写 | 不可验证 | 写明样本量与采集区间 |
| 基线期与本期口径不同 | 不可比 | 统一口径，确需调整的注明 |
| 指标定义中途改了 | 不可比 | 保留原口径，另起新指标 |

**隐去目标调整属于口径操纵。被发现一次，整套数字都不再可信。**

## 六、定性转定量对照表

| 定性说法 | 换成什么数 | 数据来源 |
|---|---|---|
| 大幅提升效率 | 处理时长从 X 降到 Y，降幅 Z% | 系统日志 / 工单记录 |
| 积极参与协作 | 跨部门协同 N 次，推动 M 项落地 | 会议纪要 / 项目清单 |
| 优化了流程 | 环节从 N 步减到 M 步，单均节省 T 分钟 | 流程图 + 计时 |
| 保障了稳定性 | 可用率 X%，故障 N 次，同比 -Y% | 监控平台 |
| 获得好评 | 满意度 X 分同比 +Y；投诉 N 件同比 -M | 问卷 / 客服工单 |
| 完成了日常运维 | 处理请求 N 件，平均响应 T 分钟，一次解决率 X% | 工单系统 |

**没有系统数据的口径**：写「按抽样统计（样本 N）」或「按 XX 台账统计」，并注明统计区间。

## 七、团队成果与个人贡献的边界

| 写法 | 判定 |
|---|---|
| 「我主导了整个项目」且未写分工 | ❌ 高风险 |
| 「我负责 XX 模块，与 A、B、C 分工为……，交付 XX」 | ✅ |
| 「我们完成了 X（共 4 人）」 | ✅ 需注明人数 |
| 「我完成了 X」但 X 是集体成果 | ❌ 会被质疑 |

**团队成果要写清人数与分工，个人贡献写清你做的那一段。**

---

## 八、脱敏要求

| 内容 | 处理 |
|---|---|
| 客户名称 | 脱敏为「客户 A/B」或行业描述 |
| 未披露财务数据 | 按公司披露口径处理 |
| 商业秘密 | 不写入 PPT |
| 个人信息 | 一律不出现 |
| 内部争议事件 | 不作为亮点写入 |

**脱敏后仍要保证评委能看懂问题本质。**
