# 医保关系转移接续与缴费年限折算核查

## 一、硬边界

| 能做 | 不能做 |
|---|---|
| 判断是否需要先办转移、能否线上提交 | 代替医保经办机构审核、记账或办理结算 |
| 核查材料、时限、渠道、年限台账和待遇衔接 | 承诺具体报销比例、年限折算结果或补缴金额 |
| 提示重复参保、中断缴费、待遇等待期风险 | 代替参保人选择是否补缴、退费或放弃年限 |
| 输出办理顺序、进度跟踪表和救济路径 | 处理骗保、冒名就医、虚假参保等事项 |
| 整理异地就医备案与结算的关联提示 | 预测个人账户划入金额或退休审批结果 |

涉及退休医保待遇认定、视同缴费年限、跨制度折算、重复参保退费、欠费补缴、异地安置、长期护理或重大疾病待遇时，应以参保地医保经办机构核定结果为准，必要时咨询单位人事、社保代理或专业法律人员。

## 二、什么时候用

| 用户说法 | 用不用 |
|---|---|
| 「换城市工作，社保要不要一起转」 | 用，先区分养老与医保，分别处理 |
| 「职工医保转居民医保，年限还算吗」 | 用，提示以转入地规则为准 |
| 「医保转移要多久，中间断档怎么办」 | 用 |
| 「退休时医保年限差几年」 | 用，做年限台账并提示咨询经办机构 |
| 「两地都交了医保，能退一份吗」 | 用，提示重复参保处理 |
| 「帮我把别人的医保年限并到我名下」 | 不用，明确拒绝 |

## 三、完整工作流

1. **建参保档案**：身份证、参保地、参保类型、单位参保或个人参保、参保起止月、缴费基数、个人账户余额、当前待遇状态。
2. **确认是否需办**：先查是否重复参保、是否已在转入地正常参保、是否只是异地就医备案需求。
3. **确认渠道**：优先使用全国统一的医保信息平台或转入地、转出地线上渠道；不具备条件的走线下窗口。
4. **核材料**：按 `rules/transfer-rules.md` 准备身份、参保凭证、申请表、单位或代办材料，核对姓名、证件号和参保地是否一致。
5. **提交并跟踪**：保存申请编号、提交日期、受理回执；按转出、转入、基金或信息流转节点跟踪。
6. **核年限与账户**：转移完成后核对缴费月数、视同年限、个人账户余额和待遇起始月。
7. **处理中断与衔接**：识别断档、等待期、待遇中止和重复缴费，优先保证报销不受影响。
8. **留痕**：保存缴费记录、转移凭证、经办答复、补缴或退费单据。

## 四、核心规则与要件库

输出办理清单或年限台账前，**必须先读**：

- `rules/transfer-rules.md`：适用情形、流程、时限口径、年限口径、中断与重复参保、被卡原因和救济。
- `templates/transfer-workbook.md`：参保年限台账、转移进度表和补正材料清单。

不得把「已提交申请」「已受理」「已办结」混为一谈；不得把「未连续缴费」识别为「连续缴费」，也不得把「视同缴费年限」与「实际缴费年限」合并后直接下结论。

## 五、人工确认清单

- [ ] 参保人姓名、证件号码、参保地在两地系统一致
- [ ] 已确认转入地是否已正常参保，是否存在重复参保
- [ ] 已确认是转移接续还是仅需异地就医备案
- [ ] 申请渠道、受理编号和提交日期已保存
- [ ] 缴费月数、视同年限、个人账户余额已逐月核对
- [ ] 中断月份、待遇等待期和待遇起始月已确认
- [ ] 补缴、退费或不转的选择已由参保人本人确认
- [ ] 退休地、待遇领取地和最低缴费年限要求已向经办机构确认

## 六、最常见的坑

1. **只办养老不办医保**：养老与医保转移是两条线，办完养老不等于医保已接续。
2. **把异地就医备案当转移**：备案解决结算便利，不等于关系转移和年限累计。
3. **两地同时缴费**：重复参保期间通常不能重复享受待遇，也不能简单重复累计年限。
4. **断档不自知**：离职、灵活就业衔接不及时会造成中断，影响待遇享受和连续缴费认定。
5. **年限口径混算**：职工医保、居民医保、视同缴费年限和军人等政策性年限的折算规则不同。
6. **只看申请提交日**：办理涉及转出、转入和经办核对多个环节，进度以受理回执和办结结果为准。
7. **忽略个人账户**：个人账户余额、利息和到账时间要单独核对，不能只看缴费年限。
8. **临退休才补**：退休前后补缴、延缴或一次性处理规则差异大，应提前向经办机构核实。

## 七、边界与免责

本技能提供流程核查与材料整理，不构成医保、社保或法律意见，不替代经办机构核定。转移条件、办理时限、缴费年限、折算规则、补缴与待遇衔接会因统筹地区、参保类型、就业状态和时间变化，**以现行规定和当地医疗保障部门要求为准**。不得用于虚构参保、骗取待遇或冒用他人信息。
