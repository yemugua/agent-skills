# 召回管理（recall-management）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据缺陷产品召回要求与《消费品召回管理暂行规定》，生成清单：缺陷识别与风险评估、召回决策与分级、召回计划与公告、实施与进度跟踪、效果评估与闭环。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 产品召回
- 召回管理
- 缺陷召回
- 召回计划
- 召回演练

## 三、工作流
1. 识别缺陷并评估风险
2. 作出召回决策并分级
3. 制定召回计划并公告
4. 实施召回并跟踪进度
5. 评估效果并闭环

## 四、核心内容（检查清单与判定）
召回是发现产品存在缺陷后的法定与责任义务；应按风险分级决策，公告并跟踪实施进度，最后评估召回完成率形成闭环。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含缺陷识别与风险评估 | 识别 |
| Q2 | FAIL | 未含召回决策与分级 | 决策 |
| Q3 | WARN | 未含召回计划与公告 | 公告 |
| Q4 | FAIL | 未含实施与进度跟踪 | 实施 |
| Q5 | WARN | 未含效果评估与闭环 | 评估 |

> 脚本 `recall-management_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python recall-management_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python recall-management_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。

## 九、免责声明
