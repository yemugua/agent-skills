# 安全生产标准化（safety-standardization）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据《企业安全生产标准化基本规范》GB/T 33000，生成安全生产标准化清单：目标/责任/制度/教育/现场/风险/应急/事故/绩效八要素与自评改进。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 三、工作流
1. 覆盖目标/责任/制度/教育/现场/风险/应急/事故/绩效八要素
2. 落实安全生产责任制
3. 开展风险管控与隐患排查
4. 建立应急与事故管理
5. 年度自评与持续改进

## 四、核心内容（检查清单与判定）
GB/T 33000 规定企业安全生产标准化以八个核心要素为框架，强调全员参与、风险管控与持续改进，并定期自评。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未覆盖8个核心要素 | 33000 |
| Q2 | WARN | 未含安全生产责任制 | 责任 |
| Q3 | FAIL | 未含风险管控与隐患排查 | 双重预防 |
| Q4 | WARN | 未含应急与事故管理 | 应急 |
| Q5 | FAIL | 未含自评与持续改进 | 改进 |

> 脚本 `safety-standardization_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python safety-standardization_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python safety-standardization_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
