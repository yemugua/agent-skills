# 固态硬盘寿命与健康度核查（ssd-lifespan）

固态硬盘没有转盘，但写入次数是实打实的消耗。**寿命指标要看趋势，不要看单次数值；健康度百分之百也不等于不会掉盘。**

这个技能做四件事：**读指标** → **估剩余** → **看环境** → **分掉盘原因**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 解释寿命指标的含义与读法 | ❌ 承诺还能用多少年 |
| 说明健康度百分比怎么算 | ❌ 用单一指标判断盘是否安全 |
| 说明通电时间与温度的影响 | ❌ 替代厂商工具的实际输出 |
| 区分寿命问题与非寿命问题 | ❌ 指导拆解、刷固件或改控制器设置 |
| 给出数据保留期的建议 | ❌ 保证数据一定能长期保住 |

**遇到以下情况，转交专业处理或直接换盘：**

- 健康度持续快速下降，短期掉多个百分点
- 掉盘且伴随数据校验错误（不只是读不出来）
- 系统盘位置且没有可验证的备份
- 重要数据无任何副本
- 需要开壳、改控制器或刷非官方固件才能处理的

**寿命数据以设备说明书与厂商工具的实际输出为准**，不同品牌的统计口径存在差异。

## 三、寿命指标口径

| 指标 | 含义 | 怎么读 |
|---|---|---|
| 总写入量（TBW 类指标） | 这块盘出厂时标称可承受的累计写入量 | 已用占比越低越好，看趋势 |
| 总写入量百分比 | 已写入量占标称的比例 | 接近 100% 属寿命末期 |
| 健康度百分比 | 厂商按综合指标折算的剩余寿命 | 看下降速度，不只看数值 |
| 通电时间 | 累计通电小时数 | 与写入量共同决定老化 |
| 写入次数增长 | 近期每日写入量 | 异常增长会明显加速消耗 |
| 重映射扇区 | 无法使用而被替代的单元数 | 持续增长要警惕 |

**核心口径**：**健康度是厂商折算值，不是物理剩余寿命的精确测量。** 不同厂商算法不同，跨品牌比较没有意义，同一块盘看趋势才有意义。

---

## 四、健康度百分比怎么读

| 健康度区间 | 含义 | 建议动作 |
|---|---|---|
| 100% ~ 90% | 早期，消耗少 | 正常使用，按周期记录即可 |
| 90% ~ 70% | 中期，性能与寿命仍充裕 | 确认备份完整，规划换盘时间 |
| 70% ~ 50% | 后期，建议开始准备更换 | 尽快完成备份，避免再放重要数据 |
| 50% 以下 | 末期，风险陡升 | 备份后安排更换，不要再依赖 |

**否定项提醒**：「健康度还有 50%，放心用」是误判。**寿命末期的风险不是线性上升，而是陡升。** 数据重要时，判断依据应该是备份到不到位，不是健康度还剩多少。

---

## 五、通电时间与温度对寿命的影响

| 因素 | 影响方向 | 说明 |
|---|---|---|
| 长时间通电 | 加速老化 | 常年开机的机器比间歇使用的消耗更快 |
| 高温 | 明显加速 | 高温会缩短写入单元的保持能力 |
| 频繁小量写入 | 影响相对小 | 分散写入比集中大量写入更温和 |
| 一次性大量写入 | 瞬时压力较大 | 不适合长期高频这样用 |
| 断电保存 | 有利 | 长期不用的盘应断电保存而非挂机 |

**温度口径**：温度越高，写入单元的数据保持能力衰减越快。**长期高温运行是比写入量更容易被忽略的消耗因素。**

**关于数据保留期**：**通电闲置比反复读写更容易保住数据。** 长期归档的数据，断电保存比一直挂着更稳妥。

---

## 六、寿命与掉盘的关系

**关键判断**：**掉盘不一定等于寿命到了。** 寿命富余时掉盘，要往这几个方向查：

| 可能原因 | 判断线索 |
|---|---|
| 固件缺陷或更新问题 | 健康度仍高，突然开始掉盘 |
| 供电不稳 | 特定负载或特定时刻才掉 |
| 控制器或硬件故障 | 健康度正常，读写错误持续出现 |
| 接口、线缆或转接问题 | 换线换口后表现变化 |
| 文件系统损坏 | 盘能识别但分区异常 |
| 温度过高触发保护 | 高温时掉盘，降温后正常 |

**反过来，寿命末期也未必立刻掉盘**：健康度接近耗尽时，可能还能正常工作一段时间，但**风险是陡升的**，不能按线性思维安排数据保留。

**排查顺序建议**：先确认备份 → 换线换口验证 → 看温度 → 查固件 → 再考虑硬件问题。

---

## 七、企业盘与消费盘差异

| 维度 | 消费盘 | 企业盘 |
|---|---|---|
| 标称写入量 | 通常较低 | 通常较高 |
| 掉电保护 | 部分具备 | 通常具备 |
| 持续写入表现 | 易掉速 | 更稳定 |
| 保修与服务 | 面向消费场景 | 面向数据中心场景 |
| 适用位置 | 个人设备、读多写少 | 高频写入、长时间运行 |

**选择口径**：写入频繁的用途优先看企业盘或高写入量型号；只是装系统放照片，消费盘够用。

## 八、脚本用法

```bash
python scripts/ssd_lifespan_audit.py --file ssd.json --out 核查结论.md
python scripts/ssd_lifespan_audit.py --text "health=72;tbw_used=45;power_hours=18000;temp=58;drop=yes"
python scripts/ssd_lifespan_audit.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 指标 JSON（自动兼容带 BOM 的文件） |
| `--text` | 直接写指标，用分号分隔 `键=值` |
| `--out` | 结果落盘路径 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

JSON / text 字段：`health`（健康度百分比）、`tbw_used`（已写入占标称百分比）、`power_hours`（通电小时）、`temp`（工作温度）、`drop`（是否掉盘）。

脚本输出**寿命区间判定、剩余寿命关注点、环境因素提示**，掉盘时给出非寿命原因的排查方向。

> 脚本只做口径换算与规则判定，**不读取硬盘数据**。输入以厂商工具的实际输出为准。

## 九、人工确认清单（这步不能省）

- [ ] 读过总写入量、健康度百分比、通电时间三项，不只看一个
- [ ] 知道健康度是厂商折算值，跨品牌比较没有意义
- [ ] 看过健康度的**变化趋势**，而不只是当前数值
- [ ] 确认备份完整，且做过恢复验证
- [ ] 确认工作温度，长期高温要处理散热
- [ ] 掉盘时确认过是否寿命富余
- [ ] 掉盘排查按顺序走过：换线换口、看温度、查固件
- [ ] 归档数据考虑断电保存而不是一直挂机
- [ ] 按用途（系统盘/数据盘/归档盘）分别定了保留期

## 十、最常见的坑

**坑一：只看健康度百分比这一个数。**
健康度是折算值，不反映全部因素。写入量、通电时间、温度都要一起看。

**坑二：拿不同品牌的健康度横向比较。**
各厂商算法不同，跨品牌数字没有可比性。同一块盘看趋势才有意义。

**坑三：寿命还剩一半就放心放重要数据。**
寿命末期风险是陡升的，不是线性下降。判断依据应该是备份到不到位。

**坑四：掉盘就断定是寿命到了。**
健康度富余时掉盘，更可能是固件、供电、接口或控制器问题，换方向查。

**坑五：长期高温运行不管。**
温度对数据保持能力的影响比写入量更容易被忽略，也更容易改善。

**坑六：归档数据一直挂着通电。**
长期归档的盘，断电保存比一直通电更稳妥。

**坑七：备份从来没验证过就安心。**
备份没验证过就等于没有备份，定期取回文件打开确认。

**坑八：写入量突然变高不知道原因。**
日志写入、频繁更新、缓存不足导致的写放大都可能推高每日写入量。

**坑九：把消费盘用在高频写入场景。**
持续写入场景下消费盘容易掉速，写入量标称也偏低。

**坑十：掉盘后继续往盘里写数据。**
盘已经不稳定，新写入的数据既可能不完整，也可能覆盖可恢复的内容。

## 十一、边界与免责

- 本技能**只做指标解读与核查指引**，不代用户操作硬盘或读取数据
- 寿命数据**以设备说明书与厂商工具的实际输出为准**，不同品牌统计口径存在差异
- 不承诺剩余使用年限，任何具体数值都只是估算
- 涉及开壳、控制器改造、非官方固件的，一律不由本技能指导
- 重要数据的持有责任在使用者本人，本技能不代为备份
