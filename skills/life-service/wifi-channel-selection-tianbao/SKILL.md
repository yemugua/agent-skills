# WiFi 信道选择与干扰排查（wifi-channel-selection）

网速慢，**先分清是覆盖问题还是干扰问题**。信号弱是覆盖，信号满格却慢是干扰或拥塞。两种问题的解法完全不同，混在一起调信道是白忙。

这个技能做四件事：**定性** → **扫描** → **选信道** → **验效果**。

---

## 硬边界（先看这条）

| 能做 | 不能做 |
|---|---|
| 区分覆盖问题与干扰问题 | ❌ 保证换信道一定能提速 |
| 给出 2.4G 与 5G 的信道规划建议 | ❌ 修改运营商光猫的注册与认证参数 |
| 说明信道宽度的取舍 | ❌ 建议刷第三方固件或提升发射功率 |
| 列出非 WiFi 干扰源 | ❌ 替代运营商线路故障处理 |
| 提示路由器摆放要点 | ❌ 替代企业级多 AP 的信道规划 |

**遇到以下情况，立即停止自行操作，转交运营商装维或专业网络人员：**

- 有线直连光猫也慢（是宽带或线路问题，与 WiFi 无关）
- 光猫亮红灯、频繁掉注册、入户光衰异常
- 企业、商铺、多 AP 环境需要统一信道规划与漫游
- 需要新增网线、面板、POE 供电或室内分布
- 需要改动光猫的桥接、VLAN、认证参数
- 涉及强电改造、天花板内布线、登高安装 AP

**永远不要修改光猫的注册与认证参数。** 改错会直接断网，且通常需要装维上门重新下发数据。

## 二、完整工作流

```
第 1 步  定性：用有线直连测速，排除宽带与线路问题
第 2 步  区分覆盖与干扰：信号格数 + 实测速率一起看
第 3 步  先读规则文件 rules/wifi_channel_rules.md（信道规划 + 宽度取舍 + 干扰源）
第 4 步  跑故障树脚本
    python scripts/wifi_channel_check.py --text "信号满格但网速慢，晚上特别卡"
第 5 步  扫描周边信道占用，选最空闲的信道并固定
第 6 步  设信道宽度：2.4G 用 20MHz，5G 用 80MHz（拥挤时降 40MHz）
第 7 步  调整摆放与双频策略，改完前后各测三次取中位数
```

## 三、先定性（这步跳过就是瞎调）

| 检查 | 怎么做 | 怎么读结果 |
|---|---|---|
| 有线测速 | 电脑网线直连光猫或路由器 LAN 口测速 | 有线也慢 → 宽带或线路问题，报装维 |
| 近场测速 | 站在路由器 1 米内测速 | 近场快、远处慢 → 覆盖问题 |
| 分时段测速 | 白天与晚高峰各测三次 | 晚高峰明显慢 → 拥塞或干扰 |
| 分频段测速 | 分别连 2.4G 与 5G 各测三次 | 5G 明显快 → 2.4G 拥塞 |

**判定口径**：信号满格但速率低 = 干扰或拥塞；信号格数少 = 覆盖不足。两者解法不同，**覆盖问题靠 Mesh 或有线 AP，不是靠换信道**。

---

## 四、信道规划（2.4G 与 5G 分开看）

| 频段 | 互不重叠信道 | 建议 |
|---|---|---|
| 2.4GHz | 1、6、11 | 三者中选周边占用最少的，固定使用 |
| 5GHz 低频 | 36、40、44、48 | 干扰相对少，兼容性好 |
| 5GHz 高频 | 149、153、157、161、165 | 也可用，设备支持差异较大 |
| 5GHz DFS 段 | 52-64、100-144 | 遇雷达信号会强制跳频，设备兼容性差时避开 |

- 2.4G 只有 1、6、11 三个互不重叠的信道，**邻居再多也只能三选一**
- 5G 信道多、干扰少，是优先使用的频段
- 6GHz 频段的使用以当地无线电管理规定与设备核准情况为准

---

## 五、信道宽度取舍

| 频段 | 建议宽度 | 原因 |
|---|---|---|
| 2.4GHz | **20MHz** | 40MHz 在 2.4G 几乎必然与邻居重叠，反而更慢 |
| 5GHz | 80MHz | 速率与抗干扰的较好平衡 |
| 5GHz（拥挤环境） | 40MHz | 牺牲峰值速率换取稳定性 |

**"自动信道"的坑**：很多路由器的自动信道算法切换不及时，可能半夜才调整，也可能一直停在出厂信道。手动固定往往更稳，但前提是扫过周边占用。

---

## 六、非 WiFi 干扰源（扫描软件看不见的）

| 干扰源 | 表现 | 处置 |
|---|---|---|
| 微波炉 | 工作时 2.4G 断流 | 路由器远离厨房，或改用 5G |
| 无绳电话、婴儿监视器 | 2.4G 间歇掉线 | 换新设备或改频段 |
| 无线摄像头 | 持续占用信道 | 独立划分或走有线 |
| 蓝牙设备密集 | 2.4G 抖动 | 减少同环境蓝牙数量 |
| Zigbee 物联网 | 与 2.4G 部分信道重叠 | 错开信道 |
| 金属柜、镜面、鱼缸 | 信号反射衰减 | 路由器避开这些物体 |

---

## 七、摆放与双频策略

- **位置**：尽量居中、离地 1-1.5 米、开阔无遮挡
- **远离**：承重墙、金属柜、鱼缸、微波炉、镜面
- **双频合一**：经常导致物联网设备找不到网或频繁掉线，**建议分开 SSID**
- **物联网设备**：多数只支持 2.4G，绑定 2.4G 的 SSID
- **大户型**：靠 Mesh 或有线 AP，不要指望单台换信道解决
- **Mesh 回程**：优先有线回程，无线回程要留专用频段

## 八、脚本用法

```bash
python scripts/wifi_channel_check.py --text "信号满格但网速慢，晚上特别卡，有微波炉"
python scripts/wifi_channel_check.py --file 描述.txt --out 结果.md
```

| 参数 | 说明 |
|---|---|
| `--text` | 直接给现象描述 |
| `--file` | 从文件读描述 |
| `--out` | 结果落盘路径 |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 跑内置样例自检 |

脚本按现象匹配故障树，输出**排查顺序**、每条的验证动作与处置，命中"有线也慢""光猫红灯""多 AP"等情形时输出停用并报装维的提示。

> 脚本只做关键词匹配，**不代表现场判断**。定性必须靠实测。

## 九、人工确认清单（这步不能省）

- [ ] 有线直连测过速，确认不是宽带本身慢
- [ ] 近场与远场各测过，区分覆盖与干扰
- [ ] 扫过周边信道占用，不是凭感觉选 1 或 6
- [ ] 2.4G 信道宽度设为 20MHz
- [ ] 双频是否合一，是否影响了物联网设备
- [ ] 路由器位置远离金属、鱼缸、微波炉
- [ ] 改完前后各测三次取中位数，有对比数据

## 十、最常见的坑

**坑一：网速慢就换信道。**
先做有线测速。有线也慢是宽带或线路问题，换一百次信道也没用。

**坑二：信号满格就以为没问题。**
满格只代表信号强度，不代表信道干净。满格但慢恰恰是干扰或拥塞的典型表现。

**坑三：2.4G 设 40MHz 想要更快。**
2.4G 只有三个互不重叠信道，40MHz 几乎必然与邻居重叠，实测通常更慢更不稳。

**坑四：只改信道不改位置。**
路由器塞在弱电箱里、挨着金属柜或鱼缸，信道再好也白搭。

**坑五：双频合一图省事。**
物联网设备、老设备会找不到网或频繁掉线，分开 SSID 更稳。

**坑六：迷信"自动信道"。**
算法切换不及时是常态，手动固定前先扫一遍占用情况。

**坑七：换了信道没效果就认为不是干扰。**
扫描软件看不到非 WiFi 干扰源，微波炉、无绳电话、无线摄像头的干扰扫不出来。

**坑八：大户型靠一台路由器换信道。**
覆盖问题要靠 Mesh 或有线 AP，信道解决不了穿墙衰减。

**坑九：动手改光猫参数。**
改错注册与认证参数会直接断网，需要装维上门重新下发数据。

## 十一、边界与免责

- 本技能**不替代**运营商装维与企业级网络规划
- 5G DFS 信道、6GHz 频段可用情况**以当地无线电管理规定与设备核准为准**
- 不得修改光猫注册与认证参数，不得刷第三方固件，不得超出发射功率的合规范围
- 涉及网线布设、POE 供电、天花板内布线与登高的，应由专业人员施工
- 企业、多 AP、高密度场景应做专业网规与信道规划
