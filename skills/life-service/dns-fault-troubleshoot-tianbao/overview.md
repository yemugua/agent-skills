# DNS解析故障排查 · 能力概览

## 你会得到什么

一套按五层推进、每步都有明确判定的 DNS 排查路径——DNS 故障最常见的弯路是**在你自己的机器上测通就下结论**，因为你的机器有 hosts、有本地缓存、连着内网 VPN。

**五层定位**：L1 本地（hosts + 缓存）→ L2 客户端配置（resolv.conf 可达性、ra 标志）→ L3 递归解析器（换公共 DNS 对比）→ L4 权威记录（`dig +trace`）→ L5 传输与劫持（53 端口、污染识别）。铁律是 L1 不通过不进 L2，且全程用 `dig` 而不是浏览器。

**dig 判读**：十一类常用命令（含 `+trace`、`+short`、`+tcp`、`+noall +answer +stats`）、输出七个字段的判读用途、以及六个 status 码的完整含义对照。这里有一个必须理解的点——**`NXDOMAIN` 说明 DNS 工作正常**，它的含义是「域名不存在」，通常是记录被删、拼写错误或域名过期未续费；把它当 DNS 故障排查半天是最常见的弯路。

**TTL 与缓存**：五层缓存层次、四档常见 TTL 取值、变更记录的标准四步（**先把 TTL 降到 300 并等旧 TTL 过期，再改记录**），以及各系统的缓存清理命令，含最容易被忽略的 JVM 独立 DNS 缓存和浏览器独立缓存。

**污染识别**：六个污染特征（返回 IP 归属无关、多个无关域名同址、随机不存在域名也能解析、返回 `0.0.0.0` 等占位地址等）与识别命令。核心结论是**不能只在客户端绕过——问题在链路上，换机器照样中招**。

**脚本**：`scripts/dns_diagnose.py` 读取五层观测数据，输出定位层级、归因结论与分步排查命令树，并强制区分「本地缓存问题」与「权威记录问题」——后者该找域名服务商，而不是继续在本地折腾。

## 典型用法

1. 域名解析不了：按五层命令树逐层采集，不跳步。
2. 改了记录不生效：看 TTL，`记录改动时间 + TTL > 现在` 就是还没生效。
3. dig 正常但浏览器打不开：清浏览器独立 DNS 缓存，用无痕窗口对比。
4. 部分人能访问部分不能：对比各人机器的 hosts 与 DNS 配置，本地层差异是首要怀疑对象。
5. 疑似 DNS 污染：用随机不存在域名 + 多域名同址两个特征确认，然后转网络与安全团队。

## 边界

- 只做**定位路径规划与现象判读**，不代替现场网络与域名配置变更
- **全程用 dig 而不是浏览器测试**——浏览器有独立 DNS 缓存，两边结论可能相反
- 修改解析记录、NS 记录、注册商信息**必须经授权并走变更流程**，记录 TTL 与变更时间
- 遇到 **DNS 劫持或疑似污染**应转网络管理与安全专业人员，不在客户端自行绕过
- 脚本**不发起任何 DNS 查询**，只归拢观测结果；缺任何一层数据时结论只能到已有数据的边界
- 未备案域名、跨境解析、特殊行业域名的合规要求，**以现行规定和当地主管部门要求为准**
