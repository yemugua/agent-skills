# 零缺陷管理（zero-defect）

> 领域：质量 ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据零缺陷（ZD）管理理念与质量成本管理方法，生成清单：需求明确与标准共识、源头预防与过程控制、一次做对意识培养、缺陷根因闭环、质量成本与激励。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 零缺陷管理
- 一次做对
- 缺陷预防
- 零缺陷班组
- 质量意识提升

## 三、工作流
1. 明确需求并达成标准共识
2. 强化源头预防与过程控制
3. 培养一次做对意识
4. 推动缺陷根因闭环
5. 运用质量成本与激励

## 四、核心内容（检查清单与判定）
零缺陷的核心是「第一次就把事情做对」，强调预防而非检验；将质量成本可见化并与正向激励结合，避免把 Zero Defect 简单等同于惩罚。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含需求明确与标准共识 | 需求 |
| Q2 | FAIL | 未含源头预防与过程控制 | 预防 |
| Q3 | WARN | 未含一次做对意识培养 | 意识 |
| Q4 | FAIL | 未含缺陷根因闭环 | 闭环 |
| Q5 | WARN | 未含质量成本与激励 | 激励 |

> 脚本 `zero-defect_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python zero-defect_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python zero-defect_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
