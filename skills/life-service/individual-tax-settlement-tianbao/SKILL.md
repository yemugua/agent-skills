# 个人所得税年度汇算清缴办理核查

汇算清缴的核心公式只有一行，但**每一项扣什么、扣多少、已预缴多少**全都要对得上。扣错一项，算出来的补退税额能差出好几千。

这个技能做五件事：**算应纳税所得额 → 套税率表 → 比已预缴 → 判要不要办 → 核截止与逾期**。

---

## 一、硬边界

| 能做 | 不能做 |
|---|---|
| 按给定数据核算应纳税额与应退/应补税额 | 登录个税 App 代为申报、代为确认退税账户 |
| 判断是否需要办理、是否可能免于办理 | 承诺一定能退税、一定能免于办理 |
| 对比全年一次性奖金两种计税方式 | 提供拆分收入、转换所得性质、虚增扣除的避税方案 |
| 提示办理时间、渠道、材料与逾期后果 | 代替税务机关作认定或核定 |
| 解释补退税差异的常见来源 | 编造收入、扣除或已预缴数据 |

涉及以下情形，应停下来交由税务机关、扣缴义务人、税务师或律师处理：**境外所得、股权激励、解除劳动关系一次性补偿、合伙与个体工商户经营所得、两处以上工资薪金且口径复杂、已收到税务机关核查或处罚通知**。

**绝对不做**：不虚增扣除、不隐瞒收入、不提供任何以少缴税为目的的虚假安排。

## 二、什么时候用

| 用户说法 | 用不用 |
|---|---|
| 「我今年汇算是退税还是补税」 | 用，按数据核算 |
| 「能退多少钱 / 要补多少钱」 | 用，算差额 |
| 「汇算什么时候截止」 | 用，按年度汇算期核 |
| 「奖金单独计税划算还是并入划算」 | 用，两种方式各算一遍 |
| 「我这点收入不用汇算吧」 | 用，按是否需要办理与能否免于办理判断 |
| 「逾期了怎么办、有没有滞纳金」 | 用，给口径并提示尽快办理 |
| 「怎么把税做少一点」 | 不用，拒绝提供避税筹划方案 |
| 「公司怎么代扣代缴」 | 看情形，属于扣缴义务的用对应核查 |

## 三、完整工作流

```
第 1 步  确定纳税年度与居民个人身份
第 2 步  读规则文件 rules/settlement-rules.md（公式、税率表、免于办理情形、时间口径）
第 3 步  归集收入：工资薪金、劳务报酬、稿酬、特许权使用费四项综合所得
第 4 步  归集扣除：基本减除费用 6 万、专项扣除、专项附加扣除、其他扣除
第 5 步  取已预缴税额：以个税 App 或扣缴义务人提供的预缴数据为准，不要估算
第 6 步  跑脚本核算：scripts/tax_settlement_calc.py --file case.json
第 7 步  判补退：应纳税额 − 已预缴 > 0 为补税，< 0 为退税
第 8 步  判是否需要办理：结合收入水平、补税金额与是否申请退税
第 9 步  奖金方式对比：单独计税与并入综合所得各算一遍，取税负低者（以本人申报选择为准）
第 10 步 办理与归档：在汇算期内完成申报，保存申报结果与凭证
```

## 四、核心计算口径

### 4.1 计算公式

```
综合所得年收入额 = 工资薪金 + 劳务报酬(×80%) + 稿酬(×56%) + 特许权使用费(×80%)

应纳税所得额 = 综合所得年收入额
             − 60000                    （基本减除费用）
             − 专项扣除                  （基本养老保险、基本医疗保险、失业保险等个人负担部分）
             − 专项附加扣除               （子女教育、婴幼儿照护、继续教育、大病医疗、
                                          住房贷款利息或住房租金、赡养老人）
             − 依法确定的其他扣除         （个人养老金、商业健康险等，按各自限额）

应纳税额 = 应纳税所得额 × 适用税率 − 速算扣除数

应退或应补税额 = 应纳税额 − 已预缴税额
   > 0  → 应补税
   < 0  → 应退税（可申请退税）
```

**应纳税所得额可以为负**：为负时应纳税额为 0，已预缴的部分可申请退税。**不要把负数当成 0 之后就以为没有退税。**

### 4.2 七级超额累进税率表（综合所得，年度）

| 级数 | 全年应纳税所得额 | 税率 | 速算扣除数 |
|---|---|---|---|
| 1 | 不超过 36000 元的部分 | 3% | 0 |
| 2 | 36000 – 144000 元 | 10% | 2520 |
| 3 | 144000 – 300000 元 | 20% | 16920 |
| 4 | 300000 – 420000 元 | 25% | 31920 |
| 5 | 420000 – 660000 元 | 30% | 52920 |
| 6 | 660000 – 960000 元 | 35% | 85920 |
| 7 | 超过 960000 元 | 45% | 181920 |

> 税率表为现行综合所得适用口径，**以现行税法及税务机关口径为准**。

### 4.3 全年一次性奖金两种方式

| 方式 | 计算 | 适用 |
|---|---|---|
| 单独计税 | 应纳税额 = 奖金全额 × 适用税率 − 速算扣除数，其中税率按「奖金 ÷ 12」查**按月换算后的综合所得税率表** | 按现行政策可在一定期限内选择，以公布口径为准 |
| 并入综合所得 | 奖金并入综合所得年收入，按年度税率表统一计算 | 与单独计税对比后选择 |

**两种方式都要算，不能凭印象选。** 收入结构不同，结论可能相反。

### 4.4 是否需要办理与免于办理（口径）

| 情形 | 判断 |
|---|---|
| 已预缴税额 > 应纳税额，且不申请退税 | 可以不办理年度汇算 |
| 已预缴税额 > 应纳税额，且申请退税 | 需办理 |
| 已预缴税额 < 应纳税额，需补税 | 原则上需办理；但按现行规定，**年度综合所得收入不超过 12 万元**，或**汇算需补税金额不超过 400 元**的，属于可免于办理的情形（**以税务机关公布口径为准**） |
| 已预缴税额 = 应纳税额 | 无需办理 |
| 取得综合所得且有多处任职受雇、或有劳务报酬等情形 | 通常需要办理以归集数据 |

**判断顺序**：先看要不要补税 → 再看收入与补税额是否落在免于办理区间 → 最后看是否申请退税。**不申请退税的退税情形可以不办，但补税情形必须按口径判断。**

### 4.5 时间口径与逾期后果

| 项目 | 口径 |
|---|---|
| 办理期间 | 一般在**次年 3 月 1 日至 6 月 30 日**，具体起止日期以税务机关公告为准 |
| 截止 | **次年 6 月 30 日**（以公告为准） |
| 逾期未办理补税 | 税务机关责令限期改正，可并处罚款；从滞纳税款之日起**按日加收滞纳金**（按税法规定执行，以税务机关核定为准） |
| 未办理年度汇算的申报责任 | 纳税人对申报数据的真实性、准确性、完整性负责 |

**注意**：退税是权利，补税是义务。逾期不办补税，滞纳金按日累积，**拖得越久越多**；退税则应在汇算期内主动申请。

### 4.6 防误伤（否定词清单）

- 「已预缴税额 > 应纳税额」→ 判为**可申请退税**，不得写成「应补税」
- 「应纳税所得额 ≤ 0」→ 判为**应纳税额为 0**，不得写成「无需申报且无退税」
- 「不征税」≠「免税」；「免税」≠「零税率」，三者不得混用
- 「补税金额不超过 400 元」→ 判为**可能免于办理**，不得写成「无需申报」的绝对结论，需以税务机关口径为准
- 「已申报未缴款」→ 判为**未完成**，不得写成「已办结」
- 「待确认」「暂存」→ 判为**未完成申报**，不得写成「已申报成功」
- 「预缴数据为估算」→ 判为**数据未核实**，不得用于最终结论

## 五、核心规则与要件库

出结论前，**必须先读**：

- `rules/settlement-rules.md`：公式与税率表、收入归集口径、扣除口径、是否需要办理与免于办理、奖金计税方式对比、办理时间与渠道、逾期后果、常见差异来源与更正路径。

不得用估算的已预缴税额下最终结论，不得把「不申请退税」等同于「不能退税」。

## 六、脚本用法

```bash
python scripts/tax_settlement_calc.py --file case.json --out 汇算测算.md
python scripts/tax_settlement_calc.py --selftest
```

| 参数 | 说明 |
|---|---|
| `--file` | 输入 JSON：年度、综合所得收入、专项扣除、专项附加扣除、其他扣除、已预缴税额、全年一次性奖金（可选） |
| `--text` | 直接给 JSON 字符串 |
| `--out` | 结果写入指定文件，默认写 `scripts/_last_result.txt` |
| `--format` | `md`（默认）或 `json` |
| `--selftest` | 运行内置自检 |

输入 JSON 示例：

```json
{
  "year": 2025,
  "annual_income": 240000,
  "special_deduction": 30000,
  "additional_deduction": 36000,
  "other_deduction": 12000,
  "prepaid_tax": 9000,
  "bonus": 60000,
  "apply_refund": true
}
```

脚本输出：应纳税所得额、适用税率与速算扣除数、应纳税额、已预缴税额、应退或应补金额、是否需要办理的提示、奖金单独计税与并入综合所得的两种方式对比及差额、截止与逾期提示。

> 脚本按你填的数据做静态测算，**未含境外所得、股权激励、经营所得、减免税额等特殊情形**；已预缴税额应以个税 App 或扣缴义务人提供的数据为准，最终以税务机关口径为准。

## 七、人工确认清单（这步不能省）

- [ ] 收入含全部任职受雇单位，不只是主职那一家
- [ ] 劳务报酬、稿酬、特许权使用费已按各自口径折算并入
- [ ] 专项扣除（三险一金个人负担部分）取自实际缴费记录，不是估算
- [ ] 专项附加扣除逐项核对标准与分摊方式
- [ ] **已预缴税额取自个税 App 或扣缴义务人数据**，不是估算
- [ ] 全年一次性奖金两种方式都算过，选择有依据
- [ ] 补税情形已判断是否需要办理、是否可能免于办理
- [ ] 退税情形已确认银行账户信息准确无误
- [ ] 在汇算期内完成申报，并保存申报结果与回执
- [ ] 申报数据与合同、工资单、缴费记录能对上

## 八、最常见的坑

1. **用估算的已预缴税额算补退。** 已预缴税额必须取自个税 App 或扣缴义务人提供的实际数据。估错了，整个补退税结论就是反的。
2. **漏掉第二家任职受雇单位的收入。** 换过工作、有兼职、有劳务报酬的，收入要归集全。漏一家，往往从退税变成补税。
3. **把应纳税所得额为负当成「没税也没退税」。** 应纳税所得额为负时应纳税额为 0，**已预缴的部分是可以申请退还的**。
4. **以为「不用补税」就等于「不用办理」。** 是否需要办理与是否补税是两个问题：申请退税的，即使不用补税也要办理。
5. **奖金计税方式凭印象选。** 单独计税与并入综合所得的结论随收入结构变化，必须两种方式各算一遍再选。
6. **专项扣除按整数估。** 三险一金个人负担部分应按实际缴费记录取，与社保缴费基数挂钩，估算会导致应纳税所得额偏离。
7. **拖到 6 月 30 日之后才办补税。** 补税逾期的滞纳金按日累积，且可能被责令限期改正并处罚款。**汇算期一开始就可以办，不要等。**
8. **把「不征税」当「免税」、把「免税」当「零税率」。** 三者税务处理不同，表述混用会在后续核查中造成误判。
9. **申报完不看结果。** 提交不等于办结。要确认申报状态、补税是否已缴、退税是否已到账。

## 九、边界与免责

- 本技能用于汇算前测算与材料整理，**不构成税务代理或法律意见**，不替代纳税人自行申报与税务机关认定
- 税率表、扣除口径、免于办理情形、办理时间与逾期处理，**均以现行税法及税务机关公布口径为准**
- 本测算为**静态口径**，未含境外所得、股权激励、经营所得、减免税额、跨年度结转等特殊情形
- **不承诺一定能退税、一定能免于办理、一定按某个金额补退**
- 不提供虚增扣除、隐瞒收入、转换所得性质的任何方案；涉及补税、滞纳金、处罚或争议，应及时咨询税务师或律师
