# 安全观察与隐患上报（safety-observation-card）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据行为安全观察与全员隐患排查要求，生成清单：观察卡要素与填写规范、观察频次与覆盖面、沟通式反馈而非指责、数据聚合与趋势分析、整改闭环与趋势预警。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 安全观察卡
- 行为安全观察
- 隐患随手拍
- 观察数据统计
- 隐患上报闭环

## 三、工作流
1. 规范观察卡要素与填写要求
2. 落实观察频次与覆盖面
3. 采用沟通式反馈而非指责
4. 聚合数据并分析趋势
5. 督促整改闭环与趋势预警

## 四、核心内容（检查清单与判定）
观察一旦变成挑错工具就会被抵制。要点是把焦点放在安全的作业方式上并以请教口吻沟通，用数据看趋势而非用数量压人。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含观察卡要素与填写规范 | 要素 |
| Q2 | WARN | 未含观察频次与覆盖面 | 频次 |
| Q3 | FAIL | 未含沟通式反馈而非指责 | 反馈 |
| Q4 | WARN | 未含数据聚合与趋势分析 | 趋势 |
| Q5 | WARN | 未含整改闭环与趋势预警 | 预警 |

> 脚本 `safety-observation-card_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python safety-observation-card_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python safety-observation-card_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
