# 现场急救与救护员管理（first-aid-responder）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据现场救护指南与 GB/T 相关培训要求，生成清单：救护员配置比例与持证、急救箱配置与药品效期、常见伤情处置流程、AED 配置与心肺复苏、送医绿色通道与演练。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 现场急救管理
- 救护员配置
- 急救箱清单
- 心肺复苏 CPR
- AED 配置

## 三、工作流
1. 配置救护员比例并持证
2. 规范急救箱配置与药品效期
3. 明确常见伤情处置流程
4. 配置 AED 并掌握心肺复苏
5. 建立送医通道并演练

## 四、核心内容（检查清单与判定）
心搏骤停的黄金抢救时间仅 4 分钟，等救护车往往来不及。救护员与 AED 的现场可及性、以及平时演练的熟练度，直接决定生死结局。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含救护员配置与持证 | 救护员 |
| Q2 | FAIL | 未含急救箱配置与药品效期 | 急救箱 |
| Q3 | WARN | 未含常见伤情处置流程 | 流程 |
| Q4 | WARN | 未含 AED 与心肺复苏 | AED |
| Q5 | WARN | 未含送医通道与演练 | 演练 |

> 脚本 `first-aid-responder_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python first-aid-responder_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python first-aid-responder_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
