# 停止作业权机制（stop-work-authority）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据全员安全管理与不安全行为干预理念，生成清单：授权对象与适用范围、叫停流程与汇报要求、免责保护与反报复承诺、叫停后处置与恢复作业、数据统计与文化培育。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 停止作业权
- 员工叫停作业
- 不安全条件干预
- 安全免责文化
- 叫停作业流程

## 三、工作流
1. 明确授权对象与适用范围
2. 建立叫停流程与汇报要求
3. 提供免责保护与反报复承诺
4. 规范叫停后处置与恢复作业
5. 统计数据并培育安全文化

## 四、核心内容（检查清单与判定）
若叫停后会被追责或耽误工期，机制必然名存实亡。公开表彰有效叫停并保证不影响绩效，是把停止作业权真正用起来的前提。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含授权对象与适用范围 | 授权 |
| Q2 | FAIL | 未含叫停流程与汇报要求 | 流程 |
| Q3 | FAIL | 未含免责保护与反报复承诺 | 免责 |
| Q4 | WARN | 未含叫停后处置与恢复作业 | 恢复 |
| Q5 | WARN | 未含数据统计与文化培育 | 统计 |

> 脚本 `stop-work-authority_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python stop-work-authority_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python stop-work-authority_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。

## 九、免责声明
