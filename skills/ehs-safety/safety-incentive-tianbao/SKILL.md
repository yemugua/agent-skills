# 安全激励与举报奖励（safety-incentive）

> 领域：EHS ｜ 作者：刘天宝｜墨燊 ｜ House Style 合规技能

## 一、硬边界（什么场合用 / 不碰）
**使用场景**：依据安全生产举报奖励与安全文化建设要求，生成清单：正负激励组合设计、举报渠道与匿名保护、奖励标准与兑现时效、结果型与行为型指标平衡、瞒报防范与负面效应控制。
**不适用**：非本行的通用咨询、法律诉讼代理、与现行规范冲突的诉求。所有结论须以**现行有效**法规/标准为准，本技能不做最终合规裁定。

## 二、使用场景（触发词）
- 安全激励方案
- 隐患举报奖励
- 安全生产举报
- 三违考核办法
- 举报人保护

## 三、工作流
1. 设计正负激励组合
2. 建立举报渠道与匿名保护
3. 明确奖励标准与兑现时效
4. 平衡结果型与行为型指标
5. 防范瞒报与负面效应

## 四、核心内容（检查清单与判定）
只按事故数奖励会诱导瞒报。应鼓励上报未遂事件与隐患，并严格保护举报人，让主动上报被认可而不是被追责。

| 编号 | 等级 | 检查项 | 依据 |
|---|---|---|---|
| Q1 | FAIL | 未含正负激励组合设计 | 组合 |
| Q2 | FAIL | 未含举报渠道与匿名保护 | 保护 |
| Q3 | WARN | 未含奖励标准与兑现时效 | 兑现 |
| Q4 | WARN | 未含结果型与行为型指标平衡 | 指标 |
| Q5 | FAIL | 未含瞒报与负面效应防范 | 瞒报 |

> 脚本 `safety-incentive_check.py` 可对上述清单做自检：传入 JSON 记录，输出 FAIL/WARN 与命中条款。

## 五、脚本用法
```bash
# 对单条记录核查
python safety-incentive_check.py --file record.json --today 2026-10-13
# 自检（内置 good/bad 样本断言）
python safety-incentive_check.py --selftest
```
退出码 0=通过，1=存在 FAIL 或自检未过。

## 六、人工确认事项
- 法规条款以最新发布版本为准，标准更新后须复核本清单依据。
- 重大隐患/高风险判定需由具备资质人员签字确认。
- 涉及行政处罚或争议时，以主管部门认定为准。

## 七、输出结构
- 核查结论（通过/存在不符合项）
- 不符合项明细（编号/等级/条款/说明）
- 整改建议与闭环时限
- 留痕记录（谁/何时/依据）

## 八、常见坑
- 把"建议"当"强制"，混淆规范性条文与推荐性条文。
- 漏查时效性：证书、检测报告、许可证均有时效，过期即不符。
- 只看有无、不看有效性（如制度上墙但从未演练）。
- 样本数据造假：自检用随机样本，不等于真实合规。
