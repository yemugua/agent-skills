# 更新日志

格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

**版本号规则**：保险库格式（`docs/FORMAT.md` 里的 `FORMAT_VERSION`）与软件版本分开。
只要 `FORMAT_VERSION` 还是 1，任何新版本都能打开旧保险库；破坏格式的改动一定会升
`FORMAT_VERSION`、附带迁移工具，并保留旧格式的解密代码。

## [0.1.0] - 2026-10-27

第一个可发布版本。

### 新增

- **保险库**：一个普通文件夹即一个库，可整份复制、改名、放 U 盘；不挂载盘符、不装驱动。
- **加密方案**：Argon2id 派生 KEK（64 MiB / 3 轮 / 4 并行）→ XChaCha20-Poly1305 包装随机主密钥 →
  每个文件独立 FK → 1 MiB 分块流式 AEAD，分块 AAD 绑定「域名 + 文件 id + 块序号 + 是否末块」，
  重排、截断、跨文件拼接都会在解密时报认证失败。
- **文件名也是密文**：索引 `index.enc` 由主密钥加密，磁盘上只看到无意义 UUID。
- **类型**：图片、视频、文档、任意文件均可导入；图片自动生成加密缩略图，库内直接预览。
- **目录结构**：导入文件夹时把「所选文件夹名 + 里面的相对路径」一起记进加密索引（`Item.path`，
  可选字段，旧库照常打开），整库导出按原样还原目录树。索引被篡改时 `path` 一律当不可信输入处理，
  越界路径降级成纯文件名。
- **方块平铺，点进去看**：加密进去的是一个文件夹，库里就是**一个黄色文件夹方块**，和文件卡片排在
  同一张网格里、文件夹排最前；方块上只显示名字、文件数与合计大小（数字按整棵子树汇总）。
  **点方块走进这一层**，里面的子文件夹仍然是方块，不会被移出来拉平成并排的长栏；顶部一条面包屑
  `库名 › 这一级 › 再下一级`，点哪段回哪段，另有「‹ 上一级」按钮和 `Esc` 退回。
  单个导入的文件仍然直接是卡片，跟文件夹并排放在根目录那一层。
  搜索是全库范围的：命中结果直接摊平给你看，卡片上标出它原来在哪个文件夹里，绝不会搜到了却看不见。
  方块上有「打开」和「删除文件夹」：这一整枝（连子文件夹）一次删掉，走同一个批量删除通道，
  索引只落盘一次；删的只是库里的密文，磁盘上你自己的那个文件夹不会被碰。
- **全部导出**：一次把整库解密到一个目录，带进度条与取消；取消只保证「当前这个文件做完」，
  已解出的文件照常留在目标目录里。
- **多选与批量删除**：每张卡片和每个文件夹方块左上角一个勾选框，勾方块就是连子文件夹整批选中；
  工具栏「全选」按当前这一层算（在根目录就是整个库，走进文件夹就是这一层连它所有子文件夹，
  搜索时就是筛选结果），底部选择条显示「已选 N 个 · 合计大小」，
  点「删除所选」一次删完——清单在内存里改完，**索引只落盘一次**，几百个文件也不用一个个确认。
  确认框点名前几个文件并提醒「库里只有一份密文」；`Esc` 或「取消选择」清空选择，不碰任何文件；
  个别没删掉的单独报数量与原因。
- **原件处理**：导入完成会问一句要不要删掉原件；工具栏另有「清理原件」，随时选一个文件夹扫描，
  把文件名与大小都能和库里对上的原件一次挑出来删。两条路都默认保留，勾选之后仍然逐个先验证
  库内密文确实能解开，验不过、磁盘大小与记录不一致、原件已挪位、不是普通文件的都拒绝删并说明原因；
  保险库自己写出来的条目（`vault.json`、`index.enc`、`blobs/`、`thumbs/`）永远在拒绝之列。
- **界面**：中文，创建/解锁/拖拽导入/库内预览/导出/改名/删除；无操作 10 分钟自动锁定，`Ctrl+L` 立即锁定，
  `Esc` 先取消勾选、没勾选时退回上一层文件夹。
- **配色**：暖白浅色为默认（首次运行跟随系统），右上角一键切深色，选择存在本机 `localStorage`；
  两套主题各 40 余个颜色变量，两种主题下的正文/次要文字/按钮文字对比度都实测 ≥ 4.5:1。
- **名称**：软件叫「秘匣」。磁盘上的格式标识（`MIXIA01`、`MIXBLOB1`、所有 `mixia-*-v1` AAD 域名）
  和 crate / 可执行文件名 `mixia`、`mixia-cli` 都不跟着改——它们是格式的一部分，改了会让已有保险库解不开；
  拼音一致，所以改名不动 `FORMAT_VERSION`，也不需要迁移。
- **临时明文**：双击打开时解密到 `%TEMP%\mixia-<uuid>`，锁定或退出即删除；启动时清理 24 小时以上的残留目录。
- **完整性体检**：`Vault::verify()` 逐个把密文解密到空设备，校验认证标签与长度，不写出任何明文。
- **逃生通道 `mixia-cli`**：不依赖图形界面的命令行工具，支持 `info` / `list` / `verify` /
  `export` / `extract` / `create` / `import` / `set-password`；`extract` 同样按记录的相对路径还原目录树。
- **公开格式规范** `docs/FORMAT.md`：任何语言、任何人只要按文档就能解开一个库，不依赖本项目。
- **威胁模型** `SECURITY.md`：明确写出「防什么」与「不防什么」。
- **许可证**：代码 GPL-3.0；文档与格式规范 CC BY 4.0。
- **CI**：`.github/workflows/build.yml` 在 windows-latest 上构建 release、跑 18 项测试、
  产出 `SHA256SUMS.txt` 并打包发布；其中 2 项是 `mixia-cli` 的端到端契约测试
  （起真进程建库、导入、体检、整库解出并逐字节比对，再篡改一个密文字节确认 `verify` 退出码为 2）。

### 修复

- **库建在照片文件夹里时导入没有任何反应**：候选扫描原先把「路径在保险库目录之下」整片跳过，
  于是把库建在自己的照片文件夹里之后，选同一堆照片会一个都不剩，而界面收到 `total: 0` 就直接 return，
  既不报错也不提示，看起来像按钮坏了。现在只排除保险库自己写出来的四样东西，
  同目录下的用户文件照常加密进去；真的一个候选都没有时，后端给出原因，界面明确提示，
  取消选择仍然是安静的。`cargo test` 里新增两项覆盖这条路径，包括 Windows 下
  `fs::canonicalize` 带 `\\?\` 前缀时前缀比较也对得上。

### 已知限制

- 只有 Windows。macOS / Linux 的构建没有验证过（代码本身是跨平台的，缺的是打包与图标）。
- 没有增量备份、没有多设备同步，也不会有——同步会破坏「零网络」这个前提。
- 缩略图只对图片生成；视频和文档没有预览。
- 忘记密码无法恢复。这是设计，不是缺陷，见 `SECURITY.md`。
- 更大的文件只受磁盘速度限制，尚未做压力测试；自动化测试覆盖的边界是空文件、
  非整块长度（2 MiB + 123 B）与整块倍数（2 MiB）。

### 安全

- 从创建到删除、从加密到解密，全程不产生任何网络请求。
  这条声明是可验证的：`Cargo.toml` 里没有 HTTP/TLS 客户端依赖，
  `tauri.conf.json` 的 CSP 只放行 `ipc:` 与本地资源。
