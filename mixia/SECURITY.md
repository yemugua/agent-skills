# 安全说明与威胁模型

加密软件最怕的不是有漏洞，而是**用户以为它防的东西和它实际防的东西不是一回事**。
所以这一页请在使用前读完。

## 一句话概括

秘匣保护的是**离开这台电脑之后的文件**：U 盘被捡到、电脑被偷走、
保险库文件夹被误发给别人、云盘里存了备份被人下载。

它**不保护**正在使用中的这台电脑。

## 秘匣防什么

| 场景 | 是否防护 | 说明 |
| --- | --- | --- |
| 保险库文件夹被拷走 / 电脑丢失被盗（关机状态） | ✅ | 没有密码，`blobs/` 里任何一块都过不了 Poly1305 认证 |
| 文件名、目录结构、文件大小泄露 | ✅（大小除外） | 名称、类型、MIME 都在加密索引里；密文块长度会暴露"大约是几 MiB" |
| 别人拿到库但没有密码 | ✅ | Argon2id 64 MiB × 3 轮 × 4 并行，离线爆破成本被刻意拉高 |
| 有人篡改/删除/调换某个密文块 | ✅ | 块号与 final 标志绑进 AAD，`chunks` 与总长度再各查一次 |
| 用 A 文件的块拼出 B 文件 | ✅ | AAD 里含文件 id 与 `blob`/`thumb` 域分隔 |
| 密码被改后旧密码仍能用 | ✅ | 改密码重新包装主密钥，旧 KEK 立即失效 |
| 保险库被误删一半（写入中断电） | ✅ | 临时文件 + rename 原子写，索引不会指向不存在的块 |

## 秘匣不防什么（重要）

| 场景 | 是否防护 | 为什么 |
| --- | --- | --- |
| 电脑正开着、库正解锁着，别人坐到面前 | ❌ | 解锁期间密钥在内存里，任何程序都能读。请用 `Ctrl+L` 或离开前锁定 |
| 键盘记录器、远控、恶意软件 | ❌ | 系统被控制时密码必然泄露，这是任何本机加密软件都躲不掉的 |
| 已解锁时"打开"生成的临时明文副本被取证恢复 | ❌ | 锁定/退出会删除临时目录，但**普通删除不是安全擦除**：SSD 磨损均衡、文件系统日志、休眠文件和卷影副本都可能留下旧副本 |
| 冷启动攻击、DMA 攻击 | ❌ | 需要物理接触与专业设备，超出本机软件能做的范围 |
| 你忘了密码 | ❌ | **没有任何后门、没有找回、没有超级密码。** 忘了就是永久丢失 |
| 磁盘坏道、误格式化导致密文损坏 | ⚠️ 只能发现，不能修复 | `verify` 能告诉你哪个文件解不开，但坏了的数据变不回来——所以必须自己备份 |
| 别人用你的账号登录系统后直接运行秘匣 | ❌ | 秘匣没有独立身份认证，依赖操作系统账号 |

如果你的威胁模型里包含"正在使用的这台电脑"，请配合使用：
Windows 自带的 BitLocker（全盘加密）+ 强登录密码 + 关闭休眠，
或者离开时锁定系统。**秘匣和 BitLocker 是互补的，不是替代关系。**

## 已知设计限制

1. **密码长度下限 8 位**，且不强制字符类型。密码强度决定离线爆破难度，
   建议用一句只有你自己记得住的长口令（15 字符以上），而不是"大写+符号+数字"的短口令。
2. **Argon2 参数写死在库里**（64 MiB / 3 轮 / 4 并行）。设备更强了以后可以提高，
   但老库不会自动升级参数，需要改一次密码来重新派生。
3. **文件被"打开"时会写出明文副本**到 `%TEMP%\mixia-<uuid>\`，用系统默认程序打开。
   那个程序保存时可能另存新副本、生成缩略图缓存——这些都不在秘匣控制范围内。
   改完记得重新导入并删除旧条目。
4. **未做第三方审计。** 代码是可审计的（见 `docs/FORMAT.md`），
   但"开源"不等于"已验证安全"。放极其重要的东西之前，请先小量试用并保留原始文件一段时间。
5. **不防"你自己"**：秘匣不会替你备份。整个保险库文件夹复制到另一块盘就是备份，
   但请把它当成同样敏感的数据来存放。

## 备份与恢复

- **备份**：直接复制整个保险库文件夹。秘匣不依赖注册表、不依赖系统目录、不依赖云。
- **换电脑**：把文件夹拷过去，用同一份密码打开即可。
- **秘匣停更了怎么办**：格式规范在 `docs/FORMAT.md`，并有命令行工具
  `mixia-cli extract <保险库目录> <输出目录>` 可以整库解出。你也可以用任何语言按规范重写。
- **体检**：定期跑 `mixia-cli verify <保险库目录>`，它会逐块解密认证但**不写出任何明文**，
  能在真正需要之前发现磁盘静默损坏。

## 网络行为

秘匣不发起任何网络请求：没有统计、没有检查更新、没有崩溃上报、没有许可验证。
`tauri.conf.json` 里的 CSP 只允许 `ipc:` 与本地资源。
这是可以验证的——用防火墙拦掉该进程，所有功能照常；抓包为空。

## 发现漏洞怎么办

- 通过仓库的 **Private Vulnerability Reporting** 提交（GitHub → Security → Report a vulnerability），
  只有你和 maintainer 能看到，这是首选渠道。
- 不方便用 GitHub 的话，用仓库资料里我的邮箱联系。
- 请在公开披露前给我 30 天修复窗口。影响他人数据完整性的问题优先级最高。
- 我不承诺赏金，但会把致谢写进 release notes（除非你要求匿名）。
